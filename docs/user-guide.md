# YummyAI 使用指南

本指南面向 YummyAI 的业务使用者和本地管理员，说明如何从竞品研究开始，完成产品、设计、Listing、订单履约以及 P3 经营分析。

YummyAI 是一个面向 Amazon、Etsy 定制及 POD 商品的多租户 ERP。当前本地功能主体已经实现；真实店铺发布、订单同步、库存报告、结算和广告数据仍需要相应平台的正式授权。

创意项目、订单详情和生产文件详情现有「AI 分析 / 预审 / 预检」入口。在 **系统配置 → AI 模型配置** 添加并启用文本模型后，业务助手自动共用服务端配置；分析图片时，所选模型还须支持图像输入和结构化输出。手动开始分析，核对建议后填入草稿，保存、推送与审核沿用原流程。详见 [AI 辅助使用与配置说明](integration/ai-assists.md)。

第二批新增：**来图定制 → 导入检查**中的 PSD 模板配置助手，以及 **Listing → Content** 中的 SKU 资料包助手。订单详情新增「模板制图条件」，先保存并检查字段，再选择模板自动制图和确认推送。模板建议与文案都先填入可编辑草稿，正式审核仍需人工完成。

第三批新增：**财务利润 → 经营 AI 分析**、**采购与库存 → 采购 AI 分析**，以及售后单中的 **售后 AI 分析与回复草稿**。先选择分析对象并「读取分析依据」，核对缺项，再用已配置模型分析。经营数字和补货量由系统计算；售后可另填问题说明，生成英文或中文草稿供编辑、复制，原始客服消息和附件不会自动发送给模型。AI 建议不自动创建采购单、退款或发送回复，旧资料变化后需要刷新分析依据。

## 1. 快速开始

### 1.1 环境要求

- Node.js 24.17.x
- pnpm 11.10.x
- Docker Desktop 与 Docker Compose v2
- Chrome 或 Edge

不要使用 npm、Yarn 或其他包管理器重新生成锁文件。

### 1.2 启动系统

在项目根目录执行：

```powershell
Copy-Item .env.example .env
pnpm install --frozen-lockfile
pnpm infra:up
pnpm --filter @yummyai/database db:migrate
pnpm --filter @yummyai/api bootstrap:local
pnpm dev
```

默认启动行为保持完整：基础设施包括 PostgreSQL、Redis、MinIO、Keycloak、ClamAV 与遥测采集器，开发进程包括 API、Web、Worker 与浏览器扩展热更新。

只进行同步 API 与 Web 开发时，可以从已停止的 Compose 项目使用低内存模式：

```powershell
pnpm infra:lite
pnpm dev:lite
```

低内存模式不会修改正常启动配置，但不会运行文件扫描、后台任务、扩展热更新和遥测采集。需要这些功能时，可分别运行 `pnpm infra:file-scanning`、`pnpm dev:worker`、`pnpm dev:extension` 或 `pnpm infra:observability`；完整联调仍使用 `pnpm infra:up` 与 `pnpm dev`。

启动后使用以下地址：

| 服务         | 地址                           | 用途                  |
| ------------ | ------------------------------ | --------------------- |
| Web          | `http://localhost:3000`        | ERP 主界面            |
| API 健康检查 | `http://127.0.0.1:8000/health` | 确认 API 与数据库状态 |
| Keycloak     | `http://localhost:8081`        | 本地身份服务          |
| MinIO 控制台 | `http://localhost:9001`        | 本地私有对象存储管理  |

本地默认账号为 `yummyai-local`，默认密码为 `yummyai-local-2026`。如果 `.env` 覆盖了 `LOCAL_EXTENSION_USER*`，以实际配置为准。

### 1.3 检查运行状态

```powershell
docker compose --env-file .env -f infra/docker-compose.yml ps
pnpm --filter @yummyai/database exec drizzle-kit check
```

API 健康接口应返回 `status: ok` 和 `database: connected`。

## 2. 导航与模块

所有业务页面共用同一套双栏导航，包括加载中、详情和异常页面。最左侧固定显示常用、总览、订单与履约、创意设计、商品与刊登、选品研究、采购与库存、经营分析和系统配置。点击模块后，旁边的页面栏显示对应入口；模块的位置保持不变，点击具体页面才会跳转。进入页面时自动显示所属模块并标明当前位置。手机端点击顶部“菜单”使用相同的两级导航。

页面右上角可选择**浅色、深色、跟随系统**。桌面端的“收起页面栏”按钮可隐藏第二栏，为表格和画布留出更多空间，最左侧模块名称仍然可见。再次点击模块或“展开页面栏”即可恢复。主题和页面栏偏好会在本浏览器中保留，手机菜单不会改变桌面的收起状态。

- **找功能**：点击最左侧底部的按钮，或按 `Ctrl K`（Mac 使用 `⌘ K`）。支持页面名称和业务关键词，例如“ZIP”“订单导入”“猫咪”“轮胎罩”“生产图”“待发货”。使用方向键选择、Enter 打开、Esc 关闭。
- **全部功能**：打开 `/navigation`，默认只展示订单与履约相关入口。点击业务分类切换，或点击“全部”查看完整目录。搜索始终覆盖全部分类，支持“猫咪”“备胎罩”等业务叫法。顶部常用任务可直接进入订单导入、创意项目及待发货订单。
- **当前位置**：页面顶部显示可点击的上级路径。订单内作图可返回当前制图任务，创意项目内作图可返回当前项目；刊登、店铺和工作流详情可返回各自列表。
- **收藏页面**：点击页面旁的星标，将它加入最左侧的“常用”。可以把订单、生产文件、产品和供应商放在一起，跨模块直接进入；再次点击星标即可移除。收藏在当前浏览器中保留。
- **常用任务**：页面栏底部固定“导入订单报告”“开始创作”“查看待发货”三个快捷入口。日常接单进入“订单与履约 → 订单中心”，开发新品进入“创意设计 → 创意项目”。创意设计下还保留“生产文件与底稿”和“商品套图”；批量生图、图片处理和设计校样放在创意工作台的“辅助工具”中，也可搜索找到。抱枕与备胎罩仍是各自独立的产品工艺。

## 3. 推荐业务流程

### 3.1 无店铺也可完成的研究到导出流程

这是最适合首次使用的流程，不需要 Amazon/Etsy 店铺授权：

1. 使用浏览器扩展采集公开商品页面。
2. 在研究资料库检查标题、店铺、价格、图片、卖点、物流和诊断。
3. 将多个商品或店铺整理为竞品研究对象。
4. 根据研究结论创建产品企划。
5. 审核企划后生成 SPU、SKU 和定制字段。
6. 创建设计任务，上传合法来源的设计文件。
7. 审核设计版本并绑定 SKU 和 Listing 图片槽位。
8. 创建 Amazon 或 Etsy Listing 草稿。
9. 完成平台校验和人工审核。
10. 生成不可变的上架导出包。

竞品图片只能作为研究证据，不能直接变成可发布资产。正式 Listing 图片必须来自已授权并审核通过的资产。

### 3.2 店铺发布流程

真实发布需要受支持的平台 API 和明确的测试店铺授权：

1. 在店铺运营顶部点击“新增店铺”，填写名称、平台和站点，保存店铺档案；这一步无需授权凭证。Amazon 档案保存后即可手动导入订单报告。
2. 从巡检台账进入单店详情，先核对概览、Listings、订单和健康摘要，再在设置区完成 OAuth/官方授权和能力同步。
3. 确认账号状态为可用，类目和站点能力仍在有效期内。
4. 打开已通过审核的 Listing。
5. 先执行平台预检或创建草稿。
6. 查看平台返回的字段问题并修正 Listing 新版本。
7. 通过单项或 2–100 项不可变批次继续发布。
8. 在刊登控制台查看发布事件、外部 ID、失败原因和对账状态。
9. 发布成功后，按需读取在线内容、价格和库存，再决定是否推送批准版本。

Amazon 批量续发使用单个 JSON Listings Feed；Etsy 批次按项目逐项激活。外部结果不确定时，系统会进入 `reconciliation_required`，不要盲目重复发布。

店铺详情的“编辑店铺资料”可以改名；尚未授权时可选择 Amazon 私有应用或公开应用 OAuth。平台授权与档案创建分别操作，保存档案不会自动授权或发布。

## 4. 浏览器扩展

### 4.1 构建和安装

```powershell
pnpm --filter @yummyai/extension build
```

开发输出位于：

```text
apps/extension/.output/chrome-mv3
```

在 Chrome 或 Edge 中：

1. 打开扩展管理页面。
2. 开启开发者模式。
3. 选择“加载已解压的扩展程序”。
4. 选择上面的 `chrome-mv3` 文件夹。
5. 修改或重新构建扩展后，点击扩展的“重新加载”。

### 4.2 采集商品

1. 打开公开可访问的 Amazon 或 Etsy 商品页面。
2. 打开 YummyAI Capture 扩展。
3. 检查预览中的商品、店铺、媒体和解析诊断。
4. 如需评论，主动开启评论采集并设置翻页延迟。
5. 点击 **发送到研究库**。
6. 在 `/research` 确认商品出现；重复采集会增加快照版本，不会覆盖历史。

扩展中的 **重新读取** 只刷新本地预览，不会写入研究资料库。

Amazon 商品媒体按页面顺序保存商品高清套图，并补充商品描述区域中的普通 A+ 和高级 A+ 图片。采集会优先读取高清、懒加载和响应式图片源，去除尺寸转换参数并按图片资产去重；推荐商品、评论图片、页面装饰图和独立的 Brand Story 不计入商品媒体。

Amazon 的 **Product information** 会按页面分组保存全部公开键值参数及参数内链接。字段名称不写死，服装、家居、电子、定制商品等不同品类出现的专属参数都会保留；旧快照保持原样，新采集生成包含产品参数的新版本。

Etsy 商品页如已安装 EHunt 且页面中显示 **EHunt 商品分析**，YummyAI 会把该面板的可见经营指标、类目、商品标签及标签指标作为独立第三方证据写入当前快照，并在扩展预览和研究详情中标明来源。EHunt 面板不存在或尚未显示有效数据时，快照不会创建 `ehuntAnalysis` 字段；YummyAI 不读取 EHunt 的 Cookie、登录令牌或隐藏请求。

### 4.3 评论采集

- 评论采集默认关闭。
- 开启后应设置合理的页面延迟，避免高频访问。
- 可以暂停并保留已采集进度。
- 页面报告的评论总数和实际可访问数量可能不同，系统分别保存“已采集”和“页面报告”数量。
- 只读取普通用户在公开页面上可见的内容，不访问 Cookie、卖家接口、验证码或受保护端点。

### 4.4 字段缺失与解析提示

页面不公开某个字段时，系统会保留部分采集并显示诊断，不会编造数值。例如：

- 链接发布日期不可见
- 收藏数量不可见
- 发货地或运费因收货地区不同而不可见
- 卖点未出现在当前页面结构中

页面改版后如字段突然缺失，应先重新加载最新扩展并刷新商品页，再查看解析提示。

## 5. 研究资料库与竞品店铺

### 5.1 查看商品详情

研究资料库支持查看：

- 缩略图、全部已采集图片与视频；点击缩略图切换，图片支持放大
- 商品标题、价格、评分和评论计数
- 店铺名及店铺链接
- 卖点和正确换行的商品详情
- 类目节点、发布日期和收藏数量（页面公开时）
- Amazon Product information 的分组、参数值及公开链接
- 运费、发货地和预计送达时间
- 个性化选项、变体和材料
- 每次采集形成的历史快照
- 缺失字段和解析器诊断

预计送达时间应来自页面可见区间或基于页面明确提供的运输信息计算；信息不足时显示缺失状态。

**研究结论与创意衔接**：展开商品详情后切换到“研究结论”，填写设计主题、目标人群、购买动机、风格观察、原创差异化方向与定制要求，也可按媒体编号添加图片/视频批注。研究状态分为“待研究 / 已研究 / 暂不采用”，与采集状态、产品分类状态分别记录和筛选。标记“已研究”前需填写主题和差异化方向。

图片加载失败时会显示重试入口；详情中的“重新加载媒体”可重试当前图片或视频。失败图片暂时无法放大，仍可切换到其他媒体。

暂时不用的资料可在行尾“归档”，再从“资料范围 → 已归档”查看或恢复。归档保留历史快照、研究结论和创意项目引用；有未保存的研究结论时，先保存再归档。

保存结论后，在列表勾选最多 30 条竞品并点击“加入创意项目”。需求单会预览采用的研究版本，将结论摘要带入空白需求项；运营继续确认定制类型、原创元素和计划适配的 SPU 规格。保存需求后，美工或设计 Agent 可读取同一份研究依据。竞品素材继续作为研究参考，生产素材须使用原创或授权文件。

每次保存研究生成一个新版本。创意项目固定采用创建时的快照与结论，重新采集或修改研究不会改变已有项目。项目中的“查看采用的研究快照与媒体”可打开只读的历史版本。列表显示关联创意项目数，研究详情可跳转相关项目。保存冲突时填写内容会保留，须核对最新研究后再合并。

### 5.2 统一产品类型与批量整理

统一产品类型是研究索引中的单选分类，不会改写 Amazon/Etsy 原始类目、历史快照或 Listing 平台类目。风格、节日和用途继续作为多标签管理。

- **待复核**：系统从最新快照的原生类目、EHunt 类目或 Amazon Best Sellers Rank 公开类目生成了建议，需要人工确认。
- **已确认**：成员已确认或修改该条目的统一产品类型；后续重新采集不会覆盖。
- **未分类**：没有可靠结构化证据，或成员主动清除了类型。

可以用标题搜索、产品类型和分类状态组合筛选。勾选当前页中的明确条目后，可批量选择已有类型或输入一个新类型；“标记未分类”只清理研究索引分类。确认或修正建议时，系统会学习同平台、同证据来源的原始类目别名，并同步修正仍处于待复核状态的相同建议，已经确认的条目保持不变。分页、刷新和返回资料库时，URL 中的筛选条件会继续保留。

### 5.3 管理竞争店铺

竞争店铺模块用于保存：

- 店铺名称、链接和平台
- 店铺公开销售、评分和评论信号
- 页面中的 All、On sale 与商品分类标签，以及各标签报告的商品数量
- All 和真实商品分类的公开跳转链接；On sale 未提供稳定目标时仅保存名称与数量
- 代表商品和价格区间
- 店铺政策、物流和定位信息
- 最近采集时间和证据来源

这些信息只用于研究，不会自动写入自有 Listing。

标签数量是 Etsy 当前页面报告值。扩展不会逐条打开或统计店铺中的每个商品链接；重新采集会创建包含当时标签结构的新快照，不覆盖历史记录。

Etsy 店铺页如已安装 EHunt 且页面中显示 **EHunt 店铺分析**，扩展会额外保存顶部汇总指标和当前打开的一个 EHunt 页签，并在扩展预览及竞争店铺详情中标为第三方证据。扩展不会自动切换 EHunt 页签；如需保存其他页签，应先在页面中切换，再点击扩展的 **重新读取** 并创建新快照。历史趋势只有在周期与数值存在于可读取 DOM 时才保存；仅以 canvas 绘制的曲线不会被推断。EHunt 面板不存在时不会创建字段，也不会增加缺失诊断。

## 6. 产品、设计和 Listing

### 6.1 产品开发

产品企划通过审核后才能进入正式设计和 Listing 流程。建议依次维护：

在前端新增产品：

1. 打开“产品目录”。
2. 展开“新增产品”，填写产品名称；描述、目标成本和研究报告 ID 可按当前资料补充。
3. 点击“创建产品企划”。创建成功后系统会直接打开新产品的开发档案。
4. 新产品初始状态为“研究中”。可以先保存未关联报告的草稿，但提交立项前必须关联至少一份已审批研究报告。
5. 立项审核通过后，在产品详情创建 SPU，填写稳定的内部 SPU 编码和名称。
6. 产品进入开发中后，在同一详情页创建 SKU，填写 SKU 编码和 `属性: 值`；多个属性使用逗号或换行分隔。
7. SKU 创建后，点击“为 SKU 创建设计任务”进入设计校样。系统使用真实 SKU ID 关联任务，不接受手工拼接的占位 ID。

- 品牌、类目、材质、工艺和产品状态
- 尺寸、重量和包装信息
- SKU 规格维度和内部编码
- 定制字段、条件显示和生产映射
- 成本、目标售价、币种和目标毛利
- 候选供应商及优先级

产品详情的“关联工作”同时列出研究报告、设计任务和 Listing。每条关联都来自当前租户可见的数据库记录，并可直接打开对应报告、筛选后的设计任务或 Listing；尚未创建的关联会显示明确空状态。

已审核内容发生变化时，需要创建新版本并重新审核。

### 6.2 从研究资料导出 Amazon Studio 产品包

Amazon Custom 产品在“产品目录”的产品详情中维护。使用步骤：

员工应先打开左侧“工作流中心”并启动 **Amazon Custom Product Development V1**。该流程把研究资料、产品事实、定制字段、SPU/SKU、设计校样、Amazon Studio 内容生产、上架资料导出和齐套验收串成 14 个执行步骤；每一步都明确责任人、输入、必做操作、交付物和阻断条件。产品详情的“Amazon Studio 产品包”也提供同一流程的快捷入口。

页面顶部的“产品开发进度”是员工任务看板：

1. 所有产品企划都会显示在表格中，包括尚未开始 Amazon Custom 流程的产品。
2. 点击产品右侧“开始”或“查看”，打开该产品的 14 个任务。
3. 新流程创建后，第一个任务自动进入“执行中”。
4. 当前任务可以完成或设为阻断；设为阻断必须填写原因。
5. 解除阻断后继续执行。完成任务会把当前任务推进到下一步的“待开始”状态。
6. 系统按顺序推进，不能跳过前置任务。多人同时修改时，旧页面会被拒绝，应刷新后再操作。
7. 完成后仍可展开“编辑完成记录”，修改或清空完成说明；这不会改变完成度或当前任务。
8. 每次开始、完成、编辑说明、阻断、解除阻断或重新打开都会进入事件记录。
9. 已完成任务只有在后续任务尚未开始时才能“返工重开”，并且必须填写原因。

产品生命周期状态与 Amazon Custom 任务进度是两个独立概念。例如产品可以处于“开发中”，同时停留在“完成设计校样”任务。员工判断当日执行位置时以任务看板为准，判断产品审批和目录状态时以产品档案为准。

1. 先在研究资料库找到竞品记录，复制其研究资料 UUID。
2. 打开仍处于“研究中”的产品企划，在“客户定制字段”中维护图片、文字、选项和备注字段并保存。
3. 在“Amazon Studio 产品包”中粘贴研究资料 UUID，选择目标站点，点击“生成临时事实”。
4. 系统会预填竞品研究中可识别的产品类型、材质、尺寸、工艺、目标人群和卖点。所有值都保留来源并标记为未确认，可直接修改。
5. 补充自己的 SKU、品牌、包装数量、包装内容、定制区域毫米尺寸和授权素材 UUID。素材关联每行使用 `素材 UUID,角色`，例如 `019f...,real_product`。
6. 未核对前直接点击“下载草稿 ZIP”，交给 Amazon Studio 建立不可发布的草稿项目。
7. 按实物和生产规格核对全部字段后，勾选卖家确认并保存。系统只有在必填事实、加工区域和授权素材全部通过时才开放正式 ZIP。

“按研究源重建”会用最新研究快照覆盖当前产品事实草稿，适合重新采集后刷新参数；已经人工修改的内容会被替换，使用前应先确认。

草稿包中的竞品图片只有分析清单，不包含图片文件，不能用于生图或最终 Listing。自有图片必须先进入授权素材域并通过权利审核。草稿包显示 `blocked` 是正常状态，`compliance/completeness-report.json` 会列出需要补充的项目。

下载得到的 ZIP 已包含：

- 产品事实和事实来源
- Amazon Custom 字段和定制面映射
- 竞品来源和评论洞察
- 宣称限制和完整度报告
- 授权素材清单及允许写入的素材文件
- 每个文件的 SHA-256 完整性清单

Amazon Studio 产品包只负责 YummyAI 到 Amazon Studio 的资料交接。内容和图片完成后，产品详情下方的“Amazon Custom 上架资料齐套包”会继续检查最终交付物；系统不会登录 Seller Central 或发布 Listing。

### 6.2.1 导出 Amazon Custom 上架资料齐套包

完成 Amazon Studio 内容并在 YummyAI 创建、批准 Amazon Listing 版本后，返回产品详情执行“重新检查”。系统按八组资料验收：产品事实、SKU 与变体、Listing 文案与类目属性、9 张 Listing 图片、A+、Custom 配置、设计校样与生产文件、合规与最终校验。

齐套率达到 100% 后才能下载正式 ZIP。ZIP 包含：

- `listing/listing-copy.txt` 与 JSON：标题、5 条卖点、描述和搜索词；
- `listing/category-attributes.json`：批准版本中的 Amazon 产品类型和类目属性；
- `listing/offer-and-fulfillment.json`：价格、库存、商品状况、处理时间和卖家配送模板；
- `listing/variants.csv`：SKU 与变体值；
- `listing-images/`：按 `SKU_MAIN`、`SKU_PT01` 至 `SKU_PT08` 命名的 9 张授权图片；
- `a-plus-images/`：A+ 图片；
- `customizer/customizer-config.csv` 与 JSON：定制面、加工区域、字段、限制和选项；
- `production-files/`：已授权的印刷或加工模板；
- `compliance/`：宣称边界和资料齐套报告；
- `upload/upload-checklist.csv`：员工在 Seller Central 中逐项执行的上传清单。

正式包只读取已批准 Listing 版本和授权域素材。缺少主图、图片不足 9 张、A+ 缺失、校样或生产模板缺失、类目属性、价格、库存、商品状况或卖家配送资料不完整、事实未确认或素材权利未批准时，下载入口保持关闭并显示具体阻断原因。竞品原图和 `reference_only` 素材不会进入上架资料包。

### 6.3 设计校样

设计任务应包含尺寸、印刷区域、出血、分辨率、格式和禁用元素。上传文件时必须记录合法权利来源。

当前租户的研究资料库只有一条记录时，“创建设计任务”会将该记录显示为“RESEARCH ONLY”样例，并预填原创设计要求。样例仅用于理解公开市场需求，不会把 Etsy 图片、商品文案或竞品文件复制进授权资产域。当前本地样例使用 `ThePineTroveGifts` 的个性化抱枕套研究记录，关联 SKU 为 `P1G-PILLOW-STD`。

`/design` 支持 `task` 精确任务深链，以及 `status=active`、`status=overdue` 等队列筛选。仪表盘的设计逾期风险会直接进入逾期队列，而不是打开一个未筛选的默认任务。

推荐流程：

1. 打开“设计校样”，展开“创建设计任务”，选择一个真实 SKU；需要时设置截止时间。
2. 填写任务标题和设计要求。使用研究样例时，保留需求来源和“不得复制竞品图片或文案”的边界说明。
3. 创建任务后，在任务详情上传源文件、效果文件或生产文件。单文件最大 20 MB。
4. 为每个文件选择“自有版权、许可使用、委托创作、AI 生成或客户提供”，并填写项目号、合同号或许可证编号。竞品文件不能作为设计资产上传。
5. 上传会依次创建私有授权资产、记录权利来源，并生成不可变的待评审版本。后续修改必须再次上传并创建新版本。
6. 设计负责人批准或驳回版本；驳回必须填写原因。批准后将目标版本设为主版本，任务才进入已完成状态。
7. 需要查看文件时点击“获取安全链接”。链接是短期授权地址，不应长期分享。
8. Amazon Custom 产品还应把已批准完成品校样关联为 `finished_sample`，把生产模板关联为 `print_template`；两者都是上架资料齐套检查的必需项。

已通过版本不可覆盖；修改必须创建新版本。

### 6.4 Listing 编辑和审核

Amazon 与 Etsy 使用各自的平台字段模板。编辑时重点检查：

- 标题、描述、要点、标签和 Search Terms
- 类目、属性、材料和变体映射
- 价格、数量和 SKU
- 图片槽位、视频和授权状态
- 个性化说明、处理与配送配置
- 平台限制、敏感词、知识产权和合规问题

`/listings` 目录显示当前最新版本的标题、SPU、平台、店铺/站点标识、语言、主图可用性、完整度、阻断数和更新时间。搜索、平台、店铺/站点、语言、状态、完整度、阻断筛选、排序与分页会写入 URL，便于分享和恢复工作视图。批量选择区只汇总真实审批与阻断门禁，不会把草稿伪装成可发布项目。

进入 Listing 后：

1. 标题、Amazon 卖点、描述和 Etsy 标签共同组成当前本地草稿。
2. 右侧“平台本地预览”只用于检查字段排版，不代表平台在线状态或最终渲染。
3. 离开含未保存改动的页面时，浏览器会要求确认。
4. 点击“保存为新版本”会运行平台规则并创建不可变版本；不会覆盖当前或已批准版本。
5. 右侧版本活动显示最近的人工、AI、批准和替代记录；校验结果在保存后更新。

目录中的 **连续修订** 按当前页顺序打开编辑队列，也可从某条 Listing 开始。顶部支持 **上一条 / 下一条**、**保存并下一条**，最后一条保存后返回原筛选目录。保存失败或版本冲突时保留输入并停在当前记录。从销售 SKU 进入时，使用 **返回来源页面继续处理** 回到该 SKU。

只有通过审核的版本才能生成正式导出包或进入发布流程。

## 印花、商品 SPU 与销售 SKU

**一个 SPU 管理多个规格。** 例如同一款产品的蓝色、红色和不同尺寸都维护在这个 SPU 内；规格不会各自变成一条产品档案。

1. 在 **创意设计 → 印花库**（`/print-library`）登记印花方案并分配独立印花 SKU。固定印花需要已审核的创意主文件；来图或文字定制可以没有固定主图，但必须设置必填的顾客图片或文字字段，并填写制作说明。背景、装饰、字体和内部参考图可保存在版本化素材包中，后续补充时建立新版本。顾客原图保存在订单中。展开 **制作说明与素材** 可核对规则；无用测试印花可点 **归档印花**，从 **已归档（可恢复）** 中恢复，历史商品和订单关联保留。
2. 在 **商品与刊登 → 商品 SPU**（`/product-specifications`）点击 **新增 SPU**，保存后直接进入这个产品的规格管理；已有产品点击 **查看产品与规格**。点击 **绑定多个规格**，为尺寸、形状、颜色或自定义维度添加多个选项，用逗号分隔或回车添加，然后 **预览规格组合**。例如 2 个尺寸 × 2 个形状得到 4 个候选组合，勾选实际销售的组合即可。填写共用材质、包装和默认工艺后，逐行核对编号、实际尺寸和制作工艺；个别规格的其他差异在 **更多设置** 中调整。每批最多预览 50 个组合，整批保存；已有组合会标记并跳过。通用底稿在 **工艺底稿**（`/process-library`）维护。
3. 在 **产品开发**（`/product-development`）选择印花，按 SPU 分组勾选规格，核对销售 SKU 编号后生成。一个印花 × 两个 SPU × 每个 SPU 两个规格，会得到四个销售 SKU，产品仍然只有两个 SPU。
4. 打开销售 SKU 的详情，完成制作稿适配、预览、审核和生产出图。回到详情审核制作版本后，进入商品套图；套图和生产使用同一个已审核制作来源。
5. 同一“印花＋SPU”下的多个已审核规格，可以放进一个渠道 Listing 草稿。完善文案和图片并审核后，按销售 SKU 封存资料包。每个规格需有其准确制作版本的已审核套图；共用的 Listing 图片保留各自来源。
6. 资料包可下载 ZIP。登记已经在店铺使用的平台 SKU、Listing 编号和生效时间后，订单按下单时的映射匹配制作资料。未匹配或存在歧义的订单须由运营处理。

SPU 详情中的 **编辑 SPU** 可以修改编号、产品名称和通用说明，并同步到产品档案。原有规格、SKU 和历史资料继续关联到同一个产品。保存遇到版本冲突时，当前输入会保留；先记录修改内容，再刷新核对最新资料。

工艺资料还没齐全时，可以先保存 **规格草稿**：录入尺寸、材质和包装信息，工艺留空，保持事实确认未勾选。草稿会显示在 SPU 详情中；补齐已审核工艺并创建确认后的新版本，才能用于订单制作。销售页的成品尺寸不能直接当作印花尺寸或裁切尺寸。

新印花、规格和制作稿都创建新版本，已封存资料包和旧订单保留原记录。旧销售 SKU 在产品开发中明确关联到印花和规格；系统不会仅凭相似编号猜测。已审核的 SKU 制作稿锁定，修改从产品开发创建新版本。

产品开发列表提供 **连续处理 SKU**，详情内可按当前页顺序切换 **上一个 SKU / 下一个 SKU**，返回时保留搜索和筛选。从 SKU 进入套图或 Listing 后，使用来源返回入口继续处理同一 SKU。创意项目登记印花后，可点击登记结果旁的组合商品入口，直接带入已登记版本，再选择规格与编号。

缺少规格、工艺或 AI 配置时，按页面入口补齐后使用 **返回原任务**。组合商品、单个规格和批量规格表单会在当前应用标签页内暂存输入，最长 2 小时，保存成功后清除；刷新整个页面或关闭标签页会清除暂存。回程后仍须核对并选择适用资料。

SPU 详情会汇总已绑定的尺寸、形状等选项，刷新后仍可继续添加。每一条已保存规格只对应确定的一组属性；修改已有规格会创建新版本。尺寸或形状不同，必须选择对应的工艺底稿并核对实际生产尺寸，组合预览不会自动生成适用的生产模板。

当前制作编辑器沿用圆形胎罩与异形抱枕能力；真实商品套图还需已配置并审核的套图模板。买家原图和定制信息保存在订单私有域，运营推送后才进入制图。完整技术边界见[产品开发说明](integration/product-development.md)。

## 7. 订单与履约

真实订单自动同步需要授权店铺；手动导入亚马逊订单报告只需先建立对应的 Amazon 店铺档案。日常履约工作分为五个页面：

| 页面 | 主要工作 |
| --- | --- |
| 订单中心 `/orders` | 导入、审单、编辑印花版本和定制内容、选择图片、推送制图 |
| 制图中心 `/order-artwork` | 领取任务、制作文件、审核、记录客户校样确认、生成正式文件 |
| 生产中心 `/production` | 固定文件和工厂后下达生产，记录进度、质检及重做 |
| 发货中心 `/shipments` | 建立和审核包裹，记录实际交运与物流进度 |
| 售后中心 `/after-sales` | 记录问题、已发生的沟通、处理方案和实际完成凭证 |

订单详情顶部可切换同一订单商品的各个环节。列表支持订单号、商品 SKU、印花 SKU、物流单号搜索，以及店铺、各环节状态、日期、暂停和超期筛选。筛选条件保留在网址中，也可按当前用户保存常用视图。

制图、生产、发货和售后也支持 **连续处理**：在列表上打开侧栏，按 **上一单 / 下一单** 处理当前页。制图可选择操作成功后继续；生产、发货和售后可勾选 **本次操作保存成功后处理下一单**。保存失败或还有其他表单未保存时，停留在当前单；数据加载和提交期间禁止切单。跨环节查看后，点击 **返回来源订单队列** 恢复原筛选、页码和队列。从店铺详情打开订单履约时，会自动选中该店铺。

异常状态独立于主流程，包括地址异常、资料缺失、生产异常、物流异常、取消、退款、重做和补发。

### 7.0 每天导入亚马逊订单报告

1. 在亚马逊后台下载订单报告，保留原始 TXT 文件。在 **订单中心 → 导入订单报告**（`/orders?view=reports`，旧 `/orders/import` 会自动进入这里）选择订单所属店铺和站点。
2. 拖入报告或点击 **选择报告**，再点击 **导入报告**。支持不超过 5 MB 的 TXT / TSV；默认按 UTF-8 读取。提示编码不匹配时，可选择 **GB18030 / 中文 Windows** 后重试。
3. 页面先列出订单，再逐行获取 ZIP、检查文件并解析定制内容。打开订单可查看亚马逊预览、买家图片、原始文字和选项。放大预览核对布局；原图下载与用于显示的图片预览分别标识。
4. 核对无误后点击 **标记已核对**。这只记录当前定制版本的内部审核，不会向亚马逊回传发货信息，也不会自动生成生产文件。
5. 点击 **去订单中心审单**，为每个订单商品匹配 **印花 SKU → 产品 SPU → 具体规格**。已有渠道映射会自动带入，也能直接匹配，不要求先建立销售 SKU 制作版本。核对“本单印花素材”，填写定制文字并选择买家原图；图片用途填写对应定制字段的名称，例如“宠物照片”。补传图片前先保存草稿。选择 **美工领取制作** 或 **无人设计 Agent · 模板排版**，再点击 **确认审单并保存**。
6. 点击 **确认并派发设计** 才开始制作环节，固定本次需求、印花素材清单、规格工艺和所选原图。美工从制图中心领取，系统带齐素材；Agent 按印花的定制区域放入原图和文字，生成仍须审核的本单草稿。未配置区域、未匹配字段、特殊字体或复杂规则须先完善或交给美工。Agent 不执行 PSD 分层编辑、抠图和重绘。尚未下达生产时可以填写原因 **撤回并修改需求**，原版本和操作记录保留。
7. 从 **制图中心** 领取任务，在编辑器素材面板中按用途选择和放置图片。查看后台预览并核对实际尺寸，保存后返回制图任务提交审核。审核通过且生产预检通过后生成正式文件；需要客户校样确认的订单还须记录确认依据。
8. 在 **生产中心** 选择生成成功的正式文件、工厂、数量和完工时间，点击 **下达生产** 建立内部任务。工厂接单、完工、质检与实际交运分别记录；保存文件、下达任务和平台回传都不会自动代替这些实际事件。

订单中心按订单分组，每件商品独立显示商品 SKU、印花 SKU、产品 SPU / 规格、买家定制内容、图片、状态和内部截止时间。点击图片放大；内容较多时可展开其余字段，或勾选 **展开全部定制内容**。点 **展开编辑** 在当前商品下修改并保存，筛选和多选会保留。保存后不再符合筛选的商品，会在收起编辑后隐藏。

顶部按 **待审单、待补资料、待派发制图、待开始制图、制图中、待审图、已审图、待发货** 显示数量，其他环节及 **缺少面单、已暂停、已超期、资料有更新** 可直接点击筛选。数量按当前店铺、日期等条件统计全部商品行，不只统计本页；“缺少面单”等异常条件可以与当前环节重叠。新导入、尚未建包裹的订单不会直接计为缺少面单。

常用筛选包括订单/物流单号、店铺、商品 SKU、当前环节和日期。日期范围支持双月日历及今天、昨天、近 7 天、近 30 天；**时间类型** 区分平台下单、导入、内部截止和最近一次实际交运，按当前浏览器时区计算。**更多筛选** 可查印花 SKU、SPU、规格、设计执行方式、面单及各环节状态；**批量订单号** 支持换行或逗号分隔，最多 100 个。**我的视图** 可保存常用筛选，保存位置为当前浏览器。

每件商品右侧显示对应的下一步操作，如 **开始审单、推送设计、查看制图、审核生产图、安排发货**。筛选 **待审图** 后可用 **连续审图**；面板顶部显示实际 AI/文件任务的等待、处理、完成或失败状态，以及当前稿件最近一次校验的问题。没有任务或当前版本没有校验时会明确提示。AI 完成、文件下载与工厂实际生产是不同事件。

清理测试订单时，在商品详情的 **处理与交接** 填写原因后点 **归档此商品**。归档会暂停该商品并从五个日常工作队列移除，保留原始报告、历史版本和履约记录；不会取消平台订单。可在 **更多筛选 → 记录范围 → 已归档记录** 中查看，填写恢复原因后 **恢复到订单列表**，核对完成再解除暂停。

待审单商品也可以多选：商品前的勾选框选一件，订单标题前的勾选框选该组符合筛选的商品，**选择本页商品** 只选本页；跨页选择会保留。**选择全部筛选结果** 会明确选择当前筛选中的全部商品，单批最多 100 件，超出时需要缩小范围。修改筛选会清空选择。

选中后可以 **检查缺项、AI 预审、绑定印花 / 产品、设计安排、待补资料、确认审单、推送设计**。批量修改先点 **预览变更与检查**，核对每件商品将改成什么、哪些受阻，再点 **确认处理 N 件**。默认仅补空值；关闭后会替换所选字段已有的绑定或安排。买家文字、图片与备注保持原样，需展开商品单独编辑。变更制作依据或安排后回到待审单，审单与推送分两次完成。成功项会取消选中，失败项和受阻项继续保留。

批量 AI 预审先选模型并核对费用上限，再明确开始；没有配置模型时会显示设置提示。每件商品的建议保存在其 AI 预审面板，仍需运营核对并采纳。**停止后续处理** 不撤销已完成操作，已提交的 AI 任务会继续运行。

订单较多时，先筛选 **待审单**，再点列表上方的 **连续审单**。审单面板在右侧打开，列表与滚动位置保留；顶部的 **上一单 / 下一单** 按打开时的本页顺序切换。底部的 **确认审单并下一单** 保存当前需求为待推送后继续下一条；资料缺失时可选 **待补资料并下一单**。本页最后一条保存后返回列表。保存失败会保留当前填写内容，放弃未保存的修改前会提示确认。如需留在本单继续操作，可使用“处理与交接”中的 **确认审单并保存**。审单完成后仍需明确派发设计。

没有店铺档案时，先到 **店铺运营** 创建 Amazon 店铺连接；手动导入不需要填写平台授权凭证。每天重复下载含有旧订单的报告可以正常导入，系统按店铺、订单和订单行识别重复项，并显示新增、重复和异常数量。报告中不再出现的旧订单不会被当成取消订单。

解析按订单行分别处理，某个 ZIP 失败不影响其他订单。页面显示 **处理中** 时可以先查看已完成的行；关闭页面后尚未开始的任务保留待处理状态，下次进入点击 **继续解析**。链接失效时可以单独 **重新获取附件**，或 **补传 ZIP**（不超过 20 MB）。内容发生变化后需要重新核对；旧版本不会沿用已核对状态。

定制文字与图片仅向有相应权限的成员开放。看不到图片或提示未授权时，请联系管理员检查订单与定制资料权限。没有亚马逊预览时会明确提示，系统不会把买家原图当成最终效果图。报告未提供的平台状态或发货期限也不会自动补造。

### 7.1 定制资料

- 普通订单列表不会显示买家姓名、完整地址等受保护信息。
- 只有具备专门权限并提供合法用途时才能读取履约详情。
- 买家文件先进入隔离区并由 ClamAV 扫描。
- 只有扫描结果为 `clean` 的买家文件才能供对应订单制作使用。买家图、姓名和定制文字保存在订单私有域，不进入通用印花库。

### 7.2 分单、生产和质检

系统根据产品能力、地区、成本、交期、产能和质量生成供应商候选。自动结果仍需经过必要审核。

生产任务固定供应商决策、采购版本、数量、设计版本和生产资产。质检失败不会覆盖原任务，而是保留原证据并创建重做或其他恢复链。

### 7.3 发货与售后

- 发货版本包含包裹、订单行数量、承运商和追踪号。
- 平台接受发货回传不等于商品已经送达。
- 外部写入结果不确定时进入人工对账，不自动重复写入。
- 退款决策不等于平台退款已执行；真实退款仍需平台支持的外部流程。
- 分批完工和发货按订单商品数量累计。质检未通过的数量不能装入包裹；包裹审核后，填写交运凭证和实际时间才记录已发货。
- 售后页面可读取受权限保护的问题和沟通内容。处理方案保存后，需登记退款流水、补发运单或其他执行凭证才能手动结案；页面不发送客户消息或执行退款。

## 8. P3 经营管理

### 8.1 库存台账

顶部提供“新增仓库”“新增库位”“新增物料”“期初入库”和“库存调整”。编码会自动生成，也可替换为已有业务编码。新增库位时可以就地新增仓库，保存后自动选中。展开“仓库、库位与物料”可以编辑名称等资料；编码、物料单位和所属仓库保持固定。

第一次建账时，在“期初入库”选择物料、库位、可选批次，填写实际数量和记录原因。盘点差异使用“库存调整”，增加填正数、减少填负数，并填写原因。采购到货从采购单“登记收货”入库。失败时输入保留；校正后重试。采购和库存流水使用幂等请求，网络结果不确定时可原样重试；如已改动输入，应先刷新确认原记录。

库存数量以不可变流水为准，余额只是可重建投影。常用数量包括：

- 实物库存
- 已预占
- 可用库存
- 在途库存
- 平台/提供方库存
- 虚拟库存

调拨、收货、发货、退货、损坏和调整都会保留来源与时间。不要直接修改余额表。

### 8.2 采购补货

在“采购与库存 → 供应商档案”点击“新增供应商”，填写名称、地区和结算币种；列表可以搜索和编辑资料。

手动采购可以直接从“采购补货 → 新增采购单”开始：

1. 选择供应商、采购币种、预计到货时间，添加物料、收货库位、数量和单价。
2. 缺少供应商、物料或库位时，点击选择框下方“新增”；当前采购输入保留，新记录保存后自动选中。新增库位时还可继续新增仓库。
3. 点击“保存采购草稿”，列表中立即出现新单据。草稿及驳回单可“编辑草稿”，保存产生新版本。
4. 在对应单据点击“审核采购单”，核对供应商、版本、明细和金额，再保存批准或驳回决定；审批需要采购审核权限。
5. 批准后点击“登记收货”，按实际填写实收、拒收、原因和批次编码。每次收货使用新批次，实收数量自动记入对应库位。部分收货和异常差异保持可见。

手动采购不会向供应商发送订单，也不会执行付款。询价、供应商发票和补货策略的手动表单不在本轮新增范围；已有记录仍可查看。

标准流程为：

```text
采购申请 → RFQ → 供应商报价 → 采购单版本 → 审批
→ 收货/拒收 → 供应商发票 → 三单匹配或对账
```

补货建议固定安全库存、补货点、MOQ、交期和当时库存，但不会自动创建或批准采购单。

### 8.3 渠道库存

系统区分自有、FBA、FBM、海外仓、3PL、供应商、在途、隔离、损坏和虚拟库存。渠道可售数量由版本化策略计算，不能超过当前有效投影。

新的库存快照或策略版本会使旧投影过期；推送 Listing 库存前需要重新计算。

### 8.4 财务与利润

财务模块保存不可变结算和成本事实，包括收入、佣金、广告费、退款、采购、生产、物流、汇率和税费。

利润计算固定具体事实和汇率版本。缺少结算、成本、税费或汇率时显示“不完整”，不会把缺失成本当成零。

### 8.5 供应商绩效

评分来自实际业务证据，包含：

- 质量
- 准时交付
- 价格准确性
- 响应时间
- 订单接受率
- 取消/履约稳定性
- 产能履约

评分卡只用于分析，不会直接改变供应商路由策略。

### 8.6 广告与 VOC

广告报告固定币种、归因窗口和报告期间。评论、退货原因、客服和质量问题会先脱敏，再进入版本化 VOC 主题。

分析建议只能进入人工审阅，不会直接修改 Listing、广告预算或产品。

### 8.7 运营驾驶舱

运营驾驶舱集中显示：

- 销售、库存和利润预测
- 指标新鲜度与完整度
- 开放对账事项
- API 客户端和 Webhook 端点
- Webhook 重试、死信和人工重放链

预测和经营建议只生成分析证据，不会自动修改库存、采购、Listing 或财务事实。

### 8.8 POD 作图中心

从 **创意工作台 → 辅助工具 → 图片处理工具** 进入，也可搜索“POD 作图中心”。工作台固定显示印花提取、印花设计、图案处理、侵权检测、套图&标题、来图定制和生产图七个模块，服务平台为 Amazon 与 Etsy。批量生图、图片处理、设计校样作为创意辅助工具；商品套图保留独立入口；产品目录、工作流中心和刊登控制台归入“商品与刊登”分组。

每个工具会显示交付阶段、素材范围、输入、输出、参数摘要和当前可用状态：

- **正在实现**：工程正在接入，不能创建任务。
- **规格就绪**：需求和数据边界已经确定，执行能力尚未开放。
- **可用**：工具已接通真实异步任务和审核路径，可以创建任务。
- **不可用**：环境或权限不满足，不能创建任务。

当工具显示 **可用** 时，点击工具行的 **创建任务**，选择真实 SKU 和符合范围的素材，再填写参数。提交后可在页面顶部“最近任务”查看排队、处理、部分成功、失败和待审核状态。处理结果会生成新的设计版本，仍需在设计校样中完成权利和质量审核。

在 **印花提取** 中，图案裁剪支持通用、铁皮画和装饰画，可选择同图多图案、每图上限、PNG/JPEG、保留/透明/白底、留白与结果标签；透明底必须使用 PNG，透视校正不可关闭。任务中心会显示每个输入的裁剪序号、源图范围和输出尺寸。印花图提取支持专项、全能、透明底，以及服饰、手机壳、杯子、家纺、挂钟、风铃、桌布等场景；可选择强力校正、遮挡补全、输出背景和最低完整度。AI 补全区域始终明确标记，任务中心同时显示完整度和推断区域数量；漏标或证据不一致的结果不能进入审核或导出。

在 **图案处理** 中，可按已启用能力创建一键抠图、超分提质、扩图、裁剪压缩、转矢量图和授权素材去水印任务。每次选择 1–100 张权利已批准的授权域图片，系统逐图固定参数并要求一对一结果：抠图固定透明 PNG；超分选择 2×/4×、DPI、降噪、锐化和格式，全图新增细节作为 AI 增强记录；扩图选择比例、方向、格式和可选说明，AI 延展矩形不可隐藏；裁剪压缩固定像素、质量、DPI、色彩与透明通道，透明 JPEG 会在提交前阻断；矢量化选择 SVG/EPS、颜色数量、闭合路径与 RGB/专色，并执行脚本和外部引用安全检查；去水印必须确认素材权利并描述区域，修复范围始终进入人工审核。任务中心显示每个输入的格式、尺寸、DPI、路径数和 AI 区域数量，证据漂移、部分成功或不安全 SVG 不能审核或导出。

审核通过后，任务行会出现 **生成 ZIP**。系统会再次检查任务、结果版本、授权域、权利状态和文件校验值，然后异步生成包含生产清单的不可变导出包。任务行依次显示“等待封包”“正在封包”“已锁定”或“导出失败”；完成后点击 **下载 ZIP** 获取 10 分钟有效的私有地址。修改内容必须创建新版本并重新审核，不能覆盖已完成的包。

在 **印花设计** 中，14 个工具会按场景显示提示词、参考强度、创意程度、比例、候选数量和批量提示词。授权品牌/IP 融合必须确认许可并填写许可引用；没有许可不能提交。文生图可以不选输入素材，其余工具要求固定授权素材版本。系列图至少填写一条逐行提示词；尺寸延展的新增区域始终标记；四方/二方连续图会检查方向接缝和平铺预览；连续图拼接是确定性处理，不冒充 AI 生成。任务中心显示提示词指纹、输入数量、逐文件尺寸、AI 来源、接缝与文字复核状态，任一证据缺失都会阻止审核或导出。

进入 **套图&标题** 可创建商品套图、标题草稿、模特试衣和换背景任务。套图固定平台、站点、服装/手机壳品类、模板和数量；单个槽位失败会显示“部分完成”及稳定错误码，成功结果不会丢失。标题只能使用已确认商品事实和逐行关键词，结果显示字符/字节计数、事实与商标检查并强制人工文字审核。模特试衣必须填写模特资产许可；换背景必须启用严格主体保持，AI 背景区域不可隐藏。任务通过后仍只是内部 Listing 候选；关联面板只显示权利批准且设计版本已批准的授权素材，并固定到具体 Listing 版本与槽位，不会绕过 Listing 审核或模拟平台发布。

POD-3 中的商品短视频、裁片图提取、裁片图合成和 UV 智能分层可以复用同一异步任务与审核路径，但只有管理员接入对应处理器并显式启用后才显示“可用”。商品短视频选择 1–20 张授权图片，固定时长、镜头、画幅、分辨率、帧率、转场、字幕和音轨；许可音轨必须填写许可证明并确认授权，AI 商品运动也必须显式允许，安全区检查不能关闭。任务只接受一份 H.264 MP4，全部输入覆盖、播放、空白/损坏帧、字幕溢出、音频和许可检查通过后，任务中心才显示“商品短视频已通过检查”，之后仍需人工审核。裁片提取每次只能选择一份授权源图：分版选择透明通道，合版选择深色裁片线；每行裁片定义填写 `稳定键|名称|角度|翻转`，并配置印刷区域、缝份、格式、置信度和模板草稿名称。结果会显示每片置信度，低于阈值的裁片明确标为“需人工确认”，定位模板草稿不会自动变为可生产。裁片合成需按已选素材顺序填写唯一裁片键，并设置定位模板、自动/手动排版、适配方式、最低 DPI、间距和旋转策略；手动排版每行使用 `key,x,y,角度,缩放`。UV 分层也只选择一份授权源图，每行图层定义填写 `稳定键|名称|通道|顺序|透明度`；白墨/光油开关必须与定义一致。任务中心按顺序显示通道，任何未解决冲突都会显示“禁止导出”，人工审核不能绕过，必须修复后创建新版本。结果只有在全部裁片或图层文件、尺寸、色彩、DPI、透明度和逐文件证据通过后才能继续。ZIP 生产包会在质量检查和生产清单中记录其内容。顾客合成、合照、宠物换装与履约图生成不会出现在普通任务入口，必须从对应订单和已批准 SKU 模板进入。

进入 **侵权检测** 可创建基础过滤或深度检查任务，选择 Amazon/Etsy 适用范围、1–90 天报告有效期、是否计算视觉相似度，并按行补充商品标题、图案文字、品牌或角色线索。任务固定研究域或授权域图片版本，每张图返回独立的高/中/低/未知法律风险、置信度、规则命中、证据来源与检查时间、数据源/规则版本和模型版本。报告固定显示“辅助判断，不是法律意见”；视觉相似百分比单独显示，不代表侵权结论。高风险和数据源缺失导致的未知结果会直接显示“已阻断”，高风险素材不能继续生成、Listing 或导出；中低风险仍需人工复核，低风险不等于获得授权。已过期报告必须重新检查。页面同时支持租户内视觉检索，并显著区分研究域与授权域。

进入 **来图定制** 模块可使用模板控制台：填写画布和图片/文字槽位后创建不可覆盖版本；同类型且同名的图片槽位会标记“复用”，绑定 SKU 时自动建议相同顾客字段。模板必须先由有审核权限的成员批准，才能选择 SKU、尺寸和字段映射创建显式绑定。

已批准模板还会显示 **复制为组织草稿**。填写新名称后，系统复制固定画布、槽位、复用关系和授权素材引用，并记录源模板版本；副本使用新的模板族和草稿版本，后续修改、审核和 SKU 绑定不会影响源模板。

模板和 SKU 绑定完成后，来图定制下方的 **订单定制编排** 会列出可安全处理的订单行，并把取消订单、定制未就绪、未关联 SKU、缺少模板或绑定时间不符等候选项放入阻断列表。每个订单行只能选择一个尺寸模板。可以直接勾选，也可在 **批量表格填充** 下载 CSV 模板后填写 `external_order_id`、`external_line_id` 和可选 `size_label`；CSV 仅在本机解析，未知列会被拒绝，未匹配或有歧义的行只显示行号诊断。点击 **创建预处理批次** 后，页面显示逐行排队、解析、可渲染或失败状态；成功项可选择图片合成、合照或宠物换装。页面不会展示顾客姓名、留言或原始文件引用。

选择 **合照** 时，订单模板必须解析出至少两张不同顾客图片，并明确勾选 AI 构图确认。系统逐结果检查全部输入是否使用、人物数量是否一致以及是否出现新增或重复人物。选择 **宠物换装** 时，系统固定严格身份保持和参考身份隔离，并检查宠物身份、毛色斑纹与体型。任一证据缺失都会让任务失败，不会生成可审核版本。任务完成后，渲染任务列表只显示安全槽位键作为输入核对证据，不显示顾客文件地址。

进入 **生产图** 模块可从同一批次成功项选择“履约图合成”或“履约矢量合成”。位图模式创建 PNG/TIFF，并配置适配、DPI、色彩模式、透明背景和是否允许 AI 提质；矢量模式创建 SVG，并配置模板配置、物理宽高/单位、排版方式、专色/CMYK、最小线宽、镂空连接桥和路径修复。矢量模式强制文字转路径并禁止生成式增强、嵌入位图、脚本和外部资源。结果区显示文件数、路径数、最小线宽、连接桥和修复数；证据不完整时明确禁止导出。处理器未配置时入口会禁用。渲染完成后必须跳转到设计版本完成人工审核，之后才能创建生产清单。SVG 清单还会再次读取权威矢量质量快照并验证文件属于该设计版本；调用方自报“通过”不能绕过。生产清单仍需核对文件名、尺寸、DPI/物理单位、色彩模式和校验值后批准锁定，或填写原因驳回。

竞品素材只能用于侵权风险对照，不能进入设计、Listing 或生产导出。顾客图片、姓名和留言只能在对应订单行的私有域中使用，不能进入普通作图任务或跨订单检索。所有 AI 生成、补全和改图结果都需要人工审核；参数变化和重试会创建新版本，不会覆盖历史结果。

### 8.9 画图设计与帆布画批量套图

**ERP 创作中心**：左侧 **创意设计** 统一提供创意项目、我的画布、生图工作台、视频创作台、提示词库和我的资产。先从 **系统配置 → AI 模型配置** 添加渠道与模型；密钥加密保存在服务端。创作页面上方选择当前项目或个人工作区，切换工具保留归属。画布自动保存，刷新可恢复；保存失败时先重试或导出画布备份。提示词可保存并在画布和生图中调用，生成记录从“生成任务”查看。

**首次接入 OpenAI**：进入 **AI 模型配置 → 渠道管理 → 添加渠道**，默认接口地址为 `https://api.openai.com/v1`。在页面填写自己的 API Key，点击 **选择模型 → 拉取模型列表**，搜索并勾选需要的模型，也可全选筛选结果。渠道不提供目录时，可在同一窗口手动增加 model ID。点击 **确定** 后核对每个模型的 **生图／视频／文本** 用途，再保存渠道。目录返回与用途建议不代表实际调用已验证；生成参数仍需符合渠道要求。

配置页分为三个页签：**渠道管理** 管接口、密钥、启停和删除；**模型管理** 按渠道、用途筛选并搜索模型，可添加或删除模型；**默认模型** 设置自己的常用模型。渠道行的 **查看模型** 会直接打开并筛选该渠道的模型。图文分析模型的单价和费用上限在 **模型管理** 页签下方设置。

**删除不用的渠道**：在 **渠道管理** 点击渠道右侧的 **删除**，确认框会列出将一并移除的创作模型和独立分析模型。确认后，渠道和模型从配置列表中移除，服务端保存的该渠道 Key 也会清除；历史任务、分析结果和生成文件保留。正在排队或运行的任务会阻止删除，页面会显示具体原因。若仅暂时不用，请点击 **停用**；删除后再次添加需要重新填写 Key。空渠道或已停用渠道也可以删除。

保存后从 **默认模型** 页签选择图片、视频、文字或业务分析默认模型，点击 **保存默认模型**。默认值按当前用户保存，返回原创作页面会刷新可选模型，并保留画布、提示词及仍然有效的当前选择。同一账号和组织在不同浏览器中登录，可读取同一份已保存配置。编辑已有渠道时，Key 留空即可保留服务端凭据；获取列表不需要再次输入。

八个业务助手自动读取已启用的 OpenAI／兼容渠道文本模型，优先选择默认业务分析模型，未设置时跟随默认文本模型。已有的独立分析模型仍可使用；同渠道、同模型会共用 **图文分析模型与费用设置** 中登记的单价和单次上限。未填价格时费用显示未知，仍记录实际 tokens；填写 0 只代表按配置估算为 0，并不代表渠道免费。组织启用金额预算后，需先补充计价资料并核对历史未计价调用。图文任务须实际模型支持图片和结构化输出，具体能力以调用结果为准。上游更新采用[版本检查、兼容验证与回退流程](operations/creative-studio-upgrades.md)。

**删除不用的模型**：在 **模型管理** 中，直接点击模型右侧的 **删除**；图文分析模型也可在下方 **图文分析模型与费用设置** 中删除。确认后，该配置退出新任务的可选列表，历史任务、分析结果和生成文件仍保留；它若是你的默认模型，默认选择会同步清除。共用文本模型删除后也会从业务分析中移除；同名但单独添加的其他配置保留。模型仍有排队或进行中的任务时会提示稍后再删。以后需要时可重新添加，渠道的 API Key 无需重复填写。

进入创作工具后会自动读取项目，无需手动连接 ERP。短暂的网络或服务中断会显示“正在恢复数据读取”，恢复后继续打开原记录；这时保留页面即可。正常状态显示“自动保存已开启”。“保存失败”表示当前更改还未确认保存，应点击“重试保存”或先导出备份；遇到另一页面已保存的版本冲突时，先保留当前草稿再核对版本。

**创意项目** 用于开发可复用的印花与定制模板。项目列表可以搜索名称、按定制类型和审核状态筛选。点击 **新建创意项目** 后，依次填写四个页签：

1. **需求单**：选择固定印花、文字定制、买家图片定制或图文定制；填写创意方向、人群、场景、风格、固定元素和验收要求。可关联选品研究思路，以及计划适配的 SPU 和具体规格。
2. **设计与素材**：选择或上传授权参考素材。保存需求后进入项目画布、生图工具，或直接上传美工完成的 PNG、JPG、WebP 设计方案。项目需求会随项目带入生图指令。
3. **定制配置**：添加文字和图片字段，定义必填、文字长度、填写说明及版面区域。可输入示例文字或本地示例图预览位置；该预览用于配置，正式订单仍要按具体规格审核。
4. **审核与交付**：审核方案后，登记印花 SKU、主文件和素材包。**分层 PSD 从这里的“印花素材包 → 上传授权素材”上传**，并填写文件用途和制作说明；也能绑定背景、装饰、字体等素材。单文件最大 20 MiB。这里管理的是印花源文件，商品套图 PSD 仍走套图模板流程。

保存的需求和已登记的印花版本保留历史。修改创意要求点击 **复制为新需求**；修改印花素材创建新版本。已派发订单使用原先锁定的版本。买家文字和照片在订单中心维护。历史多步骤创作从 **历史创作与工具 → 打开原创作工作台** 进入，视频保留为创作素材；详见[集成与恢复说明](integration/creative-studio.md)。

历史多步骤工作台中，最终通过的方案可关联**已审核的通用工艺底稿**，批量创建独立生产草稿，点击方案下的“打开生产稿”，在当前项目内继续作图。点击“返回当前创意项目”后，所选方案和筛选条件仍保留。底稿只复制尺寸、工艺参数和轮廓，新图案按比例居中放入；需要重新核对实际尺寸、图案摆放、抱枕轮廓/缝边/条码区或备胎罩孔位，再审核和导出。没有底稿时点击“配置工艺底稿”，在当前工作台配置并审核一个通用项目；返回后自动刷新可选底稿。每个创作步骤最多 4 个方案。买家私有照片须在订单中心审单并派发后，从制图中心进入订单生产稿。第一次安装和恢复连接见[画布使用说明](operations/infinite-canvas.md)。

批量模式从 **生图工作台 → 批量生图** 或 **创意项目 → 辅助工具 → 批量生图** 进入，面向 SKU 前的创意
生产；**创意设计 → 商品套图** 面向已绑定 SKU 的正式设计生产。旧地址
`/pod-workbench/batch-designs` 会保留查询参数并跳转到 `/creative-designs`。

1. **批量生图**：先创建并审核印刷规格，再用页面表格或本地 CSV 提交
   1–50 条创意需求。每条可生成 1–4 个候选；勾选多个候选时，每个候选都
   会建立独立创意设计族。
2. 候选选定后系统按焦点、安全区和目标比例裁切。安全区无法保持时会转为
   AI 扩图，并在画幅卡片上显示必须人工检查的生成区域。只有母版和所有必需
   画幅一起通过审核，创意版本才会批准。
3. 批准后勾选一个或多个 SKU，并选择每条绑定固定的印刷规格版本。全部兼容
   检查先完成，成功后才创建正式设计任务和已批准版本；失败不会留下半套记录。
4. **批量套图**：先从权利已批准的 PSD 创建检查。编译通过并达到黄金图
   SSIM 0.99 后，由审核人确认，再组装和批准固定平台/语言的模板包。
5. 选择一个已批准模板包和最多 50 个兼容正式设计。桌面端使用“款式行 ×
   槽位列”矩阵；移动端自动变为逐款槽位卡片。失败或被驳回的槽位可单独
   重试，新结果保留新的尝试版本。
6. 只批量批准必需槽位齐套且无阻断的款式。最后逐款选择 Listing 版本，明确
   设置输出到图片槽位的映射。系统不会自动创建 Listing，也不会自动发布。

任一入口显示“暂未启用”时，表示处理器、Redis/Worker、ImageMagick 或批准
模板包尚未就绪。不要通过直接修改状态绕过门禁；联系管理员完成运行配置和
审核链。套图工作台只生成图片，标题继续使用 POD 作图中心的独立标题工具。

## 9. 状态和故障处理

### 9.1 常见状态

| 状态                      | 含义                           | 建议操作                     |
| ------------------------- | ------------------------------ | ---------------------------- |
| `partial`                 | 已保存可解析部分，但有字段缺失 | 查看诊断并决定是否重新采集   |
| `unauthorized`            | 未登录或凭证无效               | 重新登录或刷新本地服务身份   |
| `forbidden`               | 当前角色缺少权限               | 由管理员补充分配权限         |
| `reconciliation_required` | 外部或内部证据不一致/结果未知  | 先核对实际状态，再人工处理   |
| `dead_letter`             | 已耗尽安全重试次数             | 查看失败码并创建显式恢复动作 |
| `incomplete`              | 计算缺少必要事实               | 补充来源证据，不要手填为零   |
| `stale`                   | 投影或指标超过有效期           | 重新同步、计算或记录新快照   |

### 9.2 资料库读取失败或上传失败 401

依次检查：

1. Web、API 和 Keycloak 是否正在运行。
2. `http://127.0.0.1:8000/health` 是否返回 200。
3. 是否执行过 `pnpm --filter @yummyai/api bootstrap:local`。
4. 扩展是否为当前构建版本并已重新加载。
5. `.env` 中配置的扩展 ID 是否与浏览器当前扩展 ID 一致。
6. 浏览器是否仍保留过期授权状态；必要时重新登录并刷新页面。

### 9.3 页面没有更新

- 确认扩展点击的是 **发送到研究库**，不是只点了 **重新读取**。
- 检查扩展提示是否上传成功。
- 刷新研究资料库并展开快照历史。
- 重复采集应增加 `VERSIONS` 数量，不会覆盖原快照。
- 如果数据仍缺失，查看解析诊断和 API/Worker 日志。

### 9.4 最后一张图片不显示或图片数量异常

- 媒体按规范化来源和内容哈希去重。
- 视频与图片是不同媒体类型，不应互相计数。
- Amazon 商品媒体包括高清套图及普通/高级 A+ 图片；页面装饰图、Brand Story、推荐商品、变体缩略图和重复尺寸不应计入。
- 确认扩展和 Web 均为同一提交版本，再重新采集形成新快照。

### 9.5 本地日志

```powershell
docker compose --env-file .env -f infra/docker-compose.yml logs --tail=100 postgres redis minio keycloak clamav otel-collector
```

低内存模式下，Worker、扩展、ClamAV 或遥测采集器只有在对应按需命令启动后才有日志。开发进程日志由运行相应 `pnpm dev:*` 命令的终端输出。不要把 Token、Cookie、授权头或买家隐私复制到问题报告中。

## 10. 数据与安全规则

### 在线制作生产图

在 **创意设计 → 生产文件与底稿** 中，可以制作异形抱枕或定制备胎罩的通用底稿。
订单生产稿从 **订单中心** 审单开始：核对印花 SKU、编辑定制要求并选择买家原图，
点击 **确认并派发设计** 后进入 **制图中心** 打开编辑器。编辑器带入本次派发固定的需求和素材版本，
两个产品分别保存工艺参数。

订单生产稿会直接显示顾客的制作要求，包括保留部位、尺寸和单／双面印刷。仅识别明确的原始选项；“Only Face”对应完整头部，保留双耳、头顶和下巴。未知或冲突的选项会提示核对。

选中图片图层，点击 **抠图与修边**。框住要保留的头部／主体，可添加保留点和排除点，再点 **生成所选部位抠图**。用 **套索保留**、**擦除**、**恢复** 修整边缘；放大并切换黑／白背景检查毛发，随时对照原图或撤销重做。自动选区需要本机已安装模型，手动工具可独立使用。点击 **应用抠图并返回画布** 后保存新版本，再生成抱枕轮廓。原图保留，重新进入修边仍可恢复误删的部分。自动结果需要人工检查，尤其双耳、下巴和胡须。

毛发边缘生硬时，先点 **细化整圈边缘**。遗漏长胡须时，选择 **毛发修复**，在显示的原图上沿胡须及周围少量背景涂抹紫色区域，再点 **细化涂抹区域**。系统只重新计算这些区域的透明度，不会画出新的毛发；其余选区保持不变。画笔圆圈显示作用范围，大小按原图像素标注。细化可撤销；发生错误时涂抹与当前抠图仍保留。

切换白／黑背景放大检查残影，必要时从低强度开始使用 **清理半透明残影**；过强会减淡细毛，可以撤销。**恢复** 会连同原位置背景一起恢复，更适合补回明确的主体，细胡须优先用毛发修复。暗背景残色、低对比度白须与身体交叠的位置仍需人工核对。确认满意后应用、保存新版本，再检查抱枕轮廓和尺寸。

先创建项目，再上传原图、添加文字并调整位置。抱枕需要调整闭合裁剪轮廓、白边和
底部条码矩形；备胎罩按实际印刷直径排版，可以设置弧形文字和开孔。现有压平的
PNG 可以作为图片素材使用，但不会自动恢复为可编辑文字或图层。

选中图层后，右侧 **图层 → 快捷排版** 提供以下工具，所有操作都可以撤销：

- **水平／垂直居中、边缘对齐**：按可见主体或实际字形排版，透明图片的空白边不会影响居中。参考区域为抱枕白边以内或胎罩安全区的外接矩形；异形边缘仍需人工核对。
- **主体适应区域、恢复原图比例、左／右转 90°**：等比放置图片，旋转围绕可见主体中心。宽高默认联动，取消“锁定宽高比例”后才能单独拉伸；水平／垂直翻转在图片属性中。
- **复制所选图层、替换所选图片**：替换可以选择已有素材或上传新图，新图等比放入原占位框，保留中心、旋转和翻转。原素材与历史版本保留。抱枕换图、移动或缩放后，检查并按需重新生成轮廓。
- **铺满胎罩背景**：无透明区域的背景图等比铺满圆形并回正，画布裁掉圆形以外部分。透明抠图使用“主体适应区域”。
- **直排文字、顶部弧形、字号适应弧长**：同一文字图层直接切换排法。适应弧长时字号和字距一起调整，字体和弧形半径保持不变。
- **图片清晰度**：出图区随尺寸实时显示有效 DPI，点击条目定位图片；后台预检的图层错误也可直接定位处理。改变 DPI 标签不会补回原图细节。

点击画布或图层后，**Ctrl／⌘ D** 复制、**方向键** 移动 1 mm、**Shift + 方向键** 移动 10 mm、**Delete** 删除、**Ctrl／⌘ S** 保存；**Ctrl／⌘ Z** 撤销，**Ctrl／⌘ Shift Z** 重做。输入框、抠图和勾轮廓时不触发图层快捷键。锁定的图层无法修改、删除或移动，先在左侧解锁。

异形抱枕支持 **10、12、14、16、18、20、22、24 in** 八个订单规格，输出固定 150 DPI。
选中透明抠图后，点击 **按规格生成抱枕轮廓**：先把图片的可见主体等比例设为该规格
的最长边，再按当前白边参数生成外围轮廓；已有文字和图片随构图等比例调整。若已经
手动定好图片尺寸，使用 **按当前图案尺寸生成**。默认白边为 200 px，黑裁线为 6 px。
生成结果可撤销、重做，也可继续拖动节点修整；多块分离的主体需要先手动连接轮廓。
选中规格本身不会立即缩放现有图稿，标称成品尺寸也不等于加上缝边和条码后的排版尺寸。

空白条码框**必须接在主体最下方**，不可放在侧边或上方。工厂图示没有标出条码框
宽高，须在“工艺”中填写；点击 **条码移到主体最下方** 可恢复位置。系统会检查位置，
错误时阻止出图。**正反片排版** 可立即查看单面留白背片或双面镜像图，独立文字保持
正读；照片内已有文字仍需美工处理。**测量细窄处** 在画布依次点两点可读出毫米和厘米，
低于 5 cm 的线段会提醒；它不自动证明整张轮廓合格。放大后可用手形工具平移，点击
**适应画布** 恢复完整视图。测量线不会进入生产文件。

保存会生成新版本。先生成服务端预览，核对正反面、文字和尺寸，再完成工艺确认、
版本审核及生产文件导出。生产输出使用原图生成 PNG、JPEG 或 TIFF，并写入打印
分辨率；JPEG 需要选择白色背景。缺少尺寸、字体、分辨率或必要工艺确认时，按
预检提示处理后再导出。具体工艺边界见 [生产编辑器说明](integration/production-editor.md)。

订单来源项目沿用订单资料的保存期限；到期、匿名化或删除后，项目私密资料不可再
解密访问。独立项目可以在项目内删除。下载到本地的文件需要自行管理。

- 所有业务数据按租户隔离，调用方不能自行指定租户 ID。
- 研究资产和可发布资产使用不同对象存储域。
- 已批准版本、采集快照、发布命令和财务事实不可覆盖。
- 外部写入失败或结果未知时，先对账再重试。
- 不使用浏览器自动化模拟卖家后台发布。
- 不绕过验证码、反爬限制或受保护端点。
- 不在代码、日志、截图或文档中保存真实凭证和生产数据。
- 文件下载链接是短期签名链接，不应长期分享。

```powershell
pwsh -File tools/scripts/backup.ps1 -OutputDirectory .artifacts/backups/manual-checkpoint
```

```powershell
pwsh -File tools/scripts/restore-drill.ps1 -BackupDirectory .artifacts/backups/manual-checkpoint -Cleanup
```

恢复演练使用独立临时数据库和对象桶，不会覆盖当前环境。生产恢复仍需要冻结写入、新数据库/桶、校验和检查及审批切换。

## 产品与供应商供货资料

在“产品目录”中点击“管理供货”，可以给同一产品关联多家供应商。
在“供应商档案”中点击供应商名称，可以查看其供应产品，也可以直接新增或关联产品。
如果尚未建立 SKU，先选择“产品通用”；已有 SKU 时按实际规格分别记录供货条件。

每条供货资料可维护供方货号、采购链接、规格与定制范围、加工工艺、库存物料、
采购单价、币种、起订量、交期、报价有效期和验样状态。同一产品规格只能有一个
供货中的主供供应商。修改资料会保留历史版本，不覆盖旧报价和旧采购金额。

按实际业务勾选“定制订单”“FBA 备货”或两者。点击“创建采购草稿”后，
选择本次用途、数量、预计到货时间和收货库位，再到“采购补货”审核和登记收货。
库存物料、库位和仓库都可在表单中新增。

创建成功后点击 **查看采购草稿**，采购页会滚动并高亮对应采购单；点击 **返回供货资料** 可回到本次来源产品或供应商。

日常买家定制订单在“订单履约”中核对定制内容、设计稿、生产与发货；Amazon
订单可从“报表导入”进入指定店铺。FBA 备货按 SKU 和补货数量单独安排。
若货物先到自有仓质检，再送 FBA，采购先收至自有仓。发往 FBA、Amazon 接收和
平台库存确认是不同环节，本地收货记录不会自动建立 FBA 入库计划或确认平台库存。
