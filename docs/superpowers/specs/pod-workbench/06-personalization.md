# POD 模块 PRD 06：来图定制

## 1. 模块目标

将顾客提供的图片、文字、颜色和选项安全地映射到版本化模板，生成商品预览、校样和履约输入。模块覆盖图片合成、合照、宠物换装、模板编辑、PNG/PSD 导入、批量编排和订单定制数据映射。

顾客素材属于订单 PII，不得进入普通素材库、长期视觉索引、跨订单复用或模型训练。公共任务、资产域、版本和审核规则遵循[总 PRD](../2026-08-03-yummyai-pod-workbench.md)。

### 1.1 当前实现切片（2026-08-04）

- 已实现空白模板，以及授权 PNG/PSD 源文件的异步检查、解析结果预览、警告确认、四类槽位人工修正、不可变模板版本、模板审核和 SKU/尺寸显式绑定。
- 源检查固定资产 ID、版本、SHA-256、权利状态、解析器键与版本；队列仅携带检查 ID。完成或失败的检查结果不可覆盖，确认后同一检查只能创建一个模板版本。
- PNG 当前读取真实画布、Alpha 类型与物理分辨率，并建议一个全画布图片槽位。PNG 不含图层语义，因此建议结果固定标为需要人工确认。
- PSD 当前按文件分段边界读取画布、分辨率、颜色模式、图层几何、Unicode 图层名、文字标记和 `lsct` 分组；支持中英文图片、文字、装饰、背景别名，无法明确分类的图层显示警告并由用户确认。
- 已实现订单私有域内的批次准备：一次提交 1–100 个订单行，显式固定订单、订单行、定制版本和 SKU 模板绑定；队列只携带批次 ID，Worker 在内存中临时解密顾客字段并生成重新加密的槽位解析快照。
- 批次按订单行隔离失败并汇总为完成、部分成功或失败；每个成功项固定模板版本、解析槽位数和加密快照的 SHA-256。解析快照 v2 同时固定顾客文件资产 ID、版本、SHA-256 和媒体类型，API、队列、审计与诊断均不返回顾客原始文字、留言、图片地址或解析密文。
- 已实现订单上下文 `image_composite`、`group_photo`、`pet_outfit` 与 `fulfillment_composite` 的专用异步渲染边界。渲染队列只携带任务 ID，Worker 在内存中解密并复核 v2 快照、模板和顾客文件字节，再把结果保存为订单私有资产和待审核 `DesignVersion`。
- 作图中心已提供订单定制操作台。运营人员可从 PII 安全候选列表选择订单行和明确模板绑定、查看取消订单/定制未就绪/缺少 SKU/模板未批准/绑定未生效等阻断原因、创建预处理批次，并从成功项目创建图片合成、合照或宠物换装任务。页面只显示订单标识和业务元数据，不返回顾客原始字段。
- 合照至少要求两份不同顾客图片，并逐输出核验使用全部输入、人物数量一致、无新增和无重复人物。宠物换装逐输出核验宠物身份、毛色斑纹、体型及参考身份隔离。缺少任一机器可读质量证据时失败关闭。
- 已批准的租户内模板可一键复制为新的组织模板草稿。副本使用新的模板族和版本 ID，固定 `sourceTemplateVersionId`、画布、槽位、复用标识及仍有效的授权素材引用；源模板和副本分别审核、编辑与绑定，数据库阻止修改复制来源。
- 渲染输出先处于权利未确认和设计待审核状态；只有 `customer_provided` 权利证据获批且设计人工审核通过后才能进入后续生产清单。订单素材和结果不进入公共视觉指纹、素材关系图、Listing 候选或普通导出。
- 仓库当前提供受控渲染器接口和严格结果验证，并已交付订单候选的安全 CSV 批量选择；不内置 PSD 像素、字体、蒙版、效果或生成模型。字体映射、完整模板编辑器、跨租户公共模板市场，以及模板槽位文字、颜色和素材引用的批量表格编辑仍按本 PRD 后续实现；未配置专用订单处理器时创建新渲染任务失败关闭。

## 2. 模板生命周期

模板状态为：

`draft -> validating -> ready -> archived`

已用于 Listing、订单或生产清单的 `PersonalizationTemplateVersion` 不可修改。编辑模板创建新版本，现有订单继续使用其锁定版本；只有显式迁移后的新订单使用新版本。

一个模板归属一个商品，可以绑定多个 SKU 尺寸。每个 `SkuTemplateBinding` 明确记录画布尺寸、单位、模板版本、映射状态和生效时间，不能按 SKU 名称相似度自动绑定。

## 3. 新建模板

### 3.1 新建方式

| 需求编号 | 方式 | 行为 |
| --- | --- | --- |
| DIY-TEMPLATE-01 | 新建空白模板 | 选择商品、SKU 画布、物理尺寸、单位和背景，从空白编辑器开始 |
| DIY-TEMPLATE-02 | 上传 PNG 模板 | 将透明 PNG 导入为画布参考，系统建议图片容器但需用户确认 |
| DIY-TEMPLATE-03 | 热门/组织模板 | 复制已有模板为新的草稿版本，不共享可变内容和订单数据 |
| DIY-PSD-01 | 导入 PSD | 解析支持的分组、图层、字体和几何，生成待确认模板草稿 |

PNG 和 PSD 文件先进入隔离区执行恶意文件、文件炸弹、尺寸、颜色模式和解析器安全检查。解析失败时保留诊断，不创建部分可用模板，除非用户选择导入为静态图片。

当前实现只从已处于授权域且权利已批准的非顾客资产创建检查，并对源字节再次校验 SHA-256。内置解析器不解压 PNG 像素或 PSD 通道数据，限制单文件 128 MiB、PSD 5000 图层和输出 500 槽位。通用上传隔离与恶意文件扫描仍是源资产进入授权域之前的前置流程，不能因模板解析器存在而跳过。

### 3.2 模板与商品

新建模板时必须选择商品和至少一个 SKU 或尺寸草稿。模板名称用于业务识别，不承担 SKU 映射。一个商品可以有多个模板，一个 SKU 在同一用途和生效时间只能有一个默认模板，但履约人员可以在有权限时人工选择其他兼容版本并记录原因。

## 4. 模板编辑器

### 4.1 画布与图层

编辑器支持图片容器、文字、装饰元素和背景四类内容。每个图层具有稳定 ID、名称、层级、锁定状态、位置、尺寸、旋转、透明度和可见性。编辑器使用真实物理单位与像素换算，缩放视图不改变生产尺寸。

### 4.2 图片容器

`TemplateSlot` 类型为 `image` 时支持：

- 是否为顾客替换项；
- 稳定字段键和用户可读名称；
- 位置、尺寸、旋转、对齐和裁剪形状；
- 适应区域、充满区域、拉伸至区域或自定义裁剪；
- 描边、内容描边、阴影、半调、滤镜、背景色和不透明度；
- 可选的抠图、背景抠图、镜像、旋转、模糊或 photolab 等处理配方；
- 最低像素、比例、格式和文件大小校验。

同一模板内，多个图片容器使用相同 `reuseLabel` 时只要求顾客上传一次，并把同一输入填入全部位置；不同标签必须独立输入。标签复用是显式数据关系，不依赖图层显示名称碰巧相同。

### 4.3 文字槽位

文字槽位支持顾客替换或固定文字、字段键、字体、候选颜色、对齐、字号范围、行数、字符限制和自动适配策略。替换后文字必须保留在模板定义的文本范围内；溢出时按策略缩小、换行或阻断，不能无提示裁断。

字体必须具有可用于商业输出的许可。PSD 缺失字体时用户可以从组织字体库匹配或上传有权使用的字体；映射结果保存在模板版本中。

### 4.4 装饰元素与背景

装饰元素可以固定或可选，固定元素不作为顾客输入。背景支持固定色、候选色、固定图片或候选背景，所有可选素材均需权利评估。模板复制时只复制已授权的组织素材引用。

## 5. PSD 解析

### 5.1 四类分组

导入器识别并规范化四类分组：

1. 蒙版组：固定构图、装饰和遮罩，不直接成为顾客替换项；
2. 文字组：可替换或固定文字；
3. 图片组：可替换图片容器；
4. 背景组：固定或可选背景。

系统接受中英文受控别名，但保存时统一为内部类型。无法识别的顶层组进入“未映射”，用户必须处理后模板才能变为 `ready`。

### 5.2 PSD 元数据规范

图层名称只作为导入提示，不作为长期业务协议。导入器可以识别教程中的角度、模糊、镜像、抠图、无框和效果标记，但必须转换为显式 `TemplateSlot` 字段，并在导入确认页逐项展示。后续编辑不依赖拼接字符串解析。

以 `*` 或组织配置标记的图层导入为 `locked=true` 且不可作为替换项。特殊生产码、二维码或订单号占位必须使用明确的槽位类型和数据来源，不根据单个符号自动生成。

### 5.3 解析确认

导入结果展示：画布、四类分组、未映射图层、字体匹配、可替换项、效果、颜色和 SKU 候选。首次 SKU/模板匹配必须由用户确认；确认后同一外部 SKU 与模板版本可以自动匹配，但版本变化或尺寸冲突时重新确认。

## 6. 批量图片与文字编排

### 6.1 编辑表格

表格的列对应可替换图片、文字、元素和背景，行对应一个成品。支持：

- 快速导入：按文件选择顺序依次填充全部图片槽位；
- 横向上传：一组有关联的素材填入同一行，例如同一家庭或宠物的不同照片；
- 纵向上传：同类素材填入同一列，例如多位人物或多只宠物；
- 结构化文件导入文字、颜色和素材引用；
- 逐格替换、删除、复制和预览。

提交前展示成功行、缺失行、格式错误、文字溢出和预计输出数。无效行不进入队列，其他行可以继续。

### 6.2 自动构图

用户可以关闭自动构图以还原顾客排序，或开启全局均衡/主体聚焦。自动补齐用于容器留白，默认高斯模糊；自动提质只对低清晰度顾客图片执行并记录推断。系统不得为缺失顾客照片生成新的“顾客照片”。

## 7. 图片合成、合照与宠物换装

### 7.1 图片合成

基于模板批量生成商品预览或 Listing 候选，支持人像、宠物和普通图片。模板效果、输入顺序和输出版本全部可追溯。结果可继续进入套图，但顾客订单素材生成的结果仍属于该订单 PII 域。

### 7.2 合照

合照允许多张授权人像或顾客在同一订单中提供的人像进行智能构图。系统尽量保持人物身份、年龄特征和服装，不凭空增加人物。每个结果显示使用了哪些输入；缺失或重复人物属于质量失败。

### 7.3 宠物换装

支持官方服装预设或自有参考服装，可选择批量、比例和输出数量。自定义参考必须是有权使用的清晰宠物穿搭图。结果保持宠物身份、毛色、斑纹和体型，不把参考宠物身份带入结果。

## 8. 订单个性化映射

### 8.1 平台输入

Amazon 和 Etsy 订单只能通过主 PRD 允许的官方授权连接器进入。系统把平台字段映射为现有 `CustomizationSchema`，包含文字、图片、颜色、日期、选项和留言，并创建不可变订单定制版本。

TEMU 教程用于保留“用户上传文件包适配器”的接口形态，当前不提供 TEMU 账号授权、后台抓取、自动下载或状态回写。未来启用前需要独立产品与安全评审。

### 8.2 安全处理

顾客文件注册时记录安全文件名、媒体类型、字节数、SHA-256 和私有对象键，并在解析前完成恶意文件扫描。扫描感染、失败或超限的文件进入隔离，不能预览、生成或下载。扫描通过后的文件提升到独立 `order` 资产域，而不是普通 `authorized` 素材域。

PII 读取必须基于订单职责和操作目的；管理员角色不自动获得内容读取权。日志、任务参数、模型成本记录和通知中只使用订单/字段内部 ID，不包含原始文字、图片 URL 或留言。

### 8.3 订单批次准备

订单批次准备用于把已扫描并提升的顾客文件、加密文字字段和已批准模板解析为后续渲染器可消费的固定输入，不负责输出像素成品。创建批次同时要求 `order:write`、`order:pii:read` 和 `design:write`；读取批次只返回安全摘要，同时要求 `order:read` 和 `design:read`。

创建请求包含 UUIDv7 幂等键和 1–100 个订单行。每行必须显式提供订单、订单行、不可变定制版本和 SKU 模板绑定，且同一订单行在一个批次内只能出现一次。服务端在租户事务内验证全部引用可见后创建固定项目；相同幂等键与相同请求返回原批次，不同请求发生冲突。

操作台先调用 `GET /v1/pod/order-personalization-batches/options` 获取安全候选。候选只包含订单/订单行标识、平台、商品标题、数量、SKU、最新定制版本号与完整度、模板版本、尺寸和稳定阻断码，不读取或返回顾客文字、留言、图片地址、文件对象键和解析密文。存在多个有效尺寸模板时分别展示，用户必须选择一个；同一订单行重复选择会在服务端动作层和契约层被拒绝。

操作台的订单候选 CSV 只接受外部订单号、外部订单行号和可选尺寸列。文件在浏览器本地解析，不作为资产、任务参数或日志上传；任何未知列都会拒绝整表。预览只返回成功数以及未匹配、阻断、重复、无效和模板歧义的行号，不回显原始单元格。有效行可部分进入复选框，提交时仍转换为现有的订单、订单行、定制版本和绑定四元组，并由服务端重新校验。

队列负载只包含 `batchId`。Worker 逐行执行以下校验：

1. 订单、订单行、定制需求和版本属于同一固定上下文，订单未取消；
2. 定制版本没有缺失字段、隔离文件或被拒绝状态；
3. 订单行锁定的 SKU 与有效绑定一致，且绑定在订单下单时间已经生效；
4. 模板版本已批准，存在可替换槽位，槽位类型与锁定的 `CustomizationSchema` 一致；
5. 顾客文件已完成扫描和提升，仍属于该定制版本，资产域、来源和权利状态符合订单私有域策略；
6. 同一顾客字段当前只能解析一份已提升文件；多文件字段在后续渲染器定义明确顺序前失败关闭。

Worker 只在执行内存中使用 `ORDER_PII_ENCRYPTION_KEY` 解密定制字段，随后立即将槽位解析重新加密存入批次项目。解析快照包含模板槽位与顾客字段/文件内部引用，不进入普通资产检索。成功项保存加密快照校验和与槽位数，不能对低熵顾客明文生成可公开查询的确定性摘要；业务校验失败只终止该行，基础设施故障按任务策略重试。终态批次、项目和身份字段由数据库阻止覆盖，修改输入必须创建新批次。

批次准备完成不代表生产完成。实际渲染器必须重新校验加密快照、模板版本、文件字节和字体/蒙版/效果支持，并创建新的设计版本，不能把准备结果直接视为可下载生产文件。

### 8.4 订单上下文渲染

创建渲染任务使用一个已成功准备的批次项目、UUIDv7 幂等键、工具键和严格参数快照。图片合成、合照和宠物换装支持 PNG/JPEG/WebP，履约合成支持 PNG/TIFF；参数只允许固定输出格式、适应策略、自动构图、AI 提质开关、身份保持策略、顾客素材使用策略、参考身份隔离策略、DPI、色彩模式和透明通道，不接受自由文本或顾客值。相同幂等键与相同请求重放原任务，不同请求冲突。

合照和宠物换装必须显式允许 AI、启用自动构图、选择严格身份保持并使用全部映射顾客图片。宠物换装还必须固定“禁止参考身份迁移”。普通图片合成和履约合成不能伪装成这两类创意策略。

API 创建任务同时要求 `order:write`、`order:pii:read` 和 `design:write`；查询只返回任务、进度、稳定诊断、模型来源和结果版本 ID，同时要求 `order:read` 与 `design:read`。订单处理器通过独立地址、凭证、部署 ID 和工具白名单启用，不复用普通 POD 处理器凭证。

Worker 执行时：

1. 校验加密解析的 SHA-256 后才解密，并重新验证订单、订单行、定制版本和模板范围；
2. 验证每个顾客文件仍位于 `order` 域，版本、校验和、媒体类型和 `customer_provided` 来源与解析快照一致；
3. 只向明确授权的专用处理器发送完成渲染所需的模板、槽位、顾客值和字节，不发送租户、订单或顾客身份标识；
4. 校验输出角色、格式、尺寸、色彩、透明通道、AI 推断范围、模型版本和最大字节数；合照和宠物换装必须声明实际 AI 推断；
5. 对每个创意输出按文件名核对全部输入槽位键。合照额外核对人物数量、缺失、新增与重复，宠物换装额外核对身份、毛色斑纹、体型与参考身份迁移；
6. 将结果写回 `order` 域，创建待权利确认和待人工审核的全新设计版本，不生成公共指纹或普通导出关系。

输出声明包含 AI 推断但任务未允许 AI 提质、输出格式与工具不匹配、文件名重复、缺少模型来源或私有输入证据漂移时失败关闭。基础设施故障只保存不含 PII 的稳定诊断并按任务上限重试。

### 8.5 校样

自动模板、人工设计直产和客户确认后三种路径复用现有订单个性化状态。需要客户确认时创建锁定校样版本和截止时间；客户拒绝必须记录结构化原因，修改后创建新校样，不能替换旧校样。

## 9. 错误与异常

| 场景 | 系统行为 |
| --- | --- |
| PSD 顶层组缺失或无法识别 | 显示未映射诊断，模板不能进入 `ready` |
| 字体缺失 | 要求映射或上传授权字体，不使用未知替代字体静默出图 |
| 同一复用标签规则冲突 | 阻止保存并指出冲突容器 |
| SKU 无匹配模板 | 订单进入待配置，不自动选择相似尺寸 |
| 顾客文件扫描失败 | 文件隔离，订单定制状态为 `quarantined` |
| 批次内某订单行映射失败 | 仅该行失败并返回不含 PII 的稳定诊断，其他有效行继续准备 |
| 幂等键对应不同批次内容 | 返回冲突，不覆盖或追加原批次 |
| 一个字段存在多份已提升文件 | 当前解析器失败关闭，等待人工确认或后续有序多文件规则 |
| 文字溢出 | 按模板策略处理；无有效策略时阻止该行生成 |
| 自动构图遗漏人物/宠物 | 质量检查失败，允许人工调整后新建版本 |

## 10. 验收标准

1. 空白、PNG、组织模板和 PSD 四种新建方式均形成版本化模板草稿。
2. PSD 能解析蒙版、文字、图片、背景四类分组，并要求用户处理未映射图层和字体。
3. 同名复用标签一次上传填充多处，不同标签必须分别上传；前后端校验一致。
4. 快速、横向、纵向和结构化批量导入均能逐行预览并隔离失败行。
5. 商品、SKU、尺寸和模板版本使用显式绑定，歧义或尺寸冲突不自动匹配。
6. Amazon/Etsy 订单数据经官方连接器进入；顾客文件完成扫描、PII 授权和下载审计。
7. 订单批次只把批次 ID 放入队列；Worker 临时解密并重新加密槽位解析，API、日志和诊断不暴露顾客原始值。
8. 批次逐订单行隔离失败，固定下单时有效的 SKU/模板绑定，并阻止未扫描、未提升、跨版本或多份无序文件进入解析快照。
9. 渲染任务只在专用订单处理器启用时创建，队列仅携带任务 ID；输出保存在订单私有域并经过权利与设计双重审核。
10. 订单定制操作台能显示可处理项和稳定阻断原因；创建请求不包含顾客原始字段，同一订单行不能选择两个模板绑定。
11. 合照不遗漏、重复或新增人物；宠物换装保持宠物身份特征。
12. 模板、校样、订单定制版本、终态批次和终态渲染输入不可覆盖，修改均创建新版本、新批次或新任务。
