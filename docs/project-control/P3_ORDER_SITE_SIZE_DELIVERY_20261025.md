# P3 订单站点与抱枕尺寸入口

本批接续生产用途资料分离，复用既有订单适配器、来源快照、渠道映射、工艺编辑器和个人身份验收。没有新增依赖或数据库迁移。

Amazon正式API订单以前只有首次来源指针，自动匹配未读取追加来源的站点；缺站点时还会放开站点筛选。现在同订单、账户、平台和外部订单号的适用来源与成功报告必须提供一致的明确站点。初始空缺可由后续有效来源补齐，冲突不能按到达顺序覆盖。未知或冲突时不返回自动配方或候选编号，摘要提示核对；内部受控渠道存在性检查继续阻止移除资料包绕过核对。真正手工制作、下单生效时间、旧包和配方固定关系保持。Etsy沿已有etsy域。

抱枕英寸按钮与带入订单要求以前无条件填写成品口径。现在显式固定ps-pillow-2026-09-17才采用图案口径，16英寸为406.4mm；未固定或旧标准保持原口径。动作只修改当前草稿的声明，不改变图层、轮廓或历史，不自动核对工厂尺寸，原确认失效及生产预检继续生效。

共享响应增加可选catalog.site，状态为resolved/missing/conflict；后两种marketplaceId只能是null。旧响应可继续读取，不向客户端运输完整来源内容。详细规则见[渠道映射](../integration/channel-mapping.md)及[抱枕操作流程](../operations/custom-pillow-workflow.md)。

定向检查覆盖14项站点单元、31项真实适配器/报告与数据库集成、34项前端单元和3项共享契约。个人浏览器验证当前标准与旧无pin草稿的真实保存、重载、旧版本不变，以及1440/390布局；首次选择器不匹配的失败保留记录，修正定位方式后两场景通过。既有订单与商品封包另按完整文件顺序回归，避免跳过其前序生产者导致假失败。

相关既有回归去重104项分两次定向运行通过。租约恢复夹具显式声明派发时间已到、再验证仍然存活的租约阻止执行及过期后的恢复，时间统一为PostgreSQL时钟。原派发、租约和完成断言保留，生产调度逻辑未改；第一次失败未记录该行派发时间，不能据此认定生产时钟故障。

发布仍须以精确提交的CI、固定构建、完整备份恢复、真实运行身份和原账户核对为准。上述检查不等于客户生产图稿已审核、真实付费已开放或工厂已接收。原始测试输出按交付协议处理；自动审批拒绝的精确目标保留阻断记录，不绕过策略或冒称清理成功。完整P3业务验收独立记录。
