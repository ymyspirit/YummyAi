## 问题与行为

- 未审商品原先也使用“查看本件审核与制图”，统一进入 artwork；本件要求区又在
  全单商品、工厂、运单、售后之后，确认入口依赖滚动。现在入口按本件真实状态判断。
- 本件处理与商品选择前置，保留整单商品和履约记录。未审单进入订单要求，已派发
  查看设计进度，有候选才直接审图；暂停、来源变化、取消和异常沿原优先级处理。
- 要求区显示“核对要求 → 派发设计 → 运营审图”，复用现有缺项定位和就绪判断，
  确认与推送保留为两个明确操作，确认按钮随本件滚动可见。
- 成功派发核对身份、本件、订单和固定状态，并等待父面板空闲且无未保存内容后
  再进入进度。失败或未知不自动导航、不自动重试，不启动额外真实订单。

布局参考 [Mantine Stepper](https://mantine.dev/core/stepper/) 的步骤、当前状态与完成条件
分离方式，沿用已有 React/CSS/Lucide，不引入组件库或改造后端状态机。
