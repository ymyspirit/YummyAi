当前未测量 P3 各专属套件及备份/恢复时间，不给确定工期。首次运行后记录真实起止、测试数、资源清理和候选身份。`order-intake-integration`、`production-command-integration`、`order-review-integration` 会重复包含 workspace 大文件；按改动影响选择一个覆盖组合，缺失文件再定向补齐，不轮流重复全跑。

快速检查随相关变更执行；最终同一干净候选由 CI 完成项目规定的 lint、typecheck、unit、integration、E2E、build 和扩展交付门。复用精确提交已经通过的结果；源码变化、失败或未消除疑问才扩大回归。新迁移、重置和实际部署证据必须属于本候选。

## 6. 浏览器、真实导入与发布退出条件

1. 隔离编译候选用个人身份完成“导入 → 缺项与映射核对 → 审单版本 → 已审核生产文件 → 固定交付包 → 提交默认排产 → 工厂原表更新/异常”演练；桌面及 390 px 关键控制可操作，无横向溢出。
2. 原键恢复、权限撤销、未知提交不重做、工厂状态不倒退及敏感预览清除有实证；报错与缺项不被隐藏。
3. 真实文件只通过获授权原账户及真实业务路径导入。保留来源校验和脱敏行/单/商品数量，逐行失败可查；不因导入成功自动审核客户需求、调用付费模型或下达工厂生产。
4. 技术测试中的合成 JPG、ZIP、工厂报表和回执明确标为夹具。测试通过不证明真实图像合格、工厂已接受、实际投产或质检合格；这些事实必须有各自真实依据，未取得则明确待验。
5. GitHub 候选、CI、固定构建、运行版本及恢复方案可对应；没有必需检查、工作树未净或候选 CI 未通过，不打阶段完成标签。
6. 维护/真实导入结果、明确保留历史及未完成项写入收口；全平台 48 需求/54 包状态按实证维护，不由本次 P3 自动计为全部完成。
