## 可操作结果

在 Agent 中明确选择通用知识或一个有权读取的产品，读取已发布依据，打开引用的原始版本，在同一业务对象上生成提案，经本人确认交给原业务服务执行。刷新或响应丢失后找回原结果，不重新创建业务记录。失效知识必须明确提示，不自动重发付费请求。

复用既有 NestJS、Zod、PostgreSQL、BullMQ、React 和官方 MCP SDK。保留既有知识导入、审核发布、引用撤回、固定评测和版本化执行。本批修复产品知识范围不可选、原版本链接丢失、失效回答仍显示完成，以及导入、治理和历史问答未完整复核产品当前归属的缺口，不另建知识或 Agent 框架。

## 验收门

- 产品候选采用当前 membership 与原会话权限交集，执行原目录对象范围和强制 RLS；只返回有界 ID、编码、名称。不同租户、撤权、过期响应、查询注入和大响应均拒绝。
- 产品知识仍经过原检索服务与发布/失效门，通用模式不会自动扫描所有产品；范围改变清除旧读取结果和未提交绑定。
- 产品负责人或团队变化后，旧问答、对话列表、评测报告与审核写入重新检查原产品当前权限；不改写历史输入，也不重新调用模型。账户资料分别执行店铺和财务权限范围。
- 引用链接包含固定 entry/version，不能误跳最新版本；过期回答明确不能继续使用。
- 个人浏览器在同一个编译候选上验证知识发布、产品检索、固定引用、原生 v4 提案、实际人工确认、原命令结果恢复和知识失效。
- 固定评测和官方 MCP 客户端验证复用既有隔离测试。MCP v2 的实际执行边界仍为 native-v3；不能声称支持 v4 fulfillment 命令。
- 集成测试只能使用一次性数据库、桶、Redis、测试身份，执行原生清理。合成模型只检查协议、权限和恢复，不证明真实模型质量或计费可用。
- 相关快速检查通过后同步 GitHub，最终候选完成完整 CI、固定构建、备份恢复、采用及真实日用检查。业务验收与技术验证分别记录，不借本批关闭全平台 54 个工作包。
