# 调用与费用证据

2026-10-16 · R20/H03/H06/H08 · B09/B28 的增量实现。完整平台范围不变。

## 所有者与读取

复用辅助、工作流和 POD 的原读取接口，附加有界 `invocations`，不新增可绕过拥有者的
通用查询或写入接口。共享 `harness-invocation-v1` 只包含请求身份、固定方法/工具引用、
阶段、时间、处理/派发次数、回执校验值、产物身份、用量和费用依据。没有原始输入、
提示词、输出字节、来源正文、对象路径、签名 URL 或凭据。字段由严格 Schema 控制。

- 辅助记录来自 ai_assist_runs、ai_assist_executions 和原预算账本。缺少旧执行记录时
  显示 legacy_missing，不由 startedAt 推造提交记录。内容到期后方法快照可能不可读，
  仍保留原执行和费用元数据；当前业务读取权限继续由 AssistService 校验。
- 工作流使用原 attempt 和固定输入，从商品拥有者按原 operationId 核验业务回执。
  返回产物异常但已写入回执时，两种事实分别显示。POD 子记录只能经过当前 POD
  拥有者的权限/数据范围读取后关联，缺少权限只显示关联不可读，不泄露子任务回执。
- POD 通过原任务读取入口显示最近至多 20 次拥有者调用记录，工作流每次最多关联
  父步骤和 20 条子调用。父步骤不是另一笔模型费用，不重复累加。

派发、本地处理、提交边界和响应是不同证据。三次本地处理不等于三次扣费；提交
标记也不证明服务已经接受或执行。没有返回数据时不补造渠道请求号或响应时间。

## POD 提交与回执

迁移 `0117_pod_invocation_receipts` 新建 pod_artwork_invocations，按租户/任务/尝试唯一。
同事务领取原任务并写 pending；提交前重新验证当前权限、范围和所属工作流，再写
submitted。原任务身份继续发送到处理服务。重复投递未领取原任务时不调用网关。

HTTP 网关在产物解析和解码前保存有界回执：响应校验值、渠道请求号（若返回）、
模型元数据、服务报告金额及接收时间。返回的费用独立于产物是否合格；元数据异常
不抹掉有效金额，缺项、负值、非有限数、溢出或精度不足的正数保持未知，不能记零。
其他已实现网关在返回后、产物检查前记录响应元数据。原始响应字节不进入本表。
HTTP 校验值针对收到的正文；非 HTTP 网关针对解析结果元数据及逐输出字节摘要，
两种方式不被宣称为同一原始文件的字节校验。

收到回执后权限变化仍保存原费用证据；采用结果继续经过原拥有者当前检查。
技术成功在同一业务事务关联原设计版本；审批、工厂接受和生产放行仍分别执行。
已有回执及终态受数据库不可变触发器保护；强制 RLS、非 owner 角色及 withTenant
覆盖读写。没有回填旧调用，也没有新增另一套订单、设计或预算账本。

本表是元数据回执，不能据此重建原始 POD 输出。网络/持久化失败后按原请求核对；
没有有效产物检查点时不得自动再次购买结果。迁移 0119 对新原任务另存加密响应和
产物检查点，复用原 invocation 显示派发与本地处理次数；本表仍不保存正文。
见[POD 恢复运行说明](pod-response-recovery.md)。旧任务不补造检查点，完整 Worker
实际进程崩溃和真实处理服务继续独立验收。

## 金额和对账交接

| 依据 | 显示含义 | 保留的限制 |
| --- | --- | --- |
| configured_rate | 用量乘原固定配置单价 | 不是渠道账单 |
| processor_reported | POD 处理服务在响应中报告金额，保存至八位小数 | 不是提供方最终账单或财务批准 |
| unknown | 没有足够计价依据 | 不能记零或释放原未知预算 |
| not_submitted | 已有记录证明本步骤未跨提交边界 | 不代表未来执行免费 |
| not_applicable | 父委派/本地业务步骤没有独立外部模型金额 | 子步骤和完整人工/基础设施成本另计 |

辅助继续读取原预算的 reserved/committed/released 及金额；发现多个预算记录则明确
歧义，不任选一笔作确定结论。POD 服务报告不直接写辅助预算或财务账。

界面“调用与费用记录”支持展开、键盘操作、响应式换行、进入/展开/收起动画和减少
动态效果偏好。“下载核对记录”导出严格白名单 JSON，固定当时的状态并明确
providerInvoiceVerified=false。导出不调用外部服务或改变任务/费用状态。
[人工核对工作台](model-billing.md)保存独立权限下的原请求、凭证摘要和美元金额确认，
不可变核对事件在同一事务纠正原 AI 预算投影；原配置估价及 POD 服务报告保留。
普通调用读者只见安全确认元数据，账单编号仍由核对权限保护。
人工确认不等于渠道 API 验真；真实提供方查询、自动账单匹配与业务试点仍需验证。

## 验证与部署

改写、权限变化、重复投递及真实界面/下载。正常业务库没有随隔离验证迁移；部署前
按备份/迁移运行手册应用 0117，API/Web/Worker 一起升级，不能仅替换前端。
原始验收日志、截图、trace 和下载在复核后清理，只留紧凑结论与校验记录。
