# 实物组报废归属与补做数量

2026-10-21 · c54e17a8 · PRD1.1.75定向技术验证及本批清理完成；普通148环境未采用0161。

## 原数量与来源

归属操作把已经核准的报废量固定到原失败实物组，不改原四桶数量、质检记录或原生产版本，也不执行库存报废、退料、退款或释放产能。复用既有质量、生产、权限和不可变审计边界。

每次新增报废批次固定实际quantityReviewId，用量为本次S减前次S；零增量核准没有新的报废额度。所有分配共享该批次余额，包括已经退休祖先组的归属，不能按新核准重新取得完整S。

只有在原组检验实际入库后观察到、核准的新增报废可归入该组。先报废2件再对剩余8件检验时，前2件已排除，不允许再次扣组。检验前已核准的批次显示为组外报废，不产生此组补做信用；观察早而记录晚的来源保持冲突阻断。没有分组的报废需要后续真实来源流程，不补造质检组。

## 分配、复检与补做

运营明确选择原失败组、原新增批次及本次数量，确认实际隔离和凭证。允许同组部分归属。已通过、已审核分配或实际交运、已被替代的组不能再扣原实物。

当前叶子组原Q、累计归属d，后续复检只覆盖Q−d；没有剩余实物时不创建零数量复检。任何原补做child固定版本的净占用仍大于0时，不能先退休原组再重开份额；完工、交运或案件结束不会自动释放原补做占用。

复检子组覆盖剩余实物，原父组退休后仍保留真实d份补做信用，不能重新取得Q。不同缺陷共享原组余额。原缺陷处理为scrap时，只能使用真实归属d减全部既有补做净占用的余额；不能借报废处理名义为整组补做。

归属不返还initial空额；补做仍使用原恢复owner、固定制造版本及全部资源池新预约。已有报废或归属的实物分组根不能整体覆盖重检来洗去来源；首次分组可按已核准完工数建立。旧式整批检验没有实物组且没有归属记录时，可以继续按当时核准完工数保存新检验，旧检验数量按实际执行时点保留。

新增scrap处理方式仅用于明确实物分组。普通整批写契约拒绝未定位的scrap缺陷，数据库延迟约束核对同租户、检验、生产单的真实缺陷组链接。改变后续检验形式不会把旧scrap缺陷变成未分组补做来源；公开恢复入口和数据库案件约束都要求原组链接，再由原组实际归属额度限制补做。

## 接口与原子性

接口为GET `/v1/production/orders/:id/quality-scrap`、POST其`reviews`子路由，使用当前本人tenant OrderRead/OrderWrite和独立个人BFF。同键、同操作者、同对象及完整正文才回放原回执。分页必须定位本生产单。

0161新增不可变归属审核与分配行两张forced-RLS表。SQL独立检查原版本、根、实际数量核准、前归属回执、来源fingerprint、逐批次/逐组余额、实际时间与规范正文；数据库记录完整出生事务。完整分配、原投影+1与成功审计必须在同事务闭合，旧回执或caller marker不能授权新分配。

先原请求键，再父订单、商品、生产/检验和发货锁；保留原owner锁序。当前权限改变、已读不可用及迟到响应清理私有界面，未知提交保留原正文和键，不自动刷新依据重发。
