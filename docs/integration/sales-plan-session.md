# 销售工作台会话、草稿与原同步回执

2026-10-18 · PRD 1.1.7 · R01/R03/R10/R13/R14/R37，关联 B19/B20。

## 业务行为

同一 SPU 的 Custom FBM、标准 FBM 和标准 FBA 方案分别维护定位、印花、素材、
文案和关联 Listing。新建仅提供本人当前可写的 SPU；直达不可写商品时明确要求
重新选择，不静默换成另一个商品。服务端仍按实际 SPU 和当前 ProductWrite 检查。

方案编辑保留原 revision。刷新或后台发现新版本时显示差异提示，不重置未保存稿
或把原稿改成基于新版本；旧稿保存返回冲突。操作员可以保留草稿返回列表、切换到
另一方案后继续原稿，或确认丢弃后重新载入当前方案。已确认自己的保存回执会更新
编辑依据，不用一次可能失败的后续 GET 推断是否保存成功。

临时读取失败隐藏不可核对的内容和操作，恢复后保留合法草稿；401/403/404 或身份、
单项范围、归属/可写状态变化清除对应旧内容。请求代次、取消信号及对象身份阻止
A 的读取或保存晚到后覆盖 B，新建成功回执也不能把另一方案强行切回。

## 当前身份与短期缓存

options 增加服务器生成的 contextAuthority，复用 catalog-core 的普通 ERP 权限
投影；与当前个人会话和 preferenceScope 一致后才开放工作区。身份来自服务端
成员关系，客户端不能通过该字段选择权限。API、Web 和共享 contracts 应一起部署。

沿用 useTaskDraft 的当前页签内存缓存，按租户/本人、方案、当前授权、SPU、拥有者、
团队和读写状态隔离。字段另固定原 revision；缓存最多保留两小时，存在容量上限。
这里的“刷新核对”指界面重新读取，不表示硬刷新、关闭浏览器或断电后能恢复未保存
输入。服务器保存的方案和不可变 Listing 历史不依赖这个缓存。

初次进入、每30秒、页面显示或重新聚焦时核对当前选项和所选对象。选择 B 时立即
遮蔽 A，即便 B 读取失败也不能在 B 的地址下展示 A。确认失权清除缓存，之后重新
授予权限不能复活已清除草稿。普通网络失败不能当作权限撤回或保存回滚。

## 同步刊登草稿

同步使用 ProductRead 和实际目标 ListingWrite，不要求额外取得 ProductWrite。
因此有权读取方案并编写 Listing 的人员可以同步未修改的已保存方案；未保存修改
先保存或丢弃。真正新增版本仍通过原业务门禁、当前计划 revision 与最新草稿版本
比较；已审核/封存内容不被覆盖，Custom/FBA 及制作质量限制不变。

返回已提交的幂等回执前，重新读取当前方案并检查当前来源范围；同时验证原回执的
`listingId`、`listingVersionId`：实际父 Listing 必须属于原方案，版本确实属于该
Listing，调用者对这个父对象仍有当前写入权。原回执不是授权。旧回执缺少可核对
依据时返回明确冲突，不猜测目标。这里核对当前方案来源，不伪造历史来源快照。

原回执可能对应一个合法历史版本；确认原提交不要求该版本仍为最新，也不产生新
版本。编辑器在本页签缓存未确认请求的编号和原 payload；同步后切换方案再回来
重试，沿用原 expectedListingVersionId 和原编号，不能因读取到新版本而另建 V02。
改变输入需要新的请求；硬刷新或缓存到期后先核对实际原结果，再决定新操作。

## 传输与部署

`/api/sales-plans/[[...path]]` 复用个人服务端 apiFetch，允许配置的部署 API；保留
路径白名单、共享 Zod 校验、同源 JSON、1 MiB 限额与 private/no-store，不转发
浏览器提供的授权头。服务端上游限时110秒，客户端读取20秒、写入120秒；写入超时
显示结果未确认，不自动重发。生产仍须满足个人 OIDC 配置及禁止服务身份回退。

登录回跳仅为 /sales-plans 放行单个 new=1 和0—4的 step，保留有界 spuId；未知、
重复、外部和认证路径参数继续过滤。没有增加凭据、外部依赖或数据库迁移，既有
0126及完整迁移链要求仍适用。本批隔离验收不迁移普通业务库。
