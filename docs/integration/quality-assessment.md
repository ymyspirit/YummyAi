# 逐项质检与原始生产依据

PRD 1.1.28，关联 R25/R26、B37/B38、T11/T16。复用现有生产、质检、工厂回执与发货服务，完整工厂履约和实物业务验收继续。

## 业务操作

生产中心仍按整单安排、逐件保留生产稿与工厂文件回执。文件被接受不等于已经完工或通过质检。操作员选择适用的质检标准，逐项填写 0—100 分和明确的通过或未通过；初始值均为空。单件和整单共用字段。

回执成功登记后，新的回执表单完成渲染再记为已保存，避免误报未保存而阻挡下一步；其他表单未提交的内容仍保留并继续受到离开保护。

回执发生时间的初始值固定在当前草稿内，普通刷新不会随分钟变化而改写输入。成功保存或明确清空后才建立新表单的初始时间，实际发生时间仍由操作员核对。

“重新核对业务记录”在同一商品内保留表单与当前输入，读取期间禁用操作；切换商品/业务模块或读取失败时清空原记录，不能继续操作旧权限或错误资料。更新到的新生产依据仍须明确重新逐项核验。

单件有未通过项目、总分不足或另行发现缺陷时，明确选择严重度、责任归属和处理方式，并填写原因。未确定责任是操作员可明确选择的状态，不是默认值。当前表单把同一份明确处理应用到本次全部未通过项目；混合缺陷需要不同处理时，完整逐缺陷编辑仍待补齐，不能把这份共同处理当成逐项独立调查。

整单通过要求每项均通过，并由操作员确认已检查全部商品。含不合格项目的整单先到单件记录登记；即使非阻断项目总分够高，也不能走整单通过快捷操作。返工、补做、补发、退款与取消仍分别走原业务处理，选择处理方式本身不执行外部交易。

## 数据层

- 标准固定名称版本、适用 SKU/供应商、最低分、项目编码、权重和阻断标记。
- 新检验使用 assessment 格式 2，保存逐项分数、结果和可选授权素材 ID，固定生产版本 ID 与检验前的生产投影版本。
- inspectedAt 是操作员声明的检验发生时间；inspectedBy 与 createdAt 来自服务器身份和数据库。服务端拒绝未来时间及早于上一份 V2 检验的时间，不把录入时间混作实际检验时间。
- 权重合计 10000，以整数基点加权并四舍五入。任何阻断项失败、严重缺陷或尚需处理的非接受处置都会阻止通过。操作员提交的总分和结论必须与服务器计算一致。
- 标准、检验与缺陷历史禁止更新和删除，包括数据库所有者的普通更新。新结论创建新记录，不改旧检验。

## Harness 与权限

评分是共享契约与现有 API 中的确定性检查。Agent 可以提出检查建议，知识库可以提供标准依据，二者都不自动证明实物已检验、不替操作员选择缺陷责任，也不授予生产或发货权限。本批没有新增模型、队列或另一套执行事实。

单件核验、生产进度和整单核验共用原生产锁。新请求检查原投影版本，冲突返回 409，页面保留当前填写，重新读取后必须重新核验。原请求恢复只返回原回执；改变内容或操作员须使用新请求。单件指纹规范化时间、项目顺序和证据 ID 顺序；历史整单指纹继续原格式，同时核对原操作员。

读取和写入检查当前订单权限与租户范围。顶层、逐项与缺陷证据均检查当前素材读取权，只接受本租户有效的已授权、权利已批准素材；重试也重新检查。暂停、取消和核心订单发货终态不能新增质检。现代工作台另外复用实际交运证据判断同一商品是否已全部交运；全部交运转售后，原检验回执仍可恢复。相关发货正在处理时返回冲突，不等待反向锁。

当前商品存在非取消补做单时，不能重新批准原生产单以恢复原数量。部分交运不封锁剩余数量的新生产与检验。现有发货明细关联商品行，尚未逐件关联生产批次；本批不能仅凭行级部分交运判断某一旧生产批次是否已经发出。完整返工数量分配、不同实物批次及部分交运后的细分处置仍属于完整 B38/B42 验收。

## 兼容与部署

0130_quality_assessment.sql 为旧行新增可空字段。真正的旧行保持所有新增字段为空，显示“历史总分记录”，不补造核验、生产版本或指纹。原操作员使用原内容可以恢复历史回执；新的应用写入必须带 V2 明细与生产依据。真实升级测试先应用 0130 前的正式迁移，以非所有者应用角色写入完整旧业务链，再应用正式迁移并逐列比较旧记录。

本批仅升级一次性验收数据库。普通本地库仍在原迁移版本，API/Web 未切换到本批源码。正式采用需先完成备份、迁移与匹配 Web/API 候选验证；不能把局部源码、文档或隔离验收当成普通环境已采用。

## 1.1.30 新旧质检的共同提交边界

旧逐项检验与新实物分组共用当前订单权限和事务入口。检验、质量异常及审计同笔提交，失败整笔回滚；原请求恢复不重复新增异常或审计。新检验核对当前商品的暂停、归档和数据库时钟下的资料保留状态，也检查未采用业务锁的资料清除行锁；繁忙时明确返回冲突并保留操作员填写。旧生产缺少制作单ID仍不能跨过当前商品状态。原成功回执与新执行分开处理，撤权后两者均不能越权恢复。

已用两个独立事务复现归档锁被越过的问题，并以实际审计故障复现旧逐项部分提交；修复后15项专项通过，包括行锁清除、暂停后恢复原回执及个人会员撤权，已包含在1056项去重集成中。当前候选另通过2055单元、10条页面流程、25包类型、lint和独立构建，见[分组契约](quality-groups.md)和[本次验证记录](../project-control/checkpoints/2026-10-19-quality-work-authority-evidence.json)。该修复不新增迁移、环境变量、接口或运行框架。
