# 抱枕生产交付与工厂回执

2026-10-21业务规则以[工厂两态与表格同步](factory-erp-status-import.md)为准：实际提交成功默认排产，外部仅已排产/已发货，Excel/CSV导入待接入；收到/接受/开工为可选补充，不再要求按顺序补填。原有接受/拒收事件及历史语义保持。

入口是 **生产中心 → 打开整单 → 工厂交付与回执**。
生产人员先通过原有「下达生产」建立固定正式文件、工厂、数量和完工时间的内部
生产单，再按工厂及截止日期选择订单生成交付包。每包最多 50 件生产单，不能混用
工厂。跨工厂订单先确认全部商品排期，再逐工厂生成其完整数量的交付包。
下载的 ZIP 由运营到 [工厂 ERP](https://v2.jmlonline.com/task/list) 人工上传，登记实际提交成功凭据后默认已排产；后续同步工厂Excel/CSV状态。

## 使用顺序

1. 核对本单已审核的正式 JPG、客户校样状态、工厂、数量与完工时间。候选行显示
   暂停、旧稿、到期、工厂停用或工艺未确认等阻断原因；被阻断的行不能打包。
2. 生成交付包并下载。新 V3 ZIP 含 `manifest.json`、`商品交付清单.csv`、`交付说明.txt`、正式 JPG，以及 `制造材料清单.csv`、`制造工序清单.csv`、`本单生产说明.csv`。材料清单固定原制造版本、销售单位、精确计划用量及供料责任，工序清单固定执行责任。已完成云途物流任务的面单随包提供；ShipOS 固定订单编号供工厂拉取。CSV 包含逐商品 SKU、名称、数量、生产单、正式文件路径和校验值。文件按
   `orders/<商品任务 ID>/<生产单 ID>/<订单号>.jpg` 分目录，避免同一订单多件商品
   或返工文件覆盖。清单固定原生产版本、审核稿版本、工艺及源报告版本、数量、
   完工时间、实际像素、150 DPI、SHA-256，以及具体工厂、生产地址和能力版本。
3. 上传工厂ERP成功后登记提交凭证、实际时间和本次文件校验值，主跟进显示「已排产／按提交默认」。若工厂额外提供收到、接受或拒收证据，可在可选区追加，不是正常流程必填；追加V3接受时仍核对原制造清单校验值。后续导入工厂Excel/CSV原表更新两态，未知或歧义行先核对。
4. 拒收时登记影响数量、原因和已知费用。费用区分「报价」与「已确认」，支持
   CNY / USD；留空表示未知，不能理解为零成本。这些是反馈证据，不创建财务
   账本、付款或供应商采购单。
5. 需要重做时，在原文件的「创建返工生产单」核对当前审核稿。可选择部分数量、
   新完工时间和制作说明。创建后在「返工记录」关联实际生成的返工单，再为返工单
   创建新的交付包，逐次登记收件和接受结果。原包、原 JPG 和回执历史保留。

同图补做复用有效正式文件。若要改图，先按原生产流程停止原单，在制图中心驳回、
修改为新版本并重新审核、生成正式文件；再回到返工表单核对新审核稿。返工不会
自动改图、重新调用模型、代替运营审核或替工厂确认文件。

「已提交工厂 ERP」与内部 `submitted` 同事务登记；历史流程允许直接登记真实「收到文件」。两者均不替代工厂接受；「工厂接受文件」与 `acknowledged`
同事务登记；拒收会把尚未完成的原生产单标为 `failed`。有交付包的单据不能通过
旧进度按钮绕过回执；开始生产还须当前交付文件已被工厂接受。接受文件不自动
开始或完成生产，也不代替质检、客户确认和实际生产放行。

## 固定版本与文件检查

本模块只接受异形抱枕 `ps-pillow-2026-09-17` 工艺：尺寸基准为可见图案主体
最长边（`artwork`），裁线最窄处至少 50 mm（`cut_contour`），现有文档确认项已
核对。旧工艺或旧尺寸口径必须通过新制作版本纠正，不能改写历史清单或放宽检查。
完整制作依据见[异形抱枕操作流程](../operations/custom-pillow-workflow.md)。

服务器读取私有正式文件的实际字节，检查 JPG、尺寸、字节数、RGB/sRGB ICC、
150 DPI 和 4:4:4 色度采样。单文件上限 50 MiB，整包文件上限 256 MiB。打包不会
缩放、重画、修改 DPI 标签或把竞品素材转为生产文件。每次下载重新核对字节数和
SHA-256；组包后再次核对暂停、取消、版本、保留期限及拒收状态，撤销后不返回 ZIP。

已有无人设计任务同时固定 `designRunId`、输入校验值以及其原 Rule Center 快照
校验值；配方、模型路线、参数与素材来源继续通过原任务追溯。缺少规则快照的历史
任务显示 `legacy_missing`，不能以今天的规则补写。人工审核稿也保留原来源和底稿
版本，不会因此被标为已经通过无人运行验收。

## API

所有路径位于认证边界 `/v1/order-centers`，浏览器走同源 `/api/order-centers`。
契约在 `@yummyai/contracts/order/production-delivery`；不接受 caller tenant ID。

| 方法与路径 | 输入 / 行为 |
| --- | --- |
| `GET deliveries` | 可选 `line`、`supplier`、`factory` UUIDv7 与 `dueBefore` ISO 时间；数据库过滤候选和历史包，最多 100 个候选、20 个包；超限显式 `truncated` |
| `POST deliveries` | `supplierId`、`factoryId`、唯一生产单选择项及 `idempotencyKey` UUID；选择项含固定 `productionVersionId` 和 `expectedProjectionVersion` |
| `GET deliveries/:id` | 私有版本清单、当前下载阻断原因和不可变回执历史 |
| `GET deliveries/:id/file` | 重新验证后的 ZIP 附件；`private, no-store` |
| `POST deliveries/:id/items/:itemId/feedback` | `kind`、`expectedSequence`、原文件校验值、幂等键、实际时间、凭证、说明及明确的操作员核对；拒收 / 返工含影响数量，可带费用和真实返工单 ID |
| `POST recoveries` | 原有接口新增可选 `remakeQuantity`、`reviewedArtwork`；后者含正式 render ID、当前审单 revision / projection 和说明；响应含原 recovery ID 与实际 replacement production ID |

读取须 OrderRead、OrderPiiRead、DesignRead、AssetRead；写入另须 OrderWrite。
当前交付查询只支持 tenant 数据范围，其他范围显式拒绝。Web 代理对路径、字段、
重复查询键和请求来源执行白名单校验，写入只接受同源 JSON；附件响应不缓存。

同一幂等键的相同请求在当前权限下由原操作员恢复原结果，改动请求内容或操作员返回冲突。回执按商品文件递增序号
追加，陈旧序号不能覆盖其他操作员的反馈。相同幂等键重试不会重复推进生产状态。
返工单数量不得超过原生产数量，关联必须属于同一商品行并以原生产单为父单；
新版审核稿及客户确认、当前来源在事务中复核。

## 存储、保留与验收

迁移 `0093_production_delivery.sql` 新增 `production_delivery_packages`、
`production_delivery_items`、`production_delivery_feedback`，并为恢复申请增加
请求校验值。三个新表均强制 RLS、tenant 复合外键；应用角色只有 SELECT / INSERT，
数据库触发器阻止包括 owner 在内的 UPDATE / DELETE。客户定制内容、清单及自由
文字回执使用原订单 work data key 加密，订单到期或销毁密钥后不再解密或下载，
仅保留非敏感版本索引和校验值。包不另建长期明文存储，也不复制买家地址。

使用独立数据库、MinIO 私有桶和 Redis 的验收命令见
[本地开发](../operations/local-development.md#抱枕生产交付验收)。
集成验证包括真实渲染 JPG、固定版本、幂等并发、暂停 / 到期 / 改版 / 下载期间
撤销、RLS、不可变历史、回执状态与部分新稿返工；浏览器验证下载、刷新保留、
回执、报价 / 确认费用和移动宽度。测试数据在 runner 的 finally 中清除并复查。

这些验收验证 ERP 内部交付链和人工登记流程。真实工厂收件、接受、试印及实际
生产仍须逐单保留外部证据；系统不会向工厂发消息或自动提交供应商订单。

## 制造清单 V3 · 1.1.33

新包读取原生产的不可变制造绑定，固定材料/工序和责任、件/双/套单位、精确分数计划用量及明确生产说明；内部 BOM 备注、库存主键、余额、成本不进入工厂视图。V3 manifest 字节与校验值使用同一规范 JSON，正式 JPG 不变。接受文件必须提供 `manufacturingChecksum`；旧 V1/V2 保持原密文、原校验算法和请求指纹，不从已有生产绑定补写历史清单。创建、回执、里程碑及审计同笔提交，原成功恢复不重复写审计。0135 仅登记开发迁移，普通库未采用。详见[制造交付契约](manufacturing-delivery.md)。

## 交付与返工的原提交恢复

交付包创建、回执及新审核稿返工均固定原路径、输入和幂等编号。结果未知时锁住新提交并提供明确恢复；可信成功后刷新失败只读取列表。恢复成功结算原表单回执，不因第一次丢响应留下错误草稿状态。新稿返工先核对当前角色、已审核正式稿及所需校样，制造候选就绪后可创建；固定工艺要求只读，补充说明另填。暂时失败保留数量、交期、原因和说明，失权或不可访问时清除私有依据。见[入口契约](production-entry.md)。
