# 销售方案关联资料核对与显式修复

2026-10-18 · PRD 1.1.8 · R01/R03/R10/R13/R37，关联 B19/B20。

## 用户操作

已选资料不在当前可用范围时，工作台保留原编号，逐项展示类型和素材用途。用户
可以更换或明确移除；选择其他可见研究、印花或 SKU 不会顺带清掉未显示的旧关联。
实际保存后才创建新 revision。移除素材会清除该素材的全部方案关联；移除 SKU
同时清除选款配置，按钮明确说明。原件、旧版本、Listing 和订单不被删除。

有效的历史印花保持原版本，不自动换新版。已选图片持续显示，不因候选只展示
前24张或搜索变化而消失。项目、店铺和选项图片原编号不可选时显示明确占位，
不能把第一个候选伪装成原选择。只读人员能看缺项，不能移除或保存。

资料核对失败保留输入并允许重试；核对未完成或有缺项时停止保存/同步，编辑和
明确修复仍可继续。原 revision、页签草稿、失权清除及迟到响应沿用
[会话契约](sales-plan-session.md)。网络失败不能当作资料删除。

## 有界的只读核对

`POST /v1/sales-plans/:id/reference-options` 返回200，不创建版本、事件、模型任务
或执行授权。先核对当前成员和实际父 SPU 的 ProductRead，再按各资料自己的租户、
拥有者/团队、领域权限及当前状态筛选。不可读来源不返回名称或私有内容。

请求只含 specificationIds、skuIds、artworkVersionIds、researchItemIds、assetIds、
creativeProjectId 和 accountId。普通数组最多100，去重资产集合最多201，均为合法
UUID；额外字段被拒绝。正文、提示词、tenantId、权限和 executionContract 不能作为
输入。BFF 保留本人服务身份、同源、路径/Schema/限额及 private/no-store。

默认500候选不是失效判定依据。查询优先纳入明确请求的可用资料：研究和素材上限
分别为500加请求数量，项目为500加一个所选项目。权限、归档/删除、权利和用途
过滤不变。历史印花按原 versionId 补充仍可读且母版未归档的版本；SKU 沿用原配方
来源读取规则，不以商品读取权替代印花/素材范围。

返回当前 contextAuthority、preferenceScope、方案/SPU及原选择。界面只采用匹配
当前对象、选择和读取依据的结果，丢弃旧响应。保存仍在原业务服务重新检查，
不采信客户端“已核对”。候选标签不表示原件已扫描可下载、设计已审核或生产批准。

## 实现、部署与验证

复用 SalesPlanService、共享 Zod、React/Next.js/Lucide、短期草稿和统一视图过渡。
只在引用集合或读取依据变化时核对，正文输入不触发资料查询或模型调用；请求有
短暂防抖及取消，移除使用原生过渡并尊重减少动态效果。API/Web/contracts共同
采用，无新增外部依赖、表或迁移；0126及完整迁移链要求不变。

原生用例位于 `apps/api/src/catalog/sales-plan-reference-options.integration.test.ts`，
界面用例位于 `apps/web/e2e/sales-plan-references.spec.ts`。个人身份隔离浏览器使用
`--suite=sales-plan-references`，最终编译加 `--compiled-web` 并固定 BUILD_ID。
每次明确新的归属输出目录，检查后删除临时文件和隔离资源，不重试此前自动审批
拒绝的清理目标。素材/项目候选用例为合成元数据，不代表真实文件生成或生产资格。

完整审核封包、店铺映射、真实提供方/业务和正常部署继续独立验收，不据此将整个
B19/B20或平台标为完成。
