2026-10-19 · PRD 1.1.25 · 复用既有 Next.js、Node、pnpm、OIDC 和隔离验收运行器。完整平台继续建设。

## 构建与启动

`pnpm build:web:candidate <32位小写十六进制ID> <工作区内源码清单路径>` 在新的 `.artifacts/local-web-releases/<ID>` 建立独立候选。源码清单固定文件字节和 SHA-256，构建前后复核；同一 ID 已存在时拒绝覆盖，失败操作另留记录。

复制 Web 源码、配置和公共插件文件，环境文件不进入候选。依赖与工作区类型目录使用原有只读共享路径，运行前核对实际路径、锁文件和 Next 版本。Web 构建通过后封存构建标识及运行文件清单；构建缓存、诊断、trace 和增量类型缓存单独清理。运行文件或依赖版本变化时停止启动。后续源码编辑不覆盖既有候选。

`pnpm check:web:candidate <ID>` 仅检查候选，不启动应用。`pnpm start:personal:web --candidate=<ID>` 经过相同生产身份预检后选择候选；原默认启动入口保留。直接调用启动器同样执行预检，开发模式拒绝候选参数。实际 API 目标沿用该进程的 API_BASE_URL。

这是本地依赖共享的运行方式，正式跨机器制品、依赖内容验真、干净候选提交、CI 和恢复演练仍分别验收。实现见[候选工具](../../tools/scripts/local-web-candidate.mjs)及[启动器](../../tools/scripts/start-web.mjs)。生产构建和启动遵循 [Next.js 官方部署方式](https://nextjs.org/docs/app/getting-started/deploying)。

## 精确指定被验收的构建

隔离运行器接受 `--compiled-web --candidate=<ID>`，仍要求既有个人身份套件。运行器先验证候选，记录其 ID 和 BUILD_ID，再启动隔离 API/身份服务。所有十一类个人身份配置必须保留所选命令与目录，不能静默回退工作区旧构建。商品读取和商品编辑的两个覆盖入口现已补齐这一点。

例如使用 `pnpm test:e2e:order-daily --suite=erp-identity --compiled-web --candidate=<ID>`。商品权限使用 product-access，编辑状态使用 catalog-editor。原始日志及截图应指定本轮新目录，验收后按[交付约定](../project-control/DELIVERY_PROTOCOL.md)清理。

运行器保留实际运行候选作为运行制品；数据库、桶、Redis 和身份夹具由该轮独立拥有并清理。清单中的 operationalCandidatePreserved 不应被误读为临时 Web 快照已删除。配置级回归导入全部十一类实际配置，同时保留原隔离数据库/桶检查。
