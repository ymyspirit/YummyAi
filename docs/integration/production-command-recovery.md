# 生产命令持久恢复

2026-10-20 · 本地增量实现。首批为已审核设计直接生产、审核稿单商品和整单下达。0136仅在一次性数据库中验证；普通ERP仍为0135和原候选。完整Harness与业务验收继续。

## 页面与接口

生产中心增加“待确认生产提交”。执行前服务端固定原申请人、原确认正文、订单商品、制造/文件版本、工厂、完工时间、业务编号及权限上限。准备响应丢失后可刷新查询本人原记录；只有取得意图编号才执行业务写入。本人新会话可找回原确认，不重新选择文件或勾选制造确认。

操作员明确下达或恢复。成功在本人选择“已核对本次结果”前仍可发现；确认只移除待办并清除正文，不删除生产、指纹或尝试历史。未进入尝试的准备可以取消；未知执行须核对，不能丢弃或自动换编号。前端暂停新提交，服务端按商品范围阻止冲突意图。内部安排仍不代表工厂收到、接受、实际制作、质检或交运。交付包、工厂回执、返工及其余域尚未随本批接通持久恢复。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /v1/order-centers/production-commands` | 严格解析三类原业务合同并准备 |
| `GET /v1/order-centers/production-commands?orderId=...&lineId=...` | 订单必填、商品可选；本人最多100条未确认记录，明确截断 |
| `GET .../production-commands/:id` | 当前权限、来源及原业务回执核对 |
| `POST .../production-commands/:id/execute` | 正文仅 `{}`，认领并执行原输入 |
| `POST .../production-commands/:id/acknowledge` | 正文仅 `{}`，本人确认终态已读 |
| `POST .../production-commands/:id/cancel` | 正文仅 `{}`，取消从未执行的准备 |

BFF对应 `/api/order-centers/production-commands`，限制相同路径/查询、同源JSON及正文大小，核对返回订单、商品、类型和意图编号。不能替换租户、操作者、正文或租约；响应private/no-store。视图只返回当前可读摘要与最小生产编号，不返回原执行正文或内部token。

## 数据、权限与保留

`production_command_intents`、`production_command_attempts`通过非拥有者`withTenant()`及forced RLS访问。原主体、目标、输入/拥有者指纹、权限快照、合同和创建时间不可修改。原生及审核稿单商品沿原商品级业务编号，整单沿订单编号；相同编号在不同原生商品上不错误合并。

原正文和摘要使用既有`ORDER_PII_VAULT`加密，信封绑定租户、本人、意图和经原Schema规范化的命令。执行期限最多七天，受更早的来源期限限制；每次解密前检查来源。订单匿名化、私有保留状态变化、工作密钥清除/过期或归档通过同租户触发器单向清除正文并撤销凭据；本人确认或取消也单向清除。指纹、状态、最小回执和历史继续保留。

七天是最大执行期限，不能宣称无访问场景已有独立全域定时删除扫描。来源清理触发器及查询时清除已实现，独立扫描和其余域的完整隐私验收继续。正文失效后仍核对已经提交的生产，不能将已发生的业务改成“未发生”。

当前有效成员及逐权限范围在事务内重读，与原权限快照取交集；新授权不能扩大旧提交上限。失权不展示旧私有摘要。生产拥有者继续核对原规格/设计授权、制造审核、数量、订单状态、校样和工厂，不由持久记录补造批准。

准备时已有原回执，以`admission_kind=existing_receipt`登记本次新查询意图，不回填原生产的历史权限、确认或来源。旧业务接口保留原响应；已提交重放仍可读取，受本批管理的请求缺少当前内部凭据时不能通过旧接口重新写入。

## 事务边界

服务端生成token、递增generation和120秒租约。认领短事务提交后才调用原拥有者。业务事务取得原业务、订单和制造锁后，锁定并检查原主体/指纹、当前token、正文、来源和期限；共享行锁保持至生产事务提交。新认领等待已经获准的旧事务；迟到旧执行在新认领后到达则在写入前拒绝。

隐私及读取按“当前成员→来源→意图”取锁，结果封存按“原业务锁→意图”；不持有意图行再调用生产事务。封存仅采用原拥有者实际提交的最小回执。直接生产和单商品下达已分开提交回执与完整详情读取；详情失败不再混淆为未提交。未知网络/进程结果保留不确定，可信拥有者事务拒绝保存已知拒绝；旧generation不能覆盖新状态。
