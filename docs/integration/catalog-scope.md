# 可信团队与商品对象范围

2026-10-18 · PRD 1.1.4 · R01/B06，关联B07。此契约属于完整平台的增量建设，不能据此宣布整个权限工作包或阶段完成。

## 团队的唯一来源

团队与现有有效成员由原生身份模块维护。`organization_teams`、`organization_team_members` 和不可变 `organization_team_commands` 使用租户复合外键及强制 RLS。无团队的历史商品保持未分配，不推断其团队，也不提供开户、邀请或消息发送。

运营入口为 `/settings/teams`。`GET/POST /v1/teams`、`PATCH /v1/teams/:id` 和 `POST /v1/teams/:id/members` 分别承担读取、建立、改名/归档及成员关联。管理须有公司范围的 `membership:manage`；`GET /v1/teams/options` 只返回当前可分配的有效团队。Web 的同源代理在工厂独立部署中拒绝访问，白名单路径、重复参数、严格请求结构和正文大小分别校验。

管理操作固定 requestId、内容摘要、操作者、原因与预期 revision，同事务保存审计及不可变回执。重放只读取原回执，不重新授予已被移除的关系。并发版本冲突不覆盖旧草稿，网络结果未知时先读取当前目录，不自动重复命令。

当前身份从实际有效成员、逐权限角色及有效团队关系计算 `teamIds` 与 `teamAuthority`。改名和相同状态的操作不撤销有效上下文；移除、重新加入、归档及重新启用改变授权代次，旧上下文不能因重新启用而恢复。显式空 teamIds 不回退到旧单团队字段。

## 商品及关联资料

商品企划和印花母版分别维护 owner/team。SPU、规格、销售 SKU、配方、销售方案及封包的商品权限沿父企划核对；印花仍核对自己的拥有者及团队。租户读取不能扩大仅本人写入，商品团队也不自动授予店铺、Listing、研究和素材的权限。

现代商品、配方、销售和封包写入在查询幂等结果前重新加载当前身份，并核对实际目标及相关引用。命令记录的操作者必须与当前操作者匹配。团队分配只接受本租户有效团队；非公司范围的商品写入者只可选择自己的团队。未提交 teamId 保留原归属，显式 null 清除。

商品列表、规格及印花选项、SKU详情和销售方案按对象过滤。配方读取同时核对商品与全部印花来源；当前配方无权读取时返回不可访问，不将较旧的可读版本展示为当前。归档历史仍受当前读取权保护。超出末页的查询保留实际总数。

素材预览与候选分别核对 `asset:read` 和授权素材条件。团队读取仅通过本团队印花母版中明确绑定的文件或材料关联获得，不能把同租户所有素材视为团队共享。研究、创意、Listing和账户的对象归属独立核对；已有销售方案的文字和字段属于方案本身，读取字段不授予关联文件的读取权。

订单候选使用调用者实际范围；已固定的历史制作依据继续由原订单读取策略保护，不伪造公司权限来构造可选项。事实资料包在所属事务内重新核对当前身份和企划团队，不以旧预览或回执跳过权限。

## 界面、验证与部署

商品企划、SPU和印花表单可选择团队；现有不可选团队明确显示，未改变归属时不静默清除。编辑入口根据具体对象判断写入权。团队目录定时及重新聚焦后读取；撤权清除目录和草稿，较早响应及浏览器动效回调不能恢复私有界面。连续正常更新则保留每次有效更新，支持减少动态效果。

迁移 `0126_team_catalog_access` 必须先在隔离库验证。当前仅在隔离环境运行，正常业务库尚未迁移。正式采用需备份、在受控窗口应用完整迁移并核验个人身份、角色、所属团队和各业务模块。新授权加载器依赖新表，不能先启动新 API 再补迁移。

可复跑入口为 `pnpm test:e2e:order-daily --suite=catalog-scope-integration` 和 `--suite=teams`。实际结果及限制见本批交付和检查点。真实身份提供方、正常部署、其他业务模块与异步执行、完整B06/B07和人工业务验收分别继续。

`--suite=teams --compiled-web` 明确使用当前 `.next/BUILD_ID` 的生产服务；清单保存实际模式和构建编号。缺省浏览器使用独立开发快照，不能仅凭启动环境变量或文件名宣称生产验证。两种模式分别记录，合成个人身份不代表真实IdP验收。
