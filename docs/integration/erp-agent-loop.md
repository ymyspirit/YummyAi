## 能力与边界

用户填写目标、明确模型和费用上限、勾选允许工具后，模型返回严格的 read/finish 决策。服务端决定分页并调用原业务读取实现，再把实际结果交给下一轮模型。当前注册工具只有 `orders.exceptions.page` 与 `inventory.balances.page`。其余模块目录只是接入规划；MCP 未连接。

不执行模型提供的 SQL、URL、程序、动态工具或业务写入。知识库、无限画布、无人设计和其他原有能力继续保留在各自入口，尚未全部注册成此循环工具。发布、付款、生产放行等仍由原业务流程负责。

每次任务最多 8 个模型决策、7 组读取、32 次实际分页/最终复核、1000 条已保存记录、600 秒。默认 4 个模型决策、500 条。到界限返回部分/失败原因，不以已读条数代替总数。最后一次模型决策不能再扩展读取。Agent 与原 Assist 在同一预算锁下合计最多四个活跃任务，两种入口均执行此限制。

## 权限与资料

本人会话决定租户、成员和原始逐权限/团队上限；每次 I/O 前后及最终采用时重新读取实际成员权限并取交集。WorkflowRead/Run 按本人任务授权，可为 self；当前两种业务集合仍要求各自的 tenant 范围。响应的会话标识取本次当前个人权限，业务读取授权继续取原运行上限与当前权限的交集；新增无关权限不会锁死原回执，也不会扩大原运行能力。所有操作经过 `withTenant()`、非 owner 应用角色和强制 RLS，模型不能指定身份。

运行输入、逐轮原响应、读取页检查点和结果私文加密保存，固定模型路由、执行契约和前后 SHA。读取恢复沿原游标继续，集合变化会拒绝旧页。结果中的标量引用逐项检查原步骤、原记录、原字段和值；完整集合才可引用总数。结束前分别复核每个原查询的集合版本。不同业务集合按顺序复核，各自保留 checkedAt，没有跨订单/库存的同一数据库原子快照。这不能证明自由文本语义、原因推断或业务决策正确，仍需业务审核。

## 支付、停止与恢复

一笔原请求只有一个父预算占用，活跃时保留整笔上限，已知费用另行展示且包含于占用内，二者不能相加。每轮先保存 submitted，再提交模型；原响应与 nullable usage/cost 先落检查点，再解析决策。submitted 无回执和未知费用不自动重试或切换渠道，不伪造零费用。已知终态按实际逐轮费用精确合计；未提交任务释放；未知保留原上限待账单核对。

停止仅凭本人原 run/request 标识和当前 WorkflowRun 权限发起，不依赖已被撤销的业务域读取权限。停止标记不可撤回，阻止后续提交，正在进行的原调用仍保存实际回执和费用。停止请求成功不等于调用已结束。

页面只存七个纯标量恢复字段：版本、本人作用域 SHA、原请求 ID、请求 SHA、原运行 ID、恢复状态和时间。刷新/查询回执不派发、不计费；未知或已知但未核对的原意图锁住新的付费启动。另起任务需明确确认。登出同步使迟到响应失效并清除本页标记。

## 接口与资源

本人 BFF `/api/agent-loops` 转发 `/v1/agent-loops`：GET workspace、GET receipts、POST runs、GET runs/:id、POST runs/:id/stop。启动返回 201 RunView，其他读取返回 200，停止返回最小 Receipt。严格路由、参数、大小、UTF-8 和 DTO 校验，当前身份在整个响应读取后复核，原错误私文不透传。新付费接口未对既有 API Client 读权限开放。

0172 增加 `agent_loop_runs` / `agent_loop_steps`，普通服务私文默认保留一天。到期清理密文，保留原 ID、SHA 链、步骤费用和未知状态。服务端依赖注入允许缩短私文保留期，期限仍须晚于固定执行 deadline，HTTP 不接受此设置；物理清理验收使用独立服务实例的 35 秒期限和真实数据库时钟，不改变普通配置。队列 `agent-loop` 及 `agentLoopScheduler` 负责原运行派发、租约恢复和到期清理；工作进程只持原身份标识，不从消息获得权限。复用已有环境密钥的既定内容、模型与集成加密域，无新增环境变量或依赖包。

验收使用一次性数据库、私有桶和 Redis。当前、真正旧 171 升级、旧读取回归、本人编译页面分别记录。验证和清理结论见 [本批进度](../project-control/ERP_AGENT_LOOP_PROGRESS_20261022.md)。本批67项去重定向检查和2条本人会话编译页面通过，临时输出及隔离资源已清并独立核对；只有外部模型HTTP为合成响应，不证明真实渠道质量、全平台接入或正式发布。
