# 刊登与定制配置的受控交付

入口：**商品与刊登 → 上架工作台 → 选择销售方案 → 上新任务 → 刊登与定制交付核对**。

本轮支持同一 SPU 的异形抱枕、Amazon 美国站（`ATVPDKIKX0DER`）、`en-US`、Custom FBM，一个方案最多 50 个销售 SKU。其他商品或站点显示范围提示，继续使用原工作台。功能截止到经核对的不可变交接资料包。

## 操作与修订

1. 在商品库与商品开发确认每个 SKU 的规格事实、工艺底稿、来图方案、制作版本和已审核套图；在销售方案中选择这些版本。
2. 配置实际支持的定制字段、说明、示例素材，并记录实际 Custom 页面配置的人工核验依据。保存草稿本身不证明卖家页面已配置。
3. 同步本地刊登草稿，在刊登编辑器填写必要的平台字段并审核当前版本。已审核刊登发生变更时，先在刊登编辑器建立修订草稿，再同步最新方案并重新审核。
4. 查看每个 SKU 的材质、尺寸、包装数量与包含内容，逐张打开私有图片并明确用途。主图必须核对为真实成品照片，每个 SKU 都需要自己的已审核制作版本套图。
5. 人工核对商品事实、定制配置、图片、文案与服务承诺四项，填写核对依据，点击「记录交付核对」。不预选用途或自动勾选确认。
6. 按 SKU 点击封存，再下载当前交付包。响应丢失可在当前页面重试：同一请求编号返回原核对记录或资料包，避免重复保存。刷新后读取服务端已接受的记录。

修改方案、刊登、SKU、制作版本、生产文件、套图审核状态、工艺底稿或素材授权后，页面重新比较来源指纹，列出变化及应重查项目。旧核对不能用于新的封存，旧包退出当前齐套状态，方案下载接口拒绝提供失效包。修正后需要重新核对、建立新的封存版本。相同不可变来源恢复有效时，原核对仍适用；历史及原封存包始终保留。

四项勾选是具名操作员的人工核对记录。系统校验版本、来源、SKU 映射、授权、图片用途与原封存规则；不会声称自动理解所有图片细节或验证每项服务承诺，不代表工厂接收、实际生产放行或平台发布。

## 包内容与兼容

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 原封存清单、文件版本与校验值，新增方案指纹、核对人/时间/说明、定制与 SKU 固定映射 |
| `listing-fields.json` | 本次已审核刊登字段 |
| `customization-config.json` | 定制定义、布局、说明、示例素材关联与实际配置的人工核验依据 |
| `sku-mapping.json` | 内部销售 SKU、真实规格平台 SKU、Custom 选款、全部印花版本、制作面/区域、定制字段和制作/规格版本映射 |
| `delivery-review.json` | 本次方案版本、来源指纹及四项人工核对记录 |
| `README.txt` | 交接范围与上架前核对说明 |
| 私有素材目录 | 当前 SKU 的制作文件、刊登图片、原图与定制参考素材，按原存储边界校验字节长度与 SHA-256 |

原封存服务仍是唯一封存入口，制作、同款套图、真实主图与授权校验全部保留。定制配置文件是交接草案与人工依据，不是 Amazon Custom API 的可直接提交载荷。历史包不会被修改或自动补写核对记录；原商品开发下载历史包的路径继续保留，并继续检查文件版本与授权。

## 接口与权限

| 接口 | 行为 |
| --- | --- |
| `GET /v1/sales-plans/:id/launch/delivery` | 当前固定来源、逐 SKU 缺项、图文与配置、上次核对的有效性、封存历史 |
| `POST /v1/sales-plans/:id/launch/delivery/review` | 当前方案版本、刊登版本、来源 SHA-256、逐图用途、四项确认、说明与幂等编号 |
| `POST /v1/sales-plans/:id/launch/delivery/seal` | 明确核对记录、SKU、来源指纹与幂等编号，复用 SalesPackageService |
| `GET /v1/sales-plans/:id/launch/delivery/packages/:packageId/export` | 只下载属于本方案且来源仍有效的新交付包 |

读取/下载要求 ProductRead、DesignRead、AssetRead、ListingRead；人工核对另需 ListingReview，封存另需 ProductWrite。缺少完整读取权限时返回明确诊断，不返回图片、文案和来源。租户身份来自认证成员，所有业务操作通过 `withTenant()` 与非 owner 应用角色；调用方不能指定租户、存储路径或审核状态。

事件与重试复用 development events，文件与封存复用原领域服务。没有新表、迁移、环境变量、队列或模型调用。浏览器 BFF 保持同源写入、共享 Zod 契约、路径白名单和 private/no-store；本地代理限回环开发环境，生产集成沿用正式认证边界。

## 隔离验收

```powershell
pnpm test:e2e:order-daily --suite=sales-delivery-integration
pnpm test:e2e:order-daily --suite=sales-delivery
```

浏览器/构建前停止同工作区 Next.js dev 服务，完成后使用 `pnpm start:local` 与 `pnpm check:local-runtime` 恢复。检查仍需 lint、typecheck、unit 与 build；新浏览器套件包含前三批的四个回归场景。

测试使用真实身份、API、RLS、私有存储、修订审核、封存与 ZIP 下载；上游已审核制作与套图由明确标记的隔离合成夹具提供，不调用付费模型，不写卖家或工厂。覆盖两个不同尺寸 SKU、错误图片用途拒绝、成功后响应丢失与幂等重试、来源/套图撤销/文件删除失效、重新修订与历史保留、桌面/390 px/深色显示。

截图与精确夹具 ID 在忽略目录 `tmp/sales-delivery-e2e`，运行日志可放 `tmp/sales-launch-logs`。运行器 finally 删除并核对测试数据库、桶及 Redis 不存在，清理记录在 `tmp/order-daily-e2e-<token>.json`。该验收不证明实际模型图像质量或真实样品的生产品质。
