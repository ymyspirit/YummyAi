# 版本化 ERP Agent 与共享原业务读取

2026-10-22 · PRD1.1.96 · 5c82e6b4 · 本批局部运行验证与自有清理通过。独立协议 `erp-agent-native-v2` 将原五类工具与六类业务资源接入同一模型任务；旧 native-v1 的协议、额度、来源封套和恢复语义保留。

API 与 Worker 共同调用原领域的只读实现。研究、SKU、Listing、订单、利润和广告的权限、查询及 DTO 由各领域拥有；Agent 不另存业务事实，不通过服务账户或 HTTP 回调绕过本人身份。每次读取核验当前成员和对象范围，任务出生时的权限为永久上限。

模型只选择固定绑定、申请定义、读取和形成未批准提案。最多16个绑定；默认32轮、128工具调用、5000行，硬上限48轮、192调用、10000行、96步骤。定义、分页和结束时的来源复查均计入额度。本批实际11类读取和两项命令定义使用25轮、49步骤、48调用，旧协议额度无法完成，故使用独立版本而不扩张历史任务。

这里的调用计数是模型定义/取证动作与结案复查。新模型提交前另做当前对象授权检查，不把其返回值纳入新证据，也不产生模型费用；旧五类reader需沿原网关复核，仍有真实查询开销。十一类任务按固定次序运行时，额外产生95次定义检查和95次访问探针；原网关总计121次定义、117次读取，须在验收证据中分别记录，不称实际I/O只有48次。授权检查受16绑定×48轮限制，每项沿原30秒门禁且提交前再核任务截止时间。六类资源已有独立access-only入口，避免把今天的订单序号当历史读取权限。

六类资源仍保持 resources-v1 来源和有界覆盖。单对象投影或候选子集不证明整个领域完整；金额和数量按原精度/币种/单位引用，未知值保持未知。历史查询核验当前对象访问权后展示原封存内容；订单正常修订不替换历史依据，提案准备另行检查来源仍新鲜。

每轮模型请求沿原付费提交、响应封存、费用账本和租约状态机执行。已提交但结果未知时只查原回执，不自动重买。停止、过期、撤权、重连及提案准备保留原请求键。业务写入通过原模块的准备和逐项确认；生产、付款、渠道发布与对外联系仍需对应授权和原业务门禁。

本批已实际验证：单个Redis→原AgentPlanProcessor→不可变版本router→native-v2完成十一类读取，并在独立原准备和逐项确认后执行采购/财务各一次。另对实际生产Worker owner工厂逐项核对定义及来源SHA，与API一致且跨租户拒绝；真正旧175的四种付费任务状态及原已准备命令升级176后保留原列/检查点/费用/历史，响应未知不重复购买。原native-v1五类读取及原确认实际回归通过。个人编译页面覆盖桌面/390窄屏、真实当前撤权、迟到正文清除和丢失201原键恢复。模型HTTP为合成响应，不证明真实模型业务质量或已实际付费。

普通148环境未采用新源码。正式采用、实际宿主授权、真实模型质量与账单、其余领域、跨域受控子任务、CI和灾备仍在全平台范围内。知识库、无限画布、批量和无人设计保留。
