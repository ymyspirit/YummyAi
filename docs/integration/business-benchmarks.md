# 采购与经营固定评测

本批仅接入 `procurement_review` 和 `business_review`。知识评测 v1 继续使用原协议与算术检查。其余角色、真实模型业务质量与普通库采用分别验收，完整 48 项需求、54 工作包、8 阶段保持。

## 原始业务入口

从真实对象搜索与依据核对开始。采购对象是货品与库位组合，经营对象是原利润计算；服务器调用原业务拥有者，不接受客户端提交 prepared context。读取依据不调用模型。搜索最多 40 条，`hasMore` 表示还有结果，不能当作完整目录。

发布时固定原任务指纹、依赖快照、原方法、来源、scope 与期限。两类业务可放入同一数据集，业务与知识分别发布。原 `expectedFingerprint` 与完整任务 `expectedTaskFingerprint` 是不同凭据。版本说明从原发布 manifest 返回，不用今天的数据集描述重构历史。

## 两臂与检查

`business-facts-v1` 基线只摘录原业务拥有者给出的固定数据和缺项，不重新算利润、补货或价格，不读取预期答案，不调用模型，不创建业务命令。候选使用对应原生业务 kind、生产 prompt、工具、Skill 和输出 Schema；内部 admission 将真正 native run 绑定到样本，不创建假的知识评测记录。

`business-benchmark-checks-v1` 检查原角色、生产结构、允许引用、声明的文本要求、禁止说法、拒答、原规则缺项与固定任务指纹。文本出现不证明金额语义正确，也不证明采购建议最优。必须对照原 ERP 事实人工核对；人工通过不能覆盖硬失败。

使用新的 `native_run_id` 关联业务候选，知识继续保留 `evaluation_run_id`。原生任务的 `benchmark_item_id` 仅在服务器内部创建，数据库限制为这两种角色且与原尝试在同一事务出生。原生完成、独立评分与审计同事务提交，读取不重新评分或重新检索今天的业务内容。

## 权限、恢复与成本

所有读写保留当前成员权限与原 scope 上限。Workflow 权限不能代替采购／库存或财务／订单权限；数据集取所需权限的最小范围。本批聚合业务评测要求采购／库存或财务／订单两项领域读取都为 tenant 范围，Workflow 可为 self 或 team。采购依据含多个拥有者的规则、报价和采购汇总，单个库存归属校验不足以授权全部原文；领域权限缩窄后本批拒绝继续读取或执行。普通原生业务的 self 路径保留。作用域变化后页面清除私文和迟到响应，后端重新核验。

请求沿用原 8 类命令回执、原 UUID 和 CAS 语义。新命令的 `business_roles` 由数据库按同事务的原结果固定，历史知识命令默认为空；草稿以后改变角色时，也不能用今天的草稿重新解释旧回执权限。网络中断先查询原请求；新付费尝试必须单独明确提交，不能自动重发未知请求。全部尝试、失败与未知提交、人工核对及存储维护分摊继续使用现有成本拥有者。未知渠道价格和待人审状态不能记成免费合格结果，原报告保留不变。

`GET /v1/knowledge-governance/benchmarks/task-targets` 与只读 `POST .../task-basis` 复用原对象查询。Web BFF 采用当前 authority 绑定和严格 DTO，依据读取返回 200，不把它当作 201 写命令回执。

## 本批边界与验收

迁移 0169 为追加迁移，不修改 001–168 或回填历史。普通库仍为148，普通应用保持停止；只通过隔离验收 runner 建立 disposable 数据库、桶和个人登录会话。真实168源码已逐 hash 保全并验证旧知识 manifest／报告与任务继续，临时副本在验收后清理。

规则基线零渠道调用；候选使用合成提供方 HTTP 验证实际预算、原生 Worker、评分和费用路径。这不等于真实模型业务质量验证。两角色不涉及资产解析，不声称图片、PSD、扫描或生产审批完成。本批验后删除自建临时产物和测试资源，保留源测试及简明验证与清理记录。

实现参考了 [Promptfoo 的确定性断言](https://www.promptfoo.dev/docs/configuration/expected-outputs/deterministic/) 和 [Langfuse 的原应用执行路径评测](https://langfuse.com/docs/evaluation/get-started/offline)，继续复用现有 ERP 任务与账单模块，不引入第二套任务账本。
