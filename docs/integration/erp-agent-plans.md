## 三层架构与真实范围

数据层继续使用原采购、库存、生产、财务和广告账，原私有素材及不可变版本。0174新增 `agent_plan_runs`、`agent_plan_steps` 和 `agent_plan_items`，记录计划、模型和读取检查点、预算及提案引用，不建立另一套业务事实。

Harness层负责个人身份、租户隔离、出生权限上限与当前权限交集、模型路由和价格固定、组织预算、步骤上限、Worker租约、不可重复购买、来源版本复查、加密保留及纯标识恢复。独立队列 `agent-plan` 只处理模型计划和过期清理。

Agent层使用独立 `erp-agent-plan-v1`，保留旧 `erp-agent-loop-v1` 的原协议和历史。新循环只能 `read` 或 `finish`；finish最多生成8项严格原业务输入提案。已注册的两项读取可以动态调用；五域37种命令输入可以作为提案生成。模型不能调用确认或执行，也不会自动准备原业务命令。知识、创意、工厂等剩余工具、完整跨域调度和MCP客户端仍需后续适配。

## 模型输入与依据

用户明确填写目标、补充资料、模型、最高USD费用、允许读取工具和命令。补充资料是待核实输入，不因进入提示词就成为业务事实。引用验证只证明来源集合版本和所引用字段相等，不证明建议价格、币种或所有业务填写正确。界面须显示“模型建议 尚未原业务核验”。原业务准备、具体人工核对及原owner执行门继续验证真实业务依据。

模型执行前固定完整Harness/skill/tool版本、原模型路由、价格、来源权限和限制。提示词中的JSON Schema采用现有Zod输入形式，传输schema不含运行转换；实际原输出仍使用严格业务schema解码。完整线上结构化schema计入提示字节和保守费用预估，不能只计算用户文字。原HTTP响应、解析决策和规范提案结果分别留摘要；不能改写原响应制造通过证据。

服务端在模型前为8个位置生成固定UUIDv7槽位，模型必须将对应槽位ID原样填入原命令的幂等键。提案ID、原准备requestId及原业务idempotencyKey相同，不修正模型虚构的键。模型结束即结算已知费用并释放租约；等待人工确认不占Worker租约。

## 原命令准备与执行

1. 模型完成后只保存提案，业务账不变。
2. 用户逐项查看完整建议，明确要求准备这一项。
3. API重新核对原读取集合版本、当前与出生权限、期限及原输入摘要，同事务保存这一项的准备意图和审计。
4. API调用既有 `AgentCommandService.prepare`，沿原owner生成真实原业务命令。
5. 只有原owner命令ID存在，才记录已准备；仅有协调请求ID仍为未知。
6. 工作台沿真实原ID跳转既有具体确认界面，由用户核对完整原填写并逐项确认后，原owner执行、审计并产生原结果。

每项独立确认；采购申请不等于采购批准，账务付款登记不等于银行转账，广告事件不等于平台投放，生产提案不代替设计批准、工厂接受或实际生产放行。停止计划阻止后续模型和未开始的准备，已经在途的原意图仍可落地并保留回执，不回滚已发生事实。

## 接口

个人BFF `/api/agent-plans` 对应 API `/v1/agent-plans`：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | workspace | 当前可用模型、读取与原命令能力 |
| POST | runs | 保存付费意图，返回201 |
| GET | receipts | 仅按原requestId和requestChecksum查询 |
| GET | runs/:id | 当前权限内的计划与步骤 |
| POST | runs/:id/stop | 停止后续步骤，返回200原回执 |
| POST | runs/:id/items/:itemId/prepare | 明确准备固定提案，返回201原引用回执 |
| GET | runs/:id/items/:itemId/receipt | 仅查询原提案的原准备回执 |

没有模型直接确认或执行路由。BFF严格验证路径、方法、JSON、UTF-8、大小、Same Origin、个人authority、原ID及摘要和正确状态码；读取完整私文后再次校验个人身份。POST runs响应的执行契约、读取/命令范围、限制、可用私文和费用上限须与原请求绑定。原业务错误不原样透传。

## 断线、预算与到期

父计划和子准备分别使用七个纯标量浏览器意图，POST前写入并回读。目标、补充资料、模型提案、业务原文和确认token不得写入恢复存储。刷新未知模型任务只GET原回执，不重新购买模型答案；刷新未知准备也只GET原提案回执，不自动重发。核对后可显式使用同提案、同原键和相同摘要恢复准备，不换正文或键。原命令尚未真实准备成功时保持未知，不以协调出生冒充业务准备成功。

`erp_agent_plan` 独立预算类型共享原 `erp_agent` 限额、组织月度账及Assist/旧循环/计划合计最多4项活跃任务。未知付费提交或缺失费用保留原全额预留，不自动重试或换模型。人审阶段不持续预留已知模型费用。

计划私文默认保留86400秒，测试期限仅允许服务端依赖注入，不允许HTTP指定。到期清除父输入、规范结果和步骤输入/响应/输出密文，保留最小元数据与纯标识回执；原业务命令的7天保留期不受影响。失去当前权限后隐藏私文、清除旧动作和迟到响应；纯ID查询不能重新授予内容读取权。
