# 制造接入后的回归与采用

2026-10-19 · 关联 R12、R23、R25、R41、R43 及 B33、B35、B37。本批复用仓内已有的 Vitest、Playwright、Drizzle 和一次性资源运行器，保持依赖锁文件与生产门禁。

## 当前数据与历史数据

新生产必须具有可验证的产品、审核设计、有权生产文件、明确制造版本和合法生产来源。原生生产使用路由及采购版本；已有审单使用原工作项及不可变修订，不能改用直接生产声明绕过原来源。夹具须补齐这些真实引用，而不是停用数据库约束或制造封存。

测试产品类型、工厂能力、工艺和尺寸要相互匹配。物流的异形抱枕参考声明测量依据与原尺寸，保持文件及人工审核确认项未通过；它只构造测试来源，不证明实际图稿、工厂或生产放行。供应商绩效使用匹配的矩形产品来源，七项经营指标仍由原证据重算。

同一订单、供应商拆到不同工厂时沿用采购单并追加不可变版本，生产分别固定其原采购及工厂版本。不能为了夹具便利重复创建同一采购单或回写历史版本。

质检员的原权限保持不变。返工下达由另一个拥有当前产品、设计与生产文件读取权的操作上下文完成；同时验证仅有质检权限的上下文不能下达，原审计失败回滚、错误操作员、并发余额与取消补偿检查继续保留。

历史升级采用真实旧数据库，分别执行质检、发货、质检分组、制造封存、制造交付升级。旧生产缺制造绑定、旧 V1/V2 包缺制造清单必须仍可识别，不按当前目录补造。历史字节、校验值及原审核来源分别保留。

## 执行与证据

设置一个全新、未被拒绝清理的 `YUMMYAI_TEST_CACHE_DIR` 后执行 `pnpm test:integration`。运行器顺序执行全仓及五类历史升级，每套使用独立的一次性数据库、私有桶与 Redis 前缀。最终结论必须取完整六套件终态；专项通过不能替代全仓回归。

API 的集成配置同时包含普通服务单元断言，报告须区分主集成、API 单元、Worker/数据库/队列及五类升级，重复运行不累计为新增覆盖。类型、lint、规则、工具和浏览器检查分别列证。

编译候选须绑定完整源码清单及锁文件校验值，再以个人身份运行真实 OIDC、BFF、REST、数据库与私有文件读取。开发服务器结果和编译结果分别记录。隔离恢复演练验证最新表结构、行内容、迁移账本、RLS/ACL 与对象原字节；通用恢复夹具不等于已验证真实生产历史或已完成候选正式采用。

结束后独立查询本轮确切资源名，不能只信运行器的清理标志。检查日志、截图、下载和缓存后按[交付协议](../project-control/DELIVERY_PROTOCOL.md)清理自己生成的临时文件；已发生策略拒绝的路径及其父子目录保持只读冻结，不换方法重试。源码、简明结论和清理记录保留。

实际结果见[制造完整回归记录](../project-control/MANUFACTURING_REGRESSION_PROGRESS_20261019.md)。普通数据库采用、与业务数据配对的候选恢复、其他生产入口、跨刷新命令恢复、B34 产能及 B40 实际领料，以及完整平台继续按[项目状态](../../PROJECT_STATUS.md)推进。
