# 定制订单履约与利润复盘

第六批入口：**经营分析 → 财务利润 → 定制订单履约与利润复盘**
（`/finance/order-review`），或订单整单详情中的 **履约与利润复盘**。
复盘只读取现有订单、制作事件、生产、工厂回执、交运、售后和财务账本。
没有新增表、迁移、环境变量或付费模型调用，也不创建生产、退款、物流下单或刊登任务。

## 逐单费用与贡献利润

费用证据表区分报价、已确认费用证据、未知费用和明确无需付费模型的任务。
账本单独显示原始、冲销和替换事实；两张表不重复相加。预算估计、运单报告、
工厂报价与退款决定均不自动入账。未知费用不按零处理，取消任务或运单不证明费用免收。

利润复用最新关联的不可变计算和固定口径版本。必须通过原财务完整性检查，按
`order` 或 `order_line` 核验，且口径至少要求收入、生产成本、承运费和平台佣金。
明确免收也须有零金额账本证据。模型、返工、退款或运单费用仍未知、仍为报价或没有
入账匹配时，贡献利润显示待核对。缺汇率、未分类、读取失败或超出证据上限也会阻断。

本单现有事实 ID 必须与计算贡献项完全一致；后来补录费用、零金额证据或更正，
旧计算即失效。补齐证据后通过原财务 API 明确重新计算。页面的“重新读取复盘”只刷新
已保存证据，不计算或修改账本。利润只代表所选口径和已入账费用，不能证明未来没有新增费用。

财务录入沿用 `/v1/finance/statements` 与原权限、幂等、更正机制。对应运营费用须固定
订单归属及以下 `externalReference`，原供应商或提供方凭证仍在原业务记录中保留：

| 证据 | 账本类型 | 匹配引用 |
| --- | --- | --- |
| 模型任务，包括取消或旧需求版本上的任务 | `other_fee`，USD，归属本单及本商品或整单 | `order-design-run:<runId>` |
| 工厂返工费用 | `production_cost`，与已确认回执金额和币种一致 | `production-feedback:<feedbackId>` |
| 售后退款决定 | `refund`，与决定金额和币种一致 | `after-sales-decision:<decisionId>` |
| 包裹实际承运账单 | `carrier_cost` 或 `freight_cost`，同一包裹使用一种币种 | `shipment-package:<packageId>` |

模型提供方费用未知时，明确归属的 USD 账单可补齐费用证据；费用报告与实际账单一并
显示。运单报告未知或与账单不同，也保留原报告并显示已关联账单。冲销后的事实不能
继续作为费用匹配。没有账单的报价不会被提升为已确认费用。工厂同一交付项的旧返工
费用状态保留为历史，最新反馈决定当前待核对项；历史已入账金额仍全部参与财务计算。

## 节点、交运与返工

制作依据来自已派发需求版本，未派发时来自已保存需求版本。规格、配方和工艺版本
均使用历史固定引用，不重新匹配今天的销售方案。私有制作依据到期时明确提示，
不从现行配置补写。原 Rule Center 快照缺失的历史交付项继续标记为缺失。

耗时显示承接至派发、派发至提交审核、提交至首次审核通过、审核至工厂接受、
工厂接受至首次完工、首次完工至全量交运。起始节点缺失显示未知，未完成的节点显示
当前等待；倒序或未来的事件时间提示核对。首次审核/完工耗时不是整单质检通过证明。

实际交运只使用当前已批准且未取消运单上的有效物流事件；生成面单、工厂接受文件和
生产完工均不代替交运。按每个包裹的商品分配数量累加，达到本商品全部数量时才有
全量交运时间。具体时间必须有 `picked_up` 揽收记录（含原人工交运流程）；只有在途、
送达或退回状态时保留已交运数量，但不能把该次扫描时间当作揽收时间判定准时/逾期。
此时明确提示时间待核对。部分交运仍属待交运或超期未交运。平台截止时间缺失显示缺依据。
作废订单不计入准时交运比例，原物流证据仍保留。

返工原因来自原审核事件、工厂反馈和生产恢复记录；不会推断责任。工厂记录固定原稿、
替换稿及替换生产单；恢复记录按自己的补做幂等引用匹配，避免连接到另一张补做单。
“已建立补做单”统计创建过的补做单，包含后来取消的记录，不表示实际生产件数或质量合格率。
生产或工厂回执读取失败时，对应驳回、补做数量及补做比例显示待读取，不能按零展示。

## SKU 汇总与读取边界

日期按下单时间筛选，UI 使用北京时间、包含结束当天。API 使用 UTC `[from, to)`；
不提供期间时默认截至当前的最近 30 天。一次最多查询 93 天、读取最近 50 单，
可按平台或完整销售 SKU 筛选。SKU 筛选保留整单其他商品，避免漏掉共用费用。
超过范围时明确显示部分结果，缩小期间继续查看；不把 50 单样本当作整段期间总计。

汇总按 SKU、固定规格版本、配方/工艺和工厂分别归组，不因规格名称相同而合并不同版本。只有计算的每条贡献项均明确归属订单
商品及其 SKU，且商品所需费用齐全，才汇入 SKU 利润；整单共用运费不按数量自动分摊。
多个工厂的商品不分配到某一家。利润保持相同币种与同一口径版本分别汇总。

准时比例的分母为有平台截止时间、已全量交运的商品；未交运、缺依据和作废订单排除。
商品补做比例为本次读取商品中曾建立补做单的比例，分母是商品行而非件数。
每个订单保留详情链接，便于核对未分配利润、费用凭证和返工版本。

| GET API | 权限 |
| --- | --- |
| `/v1/order-centers/lines/:lineId/review` | `order:read`、`order:pii:read`；无 `finance:read` 时财务不可用，履约可读 |
| `/v1/order-centers/review?from=...&to=...&platform=amazon&sku=...` | `order:read`、`order:pii:read`、`finance:read` |

仅接受认证租户及 tenant 数据范围。所有数据库读取使用 `withTenant()` 与非 owner
应用角色，响应 private/no-store。Web BFF 拒绝调用方租户、重复参数和未知筛选项。
返回安全元数据、事件与费用引用，不返回买家图片、定制输入、加密草稿或模型快照。
独立模块读取失败保留其他已读取证据并提示；订单读取失败另列数量，不伪造空成功。

读取上限包括期间 1000 个商品、5000 个制作事件、2000 条财务事实及 100 次相关
计算，每单 1000 个历史模型任务、200 个生产恢复记录，以及原工厂工作区自己的上限。
达到证据上限不会声称完整利润或完整返工统计。

## 验收

```powershell
pnpm test:e2e:order-daily --suite=order-review-integration
pnpm test:e2e:order-daily --suite=order-review
```

浏览器套件继承前五批回归，并在 `order-profit-review.spec.ts` 验证两个尺寸的
Amazon US Custom FBM 抱枕订单、准确利润、共用费用待分配、未知费用、部分交运、
准时/逾期、费用补录后旧利润失效，以及桌面、390 px 和暗色页面。
物流时间与模型费用历史由明确标记的隔离数据夹具提供；其余读取、导入、需求保存和
财务计算使用真实身份、API 和 RLS。验收不证明真实承运、模型出图质量或工厂执行。

API 8116/Web 3100 由隔离运行器管理，先停止同工作区 Next dev，验收和 build 完成后
使用 `pnpm start:local`、`pnpm check:local-runtime` 恢复。证据位于忽略目录
`tmp/order-review-e2e`，精确数据库、桶和 Redis 的 finally 清理结果见
`tmp/order-daily-e2e-<token>.json`。即使测试失败也须核对三项均已删除。
