# 工厂目录与生产事务权限

2026-10-21，7ca64e10。PRD1.1.72，本批定向技术验证和自有清理已完成；完整工厂业务与平台验收继续。

工厂档案是租户共享资料。目录、历史和生产工厂选择分别要求 `order:read` 的 tenant 范围，四种建档/修订要求 `order:write` 的 tenant 范围。不能用聚合 `dataScope` 代替本次权限的范围；读取和写入分别判断，不额外要求只写操作者拥有目录读取权。

个人会话的每个公开服务操作在自己的 `withTenant` 事务内调用现有 `currentOrderAuthority`，重核当前成员、角色和请求上限，并持有既有成员权限锁直到事务结束。精确幂等回放也必须先经过当前权限。既有明确非会员凭据适配器仍按原上限处理，不把旧无 `permissionScopes` 上下文伪装成个人登录。

新工厂、工厂修订、能力及能力修订和其成功审计在同一事务提交。审计失败则根对象、版本和当前投影一起回滚。原正文校验和与幂等键保持，精确回放返回原不可变版本，不再增加版本或成功审计。历史时间取不可变版本的创建时间。

目录响应包含规范的 `contextAuthority` 与 `access.canRead/canWrite`；历史另包含真实 `factoryId`，所有工厂/能力版本必须归属该工厂，版本 ID 和各对象的版本号不能重复。此标记用于绑定返回数据和当前个人会话，不是登录凭据。Web 服务操作保留这些字段，并校验请求父 ID。

客户端以个人权限、响应权限和相同 authority 的交集控制读取和编辑。切换身份、工厂或权限时隐藏旧数据并关闭历史及表单；迟到请求必须匹配请求序号、authority 和工厂才能填充。明确的 401/403/404 清理访问状态；冲突或连接结果未知时保留原填写和幂等键，供用户核对。页面外标题不携带会在撤权后残留的工厂私有名称。

直接登记生产里程碑仍调用原状态机和原外部事件 ID 去重，原审计移入同一拥有者事务。工厂文件“接受”回执仍不能替代真实开工、完工或产能承诺。

本批没有新增表、迁移、环境变量或 API 路由。`factory-authority-integration` 只接受专用标记、current schema 和同 nonce 一次性库/私有桶/Redis；`factory-authority-browser --compiled-web --candidate <ID>` 验证个人 OIDC，Web3130 与独立临时回环 API。不得用此入口重试普通 Web 启动。

后续真实容量以稳定工厂资源池、计量单位和工厂本地日为基础，明确共享设备、工作日/例外日、截单和 DST，生产版本与容量占用同事务提交。取消申请不释放，已开工消耗不因完工或取消退回；实际部分停单需要独立数量凭据，补做单独占用。旧 `dailyCapacity` 和自由文本工作时间只是参考，不能自动转成已确认可用容量。设计参考 [ERPNext Capacity Planning](https://docs.frappe.io/erpnext/capacity-planning) 和 [Workstation](https://docs.frappe.io/erpnext/workstation)，实现复用现有服务和开源依赖。
