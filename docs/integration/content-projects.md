# 商品图文项目

`/content-projects` 聚合现有创意项目的研究、设计、印花、销售 SKU、商品套图、
Listing 与封存资料包。项目以 Infinite Canvas 创意需求的根批次为入口；历史
步骤、旧制作版本和旧资料包保持原有记录。批量设计和批量套图继续独立运行。

项目任务书和研究环节提供「编辑项目需求」，跳转原创意项目表单并携带返回位置。
需求修订后仍是同一个根项目，列表按新名称可搜索；当前说明、研究和设计任务优先取
最高需求版本，再取其最新制作步骤。历史步骤与已登记的印花继续可查，旧数据不会
被新说明覆盖。编辑契约见 [创意需求版本](infinite-canvas.md#手动编辑与需求版本)。

## 接口与权限

- `GET /v1/content-projects?q=&page=1&pageSize=20`：分页读取未归档的根创意需求。
- `GET /v1/content-projects/:id`：接受根需求或其步骤编号，返回统一根项目、当前
  创作步骤和现有版本关系。每类关联最多显示 100 条，超限诊断阻止宣称完成。
- 列表要求 `design:read`；详情复用画布版本读取，还要求 `asset:read`。
  全部租户数据通过 `withTenant()` 和应用角色读取。
- 研究来源要求 `research:read`，商品和 SKU 要求 `product:read`，Listing 与
  资料包还要求 `listing:read`。缺权限的区段返回明确状态，隐藏其资料。
- 资产预览和下载入口还要求 `asset:read`；实际读取由原资产/导出服务重新授权。
- Web `/api/content-projects` 是只读白名单代理，复用现有本地 OIDC 身份，仅支持
  开发环境的回环地址。生产环境失败关闭；部署前须接入真正用户的 OIDC 会话，
  不能以本地服务身份替代。它不接收调用方租户 ID，不缓存租户响应。

## 衔接与完成条件

图文项目只聚合既有数据，不创建第二套商品事实、SKU、资产或审核状态。新建
入口打开现有创意需求表单；需求保存后携带根项目编号返回图文项目。各环节
使用固定需求、印花、正式设计、SKU、批次与 Listing 编号跳转，并通过受限的
`returnTo` 返回。研究来源仅用于分析，不成为生成或刊登的授权素材。

最后创作步骤的候选全部审核且至少一个批准，才显示设计完成。商品步骤核对
当前制作配方、商品事实、源印花与规格版本；套图核对当前正式设计、最后槽位
尝试、必需槽位审核与资产版本/校验和/权利。Listing 复用资料包服务的只读分析
依据核对。每个销售 SKU 在项目已创建的每个刊登渠道，都对应当前审核版本的
封存资料包，才显示交付完成。旧包继续显示，来源变化时标为历史。

首次实现只负责项目视图与业务衔接，不启动模型或后台生产，不更改审核门禁，
不授予市场发布或生产放行权限。AI 操作继续在现有创意分析、画布与 SKU
资料包助手中，由操作者按既有权限和预算启动。

## 异形抱枕入口

`/content-projects?view=pillow` 提供「订单任务」和「商品与制作方案」两个板块。
异形抱枕的轮廓随顾客照片变化；面料、填充、尺寸口径、包装与工艺底稿来自
既有 SPU 规格。来图方案、规格、销售 SKU 与制作配方复用产品开发模块，
不创建第二套事实或库存模型。只有已明确绑定抱枕工艺的 SPU 才进入此板块，
该 SPU 内尚未绑定工艺的草稿规格仍显示为待确认。

- `GET /v1/content-projects/pillow?q=&stage=&page=1&pageSize=20` 读取抱枕配置和
  分页订单队列。要求 `design:read`，商品和订单区段分别要求 `product:read`
  和 `order:read`；缺权限的区段明确返回不可读取。
- `GET /v1/content-projects/pillow/orders/:id` 读取本单固定方案、底稿、当前
  制作版本、自动任务及派发时的规则快照。要求 `design:read`、`asset:read`、
  `order:read` 和 `order:pii:read`，仅返回工作进度与版本依据，不返回顾客原图。
- 订单中心查询支持 `productType`，按当前已保存需求中固定的工艺版本筛选，
  在分页和统计之前应用。不根据订单标题推测商品类型；未绑定订单须先审单。
- 两个接口都复用现有服务和 `withTenant()`，只读、不缓存，无新增表或迁移。
  Web 代理仍按明确路径与查询白名单、回环身份和生产关闭规则处理。

本单按需求核对、制作图稿、审核图稿、安排生产显示四步。已审核图稿不等于
已安排生产；正式 JPG 必须来自当前已审核编辑版本、最近一次成功的生产预检
与渲染，并继续由原生产模块核对和放行。旧版本、失败尝试和暂停状态不能
显示为已完成。本单固定底稿、当前制作版本、当前确认的工厂要求分别显示，
不会替换历史工艺或将当前规则补填到无快照的旧任务。尚无自动任务时，快照
说明为待派发；存在旧任务却无快照时，明确标为历史任务。

「核对定制要求」「进入本单制图」「正式文件与生产安排」打开原订单、制图
和生产中心，并携带订单编号、抱枕筛选与受限的返回地址。来图方案确认允许
订单选用，Listing、套图与资料包仍使用各自的授权素材和审核门禁。此入口
不主动派发模型调用；已有自动任务可显示步骤、费用与异常，并读取固定规则。
规则的核验方式显示派发时固定的执行能力，本单执行结果以任务步骤与审核状态
为依据；自动核验能力不能当作该笔订单已经通过检查。

## 验证

新增覆盖包括分权限读取、跨租户隔离、版本变化与历史保留、多 SKU/渠道完成
判断、代理白名单与生产关闭、真实页面的上下游跳转和桌面/窄屏布局。
测试创建的项目、印花、模板与产品应通过既有流程归档，保留必须的不可变历史。

停止同一工作区的 Next.js 开发服务器后，运行 `pnpm test:e2e -- content-projects`。
专用配置关闭全部演示标志，使用真实 API、研究快照、私有素材与 SKU 版本；
不运行模型或生产队列。测试逐条记录自己创建的 ID，通过原模块归档，核对活动
列表与搜索结果，并将清理记录及桌面/窄屏截图写入忽略的 `tmp/content-projects`。
原演示配置跳过本套验收。租户集成验证可运行
`pnpm --filter @yummyai/api exec vitest run --config vitest.integration.config.ts src/content-projects/content-project.integration.test.ts`。

抱枕集成覆盖按类型筛选、跨租户读取、分权限、底稿修订后的固定历史和当前
需求版本切换，文件为 `src/content-projects/pillow-project.integration.test.ts`。
真实浏览器验收还覆盖来图方案、待确认规格、订单返回和 390 px 窄屏。上游
订单用现有订单服务创建隔离的合成资料；工作配置、查询与页面全部使用真实
API，不产生顾客照片、原始订单报告、模型或生产任务。清理记录和截图保存于
忽略的 `tmp/pillow-projects`，订单、方案和模板通过原模块归档，测试店铺停用，
并核对活动队列、搜索、统计和模板列表；必须保留的不可变历史在记录中注明。
