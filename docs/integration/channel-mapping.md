# 店铺映射预检、生效时间与订单原包

复用现有 SalesPackageService、ProductDevelopmentService、订单审单服务、PostgreSQL/Drizzle、React/Next 与 Lucide。没有新增外部依赖、事实表或迁移；不是平台发布或授权动作。API、Web 与 contracts 必须共同更新。

## 资料包读取范围

销售 SKU 的资料包列表、计数及 packaged 筛选统一使用原配方的 ProductRead/DesignRead 和实际父 Listing 的 ListingRead 范围。店铺映射另检查当前 StoreRead 与实际店铺归属。空结果表达当前可读范围，不能推断全租户不存在封存包。

## 只读预检

`POST /v1/product-development/channels/preview` 接收共享 SalesChannelPreviewSchema：packageId、accountId、externalSku、externalListingId、customChoice、effectiveFrom。拒绝调用方身份、evidence、幂等键等额外字段，不写入映射、操作事件或队列。

服务端按当前成员和对象范围检查原配方、原 Listing 与店铺。原包必须满足快照 SHA-256、SKU/配方/Listing/版本归属、平台站点的一致性；受控销售方案还检查原交付审核和原选款/平台 SKU。旧记录缺失这些证据时明确停止，不补写历史，不要求合法原包变成今天的最新方案。

时间轴身份为店铺、包内站点、平台 SKU、Listing 编号及完整选款指纹。预检返回该身份前后最近生效时间、同时间冲突、原包摘要和当前登记权限。区间为 `[本次生效时间, 下一条同身份映射生效时间)`，没有下一条时无显式结束时间；插入较早映射不修改后续记录。店铺可读但前后包不可读时，只显示时间边界，包编号与版本置空。

预检是观察，不能作为写入授权或锁定。`POST channels` 重新验证当前来源及写权限，在原幂等回执查询之前完成；真实写入继续复用事务、渠道身份锁和精确生效时间冲突检查。

## 个人工作台与原请求

销售 SKU 面板按对象和当前身份范围隔离。映射使用受控表单，有界延迟后自动只读预检；字段、原包或店铺改变会取消旧查询。定期及聚焦复核不产生模型或平台调用。

临时详情读取失败隐藏操作正文，重试后保留原输入；确认失权则清除对应正文和草稿。原包或店铺失去可读性保留编号提示，不能静默选择另一个来源。迟到读取、登记和预检不能恢复另一对象或已失权内容。

登记结果不明时保留本页原表单和同一幂等键，冻结字段供原样重试。即使原操作已提交导致预检显示同时间冲突，仍可用原键请求受权回执；不会为重试生成第二条映射。切换页面或关闭浏览器后的自动查询恢复不在本批范围内，须核对映射历史；不能把中断解释为数据库回滚。

## 订单依据

订单服务按实际店铺、已知站点、平台 SKU、可用 Listing 编号、选款和下单时间解析原映射。相同身份选择不晚于下单时间的最近记录；多候选或缺选款时明确待核对。

Amazon站点仅从本订单、账户、平台和外部订单号一致的正式API来源与成功报告读取。正式API使用适配器固定的版本、订单号和顶层marketplaceId；报告使用原导入来源及已导入/重复成功行的确切批次站点。更新会追加来源，不能只读订单首次建立时的sourceSnapshotId。明确值须一致；较晚的完整来源可以补初始空缺，但不能覆盖矛盾。账户首站、地址、币种、网址及任意嵌套字段均不作为站点依据。Etsy沿既有明确的etsy域。

详情catalog.site可选返回resolved/missing/conflict及marketplaceId；后两种只能是null。缺失或矛盾时没有自动资料包、配方或候选ID，摘要提示核对来源。服务端仍只检查是否存在下单时适用的受控渠道，防止通过移除资料包绕过原交付检查；这个检查不返回其他站点的候选内容。真正手工制作路径继续使用原人工选择和审核要求。

已保存审单固定原包和原配方。后来登记的较早生效映射影响尚未固定依据的新审单，不静默替换已保存订单；后续保存继续校验该原包与原订单的历史匹配关系。订单/隐私权限与商品资料库权限分别由原业务拥有者维护。

## 验证与部署边界

`product-development.integration.test.ts` 复用实际制作、审核、封存及订单服务，补充只读区间、同时间冲突、当前来源及缓存回执、不可读对照包脱敏、损坏快照拒绝和原订单固定依据。明确标记的历史导入变体仅在一次性数据库种入，不作为生产批准证据。

订单站点专项通过一次性资源入口运行：`pnpm test:e2e:order-daily --suite=order-site-integration --cache=false`，覆盖真实适配器与报告导入、追加来源一致性、跨站候选、受控与手工路径、下单生效边界及租户隔离。该入口只接受固定套件和缓存参数，拒绝普通数据库直接执行。

`pnpm test:e2e:order-daily --suite=channel-mapping` 复用个人 OIDC/API/BFF、真实原包审核与封存；测试时间区间、服务器已提交而浏览器收到 502 后同键重试、临时读取恢复、非法选款和撤权后的晚到预检。`--compiled-web` 使用当前 BUILD_ID。原模型/素材是合成夹具，不访问实际平台或发布商品。

完整 B19/B20、正常部署、实际店铺及人工业务验收仍需继续。证据、资源与清理记录见本批交付报告。
