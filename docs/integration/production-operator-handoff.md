# 运营制造选择与生产交接

2026-10-19 · 增量实施与验收中，关联R12/R23/R25及B33/B35/B37。沿用现有订单工作台、制造拥有者、OIDC、Zod和原生界面；不新增生产事实库、Agent框架或自动工厂动作。

## 页面行为

在生产中心打开整单，逐商品核对原规格、每份内容和数量，明确选择已批准制造版本，并确认销售SKU数量对应件、双或套，再选择能承接全部商品的工厂和完工时间。部件与材料由原BOM计算，不改变订购数量。原审核稿、实际JPG及原规格继续由服务器核对。

重新读取制造依据遇到临时故障时保留选择及填写，但禁用制造提交字段；重新核对成功前不能下达。原来源、当前授权或所选版本已变化时清除选择与单位确认，要求重新核对，不自动选择新BOM。失去读取权限后移除私有来源和候选。页面重新聚焦时检查当前依据，取消旧请求；已经晚到的旧成功响应不能恢复受限内容。

整单提交按钮要等全部商品的制造来源、选择和单位确认就绪才启用；交付返工按钮同样使用实际制造就绪状态，避免字段重读时点击产生误导提示。服务器仍独立核对全部业务条件，按钮状态不代替服务端门禁。

订单业务命令提交后遇到网络中断、服务器错误、不可读成功响应或提交后身份改变，保留原路径、正文和请求编号，显示“恢复本次提交结果”，暂停新操作。恢复仍核对当前权限和原操作员，并发送原内容；不能用新的制造选择或新编号重复下达。一般版本冲突和提交后身份改变的409分别解释，BFF只转发明确的`authority_changed`代码，不暴露任意上游错误代码。

恢复成功后重新读取实际生产与交付记录。当前权限拒绝会清除本页待恢复意图及重试缓存；生产、审核和交付历史继续由各拥有者保存。页面意图只留在当前页面内存，未把订单私有正文写入浏览器持久存储；跨刷新、跨设备的通用命令恢复仍须结合服务器原记录继续建设，不能据此宣称全部Harness已具备持久恢复。

## 交付与返工

按同一实际工厂生成完整V3包，核对原制造材料、工序、供料/执行责任、精确计划用量、生产说明和原JPG。工厂收到和接受分别登记，接受同时固定原文件与制造计划校验值；接受不等于生产完工、质检通过或可发货。

拆厂订单逐工厂交付，保留全单和每件数量。部分拒收及返工继续使用原记录，核对当前审核稿、明确新制造版本、数量及交期；关联真实返工生产单，再登记报价或已确认费用。确认费用以实际回执成功后回读为准，按钮点击本身不是提交证明。原包、原图和旧BOM不回写，见[制造交付](manufacturing-delivery.md)与[生产固定版本](production-manufacturing.md)。

## 验证和采用

个人身份运营套件沿用隔离运行器和真实OIDC/BFF/REST/数据库路径，使用合成资料、实际服务器渲染JPG和私有下载；不模拟卖家后台发布，也不联系真实工厂。新增`--suite=production-handoff`关联整单选择、原请求恢复、V3交付和撤权旧响应；原`--suite=production-delivery`共同采用个人身份配置。

每次设置全新`YUMMYAI_TEST_CACHE_DIR`和浏览器`--output`，不得复用已冻结路径。最终证据、未完成项及资源/本地文件清理见[项目进度](../../PROJECT_STATUS.md)。普通环境尚未采用0133—0135，本地隔离成功不等于当前3000端口已运行新功能，当前源码编译候选的5条个人身份场景与最新结构通用恢复已补验，见[制造完整回归](manufacturing-regression.md)；业务数据配对恢复、普通采用、工厂产能、实际领料及完整平台仍须继续。

开源业务参考为[ERPNext生产单](https://docs.frappe.io/erpnext/work-order)，将BOM计划、生产单和实际材料/工序执行分开；实现复用本项目现有拥有者与控件。
