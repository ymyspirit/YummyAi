# 订单工作台与自动履约

本次范围是原订单、制作、物流、工厂交付和平台回传服务之间的持续处理。共享
PostgreSQL、BullMQ、租户权限和版本记录，不另建一套订单或供应商数据。

## 日常操作

启用产品发货规则后，运营在订单工作台完成「审单通过并开始设计」，再审核
正式生产图。审单保存事务同时登记续办意图，后台使用原设计命令继续派发，
不依赖浏览器第二次请求或页面保持打开。派发失败保留已保存的审单及原命令
幂等键，不把保存成功误报成设计成功。无人设计继续使用原授权、配方、模型
预算与审核流程。物流配置尚未完善不会阻止已有产品规则下的设计派发。

审图事务同时登记自动履约意图。全部订单项的当前稿及必要客户确认通过后，
等待正式文件生成，再按已审核规格、国家、工厂能力、制造方案、实际产能、
包裹规则和共享物流连接推进。当前自动计量支持一件 SKU 对应一件成品；
套装、成对或多成品计量停到异常，需确认其换算规则后扩展。

工厂交期窗口从已审核正式文件就绪、开始安排生产时计算，不从首次审单创建
续办记录时扣减。设计与多轮返修不会吃掉工厂生产窗口；真正的平台最晚发货
时间仍独立核对。首次生产命令固定选中的产能日历与完工时间，响应丢失时
继续原命令，不重新安排或顺延。AI 与美工返修期间只等待新稿，不能沿旧审批打单。

工作台分为待审单、待审生产图、异常处理、自动处理中和全部订单。其他
生产、物流、发货页面作为本单的辅助操作入口保留，历史链接仍可使用。
「自动发货」默认显示后台进度、异常和已准备的工厂文件；手工导单、补单和
账户配置折叠保留。Printeque 已就绪订单按同一工厂包裹版本合并 ERP 表，每批
最多 50 单。处理完原因后可批量继续异常，原购单结果不确定时仍只核对原任务。
「工艺底稿」仅展示无订单/商品来源的可复用项目，「生产文件」仅展示订单
或商品项目。服务端先按来源过滤，再应用原隐私保留和权限校验。

## 一次配置的关系

供应商主体 → 实际工厂 → SPU/规格/工艺承接能力 → 工厂包裹规则 →
共享物流连接和费用规则。工厂能力可以关联具体 SPU；旧能力原版本保持原样。
发货规则引用不可变包裹版本，保存时拒绝同一规格及收货国的重叠规则。
订单匹配审核后的规格版本，不依赖卖家 SKU 的命名形式。

美国异形抱枕使用 Printeque 规则：整单合包、固定长度、按数量调整宽高，
复用现有 GOFO/USPS 尺寸限制和合规渠道询价。加拿大抱枕使用义彩与云途规则：
新 API 连接比较特惠普货与中包普货；旧连接和手工表格保留超过 20in 为中包、
其余特惠的历史规则。重量按规格换算，申报沿用已配置值。
新增产品通过新的 SPU、工厂能力和包裹规格配置，不在页面里写死卖家 SKU。

规则支持停用、只询价、自动购单。自动购单必须先有已验证 API 连接和明确
费用规则：可设单票、每日上限，也可明确不设总额上限并设置平均每件异常阈值。
2026-11-05 用户确认 Printeque 不设单票或每日总额上限，按合规渠道最低价购单，
整单运费除以实际商品总件数超过 10 USD 时转异常，不购买；等于 10 USD 可继续。
件数来自固定生产数量，报价和下单前复价均检查，实际扣费超出时保留原单并对账。
密钥仍在原独立加密域中，运营账号共用租户配置。
保存规则不批量启动历史订单；既有已审订单可从本单明确继续。

`GET /v1/fulfillment-flow/orders` 提供租户内、保留期有效的最近 100 单进度；
`POST /v1/fulfillment-flow/orders/resume` 接受最多 50 个去重订单 ID，逐单调用原
续办服务。浏览器同源代理继续验证登录、来源、路径和请求大小，不接受租户选择。

## 持久执行与边界

### 店铺自动拉单

店铺详情的「自动拉单」由具有店铺管理、订单读写和买家资料读取权限的管理员启用。
复用已有 Amazon 私有/公有应用授权与独立店铺节点，运营无需再填写一份凭据。
未授权或未绑定节点时显示原因并禁止启用。Etsy 和独立站的定时拉单尚未接通，
不能把已有报表导入或平台回传视作自动拉单已可用。

`GET/POST /v1/marketplace-accounts/:accountId/order-sync` 读取或保存设置；同源浏览器
代理继续检查本人权限、上下文、账号及请求大小。保存采用版本号和原请求标识，
不接受客户端提供租户、节点、API 地址或查询范围。迁移 `0198_order_sync_nodes`
新增租户隔离的调度状态和只含租户 ID 的发现索引；必须随对应 API/节点版本部署。

API 协调器每 15 秒检查到期设置，约每 5 分钟安排一个固定查询页。初次读取近 7 天，
后续复用原订单连接器的重叠时间窗口；截止时间距数据库时钟 150 秒，满足
[Amazon searchOrders](https://developer-docs.amazon/sp-api/reference/searchorders) 的至少两分钟要求。
节点只允许一次原 LWA 认证请求和一次固定 Orders 2026 读取，使用原加密执行日志、
凭据租约和回执恢复协议。每页最多 50 单，响应有大小上限，禁止任意 URL、写请求和重定向。

原订单事实、导入风险、页游标和调度进度在同一租户事务内保存；回执不确定时
恢复原节点任务。平台限流或临时失败保留固定时间窗口，退避后最多重试五次；
重复游标、超过 50 页、超过 30 天未同步、授权或权限变化会暂停并提示核对。
暂停会结束已有等待任务和导入运行，不调用平台。重复订单按原平台订单号归并，
相同源内容复用原快照，不依赖页位置或本次拉单时间生成订单身份。

API 的 Custom 文件引用由原报表资料服务登记，和订单分页回执一起提交。
迁移 `0199_order_api_customization_sources` 为原批次增加 `source_type` 与
`dispatched_at`：API 来源显示「Amazon API 自动同步」，不伪造 TXT 文件。
每次发现最多派发 20 个已提交批次，原保留期任务和附件任务都登记成功后才标记
已派发；队列暂时不可用或提交中断时保留原批次，重试沿用原批次幂等键。
后台继续使用原下载、病毒扫描、ZIP 解析、私有缩略图及审单入口，无须运营
再上传一次报表。队列只携带批次和原请求者 ID，下载前重新核对当前成员权限。
相同来源不重复下载；已有审核版本遇到不同远程文件时保留原稿并报附件变化，
不会自动覆盖审核。重复读取不延长顾客资料保存期限，已过期或已清理资料不能复活。

`ORDER_SYNC_COORDINATOR=off` 暂停拉单和 API 附件发现调度，保留已登记请求。店铺实际启用还须
完成正式平台授权、Orders/PII 许可及对应节点部署。Custom 文件链接仅进入原加密
订单资料；自动下载、扫描和制作需求交接必须另经原附件流程验收，不能声称拉单
成功即所有设计素材就绪。此功能不购买面单，也不确认生产或回传发货。

### 审核后的自动履约

迁移 0197 保存规则版本、单订单续办记录和租户发现索引。业务表强制 RLS，
规则历史不可变。API 中的有界协调器每 15 秒领取到期记录，使用两分钟租约，
执行前重新验证原审核人的有效权限。正式渲染、承运商请求和平台请求仍由
原 Worker 队列执行，关闭页面不会中断订单。

跨服务操作先持久化原请求和幂等键，再调用原服务。执行器重启后继续同一请求。
临时连接故障最多延迟重试三次；不确定扣费结果交由原物流对账流程处理。
修改规则、改稿、暂停、权限撤销、尺寸或费用超限会停止并提示具体原因。
已有生产或物流请求的订单不会套用新规则重新创建。

Printeque 面单创建与工厂 ERP 接单是两个外部系统。当前只掌握面单 API：
系统自动准备工厂 ERP 表及正式文件包，仍须批量提交工厂并登记实际提交回执。
义彩继续使用正式 JPG、尺寸和云途 PDF 文件包。下载文件不等于工厂接单。
未获得生产 ERP 接口文档前不声称已自动发送生产订单。

平台自动回传仅使用原发货单当前审核版本及全部包裹的真实交运依据，且店铺已
授权。工厂 ERP「已出库」本身不伪造质检、数量或承运商揽收记录。现有交运
记录齐全后自动请求回传，平台拒绝或结果不确定进入异常，物理发货状态不回退。
独立站尚无原生授权连接时不能声称已支持自动回传。

运行变量：`FULFILLMENT_FLOW_COORDINATOR=off` 仅关闭协调器，保留意图。
日用 manifest v3 可固定 `order-fulfillment-v1` 后台配置。`pnpm daily:start` 同时
恢复报表处理、附件扫描、设计、正式渲染、物流和回传队列，以及设计/渲染发现
调度器；不启用通用 AI、发布和历史媒体队列。旧 manifest 保持原启动范围。
`pnpm daily:status` 核对后台 PID、当前消费者和本机 8001 端口的实际就绪状态，
仅 API/Web 健康不能算自动处理可用。`WORKER_HEALTH_PORT` 只供本机运行监管，
接口不返回订单、租户或密钥。首次启用前需核对现有队列，不能把历史付费任务
当测试任务执行。回滚前停用新规则及协调器，保留原账单、文件和回执。

## 验证

加拿大新连接可以按整单包裹比价，比较特惠普货与中包普货的完整 API 报价，
按最长边、第二长边、长度加围长、实重与计费重量过滤。旧连接仍保留固定规格
分渠道，单单手选覆盖仍固定。义彩的规则长方体外包装不因产品是异形抱枕而
自动增加异形件费。完整条件与版本依据见[物流接入](logistics.md)。

规划单测覆盖规格识别、合包、加拿大两渠道比较与旧规格规则、无效姓名、超限和真实产能。
隔离集成覆盖 RLS、审批意图去重、事务回滚、租约竞争、失败文件、只询价、
结果不确定、撤销权限、真实交运后回传。原服务集成继续验证不可变文件、
物流预算、账单及原请求查重。

浏览器用一次性数据库、对象桶、Redis 与本地合成承运商，验证一次审单登记、
关闭页面后的服务端推进、全部订单项审图门禁、费用阈值保存和合并导出，另验证
规则编辑、整单自动询价/合成购单、Printeque ERP 文件以及底稿/生产文件分离。
合成承运商成功不代表真实工厂已收单或真实平台已确认。
