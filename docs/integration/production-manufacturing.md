# 生产固定制造版本

2026-10-19 · 1.1.34增量实施中，关联R12及B33/B35/B37，完整48需求/54工作包/8阶段保持。四条生产写入及整单/返工选择区已接入；整单选择、原请求恢复、运营V3交付及部分返工已有个人身份页面证据，见[运营交接契约](production-operator-handoff.md)。其他独立生产入口、全仓回归、候选/恢复演练及普通采用继续，不计完整功能完成。

## 来源与计数

生产必须明确选择已批准的制造版本并确认产出单位。生产数量始终表示最终销售SKU的订购单位；制造模板的件、双、套也必须对应这一单位。部件、裁切片和耗材数量在BOM行中表达，不把部件数当作发货或质检数量，不暗中做数值换算。界面显示原规格、每份内容与件数和制造产出单位，由操作员明确确认，Agent不能代替确认。

带制作工艺的定制商品固定原已推送审单版本内的产品规格和工艺，再核对所选制造版本必须完全一致。不能因为今天的商品规格改变，自动换成今天的BOM。原完整规格对应的明确已批准制造版本可被原订单使用，仍核对当前商品可用状态、读取范围、物料状态及实际工厂依据；新商品备料提案继续采用制造工作台的当前规格门禁。这两个场景分开，不放宽原有备料接口。

直接生产入口的新产品确认要求当前完整规格及制作工艺、已批准BOM、确认原因、本单实际关联SKU的已审核设计及其中的正式生产文件。画布设计还须保留其实际审核绑定的画布印刷规格并核对SKU适配；画布印刷规格不能替代制作工艺。设计、素材和商品分别按当前权限及对象范围读取，素材授权、删除状态与有效期在提交事务内复查。已有审单来源必须走对应原审核稿，不用本次声明覆盖。确认是本次新事实，不能伪称下单时已有规格或补写旧生产。

返工明确选择制造版本。使用原稿时沿用原产品依据；改稿必须引用当前已审核的新来源并重新核对制造/工厂依据。原生产、交付文件及BOM历史均不改写。

## 数据层

生产拥有者管理不可变绑定表`production_manufacturing_bindings`，连接确切生产版本、已批准制造版本及审核、原规格、来源种类/审单版本或原生产绑定、最终SKU数量/单位和BOM内容指纹。来源为`order_work_revision`、`approved_product_confirmation`或`original_production_binding`。原确认说明使用订单私有加密域，公开视图不返回原私有文字、材料用量、库存量或成本。租户组合外键和数据库完整性检查保护归属、版本与数量。

绑定与新生产版本、业务事件和审计同笔提交，并在原创建事务封存；应用写入的新生产版本不能缺绑定。旧生产保留“未固定制造依据”的明确状态，不迁移补造。整个数据库恢复按既有先数据后约束/触发器的流程验证，不添加依赖当前事务编号的历史行CHECK。

0134已在四条写入和现有整单/返工页面接线后加入开发迁移序列，普通库未执行。每个新生产版本均须原子封存制造绑定，旧生产保持明确缺项，不补写历史。绑定新增固定SKU与实际制作尺寸/面数/工厂标准依据；原稿返工沿用该原依据，改稿重新校验来源。同口径尺寸只允许浮点换算误差，不把图案主体尺寸、成品外轮廓和裁片尺寸混算。独立子库命令验证通过不代表整仓、浏览器、正式升级或备份恢复演练通过。

## Harness与模块拥有者

订单拥有者先核对当前OrderRead/OrderWrite及必要的订单私有资料权限，再在同一事务内调用商品拥有者的制造校验。商品读取按实际ProductRead范围检查，不借订单权限浏览全部商品；物料启用/基本单位作为内部业务门禁，不返回库存量或成本。整单制造选择按商品父对象和模板的稳定顺序取得锁。

单件、整单、直接生产和返工现已在开发代码中写同一绑定模型。原请求恢复先核对当前权限、原操作员、正文与请求编号，再返回已存在的原对象；不能因恢复而重新审批、重复下达或重复记成功审计。新增制造字段不得带会改变旧正文校验值的默认值，只有新命令在恢复检查后要求明确选择。直接生产的审计失败须回滚生产及版本。同单不同键共享剩余数量锁；已实际发出的原生产数量不能因内部取消释放。

工厂候选与实际下达共同使用原审单中的SKU、规格、产品计划及制作工艺，当前渠道关联不能替换原商品依据。本批回归实际改动当前SKU关联后，核对工厂候选仍使用原审核SKU及产品计划，缺当前ProductRead时拒绝读取，正式下达也固定原SKU；不是仅检查函数参数或页面配置。

交付包固定原制造指纹，具体工厂只看到受权任务对应的生产依据。新包需要完整制造来源；旧包保留原快照和回执，历史缺项显式展示。下载、文件接受、生产完成及质检通过继续分别记录，不用新BOM伪造任何实际生产事实。

## 正式接通的剩余边界

| 入口 | 新命令固定来源 | 原请求恢复与历史 |
| --- | --- | --- |
| 单件审核稿下达 | 实际推送审单内规格/工艺、所选已批准制造版本、原审核文件、数量单位确认 | 当前权限和原操作员核对后先恢复原回执；旧稿缺规格不能从今天的目录猜测 |
| 整单下达 | 每个商品独立选择制造版本，固定原审单规格，整单同笔提交 | 原整单正文和编号不变；任一商品不满足门禁时全部回滚 |
| 直接生产 | 本次当前规格确认、实际关联SKU、原审核设计及生产文件；画布沿用原印刷规格 | 已有审单不能改走直接声明；该确认不回填旧生产 |
| 补做/改稿返工 | 原稿使用实际原生产绑定；改稿引用新的已推送审核来源；明确选择制造版本及数量 | 原生产缺绑定时不能补写历史；原审单、交付包和工厂回执保留 |

正式写入代码统一锁顺序：取得本次涉及的原订单、审单及生产商品锁后，稳定排序并预锁全部制造父对象，再检查工厂与具体制作依据。订单头遇到并发占用时明确拒绝并要求核对后重试，避免与审单持锁形成反向等待。不能在持有工厂锁后才首次取得制造父锁，或让整单与单件采用相反顺序。封存函数只管理制造证据，不能单独充当订单状态校验、实际生产放行或工厂接受命令。

整单和交付返工选择区已验证原规格/每份内容/件数、明确制造选择和单位确认，临时读取失败保留选择但暂停提交。当前范围丢失后移除私有候选，晚到成功响应不能恢复；原来源或可选版本变化要求重新核对。整单结果未知时恢复原路径/正文/请求编号，不换键重复下达。当前恢复只在本页内存，跨刷新、跨设备及其他生产入口仍须继续，订单PII不写入浏览器持久存储。Harness仍须沿用工具权限及审核凭证，正文中的`true`不证明发生过人工批准。

V3交付包和工厂任务已接入固定制造快照、材料/工序责任、精确计划用量及本单生产说明，接受时核对制造清单校验值；旧包不补造。工厂最小清单不包含内部库存主键、成本或BOM备注，不等于实际领料和完整工厂生产系统。普通部署采用、备份恢复、工厂日历/原子产能预留及B40精确领料/耗用继续建设。真实pre-0134/pre-0135升级已单列通过，不代替恢复演练。
