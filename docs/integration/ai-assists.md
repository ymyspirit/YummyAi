## 配置与使用

异形抱枕审核页另提供六项自动核对：`POST /v1/ai-assists/runs` 使用现有 `artwork_preflight` 请求，增加 `automaticAudit: true`，仍必须传当前订单 revision 和生产稿版本。明确重新检查传 `retryAudit: true`；同版普通重复请求复用已有任务，进行中的任务始终复用。
`GET /v1/ai-assists/runs?kind=artwork_preflight&scope=order:<id>&automaticAudit=1` 列出该订单自动核对记录；结果的 `artworkAudit` 包含固定依据及六项状态。该类记录允许有订单/PII/设计读取权限的同租户审核人读取（包括图片），其他助手记录仍为创建者私有。服务器的 `ArtworkAuditRepository` 验证版本、需求、保留期及输入/文档校验值，API 审核和 Worker 出图复用相同证据。客户端不能提交核对结果来解除门槛，也不会自动设置人工确认或批准订单。
几何/视觉规则、异常处理和历史边界见 [抱枕制作流程](../operations/custom-pillow-workflow.md#六项自动核对2026-09-20)。隔离集成回归：`node --env-file=.env --import ./apps/api/node_modules/tsx/dist/loader.mjs tools/scripts/run-order-daily-acceptance.mts --suite=artwork-audit-integration`，执行完核验临时数据库、桶和队列均已清理。

1. 在 `/settings/ai` 的「模型渠道」添加服务地址和凭据。地址可以包含 `/v1`，保存配置不会调用模型。
2. 已启用的 OpenAI/兼容渠道文本模型自动出现在八个业务助手中，无需再次填写 Key 或登记同名分析模型。优先使用「默认业务分析模型」，未设置时跟随「默认文本模型」。图文任务仍需实际模型支持图片输入和结构化 JSON 输出；已有生图模型不会作为分析模型使用。
   可在同页「图文分析模型与费用设置」填写渠道单价和单次预估费用上限。同渠道、同模型的共用文本路由会沿用已登记的价格及上限，不会绕开预算。缺少价格时记录 tokens、费用保持未知，每次最多输出 6000 tokens，仍限制并发且不自动重试。已启用组织金额预算时，未计价模型不可提交；本月历史未计价调用也须核对后才可按金额预算继续。
3. 在以下业务页面选择分析模型，再手动开始分析。未配置时页面显示设置入口；不会生成模拟分析结果。

渠道或模型停用后，待执行任务在发送数据前再次检查。兼容渠道使用图文 Chat Completions，GPT-5 及后续模型使用 `max_completion_tokens`，官方渠道使用 Responses。协议、权限和额度错误会给出明确诊断，不透传渠道原始错误正文。单价填写为 0 时显示的是按用户配置的估算值，不代表渠道实际免费。

## 第三批业务约束

- 三个入口都要先点「读取分析依据」，无需配置模型、不会产生模型费用。页面列出范围、来源、缺项和校验结果；随后才可开始 AI 分析。重新读取失败时旧依据失效。提交时服务端重新读取并核对指纹，资料变化返回 409。
- 经营分析使用不可变利润计算及其诊断，不把缺失成本当成零。仅在两份计算均完整、使用同一指标版本和币种时计算差额；计算快照差额不是同比或环比。订单/售后汇总是所选财务事实涉及订单的**当前状态**，不是财务账期内的发生次数或退货率；最多覆盖 1000 个订单，超限明确省略。计算结果中的订单/订单行明细不发送给模型。
- 采购分析以可用库存、在途和已批准未收货采购量计算库存位置，结合阈值、目标与最小采购量给出确定性建议。草稿采购单不计入在途。缺少库存、规则、单位不一致或收货争议时不报确定补货量；在途与开放采购量同时存在时要求核对是否重叠，避免重复计数。没有销量时间序列时不推算断货日期。
- 供应商报价通过 RFQ 固定请购版本中的具体行匹配库存品和库位，展示币种、有效期、MOQ、交期及单位。不同币种不直接排名；未包含的运费、税费不当成完整到岸成本。单项最多读取 100 张未结束采购单和 100 个报价版本，超限要求缩小或整理范围，不静默截断数量。
- 售后不会自动发送原始问题描述、往来消息正文、附件、客户姓名地址或追踪号码。只发送结构化进度及操作者单独填写的「给 AI 的问题说明」。填写内容会进入所选渠道，需自行去除不必要的个人资料；说明标为待核实，不能当成已验证证据。
- 售后审批不代表退款到账或补发已经发出。已解决/已取消的售后不生成新回复；草稿必须引用本次来源。模型不能创建沟通记录、审批、退款、补发或关闭售后。历史分析可「载入这次分析的选项」，读取当前依据后再编辑、复制；状态变化后的旧回复不可复制。
- 分析建议的跳转目标必须匹配服务端提供的来源，模型不能注入任意执行链接。三项均保留人工业务操作，未新增自动执行接口。

## 第二批业务约束

- PSD 助手分析图层结构，不声称完成 PSD 像素渲染验证。字段建议保存在人工确认的模板槽位中，后续 SKU 显式绑定表单会带入这些字段，仍须运营核对。不自动确认解析警告或批准模板。
- SKU 助手要求从商品开发创建 Listing，关联 1–50 个已批准制作版本，规格事实已确认。已关联图片中只有与当前制作版本对应、权利批准的套图会发送给模型；实物照片、未批准媒体或读取失败的图片明确提示未分析，不生成其图片说明。
- 生成语言跟随 Listing 的 `locale`；Amazon 与 Etsy 分别使用现有平台规则限制标题、卖点、标签。AI 不修改 SKU、价格、合规事实、主图、媒体关联或定制能力开关。定制说明仅能采用到已经启用定制的草稿。
- 图片说明存入当前 Listing 版本的 `content.mediaDescriptions`，只接受当前媒体 ID，纳入资料包导出。此字段未新增平台写回能力。
- Listing 编辑器保存发送 `If-Match: <当前版本 UUID>`。服务端锁定 Listing 后检查最新版本，冲突返回 409，防止旧 AI 结果或另一个编辑页面覆盖新改动。兼容既有未携带该头的内部调用。
- 订单详情和制图详情提供「检查模板制图条件」：读取已保存修订、印花、SPU 具体规格、固定工艺底稿，并展示字段、原文、定制区域及阻断原因。检查不会写入订单或创建生产文件。
- 选择模板自动制图并确认推送后，已有模板执行器读取该订单绑定的印花素材版本和买家原图，生成可编辑、待审核的私有生产稿。文字保留原文（包括两端空格），图片完整适配区域。缺少/歧义字段、多行或过长文字、指定字体/颜色、条件规则、自由制作说明和不支持的字形需美工处理；本批不自动执行抠图、重绘或任意自然语言指令。原文件完整性与解码仍由实际制作阶段校验。
- PSD、SKU 分析绑定固定资料指纹。模板源失效、SKU 制作版本变化、Listing 更新或草稿变更时须重新分析；任务与图片继续使用租户及操作者权限。

创意分析不会把竞品图片转换为授权素材。采用方向只修改勾选的需求字段；不会创建印花 SKU 或修改已批准设计。采用定制方式与字段会清空旧布局，要求重新配置定制区域。

订单预审保留已经确定的渠道 SKU 映射；无法确定时才提供可用候选。候选关联的是印花版本和商品 SPU 下的**具体规格版本**，不是另建一个 SPU。采用候选不会改写买家定制文字、替换买家图片或自动推送订单。

生产预检检查当前已保存版本。编辑器打开或草稿未保存时，先保存并关闭编辑器再开始。规则检查使用原始生产文档和资源；AI 查看归一化预览，不能替代原始尺寸、分辨率、文字、裁切与实物效果的人工核对。当前生产编辑器支持的 `tire_cover`、`shaped_pillow` 使用已有规则引擎；没有对应编辑稿的订单不能进行该项预检。

## 版本、证据和图片

- 每次分析固定研究快照/笔记版本、订单修订、来源版本或生产编辑版本。输入和已完成结果不可覆盖；重新分析创建新记录。
- 页面区分事实、推断、建议以及缺失资料，显示实际发送给模型的图片。引用必须来自本次授权输入；未成功读取的图片不能被用作视觉事实证据。
- 订单资料或编辑版本改变后，旧结果不能采用；API 隐藏过时订单结果与图片。前端另检查未保存需求的变化。
- 最多选择 8 个研究来源，每个最多 2 张研究图片；订单最多 6 张买家图片，生产预检最多 3 张已绑定印花的栅格素材。无法读取的图片会记录原因。
- 远端研究图片仅允许既有 Amazon/Etsy 图片 CDN 的 HTTPS 地址，不跟随重定向。单张下载限制 4 MiB，解码限制 3200 万像素，输入模型前压缩到最长边 1024 像素的 JPEG。限制之外的内容不声称已分析。
- 每类订单匹配候选最多 50 个，优先保留当前绑定项；部分已确定的绑定保持不变。候选范围不足时由运营使用现有选择器处理。
- 研究分析历史关联 `analysisScopeId`，创建项目时写入不可变工作流；分析历史仅对创建者和当前租户开放，且每次读取重新检查业务权限。

## 服务与接口

需要 API、Web、Redis、Worker、PostgreSQL 及现有私有存储/订单服务。按 [本地开发指南](../operations/local-development.md) 启动；只运行 `dev:lite` 时另开 `pnpm dev:worker`。无需新增环境变量；API 与 Worker 使用现有 `MODEL_CREDENTIAL_ENCRYPTION_KEY` 派生独立的 `yummyai:ai-assist` 内容加密域。该内容密钥与模型凭据密钥用途分离。

迁移 `0075_ai_assists.sql` 新增 `ai_assist_runs`，强制租户 RLS，限制可变字段，并保留不可变来源、模型和提示版本。所有数据库访问使用现有租户事务。队列 `ai-assist` 仅携带任务和租户/操作者标识，不携带明文定制内容。

迁移 `0076_ai_assist_batch2.sql` 扩充已有任务类型，不新建渠道或表。新增任务请求为 `template_config { inspectionId }` 和 `sku_package { listingId, expectedVersionId }`，同样要求 `requestId`、`modelId`。历史范围分别为 `template:<inspectionId>`、`listing:<listingId>`。生产条件接口为 `GET /v1/order-centers/lines/:id/template-plan`，要求订单读取与隐私读取权限，并使用 `private, no-store`。

迁移 `0077_ai_assist_batch3.sql` 仅扩充任务类型约束。第三批先用以下选择字段调用 `POST /v1/ai-assists/basis`，取得 `fingerprint`、摘要行、来源与诊断；创建任务时添加 `requestId`、`modelId`、`expectedFingerprint`：

| ------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------ |
| `business_review { runId, comparisonRunId: UUID \| null }`                | `finance:<runId>`                        | `finance:read`、`order:read`         |
| `procurement_review { stockItemId, locationId }`                          | `procurement:<stockItemId>:<locationId>` | `procurement:read`、`inventory:read` |
| `after_sales_review { caseId, locale: "en-US" \| "zh-CN", contextNotes }` | `case:<caseId>`                          | `order:read`、`order:pii:read`       |

实际权限常量以共享权限模块为准。API 提交、历史读取和 Worker 执行均重新鉴权。采购与订单状态聚合使用 `withTenant` 的只读可重复读事务，仍使用非所有者角色及强制 RLS。单次业务上下文限制 70 KiB。结果扩展 `actions` 和可空 `replyDraft`，旧结果缺少字段时默认空列表与空回复。

| API                                         | 功能                                            |
| ------------------------------------------- | ----------------------------------------------- |
| `GET /v1/ai-assists/models`                 | 查询本租户启用的图文分析模型                    |
| `POST /v1/ai-assists/models`                | 具有模型配置权限的用户登记分析模型与计价参数    |
| `POST /v1/ai-assists/basis`                 | 第三批只读分析依据，不调用模型；私有且禁止缓存  |
| `POST /v1/ai-assists/runs`                  | 按 `requestId` 幂等创建任务，校验业务版本与预算 |
| `GET /v1/ai-assists/runs?kind=…&scope=…`    | 当前操作者的指定业务分析记录                    |
| `GET /v1/ai-assists/runs/:id`               | 状态、证据、规则与建议                          |
| `GET /v1/ai-assists/runs/:id/images/:index` | 经授权读取本次实际模型输入图片                  |

Web 通过 `/api/ai-assists/*` 的白名单代理调用以上接口，使用服务端认证；写入要求同源 JSON 且请求体不超过 128 KiB。结果和图片均禁止共享缓存。渠道支持现有 OpenAI Responses 和 OpenAI 兼容 Chat Completions 的图文结构化输出；具体模型能力仍须配置后实测。

## 费用、保留期与恢复

- 按租户限制最多 4 个未结束分析任务，使用现有月预算及账本预留额度。预估超过配置上限时拒绝提交。
- 单价由管理员填写。预估上限是提交前控制，无法保证第三方账单的硬性上限；实际费用以渠道用量及账单为准。缺少用量时显示未知并保守保留预算，不能把未知费用显示为零。
- 六项自动核对的「本次使用的资料和核对记录」显示该次调用已保存的输入、输出及合计 Token；任一项未返回时合计也显示未返回。重试是独立调用，不把一次成功用量当作含失败重试的总用量。未配置单价时仍保留 Token 记录，费用保持未知。
- 单次模型调用超时 120 秒，输出上限 6000 tokens；失败不自动重复调用模型。已可能发送的失败保持保守预算，避免重试导致重复扣费。
- 网络中断后可刷新历史查看任务。排队任务的「恢复排队」复用原任务和队列标识；运行或已完成任务不重复入队。Worker 中断后如无法确认模型响应，会标记失败而非重发付费请求。
- 研究、PSD、SKU、经营和采购分析内容保留最多 30 天；订单及售后分析最多 24 小时，且不晚于原始订单资料保留期限。售后任务绑定订单行以参与隐私清理；售后依据失效时请求说明与回复一并隐藏。到期任务清除加密输入和输出；任务状态、费用、版本指纹等审计元数据保留。读取到期任务也会执行清除。
- 买家姓名、地址、联系方式等无关订单字段不会发送。仅所选定制文字、图片及制作说明发送到操作者选定的渠道；渠道自己的数据保留规则需管理员在配置渠道时核实。
