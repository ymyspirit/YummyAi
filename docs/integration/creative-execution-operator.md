# 创作执行记录与人工处理

2026-10-19。关联 R04/R08/R13/R18/R20/R39 和 B09/B14/B15/B28。复用五类原创作执行、原预算账本、代码方法、当前成员授权与审计事件，不另建任务或费用事实。完整 48 需求、54 工作包、8 阶段保持。

## 操作入口

批量设计的详情显示候选、画幅适配和实际扩图；模板控制台按原检查记录显示编译；套图批次详情显示各原槽位；Studio 的生成任务显示原生成记录。四种拥有者范围覆盖五种执行类型。展开“执行依据与恢复”后读取当前受权记录，支持每页 20 条和更早记录。

面板保留本次方法版本、输入校验、原父步骤、派发及本地处理次数、提交/响应、原服务报告费用、原预算状态、产物版本校验及失败代码。方法入口打开原版本。历史没有执行记录时明确说明，不用今天的方法或预算补造历史。

技术完成、人工核对、渠道账单核验、业务审核和正式生产仍分别记录。服务报告费用精确到八位 USD；未知费用不记零，不把父/子费用相加成另一个事实。不提供原响应下载、私有对象键、权限快照、令牌、提示词或供应商密钥。

## 当前读取权

API 从已认证成员上下文重新核对 DesignRead、AssetRead 和真实拥有者。批次读取权与协作版本读取权分别检查；不能借批次可读取得他人的适配记录。模板原文件、实际产物按各自素材权限核对；不可读产物只显示缺项数量。只读历史不要求创作写入权，也不要求旧来源继续满足运行门禁；归档不改写历史。

面板在显示、定期及重新聚焦时复核。切换拥有者或收起时取消旧读取；确认失权立即清除结果和凭据选择，较早成功响应不能恢复旧内容。临时失败隐藏尚未核对的记录并提供刷新，不伪造空历史。

## 原任务续做申请

申请须有当前原对象 DesignWrite，且由原申请人操作。接口锁定原执行并核对状态指纹，再调用与 Worker 相同的 admission：原成员及权限上限、拥有者/素材/规格/渠道、原输入、方法与知识来源继续有效。

申请只使原记录到达调度时间，并同事务写审计。它不调用渠道，不新建拥有者，不重置次数、租约、原提交、预算、方法或响应。Worker 仍须实际运行并重新准入；“已请求”不等于已经恢复。按钮是申请入口，服务器仍可能因原来源改版或撤回拒绝。

有效租约、次数用尽、响应过期，以及 completed/failed/uncertain 终态均不能通过申请重置。已经提交而无检查点的外部请求需要人工核对；只有已固定有效原任务号的视频查询可沿原 GET 路径继续，不发第二次 POST。终态的独立人工恢复指令、找回渠道原件及费用补证不是此申请接口的能力，继续独立建设。

## 人工核对

有当前原对象 DesignReview 的人员可登记“渠道仍在处理、渠道报告失败、已找到原响应、交由业务负责人核对”。选择不超过 10 MiB 的本机凭据，由浏览器计算 SHA-256，只提交校验值和明确的原请求核对声明；文件内容、名称及路径不上传。需要后续独立核验时，操作人应按本方证据保管制度保留原件。

这是一条 operator_attested 审计记录，不能证明渠道自动验真、找回原响应字节、结清账单或通过生产审核。原执行终态、提交、费用和原产物保持不变。当前显示最近十条人工处理记录，更多记录留在原审计域；此接口不提供完整审计导出。

每次命令有独立 commandId 和所见指纹。相同命令重试返回原记录；同号改内容或归属冲突。权限在重放前仍检查。原状态已经变化则要求刷新，不覆盖新状态。凭据生成及请求途中切换或失权不能恢复旧表单。

## 接口与实现

- `GET /v1/creative-executions/history/:scope/:id?after=UUIDv7`，scope 为 design_batch、inspection、mockup_batch、studio_generation。
- `POST /v1/creative-executions/:id/actions`，仅接收共享契约中的 request_recovery 或 record_check。租户和原执行契约不能由调用方指定。
- Web 同源代理仅放行这些路径，写入要求同源 JSON 且不超过 16 KiB；读取不缓存，错误不反射私有诊断。
- API 和 Worker 共享 pod-core admission；沿用 Drizzle、PostgreSQL RLS、BullMQ 与 Lucide，不新增外部包或数据库迁移。pod-core 新增对既有 catalog-core 的显式工作区依赖；数据库的八项隔离保护单元现在纳入默认 test 入口。
