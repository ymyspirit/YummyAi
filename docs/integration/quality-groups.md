# 实物质检组、缺陷影响数量与补做

状态：PRD1.1.30的实物分组、商品暂停/归档和资料清除竞争、事务一致性已通过本地完整回归及独立构建。关联R26/R30、B38/B42；原48需求、54工作包、8阶段保持。普通环境采用、真实试点及完整平台验收继续。

## 业务事实

一次生产有五件实物，可以按真实隔离位置分为：合格框A两件、仅色差框B两件、色差及车缝框C一件。三个实物组不重叠，数量合计五件。色差影响三件，车缝影响一件，不合格实物共三件；缺陷影响数不能直接相加成四件补做。

同一组内的实物具有相同检查结论和缺陷组合。不同缺陷组合先拆组，再逐组记录标准项目、实际结果、严重度、责任、处理与凭据。每条缺陷影响该组全部数量；同一代码可以出现在多个组中，按代码汇总实际影响数量。操作员明确确认已经隔离且互不重叠，Agent不自动声明实物已分组或已检查。

参考[ERPNext检验记录](https://docs.frappe.io/erpnext/quality-inspection)、[ERPNext开源检验实现](https://github.com/frappe/erpnext/blob/develop/erpnext/stock/doctype/quality_inspection/quality_inspection.py)及[Odoo19质量检查](https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/quality/quality_management/quality_checks.html)。沿用现有订单、生产、质检及发货拥有者；不导入另一套库存或制造事实，不增加收费模型调用。

## 固定的数据与版本

新增分组检验保留独立格式版本，固定原生产版本、原生产投影、所选标准和实际操作员。每组有不可变ID、隔离标识、数量、逐项结果和缺陷记录，完整覆盖本次检验范围。整批检验覆盖生产版本数量；对未交运组复检时，新组只覆盖原组数量，并以不可变关系连接原组。原组与原检验继续保留，当前可用的是最新整批检验下尚未被复检替代的末级组。

已有逐项V2及更早检验不补造隔离组或影响数量。原明确整批通过的生产来源仍可按原版本追溯；旧缺陷显示影响数量未记录。旧请求仅恢复原响应，不能因新字段将历史解释成新的分组检验。

租户复合外键保证生产、版本、检验、实物组及缺陷属于同一来源；强制RLS、不可变历史和提交时完整数量约束同时执行。分组与复检不得隐藏或删除真实交运记录。

## 发货、复检与补做

合格末级组可以成为装箱来源，固定组ID和原通过结果；待处理组不可发。相同生产单的不同合格组可同时分配，审核与出库在同一数量锁内复核。组的合格依据固定，其他组的复检不替换其原依据；父生产版本、暂停、取消及当前权限仍单独检查。

已经实际交运的组保持原检验并转售后；同批仍在厂内的其他组可继续复检。父组复检不能重复占用已经补做安排的实物，不通过较早时间、换组ID或重试制造第二份可用数量。

补做明确选择待处理组、对应缺陷、实际数量和原生产投影，操作员核对所取实物。不同缺陷共享该组的数量余额；两条缺陷不能各申请同一组的全部数量。补做子单与原组及恢复案例关联；取消是否释放依据子单真实状态和实物证据，不能只修改案例状态。原批次的其他合格组继续可用。

## Harness与操作体验

数据层保存实物划分、原检验、缺陷数量和替代关系。Harness核对当前订单/资产权限、原依据、完整覆盖、当前末级组、并发占用、请求内容与操作员；恢复原回执与执行新操作分别处理。Agent可以整理建议，不能填写实际隔离、通过、工厂接受或交运确认。

分组及旧逐项检验共用当前订单权限与事务入口。检验、质量异常及两类审计在同一事务内提交，失败整笔回滚。补做案例、子生产单、原组数量关系和审计也同笔提交；案例状态事件与其审计同笔提交。成功回执丢失后按原操作员和原请求恢复，不新增异常、审计或补做占用。取消案例本身不表示工厂已经停单。

新检验与补做在当前商品的业务锁上取得事务共享锁；商品正被归档、暂停或改动时明确返回冲突。再以不可等待的行共享锁核对暂停、归档和实际保留状态，覆盖未使用业务锁的资料清除事务。保留期限由数据库时钟判断，只读取保留状态，不读取或解密制作密钥。原生产未记录制作单ID时仍按当前商品核对状态，不借旧空值继续执行。原成功回执恢复与新增检验分别判断。

该方案复用现有`order-work`锁和PostgreSQL原生机制，参考[事务建议锁](https://www.postgresql.org/docs/current/functions-admin.html)与[共享锁及冲突语义](https://www.postgresql.org/docs/current/explicit-locking.html)，不新增执行框架或依赖。

沿用生产中心和原发货表单。整批逐项检验保留，增加按实物组记录的入口。每组独立选择标准项目结果及缺陷处理；默认未知，禁止批量替所有项目填通过。刷新保留原草稿与并发依据，确认失权清除私有内容；依据变化后显式重新核对。桌面与390px手机验证长标识换行、组间增删、数量、错误和确认按钮。

文本、数量、分数及选择结果即时合并到最新草稿；动画只包裹增删等结构变化，不能延迟保存输入或用旧字段覆盖新填写。原请求结果未知时保留原编号和内容，即使重新读取发现余额变化，仍可恢复原回执；当前新操作继续受最新依据约束。
