# 抱枕原创图稿与商品套图的受控交付

入口：销售方案 → 上新任务 → 抱枕图稿与套图交付。首轮支持异形抱枕，固定图稿候选、场景图、细节图、定制说明图四个步骤，复用现有画布、Studio 任务、权利审核、设计版本和刊登服务。

这里交付商品视觉候选与刊登配图。生产尺寸、有效 PPI、缝边、裁线、正反片、条码框及工厂 JPG 验收继续走[异形抱枕生产工作流](../operations/custom-pillow-workflow.md)。不改写订单生产稿、旧工艺或 Rule Center 快照，不下达生产、不操作卖家后台。

## 操作

1. 选择事实已确认的抱枕规格，绑定仍有效的已审核工艺底稿。
2. 选择授权的真实样品图片，填写款式、轮廓与单双面核对依据。素材必须在 `authorized` 域、非 AI 图片、权利已审核，来源为 `owned` 或 `licensed`。运营负责确认其确实为对应款式的实拍，系统不能凭文件名证明真实性。
3. 核对设计需求、图像模型、请求尺寸、单次预算占用及总预算后固定需求。准备、刷新和读取结果不调用模型。
4. 明确提交一张图稿候选。读取完成结果，检查实际文件；由具备设计审核权限的运营逐项确认主体、轮廓、商品事实与单双面，或填写理由退回。
5. 明确选择本交付已审核并完成四项核对的图稿版本，再分别制作、审核三个套图槽位。已审核图稿作为第一张固定参考图，样品用于核对真实产品结构。每个槽位最多四次尝试，失败须明确提交新候选，成功结果保留。
6. 每个套图槽位选择一个通过审核的版本，三张图须引用同一个仍有效的图稿版本。可明确选择样品作为主图；未选择时保留原主图。采纳加入配图并增加销售方案版本。
7. 明确「同步刊登草稿」，由原刊登服务创建新草稿版本。进入刊登编辑器核对完整性、主图资格与合规要求，继续原审核、不可变封存及导出流程。

方案、SPU、规格、工艺底稿版本或审核状态变化后，旧交付保留为历史，停止新的制作、通过审核和采纳。模型路由或渠道配置变更也需重新核对费用并准备新交付。普通画布审批不能替代此处四项核对，后续制作与采纳检查版本的核对审计记录。

## 预算与恢复

USD 金额精确到六位小数。单次金额是运营核对渠道报价后确认的**预算预留**，不是供应商实际账单。没有可靠费用回执时显示「实际账单待确认」。系统限制预留总额和可提交次数，不能据此承诺实际收费等于预留金额。

- API 在组织 AI 预算的同一锁和账本内，原子检查单次、交付累计和已配置的组织月度上限。未计价的历史 Studio 调用不按零费用处理。
- 响应丢失重试沿用原 UUID，复用任务与预算记录；刷新、重复领取已结束任务均不会再次调用模型。
- Worker 提交前复查当前权限、商品来源、图稿审批、渠道指纹、素材版本与校验值。确认尚未提交模型的失败解除预留，原金额仍作为历史保留。
- 已提交供应商、结果未知或返回后失败的尝试保持占用，等待账单核对。提交中断不会自动重投，也不伪造结算或退款。

## API 与存储

基址 `v1/sales-plans/:id/launch/visuals`，契约 `@yummyai/contracts/catalog/product-visuals`：

| 方法与后缀 | 行为 |
| --- | --- |
| GET | 当前依据、权限、授权样品、图像模型及最近交付记录 |
| POST `prepare` | 幂等准备四个现有画布项目，免费 |
| POST `:groupId/generate` | 明确提交一个固定槽位的一张候选 |
| POST `:groupId/collect` | 将已完成结果登记为原审核域的版本，免费 |
| POST `:groupId/review` | 逐张技术预检、四项人工核对及原版本审核 |
| POST `:groupId/adopt` | 三槽位选图、来源校验、版本增加及幂等记录 |

BFF 严格校验命令，身份来自原认证边界；服务端检查产品、设计、素材、审核权限。操作经 `withTenant()` 和强制 RLS；交付及 Studio 历史遵循原创建者范围。

`creative_design_batches.canvas_workflow.visualDelivery` 固定组编号、槽位、方案 revision、来源摘要、样品依据、模型路由、渠道指纹、图片参数与预算。素材版本和校验值继续由原 `reference_snapshot` 固定；Studio 输入保存所选图稿版本，结果复用同一私有素材记录。渠道指纹只保存配置摘要，不保存凭据或端点。

不增加表、迁移或环境变量，也没有第二套审核队列。部署需同时更新 Contracts、Database、API、Worker、Web；原非视觉交付项目保持兼容。

技术预检读取原始私有文件，验证校验值、解码、实际短边至少 1024 px；图稿另需真实透明背景和可见主体。该门槛是商品候选检查，**不代表生产清晰度、打印尺寸或外观保真验收**。请求尺寸、DPI 标签与模型自评均不能代替实际文件和运营看图。

## 隔离验收

```powershell
pnpm test:e2e:order-daily --suite=product-visuals-integration
pnpm test:e2e:order-daily --suite=product-visuals
```

浏览器套件复用销售上新套件，API 8116、Web 3100，含原销售上新、销售方案、AI 任务回归。运行前停止同工作区 Next dev；完成后 `pnpm start:local`、`pnpm check:local-runtime` 恢复和核验。

验收使用真实认证 API、RLS、私有存储、工艺底稿审核、Studio Worker、版本审核、方案采纳与刊登草稿，仅注入合成 PNG 模型传输，不访问模型端点、不调用付费模型。覆盖响应丢失、重领、单图失败、预算并发、资料或权限变更、混用图稿及技术缺陷，并检查桌面、390 px 移动端和深色界面。

隔离 runner 在 `finally` 销毁独立数据库、存储桶和 Redis，并验证删除结果。资源标识及报告位于忽略的 `tmp/product-visuals-logs`、`tmp/sales-launch-e2e` 和 `tmp/order-daily-e2e-*.json`。合成回归证明流程控制；真实图像质量、商品一致性及工厂可生产性须另行获得授权样本和费用上限后验收。
