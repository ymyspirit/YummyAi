# 研究与采集的逐权限对象范围

2026-10-19 · PRD 1.1.17 · R01/R05/R39，关联 B06/B09/B13/B18。
复用原生授权、Drizzle/PostgreSQL、BullMQ 和私有研究域，不新增依赖、路由或数据库迁移。

## 当前身份与每项权限

成员请求同时受到原请求上下文和当前成员授权的限制。服务在自己的 `withTenant()`
事务中重新读取成员与逐权限范围；不能取全部角色的最大范围用于每项操作。
显式非成员凭据适配器保留其服务端授予的权限上限，不接受请求体选择身份或范围。
原申请人失效后，队列中的旧权限快照不能授权归档。

| 操作 | 独立检查 |
| --- | --- |
| 新采集或再次采集 | `capture:write`；已有研究条目必须在该权限的对象范围内 |
| 研究列表、总数、分类分面、快照时间线及结论读取 | `research:read`；计数与条目使用相同范围 |
| 研究结论保存、归档/恢复、手动分类 | `research:write`；批量目标全部通过才修改 |
| 采集快照和媒体元数据 | `capture:read` 与研究拥有者 |
| 私有媒体签名读取 | 同时满足 `capture:read`、`asset:read` 各自的拥有者范围 |
| 关联创意项目及数量 | 独立的 `design:read` 与项目创建者范围 |
| 后台媒体归档 | 重新加载原采集人的当前 `capture:write` 及研究拥有者 |

研究条目没有可信团队归属。`self` 和 `team` 都仅允许本人拥有的研究；
团队角色本身不能代替真实对象团队绑定。租户级研究读取不能扩大本人范围的采集写入、
素材读取或研究写入。没有设计读取权时，研究仍可读取，但关联项目列表和数量为空。

## 写事务与异步边界

服务内部执行权限检查，不只依赖控制器。成员/角色和来源行在所属事务中加共享锁，
要修改的研究索引加更新锁；既有 RLS 和不可变快照保持。
研究结论的幂等重放先校验当前父对象写权限，再读取原回执；不能借旧 requestId 取回无权内容。
本人/团队范围的手动分类只改变选中对象；共享分类别名及其他拥有者的级联修改需要租户范围。

签名读取分为授权预检、生成短期地址、再次授权及审计三个边界。签名期间发生撤权、
拥有者变化或研究归档时，不返回地址；校验对象键和校验值仍与原归档一致。
签名生成期间不持有数据库锁。已签发的地址仍受原 60 秒有效期约束，不能召回已取得的字节。

Worker 在领取、下载检查后/私有存储前、提交归档前复核原申请人权限和来源。
存储期间权限变化阻止关联归档；可能产生的未引用私有对象沿用原引用感知清理要求，
不能按单次失败盲删共享内容地址。租约、扫描、网络边界和三次尝试上限保持。
参见[媒体归档](capture-media-archive.md)与[研究到创意交接](research-creative-handoff.md)。

## 页面初始化

研究表格在客户端事件就绪前禁用选择、分类、详情及归档操作，防止页面已显示但点击丢失。
复用既有 Listing 页初始化方式；不增加固定等待时间。浏览器回归实际延迟脚本，
核对静态阶段禁用、就绪后可操作及归档/恢复结果。
实现依据见 [Playwright hydration](https://playwright.dev/docs/navigations#hydration)；
事务锁语义见 [PostgreSQL row locks](https://www.postgresql.org/docs/current/explicit-locking.html#LOCKING-ROWS)。
