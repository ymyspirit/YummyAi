# 原生角色固定评测

本批扩展 `creative`、`order_review`、`artwork_preflight`、`template_config`、`sku_package`、`after_sales_review`，继续使用原拥有者准备、原生 Assist 执行、预算、方法与费用。知识 v1 和采购／经营 v1 的已发布依据、命令、报告和任务保持。当前为实施规格，尚未计功能验收通过。

## 固定输入与原资源

真实对象搜索和依据读取沿原 task-targets／task-basis，由服务器准备本次输入，客户端不提交 prepared context 或授权资源清单。新角色采用 `role-facts-v1` 规则臂与 `role-benchmark-checks-v1` 检查版本；包含新角色的混合业务集使用这组版本，只有旧采购／经营的集合继续用原业务 v1，知识仍单独成集。

新角色发布时固定完整来源及 `role-benchmark-resources-v1` 资源 ID／父关系／版本，并在 `permissionScopes` 保存原逐权限范围。资源由原服务器封套提取，首条真实业务来源携带其授权元数据，任务指纹和加密依据绑定该集合。历史读取检查这些原资源的当前权限和归属，不查询今天的候选或配方重构旧答案；正文读取不新增写权限要求。执行则重核原角色、动态依赖、方法／知识和 Workflow 权限，不能借用后续扩大的范围。来源上限新角色256条、旧采购经营32条、知识6条；越界明确拒绝，不能裁剪。原业务包的保留期限仍是上限，不能因数据集保留设置延长订单私文寿命。

`teamIds` 另固定当时已核实的团队集合。Worker 的路由消息只有身份，不能因消息未带团队就把合法团队全部丢弃，也不能直接采用后来新增的团队授权；实际读取和执行使用原集合与当前有效成员的交集。模板解析的执行人不是素材拥有者，授权沿其实际源素材及可信印花团队逐项核验。

本人原命令可按原请求 ID 恢复最小回执，继续核原操作者、操作、Workflow 范围及数据库固定的出生领域权限。回执仅含请求／结果 ID、修订、校验值和时间；即使原对象已不可读，也不返回来源或正文。同 ID、同输入重放只返回原回执，不新增任务、预算、派发或模型调用；不同输入冲突，新请求重新过当前原对象门。领域权限本身撤销或原操作者不符时不能恢复。私有版本、尝试正文和费用对象的读取仍独立检查实际原资源。

固定题目、预期、禁止表述及任务中的人工指令／分析重点属于长期不可变评测历史，依据正文到期不会删除这些字段。只允许填写已脱敏评测内容，不自动复制客户原消息、身份信息或附件正文；没有自动检测任意输入中隐私的能力。私有业务包、实际图片及模型输出另按原期限清理。不能将这一机制表述为所有用户填写文字均已物理删除。

新六角色的“当前可用”另核发布时实际引用的知识及方法状态。原知识停用、证据失效或原方法撤回后，停止返回当前可用正文并拒绝新增人审；原封存评分、费用和报告继续作为历史读取。检查读取已认证的原加密依据，不重新检索今天的知识或业务事实；新增人审在最终写事务再核原引用，避免前置读取后撤回仍写入。普通租户共享知识沿原知识拥有者的权限，不新增虚构的作者或团队隔离。

创意远程图片须经原 HTTPS 固定主机、无重定向、大小和像素限制下载并冻结实际分析字节，形成 `dataUrl` 后进入加密依据。预览与发布字节变化须重新核对；候选使用发布时的固定图像，不能再次从同一 URL 取今天的图片。读取失败明确阻止发布，不把 URL 当固定图片。其他角色沿原拥有者取得私有图片并固定实际分析字节；固定预览不等于原尺寸生产文件验收。

## 逐角色门禁

| 角色 | 原资源与当前授权 | 本批边界 |
| --- | --- | --- |
| 原创方向 | 创意项目、研究快照／结论、规格／销售方案实际 owner 与团队 | 竞品仍为研究域；不生成或采用设计 |
| 订单预审 | 原订单／PII tenant 门；原修订及全部已固定候选印花／规格 | 不保存审单、不替人批准 |
| 生产稿预检 | 原订单、编辑器版本、材料／图片及保留状态 | 仅一般预检，拒 `automaticAudit`／`retryAudit`，不计严格生产自动审核 |
| 模板配置 | 原解析记录、授权源资产精确版本及全部槽位 | PSD 结构解析不表示像素审核，不确认模板 |
| SKU 资料包 | 原 Listing 版本、固定配方、规格、印花与实际批准套图 | 不保存、送审、发布 Listing |
| 售后分析 | 实际售后与原订单／PII 门、原保留状态 | 原入口 `en-US`；不发送回复或登记退款、补寄事实 |

Workflow 范围独立保留，不替代领域或对象权限。订单／PII 与采购／经营聚合仍保留原 tenant 硬门，创意、模板与 SKU 按各自真实 owner／可信团队及资产域核验。新权限清单包含实际附带的 ProductRead／AssetRead。资源元数据不是授权，Worker 和返回正文／图片前仍复核当前成员、原 scope 上限、对象与期限。

## 两臂、图像与采用

规则臂只摘录原拥有者事实与缺项，不调用模型、不声称看过图片、不生成伪原创方向。若规则无法满足原生产输出契约，保留硬失败和能力缺口；不能为了得到合格基线造三个创意方向，也不能据此宣称候选模型质量更好。新版本对完整的有界事实分段，超出输出上限明确停止，不能静默省略原字段。

候选仍使用原角色 prompt／工具／Skill／输出 Schema。原生结果校验和评分使用本次实际图像凭据；未读取图像的视觉结论不能被文本出现或模型自述当成已核实。原硬失败、人工复核、全部重试和未知费用继续计入固定分母与原报告，人工通过不能覆盖硬失败。

评测 native marker 在原事务绑定。常规任务、销售方案任务、自动审核去重和实际生产审核的 recent50 查询在 LIMIT 前排除评测任务。评测不能挤掉真实审核记录或成为采用与生产门禁证据；原 SalesPlan 采用拒绝评测记录，纯展示页面没有采用、发送或发布动作。不能以“没有点击采用”替代真实拥有者拒绝及业务事实不变验证。

实际 SKU 来源链需保留制作成品的原授权。制作审批沿真实配方各印花的固定素材继承来源、最早许可期限及 AI 标记，不把派生产物改称新自有素材，也不向套图 Worker 新增任意 `original_design` 白名单。继承范围只覆盖配方印花来源；编辑器额外手工编辑仍依赖原人工审核，不能声称所有像素已自动溯源。既有历史资产不由本批重新标注或补造审批。

标记任务从未完成转为完成时，0170的延迟反向门检查最终任务、同事务评分和审计事件，以及原执行器的响应接收／完成凭据。只有原native出生凭据不能代替完成评分；提前刷新约束后也不能直接终结无评分任务。既有169已完成历史不回填，正文到期清理仍沿原规则。

## 验证与升级

0170仅追加迁移，001—169与真实169旧源保持。统一 disposable runner 运行当前、真正169升级和独立个人浏览器；普通库仍148，普通应用不由本批启动。每类至少包含正常、缺项及实际来源验证，模板走真实解析 Worker、完整 SKU 图片包走实际套图编译／渲染／审核拥有者。模型 HTTP 与隔离 OIDC 为合成，业务拥有者、私有存储、扫描器、预算、Worker 和事务为真实路径。

新角色技术验证不等于图片质量、抱枕制造、工厂接受或无人生产验收。涉及抱枕仍读取原制造版本和 Rule Center 快照；旧任务缺失明确显示，不补今天规则。验后精确删除本批资源、旧源副本、候选、日志、截图、trace和缓存，保留源测试、校验结论与清理记录。

实现继续参考 [Promptfoo 确定性检查](https://www.promptfoo.dev/docs/configuration/expected-outputs/deterministic/) 与 [Langfuse 原应用数据集评测](https://langfuse.com/docs/evaluation/get-started/offline)，复用本项目拥有者和账本，不添加第二套运行平台。
