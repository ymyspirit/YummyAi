# 原发布读取与当前对象访问复核

PRD1.1.105 · B21 · f3c8a2d6 · 49项定向技术验证与本批清理已核对，完整B21未验收

## 当前对象与权限

刊登和店铺当前使用各自真实 `createdBy` 判断对象范围，没有可信团队绑定。企划的 `teamId` 不为刊登或店铺提供读取权；`team` 在缺少对象团队时仍只能按真实本人归属判断。不得凭最大汇总范围让一项 tenant 读取覆盖另一项 self 权限。

`ListingRead` 与 `StoreRead` 分别生效。原发布读取、凭据使用、每次节点HTTP和原结果采用必须复核当前角色、原授权上限、原成员及实际对象。撤销任何读取位，或真实对象移出该位允许的范围，都不能继续采用旧结果。操作人会话的 canonical authority 没有变化，也不代表对象仍在原范围。

## 无正文的读取核验

复用已有 NestJS 的标准 `HEAD` 方法及原拥有者事务，新增：

- HEAD `/v1/marketplace-publications/preview/workspace?listingId=…&listingVersionId=…&accountIds=…`
- HEAD `/v1/marketplace-publications/preview/:id`
- HEAD `/v1/listings/:id`

核验不调用外部提供方、不创建请求或事件，也不返回私有正文。成功为200和 `private, no-store`；当前失权仍为原权限错误。工作区核验中的 `accountIds` 来自本次实际收到的来源与原回执，按小写UUID去重排序，最多120个；空集合仍需要当前 `StoreRead` 和准确刊登版本权限。原请求核验从数据库读取其真实刊登和店铺，不能用调用者替换的ID授予访问。

节点预览的原请求还保持其创建人读取边界：即使同租户另一人具有 tenant 范围的刊登和店铺读取权，其 HEAD 与 GET 也同样返回404。历史读取不借用执行时的代次门禁，不把可读历史错误地要求为可继续执行。

HEAD 使用正常认证、租户RLS和原对象授权，明确注册在相应GET之前。没有新API客户端授权，不把读取核验变成可重用的授权令牌。语义依据：[NestJS HTTP methods](https://docs.nestjs.com/controllers)、[RFC9110 HEAD](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.2)。

## 两端采用边界

个人BFF完整读取并核对原响应后，再通过原API的HEAD核验当前对象；浏览器完整解析响应后，也通过同一BFF的HEAD复核，再采用私有正文。两端继续复核本人会话。HEAD的错误没有JSON正文，仅允许明确的有限身份变化code通过安全响应头返回；普通409或网络失败不得冒充撤权。

预览面板独立要求 `ListingRead` 和 `StoreRead`。原Listing编辑器的个人模式先显示正在核对，真实GET和随后HEAD完成后才展示正文；SSR会话摘要一致不能为延迟响应背书。当前对象403/404拒绝清除旧正文，临时网络失败保持原不可变意图和恢复入口。

SSR完成刊登与店铺资料读取后分别核对对应真实对象。店铺资料失权时隐藏关联店铺资料，并保留仍获准的刊登编辑；不得用虚构空值代替失败事实。原Agent回跳、准确版本、原requestKey、目标、payloadChecksum、不可变历史和节点执行路线保持原拥有者事实。

原Listing页面按实际收到的账户、发布记录、同步及自动化记录收集完整店铺ID，去重排序后每120个串行核验，不截断大集合。某块核验失败时隐藏店铺相关旧快照；没有可信店铺ID的跨站复制记录仍按自身原读取边界处理。预览遇到明确失权时只通知同一刊登重新执行真实GET与HEAD，不用本地事件直接授予访问。

原未知提交的恢复只做GET原回执及HEAD当前访问核验，不再POST，不重做外部HTTP。访问复核证明该次采用前的当前状态；它不宣称浏览器能撤回已经传输的字节或在对象变化尚未观测时永久持有授权。

最后一次成功HEAD之后发生的对象变化，需由下一次相关读取、本地重新核验通知、页面重新显示或现有30秒轮询发现。多个店铺块是各自时点的核验，不构成同一数据库快照或持续授权租约。

## 验收边界

本批定向覆盖两读取位分别撤回的三个真实阶段：首HTTP之前、LWA真实响应之后/PUT之前、PUT真实进入之后/结果采用之前；另核对逐权限范围下真实Listing或店铺创建人变化，且实际成员authority前后相同。真实CLI、mTLS和原拥有者RLS保持，外部提供方由隔离夹具响应，不等于真实店铺发布或模型消费。

前端另验证延迟200的同authority对象归属变化、独立StoreRead拒绝、原键恢复零第二POST和正常个人读取。单元、静态检查、编译个人浏览器与资源清理各自记证，不以静态渲染替代effect或真实页面。日常148继续复用原进程；无新增迁移或普通182采用。完整B21及48需求、54工作包、8阶段仍待完整验收。
