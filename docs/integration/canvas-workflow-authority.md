# POD、画布与创作工作区当前授权

2026-10-19 · PRD 1.1.21 / R01 R08 R13 R18 R20 · B06 B08 B15 B18 B28 的局部实现。完整平台与业务验收继续。

## 当前拥有者

- 项目、批量任务与创意版本按各自 created_by 检查 DesignRead、DesignWrite、DesignReview；素材按 owner_user_id 检查 AssetRead。不同权限不能借用宽范围。
- 这些旧创意对象没有可信团队绑定；team 范围只允许本人拥有的对象。历史空拥有者需要 tenant 范围，不推导当前操作者为拥有者。
- 工作区个人草稿仍按本人隔离。放入某项目的个人草稿同时要求该项目的当前读取/写入范围；未分配空间也复核当前成员。
- 印刷规格以同一 spec_id 最早版本的 created_by 为家族拥有者；后续版本 created_by 继续记录实际编辑人，协作编辑不转移归属。
- 新成员上下文在实际业务事务重新读取成员和角色，与入口上下文取权限交集；显式非成员服务适配器保留其服务器提供的上限。租户 RLS 和非 owner 应用角色保持。

## 来源与关联

参考素材、新批量创建、后续派发、选款与审核分别检查当前 AssetRead、授权域、权属状态及明确授权期限。执行/交付的时间来自数据库时钟。原固定版本及内容校验值改变须重新核对，不静默换图。只读历史保留版本关系，不将历史读取当新的执行批准。

印刷规格复核真实家族归属；SKU 候选需要真实 ProductRead 和现有商品团队范围，无 ProductRead 返回空 SKU 候选。画布目标规格使用商品拥有者的规格访问策略，固定研究来源按其 ResearchRead 范围复核。顾客/竞品来源不转成通用创作权利。

正式创意读取、审核和原生 SKU 交接按 batch → version → asset 顺序取得所需锁。实际创意批准、素材权属批准、操作员审核和生产放行继续分别记录。

## 外部 I/O

文件读写采用短事务授权 → 外部 I/O → 新事务复核。存储或扫描等待不持有成员/项目锁。撤权、范围收窄或原对象变化后不返回原始字节/缩略图，不关联待审结果。

画布参考图、工作区文件/缩略图、生成结果核对实际内容校验值、原对象指针与当前权限。工作区保存和画布提交在 I/O 后再次检查版本、归属和当前素材依据。扫描后、写入前也复核，未经当前权限不能执行后续存储。

若写入私有存储后才撤权或发生并发冲突，数据库不关联该产物；不能盲删可能被其他版本引用的内容对象。引用感知的孤立对象生命周期仍单独建设，不把私有孤立字节当已完成业务产物。

## 版本、幂等与审核

- 新画布与批量请求身份包含申请人，批量身份还包含名称及真实来源/规格版本。
- 对旧 v1 请求只允许原 created_by 在当前授权下复用原记录；其他成员创建独立 v2 请求。不改写旧 checksum、拥有者或历史版本。
- 原画布四结果上限、并发修订、原提交回执、插件兼容重试、唯一下一步和个人草稿复制语义保留。
- 草稿复制检查实际引用素材权限；媒体去重仅限本人可用的 owned/ai_generated 原件，不获得他人素材的权利。
- 工作区素材批准保留实际 licensed/owned/ai_generated 来源及期限，记录本次 approvedAt/approvedBy；不改文件内容版本或补造历史批准。
- 当前只读成员可以恢复其有权读取的素材。创意审核不要求 DesignWrite，但复核 DesignReview 的对象范围。

## 派发与未完成边界

API 每次候选派发前复核当前任务与来源，队列 I/O 在事务外；第一次派发后撤权阻止后续派发。PROCESSING_FAILED 等处理失败不能通过普通重试清掉原证据再调用，返回待核对响应/费用的冲突。

旧 QUEUE_UNAVAILABLE 名称本身不能证明未提交。旧候选/适配处理器还使用旧身份上下文与恢复语义，仍需原意图、当前成员/范围、付费提交、响应检查点、预算与恢复的完整 Harness 迁移。本批没有修改或启用这些 Worker，也不把 API 当前检查当执行时授权。

独立创作生成服务补齐直接入口的当前成员/项目/参考素材检查及结果 I/O 后复核；原模型、参数和预算规则保留。真实提供方、旧后台执行器、可信设计团队、引用感知生命周期及正常部署分别验收。
