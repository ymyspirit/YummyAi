# 中央店铺授权与凭据刷新

本批操作 `d8b7a3c6`，中央授权生命周期修复。它是 B21 的基础切片；每店独立 API 节点、真实店铺采用和完整平台验收继续。

## 契约与数据

复用 PostgreSQL 行锁、Drizzle、原成员权限/RLS、SecretVault 和现有官方 OAuth 网关，不引入第二套授权或任务数据库，也不新增外部依赖版本。实现参考 [OAuth 安全最佳实践](https://www.rfc-editor.org/rfc/rfc9700.html) 和 [PostgreSQL 显式锁](https://www.postgresql.org/docs/current/explicit-locking.html)。

`0178_marketplace_authority.sql` 为账户增加授权代次、凭据使用标识/开始时间、`known/pending/unknown` 刷新状态。OAuth 会话保存发起人的权限上限和代次；能力快照记录所验证的代次。旧会话和旧快照的新字段保留 NULL，升级不把历史事实补写成今日授权证明。旧凭据密文与历史字段保持。

旧账户、OAuth、MCP-v1/v2 和原生 Agent-v1/v2/v3 契约保持。新增只读 `GET /v1/marketplace-accounts/:id/authority` 返回严格 `erp-store-authority-v1`：同一事务的账户、生命周期、逐项权限和当前本人权限摘要。响应不含凭据、密文、请求头或 PKCE verifier。

## 执行边界

所有中央生命周期写入在短事务中锁原账户，使用当前真实成员与发起权限的交集；账户的可信创建者是 self/team 范围内唯一可用的归属，未配置店铺团队绑定时不推测团队归属。网络在事务外执行，返回后重核原代次、使用标识与凭据版本。状态与对应审计在同一事务内提交。

新授权、撤销、停用、删除或授权配置变化会使旧代次失效。OAuth state 一次消费，绑定原发起人、原权限上限、账户和有效期。迟到成功和失败均不得覆盖撤销、停用或新授权。

中央能力同步持久占用同账户的凭据使用标识；已知状态的占用租约为五分钟，可回收后必须更换标识。Etsy 刷新前先持久保存 pending，返回身份正确的 token 后，在后续 shop/taxonomy 请求之前立即加密 checkpoint。即使之后读取失败，新 refresh token 仍在原凭据版本链中。

保密 checkpoint 只允许原代次、使用标识及凭据版本，不把它当业务授权。成员在途失权时，可以保存该请求返回的唯一新凭据；后续请求与能力采用仍须当前权限。撤销、停用或新授权已改变代次时，旧请求连 checkpoint 也不能写入。pending 不明或丢响应转 unknown，不因本地计时到期而重用旧 refresh token；需本人重新授权。

Worker 的四个原凭据读取点增加忙碌、未知刷新和已删除账户门。未迁移的旋转 Etsy 发布、Listing、发货执行在解密与调用提供方之前明确拒绝，返回不可自动重试的 `ETSY_REFRESH_OWNER_REQUIRED`；Amazon 正常闲置凭据路径保留。不能仅凭前置查询门声称全平台 singleflight：全部请求序列、刷新 checkpoint 和原意图代次绑定仍需后续迁移后才能开放相应 Etsy 执行。已经发出的提供方请求也不能由本地撤销保证取消。

本地忙碌或未知状态返回不可重试的 conflict，不累计为提供方鉴权失败。真实提供方鉴权失败必须带调用前捕获的原授权代次、凭据 ID 和版本；只有当前账户仍 active、known、idle 且三者完全相同，才允许在原事务中撤销并审计。迟到的 401 不能撤销替换后的授权，缺少原调用凭据证明也不能修改当前账户。

## 前端与恢复

单店详情读取同刻 authority 工作区，不用新摘要给旧 SSR 账户数据背书。动作使用统一操作状态；撤销、停用、账户或本人变化废弃旧响应，清理秘密输入。忙碌或结果未知时仅读取状态，不自动重发授权交换/同步。OAuth 按 state 独立关联账户与本人，避免跨店标签互相覆盖；回调只接受严格参数及对应本人。

每次发起 OAuth 后，前端先核对当前代次及只向原发起人提供的 `pendingOAuthStateDigest`，与返回 URL 的 state 摘要一致才设置独立 HttpOnly cookie 和跳转。单凭更新后的代次不能给旧 URL 背书。生命周期动作使用独立状态类型，旧发布动作正文和 DTO 保持。原通用店铺元数据表单尚未逐项迁移至新动作包装，不能据此声称整个 ERP 页面写入已统一。

本地撤销只表达本地凭据失效，不宣称提供方已注销 token。每店节点登记、绑定、心跳、mTLS、离线恢复及中心不回退直连仍按[系统架构](../erp-blueprint/03-system-architecture.md)继续建设。
