# 商品编辑、草稿与当前访问范围

本规范对应 R01/R03/R07/R37 与 B06/B07。复用 React、现有 TaskDrawer、共享授权和原生商品服务；未引入新的表单库或状态框架。参考 [React 状态保留与重置](https://react.dev/learn/preserving-and-resetting-state) 与 [shadcn/ui 开源组件](https://github.com/shadcn-ui/ui)，实际继续使用本仓的 ERP 组件及 Lucide。

## 直达入口与实际对象

商品库使用 SPU/规格所属企划的当前 owner/team；印花库独立检查母版的商品写入与设计审核范围。公司读取权限不扩大仅本人或团队写入。规格版本与 URL 中的 SPU 不匹配、来源版本缺失或印花已归档时，显示不可编辑原因，不退化成新建表单。

个人登录回跳保留选中的 sku、spu、artwork、artworkVersionId、specificationVersionId 与明确的 form/compose/editSpu/archived 标记。重复参数、无效标记、自由文本及外部/认证地址仍被排除。链接只表示页面意图，不能授予访问权。

options 返回服务器计算的 contextAuthority；与当前运营会话比较时，共用普通 ERP 权限投影，排除独立工厂入口权限和未注册权限。字段只用于隔离界面状态，实际命令仍在所属事务内重新加载当前身份并检查对象。

## 输入依据与草稿

编辑器固定打开时的 SPU revision、规格/印花版本及字段初值。后台刷新用于复核当前范围和来源，不自动更换乐观并发依据；原记录被修改后保存返回冲突，保留草稿供人工核对。关闭并重新打开后再采用当前版本。

短期草稿只在当前应用标签页内保存，按租户、本人、权限摘要、对象及字段分隔，沿用两小时和 120 项上限。切换对象立即读取新对象的缓存或初值，前一对象的异步 setter 不能写进新对象。批量规格的缓存另外包含所依据的规格版本集合，防止重新打开时把旧草稿当作新的版本依据。

对象归属变化或失去读取/编辑范围时，清除相应缓存及编辑器；不清除无关对象草稿。组合中的部分规格或来源失效时阻止提交，要求明确清除失效选择或重新选择，不静默生成一个缩小后的 SKU 集合。

单规格的工艺底稿、印刷规格和空白品物料使用受控选择。关联条目停用或从当前可用列表消失时，保留明确的失效占位并阻止保存；操作者选择新项或明确清除后才继续，不能由浏览器自动回落为空值。生产仍使用已固定版本和原就绪检查。

## 当前检查与迟到响应

详情或编辑打开时，每 30 秒及页面重新聚焦/可见时读取 options。请求被替代或页面离开后，旧成功响应不能恢复先前资料。

临时网络错误隐藏并禁用编辑正文和通过 portal 展示的提交按钮，保留仍未被确认撤权的输入；读取恢复后恢复原草稿。401/403/404 或明确范围丢失清除相应内容。当前身份与快照不一致时保持不可操作，不猜测权限。

保存关联发起时的视图身份。A 的请求完成后如已转到 B，仅刷新可读列表，不关闭 B、不替换其输入、不显示 A 的保存错误。原 A 的实际业务保存不会被伪装成撤销。请求超时须核对服务器记录，同一内容的显式重试保留原幂等键。

## 来源 ID 与服务端边界

registerArtwork 在读取幂等结果前，除目标母版外，核对选中的研究、创意版本及实际主文件/附加素材。研究使用 research:read 的拥有者范围，创意使用 design:read，素材使用 asset:read 及既有的明确团队共享关联。手工填写同租户 ID 不绕过范围；重放成功命令仍检查当前来源读取权限。

使用原应用角色、withTenant 和强制 RLS。可变拥有者与实际素材记录在事务内受锁保护；不可变创意素材关联沿用不可变约束，不为读取增加更新权限。授权素材、版权、扫描、版本和原业务审核门禁继续由原服务验证。

## 验证与部署

专项浏览器使用个人 OIDC/PKCE、原 API/BFF、隔离数据库/私有桶/Redis；身份是合成夹具，不代表真实 IdP 或业务试点。入口：

~~~powershell
pnpm test:e2e:order-daily --suite=catalog-scope-integration
pnpm test:e2e:order-daily --suite=catalog-editor
pnpm test:e2e:order-daily --suite=catalog-editor --compiled-web
~~~

缺省浏览器为独立开发快照；compiled-web 使用当前真实构建并记录 BUILD_ID。测试输出可用 Playwright 的绝对 --output 参数隔离，避免覆盖前一轮待检查材料。资源须在成功和失败后清理并独立核验，本地临时文件遵循交付约定。

本批不新增数据库迁移、运行密钥或外部依赖，仍依赖 [团队与商品范围](catalog-scope.md) 的 0126 及既有完整迁移。普通库未由本批测试迁移。其他业务编辑器、异步执行、正式部署、CI、备份恢复和完整 B06/B07 的业务验收继续分别推进。
