# 原生素材上传与私有签名授权

2026-10-19 · PRD 1.1.19 · R01/R05/R18，B06/B08/B13；完整平台验收继续。

## 范围与复用

本批核验 `POST /v1/assets` 与 `POST /v1/assets/:id/read-url`，以及它们的幂等返回、
私有存储 I/O 和审计后的结果交付。核对开源 [CASL 的对象条件授权](https://github.com/stalniy/casl)
与 [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) 后，
复用已有 authz、当前成员读取、order-core 和非 owner 租户事务，不增加另一套授权引擎。
没有新增依赖、路由、环境变量或迁移。

## 当前权限和对象范围

`currentAssetAuthority` 在所属租户事务中复核当前成员，将原请求权限上限与当前授权
逐权限交集。权限后来扩大不能扩大原请求，其他权限的 tenant 范围不能扩大素材权限。
显式非成员服务凭据保留服务端提供的上限，不将这些适配器误作个人登录验收。

`asset_files.owner_user_id` 是现有可信上传者。self/team 素材权限可访问本人文件，
没有可信团队绑定的素材不能仅凭 team 授权暴露给其他成员。旧文件缺上传者时仍须
该素材权限自身为 tenant 范围，不回填历史归属。

订单域文件还需 order:read 与 order:pii:read 各自当前 tenant 范围；上传者身份不代表
订单私有读取权。订单尚无可信个人/团队归属，继续沿用原订单门禁，不能由素材绑定绕过。

## 上传、去重与签名

上传在存储前检查当前写入权限，存储完成后在素材关联事务中重新检查。
已有内容地址的返回也检查原素材拥有者与当前写入范围；归档素材不能通过同内容上传复活。
同一上传者合法重试保留原 ID、原元数据和已有内容去重行为。

签名之前检查当前读取权、对象拥有者、软删除和订单私有权限。私有签名和审计 I/O
结束后再次检查当前权限及实际文件内容标识，再返回 URL；上传审计后也复核回执读取。
成员授权与最终素材记录分别使用事务内共享锁，外部存储操作不持有这些数据库锁。

已经写入的私有对象、已提交的素材和审计不能被假装回滚。存储途中撤权不创建素材关联，
未引用对象仍需引用感知清理；审计后撤权不返回旧资料，但保留已合法提交的事实。
不得删除其他不可变版本可能共用的内容地址。

已有 URL 合同保持最长 600 秒。当前检查能阻止新的签发/交付，不能召回已经交付的 URL
或已经下载的字节；需要即时撤销读取时仍须另行评估受权流式读取或其他下载策略。

## 实际验证与剩余项

最终 23 项隔离集成包含原有八项和新增 15 项，使用真实成员/角色、非 owner RLS、
MinIO 私有对象及实际签名下载；合成内容不涉及真实订单或买家。
初始红轮 12 失败/9 通过：11 项实际返回了不应返回的 URL 或素材元数据，另有一项
缺订单私有权限已被底层存储拒绝，但未在调用前拒绝。保留这一区别，不将其说成 URL 泄露。
API 318 单元、最终 API 类型和全仓 lint 通过。没有修改 Web 或声明新增浏览器验收。

本契约不证明 DesignService、画布/创作工作台、生产编辑器、财务和履约等其他拥有者
已完成相同授权核验；可信团队绑定、正常个人会话、正式部署、CI 与完整业务试点继续。
