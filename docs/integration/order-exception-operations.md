# 原订单异常的登记、实际处理与角色准入

2026-10-16 · R36 / B26。实现沿用原 `OrderService`、`order_exceptions`、
`order_exception_events` 与 `order_events`，没有新增异常事实表、迁移或权限。
责任安排继续由 [业务跟进旁表](business-followups.md) 管理，不代替实际处理。

## 操作者与入口

整单详情的「本单异常」可登记问题、查看原说明及解决依据；业务任务的「订单异常」
定位到具体异常，使用同一个表单，可返回原订单再返回原筛选。分页、状态筛选及完整
筛选计数在同一个只读快照内读取；缺失历史事件明确标记，不能伪造或补写解决依据。

| 能力 | 当前租户范围所需权限 |
| --- | --- |
| 查看异常、原事件历史 | `order:read` + `order:pii:read` |
| 登记问题、记录实际解决 | 以上 + `order:write` |
| 修改跟进责任与内部时限 | 查看权限 + `order:assign`；需要已启用业务跟进 |
| 接收跟进通知 | 相应对象查看权限 + `notification:read` |

权限取当前有效成员与角色，并与本次调用上下文相交；不接受调用者指定租户或扩大
范围。写入锁定当前授权后再取得原订单锁。负责人必须当前具备处理及通知权限；
非法分配被拒绝，已分配后撤销处理权也不能继续处理。分配给自己不增加 `order:write`；实际
处理和责任安排是两种不同操作。正式启用先评审角色，不通过给全权限规避准入。

## 拥有者接口与兼容变化

- `GET /v1/orders/:id/exception-operations`：读取当前处理依据；仅接受
  `status=open|resolved|all`、`page`、`pageSize`（最多 100）、`exceptionId`。
  返回当前父事件序号、来源校验值、逐异常最新序号/校验值及当前可操作性。
- `POST /v1/orders/:id/exceptions`：原登记端点，提交类别、问题代码、说明和请求编号，
  另须固定 `expectedOrderSequence` 与 `expectedSourceChecksum`。
- `POST /v1/orders/:id/exceptions/:exceptionId/resolve`：原解决端点，提交实际处理依据
  和请求编号，另须固定 `expectedSequence` 与 `expectedSourceChecksum`。
- 原 `GET .../:id/exceptions` 保留数组返回；原异常队列、该数组及 `GET .../:id/events`
  同样检查当前查看权限与资料有效期。事件历史也含异常说明，不能绕过隐私门禁。

以上是公共 HTTP 契约的收紧：旧客户端缺少固定依据时返回输入错误，不能继续发送
旧命令。可信域内自动登记仍复用原拥有者方法，不模拟交互角色或制造审核快照。

登记或解决在同一租户事务追加不可变异常事件、父订单事件和审计，并推进父事件序号。
同一请求编号绑定对象、动作、内容及固定依据；相同有效重试返回原结果，变更内容、
跨异常或跨动作使用返回 409。先检查当前授权/资料，再识别幂等重试；已提交的合法
相同请求不因其自身推进序号而被当作新冲突。新操作的陈旧依据或竞争解决返回 409。
审计失败与业务写入一起回滚。

「已解决」只记录这条异常的实际处理结论，不自动解除订单挂起、改变履约阶段、退款、
发消息、安排生产或实际发货；这些操作仍走原模块的真实业务门禁。

## Web、隐私与不确定结果

`/api/order-exceptions` BFF 只代理上述固定处理路径；拒绝重复/未知查询参数、跨源及
非 JSON 写入、超出 8 KiB 的请求和无效 UTF-8，校验成功响应，不自动重放写入。
读取和失败响应均为 private/no-store。网络中断提示先读取实际记录，手工重试沿用
原请求编号和内容，不生成另一次解决事件。

表单固定打开时的依据；409 保留填写并显示变化，操作者明确放弃后再载入新依据。
未保存或提交中阻止切换其他业务动作；后台每 30 秒及窗口重新聚焦检查当前状态。
仅撤销处理权限时保留填写并禁用保存；查看权限、对象可见性或资料有效期失效时清除
保护说明与草稿。后端每次执行仍重查，不以页面轮询代替权限检查。

共享的订单资料可用性 SQL 同时服务处理入口与跟进投影，检查订单匿名化、保护资料
到期、相关制作资料密钥/到期，以及关联 Amazon 报表行到期。无正文解密或隐私复制。
缺少有效来源返回 410，不能借查看事件历史继续读取。正常数据库尚未因开发验收迁移。
