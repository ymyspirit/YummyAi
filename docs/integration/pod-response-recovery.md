# POD 原响应与产物恢复

2026-10-16 · R20/R39 · B09/B28。复用 PostgreSQL、BullMQ 和原 POD 拥有者，参照
[BullMQ 幂等作业](https://docs.bullmq.io/patterns/idempotent-jobs)。不新增预算账本或生产批准。

## 持久意图与原调用

迁移 0119 仅为随后新建的 pod_artwork_tasks 同事务创建 pod_artwork_executions。
旧任务不补造提交、响应或恢复能力。最初 Redis 发送失败保留原 queued 任务及派发
待办；每分钟的标准 Worker 调度器从原记录补发。队列只包含原任务/租户/操作者 ID；
派发失败回收节流标记，不另建业务任务。

领取、持有、续租、恢复到期和派发节流均用数据库时间。进程时钟超前或重复交付
不能抢占活跃租约；旧 token 不能提交、采用产物或把新拥有者写成失败。最多三次本地
处理共用原调用，不能视作付费次数。队列重试不授予付费重试权限。输入摘要固定
原工具、参数、素材版本、校验值与授权来源。

## 原响应先保存

迁移 0121 为新原任务固定原生执行契约和发布方法引用，并纳入原输入指纹；历史任务
保持缺失，不自动补填。workflow 委派在节点激活时固定独立的父/子方法，Worker 在提交
与采用前分别核对当前权限、撤回代次及知识来源。方法或来源撤回期间仍保存已发生的
原响应和计价回执；可以恢复的旧响应沿用原引用，不因发布新版重调。详见
[执行方法治理](execution-methods.md)。

迁移 0122 在原执行记录内增加不可变交接凭据，与实际文件及待审核版本在同一事务
保存；恢复使用原响应和费用完成交接，旧终态缺失不补造。当前处理器共享原 v1
响应 Schema，新方法输出独立于界面 DTO，原代码 v1 采用明确兼容校验。完整字段、
当前授权下载与迁移要求见 [产物交接契约](pod-completion.md)。

正式环境必须设置独立的 32 字节 base64url POD_EXECUTION_ENCRYPTION_KEY；本地
开发沿用 LOCAL_OIDC_CLIENT_SECRET 的独立 pod-execution-v1 域派生。提交边界之前
先确认密钥可用，不能用模型、订单 PII 或集成密钥代替。Turbo 已透传新变量。

HTTP 网关有四分钟中止期限、72 MiB 流式原响应上限及最多 50 MiB 的累计解码产物
上限；POD_PROCESSOR_MAX_OUTPUT_BYTES 可降低累计上限。正文读取后先记录原计价
回执和 AES-GCM 加密检查点，再解析产物。HTTP 检查点保留原正文、状态和部署标识；
其他网关保存返回的结构化结果，不能称作原 HTTP 字节。原工具质量检查继续执行。

检查点位于私有 quarantine 域，没有资产条目或公开下载入口。数据库先固定准确
对象键和加密校验值，再上传对象。上传成功但回执丢失时恢复读取该位置；核验加密
校验值、认证解密、原租户/任务/输入身份和回执。丢失或损坏的检查点不会触发模型
重调。已提交但没有可恢复检查点的请求停止为 POD_RESULT_UNCERTAIN。

## 产物与当前授权

采用前再查当前成员、产品范围、输入授权和原工作流状态。先固定至多一百项产物
位置及校验值，再上传，回读实际大小与 SHA-256；重试复用相同位置。最终业务事务
再次检查权限与租约，才创建一个 pending_review 设计版本、来源关系和原调用完成
回执。新产物的权利状态仍为 unverified；人工审核、工厂接受和生产放行分别执行。

已有原响应时恢复不准备新网关，也不要求原付费接口凭据仍在环境中。标准 POD
Worker 常驻处理本地恢复，只有新提交准备阶段才读取当前接口配置。工作流暂停时
不进入网关或采用结果；有检查点的本地步骤延后恢复。当前权限或依据失效会停止
采用，原响应及已知费用保留，不据此授予业务权限。

原任务 invocations 显示派发和本地处理次数、原报告费用及设计版本。未提交的新
任务显示 not_submitted；读取不暴露响应键、加密正文或图片字节。原金额和人工
补证仍附着同一 invocation，不重复结算财务账。

## 保留与清理

原响应保留七天；到期停止未结束的本地恢复并删除准确对象。按固定产物清单清理
没有 asset_files 引用的临时输出，保留已入库产物。不可变关系、摘要和清理时间
继续保存。删除仅允许原任务专属命名空间，重复清理幂等。维护使用租户 RLS；内部
租户选择器只缩小枚举范围，不授予任务权限。

## 验证和部署

隔离专项：pnpm test:e2e:order-daily --suite=pod-response-integration，包含原 POD 与
工作流集成。真实 Redis/Worker 和 S3 字节参与；模型 HTTP 为合成传输。并发验收
使用独立队列名和限定租户，避免消费其他测试的任务。
专项还启动独立进程的实际 POD Worker，在 S3 上传后、业务提交前终止进程，再由
另一进程恢复同一响应、产物与费用；本地 HTTP 服务只收到一次模型请求。该探针
不是包含所有队列和定时器的完整 run.ts 部署演练。

普通业务库不随测试迁移。正式启用前需备份、应用 0119、配置独立密钥并一起升级
API/Worker；保留旧密钥至相关七天检查点清理完毕。完整 Worker 的实际进程杀死与
部署恢复、真实服务/费用和人工业务验收仍独立留证。本地故障注入通过不代表所有
执行模块或真实生产已经完成。
