## 正常流程

审核正式JPG及固定制造说明 → 创建并下载交付包 → 实际上传工厂ERP → 记录提交成功凭据 → 默认已排产 → 导入工厂Excel/CSV → 工厂已发货。

工厂ERP只有“已排产”和“已发货”。提交成功后默认工厂会生产，不要求工厂逐次登记收到、接受、开工、四桶数量或完工。创建包、下载文件、生成正式稿仍属于本地准备，不是提交成功。已有submitted原回执为默认排产的依据；界面标明“按提交默认”，不会据此补写工厂的开工时刻或实物数量。旧收到、接受、拒收及返工历史保留为可选证据。

内部生产、质检、产能、物流和工厂外部状态使用各自事实。默认排产继续保守占用原预约，不生成假的产能开工承诺或释放。工厂表中的“已发货”可作为工厂状态，但承运揽收、实物质检、实际发货数量、平台回传仍按其真实凭据处理；缺失的字段保持未知。收到异常通知后明确处置，不由旧表自动撤销已经发生的发货。

## Excel/CSV接入契约

上传后先预览，再确认应用。原文件按实际字节计算SHA256，经扫描保存到租户私有存储；记录原文件名、格式、字节数、上传者、上传时间、工作表和保留期限。原字节、原始列值及原始状态不能被规范化结果覆盖。不能把规范BOM或换行后的文本校验值说成原文件字节校验值。

首次模板固定为`pillow-erp-2026-10-21-v1`，第1行必须完整包含上述13列表头，允许调整列顺序。工作表名可明确指定；CSV固定选择UTF-8或GB18030以及逗号、制表符或分号。工厂时间保留无时区原值。已审核映射scheduled，已出库映射shipped，已作废记录voided_requires_review；未知值单列诊断，不能默认为成功。

复用仓库已有开源JSZip和fast-xml-parser，无新增依赖或锁文件变化。单文件最多5MiB、5000条数据行；XLSX限制ZIP目录、膨胀字节、XML大小、深度和节点，不截断后伪称完整。拒绝公式、实际宏或主动内容、外部关系、DTD/ENTITY、损坏CRC、重复或越界ZIP路径。按实际OOXML部件核验有效类型，不把未使用的导出模板声明当成真实宏。标识字符串和前导零原样保留，危险数字精度、可能改变身份的格式和标识首尾空白要求人工处理。

匹配优先用同工厂的唯一外部工厂单号或条码，显式绑定本系统原生产单、生产版本及交付文件。保留字符串和前导零。平台订单号、商品SKU或文件名只能辅助筛选；多商品、相同SKU、补做或旧版本出现歧义时，列为待核对，不能自动选最新单。未匹配、歧义、格式错误行隔离显示，合计数量与原导入行数可核对。

预览完整分页显示13列原值、原行号、诊断和原绑定。候选限定该工厂已经实际提交、来源有效的原交付项，明确显示订单、原生产版本、文件及制造checksum和固定数量；只有整组数量总和等于原行商品总数且操作者核对后才能应用。已有外部编号只能复用其原完整绑定，不自动换单、补项或取最新版本。分页中的无合格候选扫描页仍可继续前翻，不把它解释为没有历史候选。

确认固定原文件checksum、模板和预览checksum、原数组顺序、本人和幂等键。应用前重读并验证私有原字节、当前权限、同工厂和原版本；绑定、观察、逐行决定、结果和审计同事务提交。SQL独立核验来源声明、原数量及状态，成功审计封闭该应用，不能先强制检查后追加未申请的观察。记录导入顺序与工厂原时间文本，导入时间不冒充工厂实际操作时间。

同一原键、原本人和完整原请求恢复同一个已保存结果；改文件名、请求体或操作者不能借原键覆盖。换新键上传相同文件可保留新来源，跨导出重复行保留来源但不重复新增同一观察。状态只沿已排产→已发货前进，重导旧已审核不能倒退；已作废进入独立异常，不自动取消、解绑或释放。缺少发货数量时shippedQuantity始终为null，不默认原生产数量，运单变化不猜成重新发货。

应用失联后，浏览器只在当前身份与工厂范围保存最小原确认意图：导入ID、行号、原版本/文件hash及原键。刷新后由本人明确重试原意图，成功回执需明确确认；不自动重放写操作。原文件字节、base64、原单元格、姓名及地址不进入浏览器持久存储。换身份或撤权清除私有预览和旧恢复上下文。

需要更正、解绑或重绑时必须追加明确更正流程，不能改写原表或观察。[解除与更正契约](factory-erp-binding-corrections.md)已实现不可变事件、当前修订/观察核对和整组应用；普通环境尚未采用，实际状态见[更正进度](../project-control/FACTORY_ERP_BINDING_PROGRESS_20261021.md)。未经明确核对的冲突仍保持人工异常。

## 权限、私有来源与保留

五个写权限为OrderRead、OrderWrite、OrderPiiRead、DesignRead、AssetRead，读操作使用除OrderWrite以外的四个；每个权限均要求当前有效成员的tenant范围，并与本次请求上限取交集。扫描、存储及读取I/O前后分别复核，外部I/O不持有业务事务锁。原交付API的旧非成员适配凭据继续原包及原键回放，但不取得新的factoryErp私有投影；新导入接口始终要求真实当前成员。

原文件先经真实ClamAV扫描，再以订单PII专用密钥域加密存到私有order前缀，原字节SHA与密文SHA分别保存，不发签名直链。失败补偿只允许精确删除本次新上传且已确认无数据库引用的对象；不确定提交结果时保留对象。六张新表强制租户RLS、非owner应用角色和不可变访问；历史工厂观察不回填。

来源访问期固定30天，到期隐藏原单元格、外部单号和物流原值，已验证的非私有状态及来源ID可继续展示；独立加密证明把状态绑定原来源、原预览和逐行hash。1.1.78新增三处私有副本定向清文及S3全部版本清理任务，访问到期与清理完成分开显示，见[生命周期契约](factory-erp-source-retention.md)。普通环境尚未采用。
