当前为受控本地采用增量 最终11套1514项集成及同构建4项来料采购库存、12项生产浏览器通过 含真实API提交前后中断和独立隐私维护 第六份真实业务配对备份、独立恢复及成功145演练后 已协调采用API、个人Web和两项独立维护 普通业务队列保持停止 不代表阶段、正式发布或工厂验收通过

## 业务拥有者

到货只记录实际保管 采用人工发布的实际标准记录测量与抽样数量 另行保存核准决定 最后确认本次接受与拒收处置 接受部分须确认商家实际接收并拥有 才由采购与库存拥有者同笔入账 拒收保管不增加可用库存 实际交接退回另行登记

标准、到货、检验修订、核准、入账及退回均追加不可变事实 检验保存原标准版本 缺测量或无效值不能通过 接受数量大于零时测量必须全部符合 不支持自动特采 复检只处理尚未处置的数量 原检验与已入账部分保持

库存数量和数值测量都使用十进制精确比较 数量最多九位小数 件、双、套保持整数 供应商原批号保留中文和大小写 不以内部库存分段号替代原批号 采购和供应商发票仍使用原有整单位与货币最小单位契约 无法精确表达的发票金额明确停止 不自动舍入

当前标准发布和检验核准分别检查采购核准权限 到货、检验、入账和退回检查采购写入权限 入账还检查库存写入权限 所有动作核对当前成员、每项权限的真实对象范围及原授权上限 当前未强制检验人与核准人为两名不同人员 不能把分别点击两项操作描述为已经实行双人复核

## 原提交

六类动作先保存加密原填写 再核对并执行 命令关联原物料、采购或到货明细 实际退回同时关联原拒收处置 每位操作者在同类动作和同一原对象下至多有一笔未确认原提交 先核对、取消或确认结果 再开始下一笔

执行正文只能是空对象 不能重新上传另一份输入 业务事实、库存、最小结果引用和审计共用租户非拥有者事务 不使用嵌套保存点来执行收货原请求凭据 提交前中断会整笔回滚 提交后响应丢失可以读取同一命令的实际结果 不因超时自动生成新请求

版本或数量变化保留原输入 执行时重新检查 缺少解密配置、无法解密或校验不一致会阻止执行 并保留原加密副本至人工取消或到期 恢复正确配置后仍能读取并执行原填写 不从当前页面猜补输入 取消只取消尚未执行的准备 不能撤销已真实完成的业务操作

原提交读取仍逐一核对当前物料与库位范围 包括旧采购版本中的原物料、原保管库位及原拒收库位 原权限快照不能授权新工作 无当前读取权时不返回原填写 界面清除私有输入并拒绝已失效的在途响应 临时网络失败或普通版本变化保留草稿

## API 与个人页面

API统一在 `/v1/procurement/incoming` 下

- `GET orders/:purchaseOrderId` 读取当前采购依据、授权选项和最近到货记录
- `GET orders/:purchaseOrderId/commands?before=...` 分页恢复本人未确认原提交 包括较早到货明细
- `GET lines/:arrivalLineId` 按原明细读取检验与处置记录及当前身份指纹
- `POST commands` 保存六类严格契约原填写
- `GET commands?kind=...&targetId=...` 读取本人同类同对象的未确认命令
- `GET commands/:commandId` 读取本人原填写、当前阻塞原因与实际结果
- `POST commands/:commandId/execute`、`cancel`、`acknowledge` 正文仅 `{}`

Web只通过个人身份BFF `/api/incoming/...` 调用这些接口 写入要求同源JSON并限制正文大小 不接受调用者指定租户、不代理任意路径或转发调用者认证头 返回记录必须与原命令、原对象及个人身份一致 原填写不写入浏览器持久存储

API正文 路径及查询参数校验失败返回400 不显示原私有输入或内部校验栈 服务内部业务冲突仍按实际错误处理 业务事务已完成后的刷新独立于写入占用 用户可在慢读取期间关闭页面 在途读取不能恢复已关闭或失权页面的私有状态

采购行入口为来料检验与入账 页面包含标准、实际到货、检验、核准、入账、实际退回及原提交核对 提交未确认时固定原正文 先重新读取原记录再继续 核对成功结果后可清除填写副本 业务历史继续保存

当前到货工作区显示最近50批 未确认命令按50笔分页恢复 较早命令可按原明细重新读取 标准最多500条、单明细检验和处置及退回各最多2000条 超限有明确诊断 全部历史浏览的进一步分页仍是未完成项 不以有界视图冒充全历史验收

## 配置与留存

API生产环境必须设置独立 `INCOMING_COMMAND_ENCRYPTION_KEY` 为32字节的base64url编码 不复用订单隐私、店铺、模型或API Client/Webhook密钥 保持原密钥并纳入安全的恢复流程 本地开发延用已确认的本地身份密钥派生方式 使用独立域 不修改原账号或会话密钥

数据库时间固定七天副本期限 到期停止尚未执行的准备 并物理清除加密填写 已成功的事实与最小结果引用保留 操作者确认结果也会清除不再需要的副本

独立隐私进程为 `pnpm start:local:incoming-retention` 每60秒按租户RLS、空业务权限和最多100条的批次清理 使用跳过锁定记录 失败报告延后并在后续周期重试 关闭等待当前批次结束 本地入口固定零消费者及仅来料清理调度器 即使继承 `all` 也不能扩展 普通备料清理入口仍只负责原备料能力

隔离验证已观察受控权限故障及随后两个真实周期 100条和1条到期副本分别清除 锁定记录被跳过 未到期副本保持 重启仍为零消费者 同一隔离业务队列哨兵保持等待 普通本地现已另行采用独立来料维护 并观察就绪及两次实际零清除成功批次 生产部署、密钥恢复及真实业务试点继续
