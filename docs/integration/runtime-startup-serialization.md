# 日用与容器维护串行契约

PRD1.1.122，关联R41、B09/B51/B52。此文档是实施和验收条件，不是已通过结果。

复用Node.js 24.17开源运行时及项目现有操作系统锁；不增加锁库、数据库迁移、付费调用或普通Worker。Windows使用同一根目录派生的命名管道，管道随持有进程退出释放；语义见[固定版本官方文档](https://nodejs.org/download/release/v24.17.0/docs/api/net.html#ipc-support)。该机制不证明已提交的外部Docker工作已经终止。

## 目标与拥有者

同一工作区内，daily:start、受管理的docker:up/基础设施启动、Studio start/adopt/recover和镜像配置维护采用同一协调门。日用在读取并确定绑定前获得门，覆盖Studio副作用、readiness、API/Web启动、身份核验、状态提交及失败清理。源码构建和镜像候选准备不替换当前运行版本；日用status和镜像/Studio状态检查保持只读，允许采用流程持锁读取。

已有命名管道acquireStartupGate入口兼容；嵌套函数仅能显式借用本进程、同根目录、尚未关闭的真实gate对象。不能用布尔值、路径、环境变量、CLI参数或序列化token跳过协调，借用者不释放拥有者的锁。单独CLI必须自行获得门，避免adopt和recover同时操作同一个transition。

日用成功并稳定后先释放门，再等待本次新子进程的常驻生命周期。启动过程失败或中断先停止并确认仅本次新子进程退出，再释放；清理超时仍等待真实退出，不能凭超时就放行。从原状态复用的服务永不加入清理列表。部分启动失败不允许先放锁再杀进程。未知监听者、不健康身份、来源/配对变化和未完成transition保持拒绝，不自动接管或回滚业务数据库。健康画布与API/Web直接复用，不为状态检查或重复start执行Compose up、创建应用或写运行状态。

协调仅约束这些受支持入口。手工Docker命令、外部编辑及进程退出后仍在执行的Docker操作不能仅凭管道空闲视为已完成；必须核对原transition、固定pin和现场身份。不改写旧采用receipt，不自动把188业务库恢复到187。
