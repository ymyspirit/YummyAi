# 订单定制摘要的可用状态

版本 summary-availability-v1 · PRD 1.1.115 · 状态 局部定向技术验收通过 日用185已应用 全平台继续推进

订单中心不能把已按保留规则清理的历史资料显示为可通过重试恢复的网络失败。沿现有 `POST /v1/order-centers/summaries` 及个人 BFF，原订单、工作项、导入报告仍是唯一来源，不增加事实表、数据库迁移、外部依赖或生产环境变量。

`OrderWorkSummary.availability` 为 available、cleared、expired、archived、failed。由原拥有者的当前匿名化状态、归档、密钥和保留截止判定；没有工作项的合法报告或正式订单不能仅因缺工作项而判作已清理。较旧响应缺少该字段时保留 wire 兼容，但界面显示状态待核对，不推定可读或可制作。

available 仍受原权限、版本、商品和制作检查约束，不代表已审单或已生产。其余状态只保留有权读取的标识和固定原因，私文字段、指示、图片、报告版本、产品规格、执行器及制作阻断列表均清空。旧 error 字段保留兼容的非空原因，避免其他原调用方把不可读资料误当成功。

原报告逐项读取失败不能吞掉同页其他健康商品。不可读来源不解密、不解析目录或补派生制作稿；当前来源在取私文前和最终返回前重查，不能把第一阶段取出的旧工作项密钥或旧报告内容用于晚清理后的响应。保留租户 forced RLS、当前成员和对象范围，读取不恢复密钥、不回填历史。

界面沿现有密集订单列表、Lucide 图标及动画：已清理、已到期、已归档用明确的中性提示；真正读取失败给出重试；缺摘要仍显示加载或状态待核对。不可用内容不显示图片和私文，不给出重新生成或编辑原私人资料的误导入口。订单历史和允许的公开进度仍可查看，不把“已清理”当作从未存在或制造取消事实。

参考开源 [shadcn/ui Empty](https://ui.shadcn.com/docs/components/base/empty) 的标题、原因、可执行动作分离方式，复用项目既有组件，不新增 UI 框架。
