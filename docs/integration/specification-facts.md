# 产品规格事实与确认版本

本模块复用现有商品、Zod 契约、租户事务和不可变规格版本。新表单使用事实格式 V2；旧版本、原请求结果、旧订单和封存包继续保留。

## 事实与未知草稿

V2 保存材质、结构、尺寸口径、实际测量值和单位、商品重量、含包装重量、包装内容、每份件数、包装外尺寸及人工核验依据。重量固定用克；尺寸明确选择 mm、cm 或 in，不从名称、变体文字、知识片段或旧自由文本推断数值。

| 尺寸口径 | 必要测量值 | 不适用轴 |
| --- | --- | --- |
| 成品外轮廓 平面尺寸 | 长、宽 | 高须为空 |
| 成品外轮廓 长宽高 | 长、宽、高 | 无 |
| 图案主体最长边 | 最长边 | 宽、高须为空 |
| 裁片平铺尺寸 | 长、宽 | 高须为空 |
| 成品直径 | 直径 | 宽、高须为空 |

未知值保持空文本或 null。新建规格不默认每份件数为1，也不从尺寸选项自动填入测量值。未核实的规格可以保存草稿；编号、名称和明确的属性组合仍用于识别规格。规格的数字不自动改写工艺底稿、裁线、出血、DPI 或制造容差。

## 完整商品确认与生产资料核对

完整商品事实确认 `factsConfirmed` 须具备完整的实际资料和核验引用，含包装重量不得小于商品重量。核验依据是操作员维护的测量记录、样品报告或供应商确认凭证编号；本模块不自动读取链接、联系工厂或证明凭证真实。

生产资料另用 `productionConfirmed` 明确核对：要求 V2、材质、结构、明确的生产尺寸口径/单位/必要测量轴、包装内容/每份件数、核对依据及当前可用且已审核的通用工艺底稿。未知净重、含包装重量或包装外尺寸不阻止制图准备；已填写的值仍须合法，已知净重不能大于含包装重量。含包装重量不会写入净重，生产资料核对也不会把完整商品事实标记为已确认。已满足完整 V2 商品确认的规格继续可用于生产。

生产核对额外要求当前 `DesignRead`，工艺必须来自可读取、未归档/到期且原源版本仍为当前审核版本的通用编辑项目。订单、销售 SKU 等私有底稿不能作为通用规格的确认依据。工艺发生变化时须重新核对。

`productionRuleReferences` 可选保存最多十二条 `{ ruleId, versionId, version }`，每个规则只选一个确切版本。选择引用另需当前 `WorkflowRead`；Rule Center 原拥有者在同一租户事务中验证真实版本、`order_design` 用途和全局/产品类型/SPU 适用范围。新生产确认只能引用当前启用版本；未确认草稿只可保留自身前一版原有的真实历史引用，不可新增已停用引用。校验锁定规则身份，避免停用与保存并发穿透。没有规则引用时仍可使用操作员填写的独立核验依据。

确认使用现有 ProductWrite 与当前对象权限，和规格新版本在同一事务完成。响应的 `factVerification` 和 `productionVerification` 分别取自符合对应条件的真实版本 createdBy、数据库创建时间和核验引用；客户端不能提交确认人或确认时间。它记录该次确认提交，不声称这是实物测量发生的时间，也不代替工厂接受或生产放行。

修改事实、引用或工艺会撤回界面的生产确认勾选；修改事实也会撤回完整商品确认。用户可以保存新的未确认草稿，或核对后重新勾选。原版本、原确认记录及已固定的配方和包不原地改写。批量创建逐行验证，任一行失败则全部回滚，失败请求没有部分规格或幂等结果。

## 新工作与旧任务

新销售组合、配方升级、商品制作准备和确认、新上架准备与封版仍使用完整商品事实检查。新订单匹配及制造 BOM 审核/候选改用生产资料检查，允许净重未知但生产依据齐全的订单继续。旧格式的已确认布尔值不能单独放行这些新选择，须保存满足相应用途的新 V2 版本。

旧规格仍按原 JSON 读取，不补造口径、结构、凭证或确认记录。已保存订单继续看见自己的固定旧规格及配方，按原版本核对；重新匹配另一规格或配方须满足新要求。旧封存包和已提交任务保持原快照，原命令重试先返回原结果；未完成视觉组的原请求续做沿用已固定依据，新提交则检查 V2。

事实确认只检查资料完整性、口径和值的合法性。实际图案、工艺审核、产品尺寸与制造参数的人工核对、正式文件校验及工厂接受仍走各自的原流程，不能用事实勾选替代。

## 单项、批量与恢复

单项编辑、批量共用信息和逐行覆盖使用同一组字段。只填写数量未知或部分事实时可保存未确认草稿。尺寸口径改变时以现有原生形变过渡连接相关测量字段，并支持减少动态效果。

商品规格的未提交表单可在当前标签页 sessionStorage 恢复，最长两小时；键包含租户、用户、当前权限依据和规格原版本。单项字段与属性、批量选项和逐行设置分别保存，各标签页独立，不跨设备或身份。恢复不更新并发依据，也不静默合并服务器的新版本。保存成功、明确丢弃、退出或失权时清除。其他通用表单继续默认只用内存；本次没有持久化凭据或订单买家资料。

要长期保存或换设备续做，应使用服务器的保存草稿操作。浏览器限制或损坏草稿会提示核对；业务 API 仍校验所有值与当前权限。

## 接口与依赖

沿用 POST /v1/product-development/specifications 和 specifications/batch；新增数据位于原版本 facts JSON。格式字段为 formatVersion:2；physicalDimensions 保存口径和测量值，packageMeasurements 保存包装长宽高，structure 与 verificationReference 保存结构及核验引用。dimensions 和 packageDimensions 仅在新的 V2 写入时由测量值生成显示文本；旧记录不格式化重写。

契约通过 @yummyai/contracts/catalog/development 和 catalog/specification-facts 子路径复用。迁移 `0189_specification_production_purpose` 为制造审核及生产绑定增加同用途 SQL 检查；保留原有 BOM、工序、当前规格、已批准制造源、原事务和不可变内容校验。历史已确认规格的 SQL 行为保持，应用对新选择继续要求 V2。没有新增外部依赖版本、生产配置、模型收费调用或市场写入。

定向隔离验收使用 `node --env-file=.env --import ./apps/api/node_modules/tsx/dist/loader.mjs tools/scripts/run-order-daily-acceptance.mts --suite=specification-production-integration`；运行器创建并在 finally 中删除独立数据库、桶和 Redis，不能用普通业务库直接执行集成测试。

软件与实际业务验收分别记录。最新检查、源身份、真实页面及清理结论见[本地交付记录](../project-control/SPECIFICATION_FACTS_DELIVERY_20261019.md)，一般商品入口见[产品开发](product-development.md)。
