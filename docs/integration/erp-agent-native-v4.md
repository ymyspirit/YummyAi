## 来源及用户流程

先选择实际原对象、版本、预算与允许能力。按需加载严格定义，不将51份完整schema塞入每轮提示。履约建议固定原读取step/result/dataChecksum、订单与事件序号、原目标及版本，必须来自本任务已读取的范围。集合索引已读尽不等于工厂生产、质检或外部平台事实完整。

模型给出可建议字段和缺项。模型原始响应、提案、来源与claims保持不变。用户到既有原表单补项并实际核对，再明确保存原准备；最后使用已采用的同一履约全文抽屉逐项确认。父任务query保留，正文与短期token不进入URL或浏览器持久化。

本人/实物确认字段 `verifiedByOperator`、`segregationConfirmed`、`physicalSelectionConfirmed` 和制造单位确认 `manufacturing.orderUnitConfirmed` 不属于模型可建议字段。包括嵌套数组内，模型提供这些键的任何值都拒绝。服务端仅派生待核对清单，控件初始未选。历史回执和claims不能证明本次人工核对已发生，用户修改或补充的值也不继承原claims背书。

1.1.117基线复用原13类表单，独立 `shipment_create` 当时只有完整合同/API能力，界面明确显示缺少第14个补项入口。1.1.118正在补齐原部分数量、多包裹装箱表单和来源工作区，当前实施及验收状态见[装箱工作区](shipment-create-workspace.md)。不能以仅接入部分kind或目录元数据作为完整平台完成。

## 共享契约和三层身份

| 层 | 固定记录 | 恢复行为 |
| --- | --- | --- |
| 模型父任务 | 原requestId/checksum、runId、路由指纹、父预算及逐轮原响应 | 查询原回执与checkpoint，不重新购买未知提交 |
| 提案项准备 | 原slot/item、proposalChecksum、一次固定的本人完整请求及checksum | 仅查询同一原准备回执，不同键改正文或从父ID推断子成功 |
| 原履约执行 | 原intentId/requestId/hash、当前generation/决定和短期token | 原拥有者返回真实typed receipt后才能投影业务成功 |

`proposalChecksum`固定建议、claims和来源。履约提案出生时完整原文与准备checksum为null。本人补齐后，协调事务一次性封存完整输入、canonical checksum和提案关联并写审计，随后才委托原 `AgentFulfillmentCommandService.prepare`。GET只读取原receipt与补链，不准备或执行。

沿原server slot算法固定每项requestId与native key。`production_milestone`使用 `externalEventId`，其他类使用 `idempotencyKey`；原表单的普通分支仍可生成自己的键，v4补项分支必须采用固定slot。已绑定同一slot的正文、订单或版本变化拒绝；未知状态不能清标后改键重试。

旧37类仍委托原命令服务，履约14类走独立原intent引用。新协调字段只记录来源与准备，不造影子业务成功表。出生权限与当前成员取交集，直到原业务fence；来源、TTL、清文或权限变化后晚响应不得恢复旧正文或确认能力。

本人注销先关闭身份边界的刷新资格，再同步清除各任务家族，最后通知旧分析恢复组件。任务工作台在布局监听器中关闭读取资格并中止本实例所有在途读取；清理后焦点、轮询和迟到回调不能再次发起业务读取或恢复私文。相同本人权限刷新继续保留原请求标识，不能与注销混用。正常终止的请求只记取消，不伪造成功、正文读尽或原业务回执；真实401及清理后新读仍是验收失败。

## 数据与公共端口

`NativeFamily/NativeProtocol`增加命令、提案结果和准备回执的类型关联，旧默认family保持旧类型。API共享engine将capabilities、完整请求绑定、prepare、receipt和关联核验交给仅用于准备的端口；该端口没有confirm/execute方法。Worker仅组合只读定义端口，不导入业务执行服务。

增量迁移基于真实186。提案项新增独立履约引用和受保留期约束的加密补全记录，租户复合FK、两种引用互斥、一次绑定、审计与父任务版本在数据库核验。旧行新字段保持null，旧列投影、旧guard语义、旧37与v3 DTO不得改变。历史迁移不回写。

新API、BFF、readiness和Worker路由显式识别v4，不能落入旧V3兜底。MCP宿主接入保持独立后续项，不能把本机能力目录或模型协议当作宿主已连接。

当前网页readiness增加明确的 `native_v4` 家族，短期Worker presence列出其实际已注册执行器；历史任务的输入、输出与校验不变。MCP readiness保持原五类白名单，不能随网页家族扩展而自动授权v4。单项准备为POST，单项恢复为GET小坐标，不把补全正文或确认token带入URL。

187新增原履约子意图出生门，并将父任务的保留期、停止状态、一次补全与原来源绑定保持到原业务最终fence。父任务行的共享锁持有至原业务事务结束，阻止协调提交后晚到的原准备或确认越过停止和到期。普通人工及历史意图仍走原来源语义。本人补全缺少的工作项修订可从原表单独立读取并由原prepare裁决，不能把生产投影版本冒充工作项版本或归入模型claims。

原拥有者的查询同样调用187父来源门，并将父保留期纳入最后一次时钟核对。父任务停止或到期后，原确认单正文、摘要和令牌清除，不以“执行已被拒绝”替代私文读取保护。普通及历史无v4关联的原提交保持原来源判断。
