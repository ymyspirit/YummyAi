# 销售配方制作编辑与排队出图

2026-10-19 · R09/R20、B16，关联 B28。复用 PostgreSQL/Drizzle、BullMQ、原生产编辑器和目录拥有者。没有新增依赖、迁移、业务路由或环境变量。

## 来源、权限与原事务

`@yummyai/catalog-core` 统一企划、SPU 和 SKU 的生命周期检查。销售配方编辑项目必须绑定同一原配方及 SKU，按当前商品与印花读取范围访问。编辑、审核、归档管理和新出图分别检查对应权限；宽读取不能扩大窄写入。设计操作按本人、当前团队或租户范围检查项目拥有者。

新保存、上传、审核和出图在所属写事务持有当前成员及可变来源锁。归档企划、SPU、SKU 或编辑项目后停止新制作操作；已经完成的原文件和版本仍按当前读取权访问。已审核配方继续保留原编辑锁，确定性历史文件读取不变。

销售配方启动制作时，`SalesAdaptationService` 将原租户事务传给编辑器。服务内的 `AsyncLocalStorage` 只复用相同 tenant/user 的原事务；不匹配上下文被拒绝。所有写入继续通过非 owner 角色及强制 RLS。不可变事实没有新增 UPDATE 权限，也不通过移除锁或延长测试超时解决内部事务自锁。

## 队列执行与结果采用

队列只携带原 render ID、tenant 和 requester。申请人必须与数据库原任务相同，不能借另一位有权成员执行该任务。销售配方项目从当前有效成员和逐项角色范围恢复执行权限；排队时的宽范围不作为永久授权。

Worker 在读取制作源、产物处理后、存储后及完成事务内复核来源。最终完成事务继续持有目录来源锁，失效结果不能登记为可下载清单。安全错误码区分 `production_catalog_source_archived`、`production_catalog_access_revoked` 和 `production_render_owner_mismatch`，不保存库异常原文。

已完成原任务的重复投递不重建产物。原付费图片提交中断保护保持原逻辑，不把失败或结果不明解释为可以重收一次费用。本轮验证使用确定性出图及一次性合成原图，没有真实付费调用；本契约不构成完整制作编辑器付费响应恢复或账单验真验收。

目录来源检查适用于销售配方项目。订单项目继续使用原订单、推送修订、工艺与保留期，不能以商品归档自动取消现实订单；独立底稿和其他执行模块的整体授权及恢复继续分别核验。

## 实际页面

API 投影 `catalogSource.active`，Web 缺少有效投影时停止新操作。重新聚焦及定期检查来源只更新该投影，不覆盖未保存草稿或已选历史版。归档后保留草稿和原文件；当前读取权撤销后清除私有画布、详情、项目选择及未保存内容。迟到的旧详情、保存、审核和出图响应不能恢复旧上下文。

个人登录仅在制作编辑器路径保留合法 UUIDv7 项目、历史版本和订单资料 ID，以及有限产品类型；历史版本必须关联合法项目。重复、越界、自由文本、其他页面的专用参数及外部地址仍被排除。回跳参数只决定目标，不授予读取或执行权限。

## 验证与部署

使用隔离 `--suite=catalog-scope-integration` 验证原生来源、实际 requester、当前写权限与范围，以及存储途中失效后的零清单采用；保留原文件字节及原 60 秒门槛。

`pnpm test:e2e:order-daily --suite=sales-editor-lifecycle` 运行个人登录、真实 API/BFF/RLS、原制作 Worker、归档、原文件下载及晚到响应，并回归原销售组合和商品权限。`--compiled-web` 固定同一 Web BUILD_ID。外部模型、素材和业务对象为合成夹具，原始日志和截图完成检查后按清理记录处理。

API、Worker、Web、contracts 和 catalog-core 应使用相同源码版本。本次没有新增数据库迁移；正常库的原迁移、配置、CI、备份恢复与业务试点仍须单独完成。最新本地证据见 [交付记录](../project-control/SALES_EDITOR_LIFECYCLE_DELIVERY_20261019.md)。
