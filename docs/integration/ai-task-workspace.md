# AI 任务工作台

`/ai-tasks` 是运营、设计和审核人员共用的业务任务入口。覆盖订单预审、生产稿预检、售后分析、原创方向、模板配置、Listing 资料包、经营分析、采购分析和知识问答。任务与原有业务对象绑定，沿用现有助手、Worker、私有资产、版本、权限及预算服务，无新增任务数据库或独立模型渠道。

## 使用流程

1. 选择任务类型并搜索具体业务对象；知识问答直接填写问题。无权限或无可用对象时明确显示原因。
2. 填写可选分析重点，点击「读取本次依据」。这一步没有模型费用，展示固定来源、可用图片数量、规则检查和缺项。改变对象或分析重点会立即使旧预览失效。
3. 核对依据，选择已启用模型并开始分析。沿用 `requestId` 幂等、组织预算、模型费用上限、队列和不确定调用保护。服务器再次准备上下文并核对预览指纹；变化返回 409，不创建新任务。
4. 在原任务里查看进度、引用、建议、图片与费用。关页或网络中断后，从历史或任务链接读取同一记录；不自动重发模型请求。
5. 进入对应业务页核对、采用草稿或完成下一步。分析完成不代表模板批准、Listing 发布、客户校样确认、生产放行、退款或发货。

预览的「计划采用的方法」与结果的「本次固定的方法」分别显示内置方法、团队发布版或历史缺失状态。团队方法可打开对应的原历史版，发布新版后旧任务仍显示原版本；开始前方法更新会使旧预览失效，需重新读取。查看方法和刷新权限不调用模型。

已完成记录仍按三十秒及重新聚焦/可见时复核读取权。任务列表也刷新当前可读记录；失去权限或原记录不可读时，清除详情、历史、待采用选择和未发送分析重点，较早请求的成功响应不能恢复旧内容。读取失败会显示明确错误；网络错误不自动提交或重试模型调用。

## 商品和订单业务任务

从任务工作台选择「业务任务」进入 `/business-tasks`，按销售方案或订单读取阶段、版本、产物、阻塞与执行记录。订单可在条件满足时准备按工厂拆分的正式交付包，并返回原业务页处理物流与真实工厂回执。详见[商品与订单业务任务](business-tasks.md)。

## 接口与数据边界

销售方案绑定的原创方向和 Listing 分析可从任务链接返回该方案的「上新任务」。在那里核对字段差异并显式采纳，随后同步刊登草稿、人工审核及封存；版本和权限再次检查。详见[销售方案上新任务](sales-plan-launch.md)。

| 路由 | 行为 |
| --- | --- |
| `GET /v1/ai-assists/task-workspace?kind=&status=&page=1` | 当前操作者可读取的任务与可用能力；每页 20 条，重新核对任务读取权限和资料版本 |
| `GET /v1/ai-assists/task-targets?kind=&q=` | 按任务所需权限读取租户内业务对象，最多 40 条，超限明确要求缩小搜索 |
| `POST /v1/ai-assists/task-basis` | 接收 `{ kind, targetId, taskGoal }`，返回现有助手输入、固定来源、规则检查、指纹及业务处理入口 |

`methodSelection` 是依据响应的服务器读取元数据；不嵌入可提交的 `input`，客户端不能提供方法选择或执行契约。旧响应缺少该字段时只显示未记录，不借用当前方法批准。

创建任务仍使用 `POST /v1/ai-assists/runs`。兼容原请求，新增可选 `taskGoal` 与 `expectedTaskFingerprint`；创意任务可绑定 `projectId` 并核对已保存的需求、提示词与研究来源。任务目标只作为低信任分析重点，不能更改规格、规则、权限、费用或审批。费用未知时保持未知。知识评测不进入日常任务列表。过期任务保留状态，敏感内容按原保留期清理。

知识入口默认查找通用运营知识；平台、站点、指定商品及账户报告的范围在原知识工作台选择。业务处理链接携带原对象与 `assistRun`，原助手会读取同一任务，即使它不在最近 20 条记录内；权限及当前对象仍会再次核对。来源指纹排除请求编号、模型编号、知识检索时间及保留期限，保留内容、来源版本、规则与图片变化。

列表保持创建者私有；已有自动审核证据的共享规则不扩展到其他任务。查询、目标搜索与上下文准备均使用 `withTenant()` 及应用角色。Web 代理保持认证、明确路径白名单、同源 JSON、128 KiB 请求限制和 private/no-store。对象 ID 不接受文件路径、租户选择或执行链接。未经授权的竞品资产只能参与研究。

## 验收

合成租户测试核对预览无模型调用、资料变化拒绝、幂等、租户与操作者隔离、权限撤回、费用与原业务状态。浏览器测试通过实际 API、队列和受控模型处理器完成一个知识任务，验证刷新恢复、历史与固定来源、桌面及窄屏无溢出。所有数据库、存储桶、Redis 与模型测试资源使用隔离验收运行器创建并在 finally 中清理。

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e:order-daily --suite=ai-tasks-integration
pnpm test:e2e:order-daily --suite=ai-tasks
pnpm build
pnpm start:local
pnpm check:local-runtime
```

构建及浏览器测试前停止该工作区的 Next 开发服务。POD ZIP 目录与文件沿用同一固定导出时间，同一批准快照在不同打包时刻生成一致字节；保留原有权限、审核与不可变导出记录。桌面/手机的原始截图、日志、trace 与隔离清单检查后清理；保留源码测试和 `docs/project-control/checkpoints/2026-10-16-business-methods-` 下的简明核验记录。新增业务路径使用 `pnpm test:e2e:order-daily --suite=business-methods`，数据、外部传输和真实提供方质量的边界见[业务方法交付](../project-control/BUSINESS_METHODS_DELIVERY_20261016.md)。
