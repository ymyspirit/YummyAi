# 模型费用人工核对

费用页同时展示[官方 API 价格核算](official-model-pricing.md)，根据原始 token
回执逐项计算，缺少明细时保留未知。无人设计调用进入只读费用目录；官方测算不
替代渠道账单确认，不回写原预算或已确认的历史金额。

2026-10-16 · R20 / B28。API、原调用记录和预算仍属于原 AI/POD 模块。
当前验证进度见项目状态；本说明不代表已完成真实渠道账单或财务验收。

## 依据和能力边界

参考开源 [ERPNext 的原记录匹配与对账流程](https://docs.frappe.io/erpnext/bank-reconciliation)
及 [Langfuse 对报告费用与推算费用的区分](https://langfuse.com/docs/observability/features/token-and-cost-tracking)。
复用设计原则，没有复制第三方代码、引入 SDK 或另建财务账本。

`/model-billing` 提供人工核对，原“调用与费用记录”及系统配置目录均有入口。
原始配置估价、处理服务报告、未知费用继续保留；人工确认另外保存为不可变事件。
`operator_attested` 明确表示操作员确认，不等于系统已调用渠道账单 API 验真。
导出保留 `providerInvoiceVerified=false` 与 `verificationMode=operator_attestation_only`。

凭证文件仅在浏览器本地计算 SHA-256，最大 10 MiB；服务器只接收摘要、账单或凭证
编号、渠道原请求号、美元金额及明确匹配确认。原文件由操作者在受控位置保管。
摘要不能恢复原件、证明文件真实或证明分摊正确。编号只接受有界标识符，不接收
任意备注、账号凭据、文件正文或 URL 附件。

## 权限与准入

需要当前有效成员、独立 `model:billing_reconcile` 权限及租户级数据范围。
`MODEL_BILLING_TENANT_IDS` 默认空、关闭；只在完成角色核对及迁移后显式填写租户。
允许 `*`，仅用于明确的整体启用；测试使用隔离进程中的合成配置，不改日常 `.env`。
本迁移不自动修改现有角色。业务角色需明确授权；本地开发的 Local Administrator
由显式 bootstrap 同步完整开发权限，不能将其用作正式角色准入证据。
根 Turbo 命令透传此租户开关，直接服务启动及项目 .env 也可配置。
读取和提交都重新加载实际成员与角色，客户端租户字段
不能选择访问范围。核对服务只选择费用元数据，不读取或解密业务提示词和输出。

仅接受终态原调用。排队、执行中、活动租约、未跨外部提交边界或多笔歧义预算会阻断。
活动租约使用数据库当前时间判断，与原辅助执行器的租约时钟保持一致。
已有渠道请求号必须逐字匹配；历史缺失请求号允许人工补证，但不回填历史外部回执。
没有外部调用依据的历史记录不能凭空确认费用。POD 使用具体 invocation ID，不能
把任务总费用记入任意一个尝试。委派父步骤不重复计入子任务费用。

## 事件、预算及并发

迁移 `0118_model_billing_reconciliation` 新增只追加的核对事件及原对象复合租户外键。
不更新原 assist cost、POD reported cost、用量、原响应或任务结果。
每次修订追加 sequence/previousId，保存操作者、凭证摘要、请求摘要和原依据指纹。

- 同一 commandId 和相同内容返回原结果；不同内容返回 409。旧命令在后续修订后
  重放不会重新应用旧费用。
- 原依据指纹改变返回 409，页面保留未保存内容。重新读取后再次明确确认。
- 原 AI 预算的租户事务锁序列化核对和预算预留；当前成员/角色在提交事务内锁定。
- 数据库校验事件链及原预算身份、原金额、归属时间。新事件在同一事务驱动预算
  投影纠正；普通 UPDATE 仍不能改写终态金额，身份和归属时间不可变。
- 无原预算的未知调用由 AI 拥有者建立原 request 的预算，归属原调用时间。
  原时间保留 PostgreSQL 微秒；预算按原账本 UTC 月归属，界面明确标示 UTC 月份。
  核对日期不把费用挪到新的预算月份。
- 费用证据保留八位小数，原预算六位小数用整数运算向上取整；正的小额费用不归零。
  只接受 USD，最大 `99999999.99999900`。不执行汇率转换。
- 已发生费用可以超过预算，仍如实记录；原预算门禁使用纠正后的账本拦截后续调用。
  已补证未知费用不再被当作未计价，但原未知/估价字段不改写。
- 同一凭证摘要、编号和原请求不能分配到另一原调用。此检查不能替代人工核验
  分摊或渠道真实性。

POD 的人工确认只附着在原 invocation，不写 AI 预算或财务业务账；费用总归集和
渠道自动账单匹配继续独立验收。核对不会触发模型重试、付款、退款、发布或生产放行。
只读投影仅返回确认金额、摘要、操作者与时间，不向普通任务读者公开账单编号。

## API 与恢复

`GET /v1/model-billing/workspace?scope=unreconciled|all&after=…` 每页 20 条，使用原始
微秒时间、UUID 和拥有者组成游标。`GET /v1/model-billing/:owner/:id` 读取原依据和
最近 20 次核对。`POST /v1/model-billing/:owner/:id/confirm` 接收严格契约并原子写入
核对事件、预算投影与审计。owner 为 assist 或 pod；未知字段和过期依据明确拒绝。

Web `/api/model-billing` 使用方法/路径白名单、同源 JSON、16 KiB 请求上限和私有
不缓存响应。表单明确显示处理中、无记录、未启用、无权读取和失败状态；提交超时
可以用原 commandId 重试。凭证与匹配勾选未完成不能提交。界面在聚焦及定期检查
当前读取权；失去权限后清除已显示的核对详情和未提交表单。

隔离验证命令：`pnpm test:e2e:order-daily --suite=model-billing-integration` 和
`pnpm test:e2e:order-daily --suite=model-billing`。后者使用独立 Web 快照与缓存，
真实认证/API/强制 RLS 和合成历史调用；没有真实付费请求或实际账单导入。
日常库在迁移、备份恢复与角色准入完成前保持原状态。
