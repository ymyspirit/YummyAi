| Agent 层 | 有界分析、候选生成、结构化建议、缺口和下一步建议 | 按任务选择必要模型；不能直接写跨模块表或修改门禁 |

画布是人的创作工作区，可以展示任务进度和产物；画布节点状态不能代替订单、工厂接受或财务事实。知识检索和模型输出均是数据，遵守 [OWASP 提示注入防护](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) 的权限隔离和工具边界原则。

1.1.51的[店铺 API 节点目标架构](03-system-architecture.md)沿用以上三层：ERP 数据层保持中央事实与租户隔离；中央 Harness 保存授权上限、任务、预算、活动节点绑定和有界执行许可；店铺节点是只执行本店准入操作的远程执行器，Agent 在中心使用受权工具分析与提出计划。节点主动建立认证连接，外部 MCP 委派只在中心解析。离线暂停新步骤，撤销与旧租约不能扩大授权，未知外部结果先对账；数据落库和业务批准由原拥有者完成。此增量为规划，现有 Worker、生产和创作路径不能由此被视为已完成节点迁移。

知识历史进入下一次上下文前使用同一历史读策略校验固定数据范围，不能借续问绕过
单条运行的当前权限。评测与对话上下文隔离；文档中的指令保留在数据输入，知识问答
执行器不暴露业务执行工具。相应功能证据与模型质量边界见
[知识专项核验](../project-control/KNOWLEDGE_ACCEPTANCE_MATRIX.md)。

## 3. 版本化执行契约

POD 方法 v2 的输出固定为原始产物交接，独立于任务界面字段；与响应、待审核版本及实际文件在所属事务内共同落库。原代码 v1 定义保留冻结校验与兼容标识，发布升级只影响新输入，旧任务缺失不能补造。处理器协议、读取核验与迁移见 [产物交接契约](../integration/pod-completion.md)；其他执行器及业务审核继续分别验收。

方法发布与代码能力分开记录。原生方法版本固定代码正文、步骤、工具及知识来源，补充说明留在资料域；发布只影响新输入，停用按撤销代次阻止旧任务继续，结果采用事务持有方法共享锁。后端 API、九类辅助和 `/knowledge/methods` 工作台已接通；界面复核绑定当前 revision 与版本摘要，版本变化不能复用旧勾选。已完成本地路径与其他业务对象、真实提供方及完整验收的边界见 [方法治理](../integration/agent-methods.md)。

九类辅助及独立看图审核已有发布方法的本地执行证据；新增六类及审核分别经过原业务拥有者和处理器，保留事实、隐私与制作门禁。前轮浏览器与本批合成存储/传输范围分别列于 [其余业务方法验证](../project-control/REMAINING_METHODS_DELIVERY_20261017.md)。workflow/POD 现通过同一方法拥有者固定各自发布版；委派在激活时固定父/子引用，原响应恢复沿用旧版，撤回后保留费用而拒绝采用，知识来源共享锁覆盖所属写事务。其契约、历史缺失边界与实际界面入口见 [执行方法治理](../integration/execution-methods.md)。真实提供方、其他执行器及正常部署继续单独验收。

任务依据另返回服务器选择的方法标识，位于读取元数据而非可提交输入。预览与结果分别显示计划采用版和本次固定版；查看历史不替换原版本。方法或相关业务资料改变后旧预览指纹返回冲突，不新建付费意图。共享结果面板与任务工作台持续复核当前读取权，使用取消及请求代次隔离旧响应；失去权限清除详情、结果、历史和未发送的分析重点。

注销清理先关闭身份和任务读取资格，再通知可能触发焦点刷新的恢复组件。所有在途读取可取消，清理后的轮询、焦点及旧回调不能新发起业务读取；取消本身不等于读取成功或原业务完成。相同本人权限刷新可保留原键，真实退出必须同步清文、移除恢复标识并拒绝迟到回填。

每个执行器注册以下字段，缺项时明确返回不支持，不由模型猜测：

| 字段组 | 必须表达的内容 |
| --- | --- |
| 身份 | executorKey、contractVersion、taskKind、服务端解析的 tenant/actor、业务对象及当前责任人 |
| 输入 | requestId、幂等内容摘要、对象版本、recipeVersion、ruleSnapshot 或显式 legacy_missing、knowledge/method/input refs |
| 上下文 | 来源与信任等级、适用平台/市场/SPU、数据分类、过期时间、必要事实、未知项、上下文裁剪规则 |
| 工具 | toolKey/version、输入/输出 Schema、权限、资源范围、数据域、effect、限额、超时、幂等能力和对账方式 |
| 运行 | 持久意图、步骤、租约 token、attempt、deadline、trace、取消信号、检查点与恢复规则 |
| 模型与费用 | 固定路由/模型/参数、估价依据、预留、调用尝试、实际费用或 unknown、全链路成本 |
| 交付 | 结构化输出、不可变产物、来源、技术检查、业务审核、工厂接受和生产放行分别记录 |

输入正文与买家资料加密留在原域，队列仅携带受限引用。方法文件不能动态增加工具、提高预算或扩大权限。上下文预算先保留硬约束和事实来源，再裁剪冗余资料；无法容纳关键输入时停止并给出缺项，而不是静默省略。

## 4. 一次执行的顺序

1. API 解析身份和对象范围，做版本、幂等、资源及能力预检；固定输入和方法版本。
2. 同一租户事务记录意图与必要预算，提交后派发。复用已有 outbox，缺失模块逐项补建。
3. Worker 获取有 token 的租约，重新检查当前成员、对象状态、隐私保留期和预算；旧授权快照不能继续授权。
4. 调用确定性工具或必要的 Agent 步骤。每个工具入口重新校验参数、权限与作用范围。
5. 外部提交前持久记录稳定请求身份和提交边界；响应原件先安全保存，再做扫描、解析和技术检查。
6. 原子提交步骤结果。后续本地处理失败复用有效响应，不再次购买模型结果。
7. 技术完成进入对应人工审核或下游明确的业务步骤。不能从模型成功推导工厂接受、实际交运或利润完整。

## 5. 恢复和外部副作用

| 当前证据 | 可采取的动作 | 预算与业务处理 |
| --- | --- | --- |
| 步骤结果已提交 | 复用结果，不重复执行 | 保留原费用和产物 |
| 可靠证据确认未提交外部请求 | 经当前授权后重新排队 | 释放或重建原预留，保持请求身份 |
| 收到响应且有有效持久检查点 | 继续扫描/解析/存储 | 不重发付费请求；费用有凭证才确认 |
| 已提交或提交状态不明，且无可用响应 | 查询原请求；不支持查询则人工核实与接管 | 保持费用 unknown/占用，不按失败当零费用 |
| 输入过期、被撤权、版本失效或扫描拒绝 | 阻断新执行，显示具体原因 | 历史保留；按实际证据结算，不伪造取消外部动作 |

缺少提交标记不能证明从未提交。出现网络超时也不能证明提供商没有执行。自动重试只针对明确可恢复且无重复副作用的步骤，并有次数和截止时间。`takeover` 停止新动作，但不能撤销已经发送的请求。

不同模块保留原有合法状态。Harness 对外展示业务状态和执行状态的映射：例如订单设计 `needs_attention` 携带“外部结果不明”原因，AI 辅助的历史 `failed + assist_interrupted` 不被伪装为已安全取消。新辅助任务由原模块执行记录承载派发、租约、固定协议及加密响应；派发失败仍为原 queued，响应待本地恢复仍为 running，提交未知为 failed 并明确费用待核验。旧任务不回填快照，统一读模型前先建立映射和兼容测试。实现边界见 [执行说明](../integration/agent-harness.md)。

九类辅助的加密输入另固定 `assist-input-authority-v1`：相关业务资源的语义投影、必要性、数量与校验值。API 读取上下文前后比较，Worker 在下载前、提交前、响应恢复及采用前比较。输入所属业务模块保持计算和写入所有权，依赖元数据不授予权限。无关记录和搜索缓存不纳入相关业务指纹；已发布的旧知识引用可继续固定，撤销、过期、来源失效与阻断冲突必须停止采用。旧任务缺少依据快照时说明需重新读取资料，不以当前值伪装历史依据。

原生 `executionContract` 固定方法和工具的 key/version/checksum。注册源在 ai-core，工作流定义校验与 Worker 复用 workflow-core 的同一能力绑定；辅助任务仍不向模型开放业务执行工具。方法文本和能力标注不授予权限，当前成员、对象和业务拥有者门禁仍逐次执行。现有输入/输出 Schema 及方法正文参与摘要；工具限额检查实际逻辑参数与返回产物，模型使用注册方法正文和中止信号，工作流使用带 token 的限时租约。旧记录缺契约明确停止，保持原输入；异常返回不撤销已经提交的回执。具体覆盖与剩余范围见 [运行契约](../integration/agent-harness.md#native-tool-and-skill-contracts-2026-10-16)。

## 6. Agent 职责与交接

订单模板和来图抱枕执行器沿用原任务、租约、配方、规则、预算和响应恢复，按
[订单设计交接](../integration/order-design-completion.md)固定发布方法与实际原尺寸
待审稿。旧方法缺失明确保留；当前方法/知识/成员失效停止采用，原提交结果按
原保留条件记录费用与响应。完成凭据独立于界面 DTO，引用实际不可变步骤、稿件
和文件字节，仍交由业务审核。隐私资料已到期后的迟到费用恢复另列待补。

新建 POD 原任务补充[原响应和产物检查点](../integration/pod-response-recovery.md)：
同事务持久意图、数据库时钟租约、先记录对象上传意图的加密检查点，以及固定产物位置
和回读校验。最多三次本地处理不重新购买模型结果；失去当前权限或输入依据时停止
采用。历史任务不回填；完整 Worker 进程崩溃和真实处理服务仍需单独验证。

调用记录的首批统一读模型复用原拥有者：辅助执行/预算、工作流 attempt/商品回执及
POD 原调用元数据。迁移 0117 在 POD 领取与提交边界写独立调用，响应计价先于产物
验证保存；费用依据明确配置估价、处理服务报告或 unknown。派发/本地恢复不等于
扣费次数，父委派不重复累加子费用。旧记录不补造；下载是核对交接，不是账单已
匹配或财务批准。具体字段、当前权限及恢复限制见[调用与费用证据](../integration/harness-invocations.md)。

以下是任务角色，不要求一个角色部署一个独立 Agent。确定性流程能够完成的步骤优先不用模型。

| 任务角色 | 输入与现有承接 | 交付 | 停止/交接条件 |

H06 的费用补证使用[人工核对契约](../integration/model-billing.md)：原估价、服务报告、未知费用与人工确认分别保存；不可变事件驱动原预算纠正，原月归属和普通终态写保护保留。人工确认不自动重试原请求、不改变业务结果，也不代表提供方 API 已核验账单。全链路成本、其他执行器和真实账单仍按各自范围验收。

销售配方的原编辑器与出图 Worker 现复用[目录执行生命周期](../integration/sales-editor-lifecycle.md)。执行身份取原任务申请人和当前成员授权，来源锁覆盖最终采用；归档、撤权或窄写入阻止新结果成为可下载清单，原订单及历史文件沿所属边界保留。此路径没有新增真实付费模型验证，也不代替独立底稿、订单执行器或完整 H01—H12 验收。

原制作任务的确定性恢复按[原生派发与租约](../integration/catalog-render-recovery.md)固定 render、tenant、requester 和版本。数据库租约及 token 决定实际执行权；Redis 投递 UUID 可以变化，不能据此新建业务任务或重复付费。完整 Harness 验收继续。

正常环境启动执行器前区分运维盘点和执行授权。新增本地队列工具只读统计声明队列的状态键，不读取正文、不构造消费者、不改变状态；采样不是跨键原子快照。持久任务及调度器可能在 Redis 为空时恢复工作，仍需核对原申请人、当前授权、付费和未知外部提交边界。个人 Web/API 可独立启动；只读盘点本身不选择或授权消费者；按队列和调度器选择运行已另行接通，见[Worker 契约](../integration/worker-runtime.md)，不自动授予旧任务恢复许可。见[本地运行契约](../integration/local-personal-runtime.md)。

采集媒体作为原生异步执行器，保留原申请人及逐项 capture:write 范围，在下载后/存储前和提交前复核；租户级研究读取不能授权归档。只读准入检查不消费队列，也不代表可启动 Worker。见[研究与采集授权](../integration/research-authority.md)。

订单编辑/审单 API 和跟进派发复核原请求上限与当前逐权限范围，不把原命令键或责任分派作为授权。私有文件 I/O 后及关联前复核，保留原版本/审核与幂等结果；这不代表所有设计 Agent、费用与履约拥有者已完成相同改造。见[订单授权](../integration/order-authority.md)。

素材引用不能仅因 ID、重复内容或原签名请求而被视为授权。原生上传与签名已复核当前拥有者和逐权限，外部 I/O 后再次核验；其他 Agent 直接存储/素材服务仍按所属拥有者分别审计。见[素材运行边界](../integration/asset-authority.md)。

原生设计工具不能只通过控制器或早期快照鉴权；实际仓库复核每项当前权限、拥有者和原固定文件，审核/主版本及SKU交接在所属事务内判断。外部签名后复核当前父任务，原生批准设计并非生产放行。其他Agent拥有者仍需独立审计，见[原生设计边界](../integration/native-design-authority.md)。

画布/工作区工具入口和独立创作生成服务在拥有者事务内复核当前权限；文件字节和待审关联在外部 I/O 后复核。API 派发预检不能代替 Worker 执行授权；旧 QUEUE_UNAVAILABLE 不是未调用证明，旧处理器的原身份、预算和响应恢复继续迁移。见[创作执行边界](../integration/canvas-workflow-authority.md)。

PRD 1.1.23 的[创作执行操作入口](../integration/creative-execution-operator.md)复用原方法/知识选择与原拥有者，保留原输入及费用。申请续做仍复核当前原准入，人工核对不替代终态恢复、账单验真或业务批准；普通部署和完整验收继续。

本地执行的版本证据还包括实际 Web 候选与 BUILD_ID。隔离个人身份验收必须使用指定产物，不能由旧配置覆盖；普通采用、原输入/原权限及配对恢复仍独立核验，见[候选运行契约](../integration/local-web-candidates.md)。

2026-10-20的[普通运行采用](../integration/normal-runtime-adoption.md)已关联真实业务备份、原数据/文件恢复、目标135升级、同源码构建及HTTP制品。它提供当前执行环境证据，尚不等于生产页面的意图已支持跨刷新或设备持久恢复。验收运行器还须核对最终输出目录并显式选择独立`--output`；已记录的冻结目录写入例外不得被其他清理成功覆盖。原Worker积压保持停止，不因网页恢复自动恢复付费或对外工作。

## 确定性质检检查 · 1.1.28

逐项质检沿用 ERP 生产事实与当前权限，不由 Agent 另建“已检验”状态。共享校验器计算权重、阻断和待处理缺陷，API 固定原生产依据并比较原请求/操作员；冲突保留草稿后复核。知识与 Agent 可解释标准或建议处置，只有实际操作员明确填写的核验与责任进入权威业务记录，外部交易仍使用原业务边界。详见[质检契约](../integration/quality-assessment.md)。


## 发货来源的受控执行 · 1.1.29

工具输入明确原包裹/生产版本、通过质检和数量。执行网关在同一非owner租户事务内复核当前权限和原依据，再按统一锁顺序核对审核占用；草稿与实际物理消耗分别计算。相同请求必须同内容同操作者，失权后不能以旧回执恢复私有内容。依据冲突保留原填写，核对后用新发货版本修正，原审核不自动转为新版本批准。真实物流另记事实与异常，Agent不能把收到轨迹当作生产通过或平台确认。


### 1.1.30 实物分组的执行边界

Harness按当前权限读取原生产版本、固定标准和原组，核对互不重叠的完整数量、当前末级组及跨缺陷共享补做余额；发货固定原通过组，已交运事实不可复检改写。原回执先按操作员及内容恢复，再分离新操作的当前依据，不能以新组ID重放出第二份数量。Agent不填充隔离、检查通过或实际交运确认。详见[分组规格](../integration/quality-groups.md)。

新旧质检共用订单事务入口，质量异常与审计不能晚于检验独立提交。当前商品的共享业务锁和不可等待的行共享锁共同保护暂停、归档及资料清除，锁冲突明确返回；保留状态按数据库时钟读取且不读取制作密钥。历史生产未固定制作单ID仍按当前商品核验。原请求只恢复原回执，不重新增加审计、异常或实物占用。

## 制造基础增量 · 1.1.31

制造建议使用确定性精确分数计算。数据层保留原规格、BOM/工序/责任版本、审核和原回执；执行服务核对当前成员/对象范围、未知项、物料单位、顺序锁及事务审计。Agent可整理建议，不能代填供料确认、制造批准、实际领料、工厂开工或产能释放；当前还未注册自动生产动作。


## 制造原请求恢复 · 1.1.32

制造服务在实际拥有者事务内核验当前权限，再恢复同一操作员、相同原内容和请求编号对应的原业务响应；新响应包装当前权限标识。浏览器提交前固定原意图，响应不可确认时锁住内容并提供原请求恢复。网关在业务提交后发现权限变化的409须保留独立code，不能误作普通版本冲突而丢弃原意图。权限/范围真正丢失后清除私有填写；短期标签页草稿不替代服务端版本、命令回执或业务备份。Agent不得以恢复为由更换请求编号或绕过独立审核。

生产固定版本：Harness协调当前权限、原请求恢复、原审单来源、已批准制造选择、工厂能力和同笔审计；订单头使用明确的非等待冲突反馈，避免跨商品审单与整单锁的反向等待。Agent不能替人勾选销售单位确认，也不能给旧生产推断或补造制造历史。直接生产、单件审核稿、整单和补做共用制造来源拥有者校验，运营完整页面和普通采用继续。

### 制造交付的原凭据与事务 · 1.1.33

交付工具沿用实际订单/工厂分配拥有者和当前权限，读取原生产绑定后严格投影工厂计划，不能把完整内部BOM交给模型或工厂。新接受命令同时携带原文件SHA-256、原制造计划checksum、顺序及实际核对；错误或缺少制造指纹不推进状态。创建、接受和审计原子提交，成功响应丢失后按原操作员、正文和请求恢复，不换键重做。新V3规范JSON与原文件分别校验；旧V1/V2的字段缺省、密文及原校验算法保持。当前未注册由Agent自动供料、接受、开工或付费的动作，规则/知识文本也不能授权这些动作。见[制造交付契约](../integration/manufacturing-delivery.md)。

### 运营原意图与当前依据 · 1.1.34

页面对不确定提交固定原输入和请求，提供人工明确恢复，恢复本身不授予额外权限。HTTP409中的`authority_changed`表示提交后身份变化，不能当作普通版本冲突而放弃原意图并创建新请求；其他上游错误代码不透传。真实401/403/404清除本页意图和重试缓存。制造读取按当前范围核对，重新聚焦取消旧读取，临时故障保留填写而不允许提交。当前内存恢复不替代服务端持久调用记录、跨刷新恢复或业务审核，Agent仍不能代选制造确认。见[运营交接契约](../integration/production-operator-handoff.md)。

### 生产命令的确定性与原意图

跨刷新/设备的持久命令拟按[服务端恢复设计](../architecture/order-command-recovery.md)实施：不可变原意图、当前权限与原范围上限、同编号业务回执、尝试租约和业务事务内执行凭据检查。认领与结果封存不在持有意图锁时调用生产事务；迟到执行须在写入前拒绝。当前尚无这条新接口或迁移；首批直接/单商品/整单生产及后续交付/回执/返工分别验收。

本轮已实现[验收输出隔离](../integration/acceptance-output-isolation.md)，每次使用新的缓存叶目录和显式生效的Playwright标准输出，并保存拥有权回执。已有/冻结/链接目标在测试业务资源建立前拒绝；自动目录不替代任意辅助代码的文件归属检查，也不代表上述持久恢复已经完成。

数据层保存不可变审单/规格/设计/制造及路由采购依据，数量占用以实际交运事实为准。Harness在所属拥有者边界内复查当前权限、对象范围、原数量、显式选择和同笔审计；直接生产不能用今日声明覆盖已有审单，Agent不得代勾确认或以知识文本制造审核权。UI对整单、单商品、交付、回执、返工和直接生产保留原路径/正文/请求编号，未知时只明确恢复原命令；可信回执后刷新失败不重做。HTTP输入格式错误在业务调用前返回已知400，真正输出或事务故障继续按不确定结果处理。当前页面内存恢复不替代服务端持久意图和跨刷新恢复，仍须按H类验收继续。接口与局部证据见[生产入口](../integration/production-entry.md)。

## 1.1.42 维护范围与拥有者事务

工作流维护调度可由可信内部构造参数限定租户集合；省略表示正常发现，空集合表示零任务。该选择不接受HTTP原始租户ID，也不替代执行时的成员关系、权限与对象范围。隔离测试使用自己的队列和租户；负向测试须证明被排除租户的持久意图未被派发或消费。详见[执行契约](../integration/workflow-node-execution.md)。

## 1.1.43 观察排序与重放依据

Harness只引用业务拥有者承认的观察身份和原幂等回执。同步序号由数据库分配；时间用于证据显示，不能替代顺序、版本、权限或留存门禁。历史NULL必须重新同步后才能成为新选择，旧包裹固定来源保留。选定来源时的共享锁延续到拥有者事务提交；冲突保留原填写并请求刷新，不改旧证据、不改请求编号冒充重放。已有面单下载不证明购单、实际交运或物流计费恢复已经完成。

## 1.1.44 精确库存与原BOM实际物料

新增的纯数据库耗用命令在同一事务保存原事实、库存、部分预留与审计。复用原编号恢复成功事实，异操作员/正文复用冲突，原权限和当前成员都必须允许；查询暂无回执时保留不确定提示。客户端跨刷新不能只保存内存正文或一个找不到回执的编号，完整页面接入前须补持久原意图及取消/采用边界。此类回执是物料事实，不能伪装为productionOrderIds或强制增加无关买家资料读取权。Agent提案不自动记实际耗用。

接口、已验证结果与剩余项见[物料契约](../integration/production-material-execution.md)及[本批进展](../project-control/INVENTORY_EXECUTION_PROGRESS_20261020.md)。

## 1.1.45 数据库事务型物料适配

原物料命令保存真实拥有者、原权限上限、原BOM绑定、规范输入校验、7天加密正文和物料事实回执。该适配只持一个有界数据库事务：不人为增加外部执行租约，不把回执换成生产单列表。业务冲突通过保存点记录拒绝，基础设施或审计失败回滚整笔；实际库存、原事实及成功命令头不能分开提交。数据库原命令凭据阻止其他入口绕过取消或过期。

当前身份BFF严格验证原业务对象、原正文、请求编号及回执一致性。界面先准备后执行，未知响应只读恢复；新本人会话在当前权限下读取同一原结果，私有正文不写浏览器持久存储。独立输入留存调度通过租户RLS和空业务权限清除过期原文，成功事实保持；其运行选择不能启动业务消费者。物料执行尚未开放给Agent自动记账，建议、操作员实际确认、工厂接受和正式生产放行继续分别记录。源码、专项证据及未完成项见[当前进展](../project-control/MATERIAL_RECOVERY_PROGRESS_20261020.md)。

## 1.1.47 独立隐私维护运行

留存维护属于Harness的运维能力，不是Agent的业务执行权。物料原填写清除使用固定零消费者入口和空业务权限的租户RLS，只更新到期输入及允许的过期状态，保留成功回执、实际库存和制造原依据。周期调度必须在其他句柄空闲时继续运行，停机等待当前批次；ready、实际批次、失败延后和业务结果分别观察，跳过触发不能伪造完成心跳。

当前入口复用标准Worker，继承all也不能扩大到其他消费者或调度器；私有配置和底层错误不进入心跳。真实子进程、实际60秒周期、重启、终态保留及排队任务不消费分别验收。普通采用不等于Windows开机服务、生产集群监管、其他执行器或完整Harness完成。见[独立清除契约](../integration/material-input-retention-runtime.md)与[实际进度](../project-control/MATERIAL_RETENTION_PROGRESS_20261020.md)。

## 1.1.48 业务请求绑定与检验责任

分类及收货的成功请求必须绑定原对象、原操作者和规范内容，当前成员与逐权限范围在拥有者事务内复查；宽读取不能扩大窄写入。旧收货缺原请求依据不猜测补造，正文变化不得凭同编号返回旧成功。库存、收货、请求依据及成功审计同笔提交，后段失败全部回滚。该最小成功请求依据不等于准备意图、尝试和跨会话恢复的完整适配。

到货待检、标准/测量核准、接受入账和拒收处置必须引用原事实并按数量协调，不能以分类、AI判断或知识文字取得核准权。未来持久命令沿用当前基础，禁止建立平行库存写入。具体分工及必须验证的行为见[来料检验设计](../architecture/incoming-material-inspection.md)；当前实施、普通采用与清理分别见[本批进展](../project-control/INVENTORY_RECEIVING_PROGRESS_20261020.md)。

工作流的开始、节点状态变更和业务事件使用数据库时间。受控实验分别将API进程的Date时钟偏移正负5分钟，原实现记录偏差约300秒；新实现复用workflowDatabaseNow，不修改操作系统时间或历史记录。立即执行型隔离夹具显式准备已到期任务，未来调度、原租约、权限、预算和审核断言保持；不能以skipped作为业务成功。该实验独立于前次四项间歇失败，不推定所有失败共享同一根因。

### 1.1.87 当前实现边界

实际2个read adapter使用现有HarnessRegistry、严格Schema校验和固定执行契约。Owner事务10秒SQL时限、调用15秒中止，续页固定原15分钟截止、真实锚点及全投影指纹；返回再次核对完整权限，传输只复用ERP身份展示摘要。读取失败或权限变化不会自动转写入。原GET receipt是无排队、无预算、无重派发的恢复工具；提交不确定保留原键，队列暂不可用仍返回原持久queued任务。剩余工具循环、跨域计划、写adapter与MCP未实现。

## 1.1.113 原业务凭据驱动的持久依赖

`erp-agent-dependency-plan-v1` 首个固定依赖是 `procurement_invoice_to_finance_bill`。数据层仍拥有原采购发票、原版本、财务应付和审计；Harness 只保本人身份、出生权限上限、原命令引用、固定下游双键、明确到期时间及来源/原文/准备请求摘要。Agent 后续只能选择经注册的这种能力，不能把旧并列提案补写为依赖图或自行授权执行。

来源适配器重入原采购拥有者读取真实成功凭据。下游字段逐项映射供应商、发票号、币种、最小货币单位金额、原日期和实际发票 ID；原财务服务继续裁决合法性。先用短事务固定来源和准备摘要，提交后才调用原命令准备，再用短事务链接原结果，禁止持协调锁进入拥有者。数据库另从实际前置成功、发票凭据和采购版本重建三项规范摘要，出生字段不可改、引用单调、事务凭据由数据库铸造，协调变更与成功审计必须在同一事务。

每个依赖任务按当前成员与本任务出生上限取交集；前置原命令仍有自己的读取上限，不能将前置的旧财务权限一并套给新下游，也不能把前置执行确认传递给下游。下游仍使用原具体确认、原结果核对和原私文留存机制。GET/receipt 可以补回同一原键的协调引用，不能准备、确认、付款或派发队列。

取消只阻新准备，不撤销已经提交的原业务事实。已固定准备意图的在途调用可能产生待确认原命令，按原键读取并分别核对。页面只保存七个标量，以创建未知、准备未知和取消未知区分所需凭据；明确失权先失效读取代次再清正文。权限和对象核验保证读取/返回时的授权边界；服务器完成响应后发生的对象变化，不承诺实时撤回此前已传快照。

本增量复用现有 PostgreSQL、Nest、Zod 与命令拥有者，不新增工作引擎、模型调用、消费者或日用环境变量。真正183升级、同候选本人桌面/手机验收、普通采用与清理分别留证，未获得证据前不能标记通过。详见[执行契约](../integration/agent-dependency-plan.md)。
