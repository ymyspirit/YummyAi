## 1. 业务对象与责任

经营主线以商品方案为中心；执行主线以订单商品行为中心。业务任务只是这些对象的处理入口，不能另造一套与真实业务相冲突的完成状态。

| 对象 | 业务负责人 | 关键结果 |
| --- | --- | --- |
| 商品方案 | 商品开发 | 事实、样品、工艺、成本和供给可核验 |
| 销售方案 | 运营 | 定位、销售 SKU、定制内容和渠道资料完整 |
| 订单商品 | 审单与履约 | 要求准确、版本固定、数量可核对 |
| 制作任务 | 设计与审核 | 原图来源及正式文件可追溯 |
| 生产单 | 生产协调 | 工厂、数量、文件与排期已固定 |
| 发货单 | 物流 | 包裹和具体商品件数已实际交运 |
| 费用与结算 | 财务 | 依据充分、币种明确、差异可处理 |

## 2. 商品开发到销售

~~~mermaid
flowchart LR
  A[机会与竞品证据] --> B[商品事实草稿]
  B --> C[样品与供应能力核验]
  C --> D[规格和工艺版本]
  D --> E[印花与定制字段]
  E --> F[销售 SKU 与配方]
  F --> G[素材 文案 渠道资料]
  G --> H[审核并封存资料包]
  H --> I[授权接口或人工渠道执行]
  I --> J[核对平台结果与可售状态]
~~~

1. 研究人员保存带采集时间和缺项说明的研究证据，提出目标人群、购买场景与初步经济模型。
   评论采集默认关闭；启用后保留用户设置的页间延迟、进度、暂停状态与已采集/页面报告数量，不能为完成采集绕过平台保护。
2. 商品开发确认物理结构、尺寸口径、包装及定制范围；未核验项保留草稿状态。
3. 供应人员按实际工厂做样品与能力核验，固定工艺模板和报价版本。报价与量产验收分开。
4. 设计建立原创印花或来图模板；固定多个表面、区域、客户字段和款式映射。
5. 运营组织销售方案、渠道 SKU 和素材。所有产品事实回到商品主档引用，渠道文案不能反向修改工艺。
6. 审核者封存资料包。发布能力未核验时交付可用包及人工清单；实际发布后登记有凭据的执行结果。

异常：样品不合格退回供应核验；权利来源不完整阻断相关素材；站点不支持某字段时要求调整方案或人工配置，不静默丢弃；历史资料包保持原版本。

## 3. 接单到审单

~~~mermaid
flowchart TD
  A[授权同步或报告导入] --> B[订单身份去重]
  B --> C[逐商品获取定制资料]
  C --> D{匹配与资料完整吗}
  D -->|是| E[固定来源 规则 模板 配方]
  D -->|否| F[缺项或歧义待办]
  F --> G[补充资料并保存新版本]
  G --> D
  E --> H[审单并安排制作]
~~~

- 身份键包含租户、店铺账户、站点、平台订单号和平台订单商品号；SKU 不是订单唯一身份。
- 原始买家文字、字体、颜色、图片和选项保存在订单私有域，解释后的需求引用原件和解析器版本。
- 匹配采用下单时刻有效的渠道映射；无法唯一匹配时暂停该商品。其他完整商品继续按拆单策略推进。
- 审单可以记录人工纠错依据，但不伪装成修改了亚马逊买家原始提交。
- 后续报告出现取消、数量或地址变化时生成修订和待办。已经生产或购单的外部动作需单独处理。
- 订单要求变化使受影响制作审核失效；无关商品和历史审核不被重置。

## 4. 制图、检查与审核

制作状态：待资料 → 待制作 → 制作中 → 待技术检查 → 待审核 → 已批准。失败、需人工、暂停和作废是独立异常，不算完成。

| 步骤 | 输入 | 检查 | 输出 |
| --- | --- | --- | --- |
| 固定制作来源 | 商品行和已审需求 | 模板、规则、原图、工厂工艺版本齐全 | 制作任务快照 |
| 模板排版或 AI 制作 | 固定输入和模型配置 | 预算、授权、尺寸与允许变换 | 候选版本与费用记录 |
| 确定性处理 | 候选版本 | 原图不变；几何与颜色处理按配方执行 | 可重现的处理版本 |
| 技术检查 | 实际输出字节 | 文件格式、实际像素、有效 PPI、色域、出血与裁线等供应规范 | 技术报告及阻断项 |
| 人工审核 | 原始要求、候选稿和报告 | 内容准确、相似度、文字、布局和工艺 | 针对本版本的批准或驳回 |
| 客户校样 | 仅规则要求时执行 | 使用获准渠道、实际版本和真实反馈 | 确认、修改要求或待反馈 |

产品预览、亚马逊预览和正式印刷文件各自标注用途。技术检查通过不代表客户或工厂已同意。需要客户确认时，不能以内部审核替代；不需要时也不强制发起沟通。

异形抱枕执行前必须读取当前项目的 [专门流程](../operations/custom-pillow-workflow.md)，以订单固定制造版本和规则快照为准。本蓝图不复制任何 DPI、缝边或裁线数值到其他品类。

## 5. 路由、排期和工厂交付

路由先检查硬条件：产品工艺、实际生产地、可执行工序、模板、能力有效期、数量、产能、材料、工厂时区和承诺时限；再比较有证据的总成本与表现。缺少关键交期或价格时进入人工选择。

产能槽按工厂、能力、当地日期、工序、计量单位保存。预留在事务中竞争同一槽；过期预留可释放。工厂接单固定承诺，实际进度继续单独记录。改厂需要释放未执行分配并建立新分配，不能改写原工厂已发生的生产事实。

~~~mermaid
sequenceDiagram
  participant O as 生产协调
  participant E as ERP
  participant F as 工厂
  O->>E: 选择已审核稿和具体数量
  E->>E: 校验能力 预留产能 固定版本
  E-->>O: 返回生产单及交付包
  O->>F: 经接口或人工提交指定包
  F->>E: 收到文件的回执
  F->>E: 接受或拒绝指定文件与交期
  E-->>O: 接受后允许实际生产流转
~~~

生产状态：草稿 → 待安排 → 待工厂接受 → 已接受 → 生产中 → 待质检 → 合格待交运 → 已完成。暂停、拒收、取消和失败保留原因。

“发送成功”只证明发送动作。“收到”证明工厂取得文件。“接受”证明其对指定文件、数量和交期作出承诺。发货前仍需实际生产与质检证据。

## 6. 部分完成、拆单与返工

一个订单商品可以有多个数量分配和生产批次。各批次固定工厂、文件和计划。整单列表展示汇总进度，详情必须能展开每条商品与分配。

例：一条商品数量为 3，工厂 A 做 2，工厂 B 做 1。A 的 1 件不良，返工只关联该件，不增加客户购买数量。发货只可消耗合格且未发出的履约分配。退款 1 件不自动生成退货、不自动抵消另一件补做。

返工路径：登记不良与受影响数量 → 判断改图、同图补做或工艺调整 → 确认责任和费用状态 → 建立关联原单的返工生产单 → 新交付回执 → 再质检。原包、费用和拒收事实保持可读。

## 7. 采购与库存

- 备料：BOM 固定版本 → 毛需求 → 扣减合格可用库存及有效在途 → 形成建议。建议不能直接付款或下采购单。
- 采购：询价 → 供应商报价版本 → 采购审核与外部下单 → 到货验收 → 入库 → 发票核对 → 应付与付款证据。
- 扣料：生产预留 → 实际领料 → 退料或报损。库存余额由流水重建，不通过直接修改余额纠错。
- 转仓：发出与收到分别记录；在途不是目的仓可用库存。第三方仓快照有时间与来源，不直接覆盖本地账。
- 工厂自备材料以委外成本或工厂库存证据管理，不虚增为自有材料库存。

## 8. 物流与实际交运

1. 核对生产地点、发货地址、收件版本、包裹尺寸重量和承诺日期。
2. 询价并按已核验路线和服务条件选择。购单前重新核验报价与预算。
3. 写入稳定外部客户参考号和付费意图，再请求面单。超时或丢失响应转“结果不确定”。
4. 仅查询原意图。即使一次查询未找到，也不自动重新购买；由对账与人工核实解决。
5. 面单可提前交给工厂，但只有实际合格件完成交运才登记发货事实。
6. 按已授权能力向平台回传，并记录提交、接受、失败与对账。物流轨迹和实际送达不从面单状态推测。

一个包裹关联具体生产分配与数量。平台不允许的部分发货必须在预检中提示并提供人工处理方式。

## 9. 取消、地址修改、售后和退款

| 触发 | 处理 | 不允许自动推断 |
| --- | --- | --- |
| 制作前取消 | 固定取消来源，停止未执行任务，释放预留 | 本地取消已在平台完成 |
| 工厂接受后取消 | 向工厂提出停止请求，登记实际反馈和费用 | 请求已发等于停止成功 |
| 已购面单后改地址 | 阻断旧址继续使用，核对撤单与费用，建立新版本 | 旧面单自动失效或供应商自动退款 |
| 部分退款 | 关联商品、数量、币种、原因与授权 | 退款必然对应退货或补做 |
| 需重做 | 关联原履约分配，明确是否重新制图及谁承担成本 | 新生产件扩大原销售数量 |
| 退件 | 建立 RMA 或异常收件，检验可回用性与 PII 清理 | 定制商品一律可退或一律不可退 |

售后条件以站点、商品及实际政策版本核验，不在系统写死通用结论。退款、平台消息和供应商联系均需真实授权；本地登记不能伪装外部操作成功。

## 10. 财务、广告与经营反馈

销售、生产、面单、返工、退款和供应商账单通过外部参考与业务分配关联。财务处理来源相同的重复账单、币种、税费、发生时间及冲销关系，再计算固定版本的利润。

广告报表不能与订单强行一一关联。按平台实际报表粒度分析归因；需要分摊到 SKU 或日期时，固定规则并显示“管理分摊”。日报重跑使用新计算版本，不覆盖上次结论。

复盘落到可执行变化：未来生效的价格、模板、质检规则、路由、库存政策或广告建议。所有高风险执行继续保留审核和结果核对。

## 11. 通用异常处理

每个异常记录：对象与版本、业务影响、已发生外部动作、责任人、下一步、截止时间、安全重试条件和证据。通知只提示必要信息，不包含买家原图、地址或秘密。

关闭业务异常要求有解决依据；“忽略通知”不能关闭生产阻断，“任务完成”不能代替业务对象完成。后台超时任务由持久状态恢复，不依赖浏览器一直打开。

## 渠道登记与历史订单

资料包当前可读范围 → 只读核对店铺、平台编号、选款和生效区间 → 操作人员填写依据 → 原生事务重新检查并登记。已有未来映射不改写，结果不明复用本页原请求。订单按下单时间采用有效映射，已保存原包不随补录变化。见[运行契约](../integration/channel-mapping.md)。

## 研究采集的当前范围

研究、采集、私有素材和关联设计分别校验自己的权限范围，读取总数与条目同范围。
研究结论幂等重放先检查父对象当前写权限；签名及后台存储/提交之间发生撤权会阻断结果。
完整行为与本地验证边界见[研究授权](../integration/research-authority.md)。

订单审单/制作工作台在实际业务事务中核对每项所需订单权限；上传、私有读取、旧命令重放和父级跟进保持相同依据。责任安排不能扩张数据授权，原审核、生产及对外执行门禁保持，见[订单与跟进授权](../integration/order-authority.md)。

创意审核到正式设计复用原批次和版本，实际审批确认来源并记录当前决定；绑定SKU前复核全部目标、规格与素材，拒绝部分落地。设计审核和主版本选择不等于渠道发布或工厂接受，见[原生设计交接](../integration/native-design-authority.md)。

画布/批量设计、选款、素材审核及创意交接逐步复核项目拥有者与原引用。工作区个人草稿还受项目当前写入范围控制；素材批准保留真实授权种类，不替代生产放行。见[画布与工作区契约](../integration/canvas-workflow-authority.md)。

## 工厂执行与逐项检验 · 1.1.28

按固定生产文件登记真实工厂收到与接受，再记录开工和完工。新质检逐项明确核验，单件不合格登记实际责任和处理；整单通过要求全部项目通过。检验原版本冲突时保留填写，重新读取并重新检查。发货后发现问题进入售后；缺陷处置选择不会自动执行退款或补发。旧回执可按原内容恢复。见[质检契约](../integration/quality-assessment.md)。


## 发货来源核对与冲突修正 · 1.1.29

完工并逐项质检通过 → 核对实际装箱批次与数量 → 保存发货草稿 → 核对原生产版本与通过质检后审核占用 → 正式出库前再次核对 → 独立记录实际交运和平台确认。来源变化时保留原填写，重新核对并建立新发货版本，再重新审核。旧来源缺失不推断批次，已交运旧版本不进入改版路径。原始物流即使与当前计划冲突仍保存，异常处理不能释放实际消耗。见[完整接口与边界](../integration/shipment-production-sources.md)。


### 1.1.30 实物质检组

按互不重叠的实际位置划分同一检查结论及缺陷组合，完整覆盖原生产数量；合格组进入装箱，待处理组选择复检或补做。复检只替代所选原组，补做按原组共享数量约束，原记录与已交运事实保留。详见[分组与补做](../integration/quality-groups.md)。

## 制造基础增量 · 1.1.31

制造模板先选择实际SPU和当前规格，逐行记录材料、耗量基本单位、损耗及责任，再由有制造审核权限的操作员明确批准。新草稿不自动取代原已批准版本；规格变化阻止新备料建议，原版本历史保留。后续生产要固定制造版本与独立工厂版本，当前0133基础未接通生产下达及物料实际耗用。见[制造契约](../integration/manufacturing-recipes.md)。


## 制造模板工作台 · 1.1.32

具体SPU/规格 → 制造草稿 → 实际物料与耗量/损耗口径 → 供料与工序责任 → 独立审核 → 已批准版本的精确备料提案。修改生成新版本，不覆盖上一批准版本。已下达生产固定制造版本的步骤继续建设，不能将本页面当作生产下达或实际库存流水。见[制造契约](../integration/manufacturing-recipes.md)。

## 固定制造后交付 · 1.1.33

原审核来源 → 明确选择已批准制造版本并确认销售单位 → 原子下达并固定制造绑定 → 按实际工厂生成V3包 → 工厂核对原JPG、材料/工序/责任及数量 → 记录收到 → 携带原制造清单校验值独立接受。接受不自动产生完工、质检、可发数量或实际领料。旧包和原回执保持原依据，缺制造历史不从今天的模板补写；任何改稿/补做继续生成新版本并重新交接。见[制造交付契约](../integration/manufacturing-delivery.md)。

### 运营异常恢复 · 1.1.34

制造读取暂时失败 → 保留原选择并暂停下达 → 明确重新核对 → 只有当前来源和权限成立才继续。生产提交结果未知 → 锁定原正文和请求编号 → 恢复本次提交结果 → 回读实际原生产，再交付。当前失权移除私有来源，旧成功响应不能恢复；部分返工和费用以实际回执回读为准。见[运营交接契约](../integration/production-operator-handoff.md)。

### 当前生产入口与失败恢复

审核稿按整单或单商品/拆厂安排；无审单商品在已审核设计直接生产中明确产品规格、设计文件、采购来源、制造版本和工厂，再建立内部安排。单商品数量按原履约数量账核对；取消但已经实际交运的原生产不能重新释放。固定来源、创建与审计同笔提交，原版本不被今日目录覆盖。读取失败保留填写，提交未知恢复原请求，已知保存后的刷新失败只重新读取。新稿返工只读固定工艺要求，补充说明独立填写。工厂接受、实际生产、质检和交运仍是独立事实，见[入口契约](../integration/production-entry.md)。

## 1.1.44 精确库存与原BOM实际物料

备料按原生产绑定核对物料、单位与责任 → 明确库位和批次预留 → 实际发生后确认耗用 → 逐次减少原预留余量并扣实物 → 释放未用预留或引用原耗用实际退料。工厂自备材料走手工报告及原报告更正，不经过商家扣料路径。各事件不能替代工厂接受、开产、完工、质检和交运。执行中网络中断先查询原编号回执，未查询到不能断言未执行。

接口、已验证结果与剩余项见[物料契约](../integration/production-material-execution.md)及[本批进展](../project-control/INVENTORY_EXECUTION_PROGRESS_20261020.md)。
