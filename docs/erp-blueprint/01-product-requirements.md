### 3.1 总体架构决策：统一产品，店铺节点独立部署

用户确认采用“YummyAI 作为大脑，调用各店铺 API 服务”的方向。产品入口、人员身份、权限、业务数据与任务记录统一归属 YummyAI；运行服务按中心和店铺节点分开部署，现阶段仍在同一个代码仓库维护。此处“大脑”包括确定性的业务后端和 Harness：Agent 理解需求、生成计划及分析，业务服务核验当前权限、版本、预算和副作用后执行。

| 组成 | 产品职责 | 部署与数据边界 |
| --- | --- | --- |
| YummyAI 控制中心 | ERP 工作台、租户成员与店铺绑定、业务事实、任务与审批、数据汇总、分析、调用费用和审计 | 复用现有 API、Worker、数据库与私有存储；业务事实仍由各模块拥有者保存 |
| 每店 API 节点 | 使用本店授权读取或执行已获准的平台操作，处理本店限流、同步检查点与执行回执 | 每店一台独立服务器、一个活动节点绑定；同一节点程序部署多份，凭据与执行范围按店铺隔离 |
| 共享数据连接器 | SIF、XYDC、SellerSprite、Sorftime、Keepa、独立站分析等研究或分析能力 | 中心按组织/账号授权、许可、出口和额度受控调用；无需为每个店铺重复部署全部供应商 |
| 模型与媒体服务 | 文本分析、图片、语音和本地推理能力 | 中心复用模型路由、方法、预算及费用拥有者；GPU 等资源按负载独立部署 |
| 紫鸟人工运营环境 | 人工登录后台、查看页面及办理需人工完成的业务 | 保留浏览器运营职责，API 节点部署在另行购买的服务器上 |

店铺节点只处理绑定店铺和已准入操作。店铺 LWA、SP-API 及 Ads API 访问经过对应节点；Ads 仍独立核验广告账户、授权和操作能力。节点不取得中央数据库或 Redis 凭据，返回的数据和回执由中心业务拥有者校验、去重并入库。

日常报表优先读取已经同步且当前有权查看的 ERP 数据，展示来源、业务时区、数据截至时间、最后同步时间与缺数覆盖。用户要求刷新或定时同步触发时，中心创建持久任务，各节点领取本店任务并返回结果；跨店汇总按权限、时间、币种和指标口径计算，Agent 使用受权结果分析。部分店铺失败时保留逐店状态，不把部分结果显示为全部完成。

节点离线时暂停新平台请求，已同步结果按实际时间展示；恢复后核对原意图与同步检查点。写操作或付费请求结果未知时先查原结果，不能因更换节点或重复点击再次提交。节点迁移、证书撤销、授权撤销和备用接管均需独立验收。

对外由 YummyAI 提供统一 MCP 入口和委派权限，Codex、Claude 等客户端只调用获准能力。店铺节点使用内部受限任务协议，实际通信由节点主动建立认证连接并领取任务。外部 Agent 的身份和 Token 不能直接用于访问节点。

数据与工具的完整功能、连接方式、费用、结果读取及逐供应商最低能力，继续由[数据与工具专项 PRD](../upgrade-plans/data-tools-mcp-2026-10-18/PRD.md)、[最终集成范围](../upgrade-plans/data-tools-mcp-2026-10-18/FINAL-INTEGRATION-SCOPE.md)及其结构化登记承载。44项截图最低目标、12项补充和10类 Agent 客户端的范围保持；它们属于升级建设目标，不改变 P0 审核导出与 P1 授权执行边界。专项冻结基线早于当前主蓝图，实施前必须重新对齐现行拥有者、契约、权限及项目状态。

### 3.2 本架构的交付口径

关联 R15、R20、R34—R35、R38—R41；主线仍使用原48需求、54工作包和8阶段，供应商细项沿用专项编号追踪。节点的安装、身份登记、心跳、准入、读同步、撤销、升级、停用及恢复全部可验证，才计入对应工作包。接通只读不代表写入获准，安装或出现工具卡片不代表真实接口接通；具体场景见[质量与运维验收](08-quality-security-operations.md)。本次文档更新不计作软件验收或正式部署。

## 4. 三条关键用户旅程

1. **开发并销售商品**：研究机会 → 产品事实与样品 → 工厂与工艺 → 原创设计与定制字段 → 销售 SKU 与配方 → 素材及文案 → 审核导出 → 授权渠道执行与核验。
2. **履约一件定制商品**：接单 → 固定原始资料及版本 → 匹配 SKU → 审单 → 制图 → 技术检查与审核 → 提交工厂默认排产 → Excel/CSV工厂状态同步 → 质检 → 实际交运 → 售后。
3. **改进经营**：导入收入与费用 → 补足成本与汇率 → 固定利润计算版本 → 识别亏损或延误原因 → 修改未来有效的商品、供应和广告方案。

## 6. 核心业务约束

- 同一订单报告重复导入不能重复创建订单；相同文件不能冒充新的审批结果。
- 客户选择的“款式”可用于匹配内部销售 SKU，不能误印成生产文字。
- 修改产品模板只影响未来选择，不能静默改变已接订单。
- 低清图片不能靠修改 DPI 标签通过；几何修正不得重新生成或改画原图。
- 未收到客户确认不等于客户拒绝；是否需要校样由已固定商品与订单规则决定。
- 工厂确认收到文件不等于接受文件；接受不等于完工；面单签发不等于交运。
- 自动购买、退款、广告改价、采购下单、付款分别受操作权限、范围和预算约束。

## 7. 衡量成功

先采集 2 周基线，再由经营负责人确认目标。下面是指标定义，不是已达到的业绩或通用行业门槛。

| 指标 | 定义 | 使用限制 |
| --- | --- | --- |
| 单均人工耗时 | 记录的有效处理分钟 / 对应完成商品件数 | 区分审单、制图、催单、售后，不把等待计成人工 |
| 首次制作通过率 | 首个提交版本通过审核的任务 / 有审核结论的任务 | 客户、操作员和工厂的通过率分别统计 |
| 准时交运率 | 截止时间前实际交运的应交运件 / 到期应交运件 | 无承诺日期、取消件和待核实交运单独列示 |
| 返工率与退款率 | 返工件数 / 已生产件数；退款金额 / 同口径净销售额 | 标明时间窗口、原因和迟到结果 |
| 订单贡献利润 | 可归属净收入减可归属变动成本和规则分摊费用 | 成本不完整不显示确定利润；币种先统一 |
| 供应商表现 | 按时接受、交付、质检和争议处理的独立指标 | 小样本显式显示，不能仅按最低报价排序 |

## 1.1.113 原采购发票到财务应付的依赖计划
