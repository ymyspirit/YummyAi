## 1. 怎么使用这份计划

先把当前系统逐项映射为可沿用、需修复、需补建和待外部验证，再依次交付可演示的业务结果。每一阶段都包含界面、契约、服务、数据、权限、异常、测试和手册，不能只做页面或数据库。

蓝图覆盖整个 ERP；实施时按纵向业务切片推进。现有功能只有通过真实路径验收后才计入交付。接口审批、样品等待和工厂商务谈判单列为外部依赖，不能被开发完成代替。

## 3. 每阶段的可演示脚本

- S1：运营建 SPU 草稿 → 补规格 → 供应登记实际工厂与样品 → 另租户无法查看 → 未核验能力不能用于生产。
- S2：原创印花加来图字段 → 绑定正反面 → 生成销售方案 → 审核封存 → 下载后核对内容与文件字节。
- S3：导入一单多商品 → 一行缺图 → 完整行进入审单 → 手工补 ZIP 只修复对应行 → 再导入无重复。
- S4：按固定模板制作 → 低像素触发阻断 → 合法修正 → 重新核验和审核 → 改图后旧批准失效。
- S5：一条数量 3 拆给两工厂 → 同时预留产能 → 文件接受 → 一件不良 → 只返工该件 → 保持原件数量与责任关系。
- S6：备料收货 → 合格件询价 → 模拟购单响应丢失 → 查原参考号 → 实际交运 → 部分退款 → 有证据重算利润。
- S7：导入实际授权广告报告 → 建议审核 → 登记真实执行 → 第二品类按独立供应规范运行 → 演练恢复与 PII 清理。

模拟故障只能在测试环境发生，不伪造真实工厂、生产或发货事实。真实外部付费验证必须具备相应授权并明确金额范围。

## 6. 一张工作包如何真正完成

1. 写清业务触发、输入输出、权限、版本和异常。
2. 核对已有开源与内部模块，选择复用方式。
3. 先改共享契约和迁移设计，再做拥有者服务及作业。
4. 做真实页面与人工纠错入口，显示空、缺、错和不确定状态。
5. 验证不变量、失败恢复及真实浏览器行为。
6. 清理测试资源，更新手册、能力台账和需求追踪。
7. 由业务负责人演示验收；技术完成和外部已成功分别记录。

## 7. 扩大自动化的条件

每个流程先有人工或规则基线，再做固定样本的辅助模式与影子运行。检查合格交付成本、关键错误、返工、复核分钟及恢复。只有操作权限、预算、回退与可观察性具备时才扩大执行范围。

多 Agent、模型切换和跨渠道扩展各自形成受控实验，不因“人数增长”自动升级架构。参考 [材料辩证阅读](14-critical-reading-agent-decisions.md)。

## 8. 阶段停止与回退

出现跨租户、错单生产、重复付费、原图被覆盖、无法恢复或关键成本漏算，停止相关自动执行，保留安全读取和人工处理入口。回退应用版本不得重放已发生外部动作；数据库采用兼容迁移及事件纠错，不直接恢复旧库覆盖新交易。

阶段验收没有完成就保留缺口与负责人，不把“界面能点”或“单测通过”改称业务已交付。完整发布条件见 [08](08-quality-security-operations.md)。
