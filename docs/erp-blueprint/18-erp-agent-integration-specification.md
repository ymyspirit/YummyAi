## 全 ERP 接入的实施口径

数据层继续以订单、商品、设计、工厂、物流、库存和财务等原模块为事实来源；知识库保存经治理的资料与版本，设计资产继续使用无限画布和原创意流程。Agent只通过有权限、有来源和固定版本的接口取得资料，不能另建业务真相或直接写数据库。

Harness层统一能力注册、身份与逐项权限、上下文与版本、预算、工具调用、持久任务、检查点、幂等恢复、审计与产物核验。读取、提出方案、准备原业务操作和明确确认分开；未知提交先查原回执，已提交付费请求不自动重买。具体业务服务继续决定数量、金额、生产资格和实际外部动作。

Agent层由一个目标入口结合领域能力完成分析与计划，需要时派发受控子任务。日常使用者可以提出“核对这批订单的排产、质检、发货与费用，并列出异常”，任务应显示当前步骤、已读来源、待补资料、费用、检查点和待确认动作。跨领域组合必须在对应工具、来源核验、费用和恢复均通过后开放，不能从目录中的能力名称推断已经可调用。

当前 native-v3 已将十一类业务读取与生产、发货、物流三类履约读取绑定到同一持久模型任务；原五域37种命令通过原准备和逐项确认接入。个人 MCP-v2 复用同一原业务服务、任务、费用和权限，隔离 Codex CLI 已实际发现五入口并读取原 SKU，尚不代表日常桌面采用。相关局部证据见[内置模型接入](../project-control/ERP_AGENT_NATIVE_V3_PROGRESS_20261022.md)及[个人 MCP 接入](../project-control/ERP_AGENT_MCP_V2_PROGRESS_20261022.md)。中央店铺授权生命周期和Windows每店节点身份、双向TLS、绑定及心跳已有局部验证与清理证据；原身份v1仍只表示身份与心跳；节点原能力同步已按独立执行协议通过局部36项检查及清理，真实店铺或普通环境尚未采用，其他节点操作继续逐项接入。跨域依赖和受控子任务、普通环境采用、实际宿主及真实业务试点继续。每一步同步源码、PRD、状态与清理证据。

## 1. 用户得到什么

1.1.103 前置修复已通过局部38项检查及清理：原 Listing 同步固定完整目标与本人 requestKey，丢响应只读取原回执。Agent 接入必须继承这一原业务身份，不能以再次提交或换键作为恢复。当前未新增节点校验预览、Listing 读取或发布能力；原能力同步局部验证保留。具体派发崩溃窗口、权限和采用限制见[原同步意图契约](../integration/listing-sync-intent.md)。

现有AI任务工作台成为统一入口，用户描述目标、选择有权业务对象，系统读取真实依据，产生可核对的步骤，执行已允许的查询和分析；业务变更由原服务准备命令、按原流程确认、执行并返回实际回执。每步可见来源、版本、费用、状态和下一步，断线后继续原任务。

设计目标是覆盖ERP全部业务域，同时保留原表格、表单和无限画布。内置Agent与外部Agent共用同一受控能力目录和业务服务。外部接入通过标准MCP适配层，具体客户端兼容性逐个验证。1.1.85当时没有客户端运行证据；1.1.99已补隔离Codex CLI实调用，日常桌面用户采用仍待完成。

例：“检查今天抱枕订单的履约异常”。任务应读取完整有权订单集合、原生产及工厂观察、实际发货/物流依据，给出带来源的异常和处理建议；缺少某域权限或分页未完成时显示具体缺口，不能把当前页当全部订单。该请求本身不构成对外催单、重新生产或发货批准。

## 3. 三层职责

~~~mermaid
flowchart TB
  U[ERP统一AI工作台 或外部Agent] --> A[Agent 识别目标 选择已注册能力 解释结果]
  A --> H[Harness 当前授权 固定计划 预算 确认 执行 恢复 审计]
  H --> O[原业务应用服务 版本与并发 实际操作 原回执]
  O --> D[原租户数据库 私有文件 不可变事实及执行记录]
  K[已发布知识 规则 方法] --> H
~~~

数据层保留现有业务事实和来源，不另建Agent库存、生产、利润或支付账。Harness复用现有注册器、持久命令、预算及恢复策略。Agent做目标拆分、受限工具选择和解释，不持数据库凭据，不执行任意SQL/HTTP/Shell，不从工具描述或知识文本安装新能力。

跨模块计划只保存编排身份、固定输入、依赖及原owner命令/运行/回执引用。实际执行、数值计算、订单状态、审核和外部回执仍由原owner负责。读计划不得隐式推进任务。多Agent仅在具体评测支持时用于运行；开发阶段的主控加三个子Agent分工不等于每个业务任务都并行多Agent。

## 4. 工具目录与执行协议

每项能力固定key/version、所属模块、严格输入输出Schema及checksum、权限与对象策略、数据类别、效应、费用/预算、运行期限、恢复方式、原批准门及结果读取方式。不同能力分别表达查询、分析、生成候选、准备业务命令、执行原命令和读取原结果。

目录必须区分“当前可用”“未授权”“缺少来源”“未配置”“未实现”“上游未知”，不可将路由存在、模型能描述或目录可搜索视作已接通。搜索隐藏无权对象和秘密。调用者不能传tenant、任意URL、任意SQL、执行器位置或自选授权证明。

对外沿主架构的五类固定入口：能力搜索、单项Schema、受控查询/执行、保存结果读取、用量/余额。入口可承载很多业务能力，不把每个API原样暴露成工具。MCP只适配协议，内部网页与工作流直接复用相同应用服务，不绕道公共MCP后端制造第二次身份或计费。

一次运行依次固定：请求人/委派来源与上限、真实对象/版本、允许工具及Schema、知识/方法版本、原生模型路由、费用边界、步骤依赖和保留期限。执行前和外部I/O后重新核对当前权限与来源；幂等、并发、提交标记、租约、原响应、费用和未知结果沿用原owner。

查询和准备草稿可以按已有权限自动完成。内部业务写入与审批操作分别授权；付款、对外发布、生产放行、联系工厂等沿原业务确认，不因Agent计划或聊天中的模型建议绕过。用户已有的明确授权应复用，不重复索要内部步骤许可；批准必须指向可核对的具体对象、版本和动作。

## 5. 委派身份是首个实施前置

目前API Client只有九个read scopes；当前loader返回tenant dataScope，没有逐权限scope和team上限，旧认证函数与创建路径尚需补当前成员和原始范围交集的运行证据。不得直接给旧key增加write/run作为全ERP Agent身份。

目标有效权限等于原委派上限、当前委派许可、当前成员逐权限scope、当前团队及业务对象授权的交集。原授权不能因之后加入团队或升级角色自动扩张；撤销/成员停用/范围缩窄必须影响新执行及历史私有内容读取。最小成功回执与可读私文分开，丢失权限不能凭回执恢复原正文。

新增明确版本的委派契约及旧key迁移策略；旧记录没有原scope或team证据时不得用今天权限补造出生上限。兼容和收紧行为先通过真实RLS、撤权、团队及旧记录反例，再用于统一工具网关。此处记录当前静态缺口，不宣称已完成安全修复或漏洞运行验证。

## 6. 工作台与断线续做

扩展现有[AI任务工作台](../../apps/web/src/features/ai-tasks/ai-task-workspace.tsx)，保留全局导航和[业务任务](../../apps/web/src/features/business-tasks/business-task-source-picker.tsx)。各模块提供小型“交给AI处理本对象”入口，传类型、真实ID、固定版本与受限返回位置；服务端按当前本人权限重读依据。

工作台展示目标、对象及当前依据、可审查计划、每步状态、具体费用/未知、需核对事项及实际回执。异常能定位到原业务表单；更新版本后重新准备，不悄悄替换操作者已核对的输入。

普通Assist当前请求键主要在内存中，不能把benchmark的专用恢复机制当作所有Agent已可跨刷新恢复。先补普通任务持久原请求与最小回执，再汇总多步骤原键；未知POST只查询原键，确认未提交前不能换新键重复收费或执行。当前身份变化立即隐藏私文、关闭旧抽屉并隔离迟到响应，刷新后按新身份重读。

## 7. 知识、数值与成本

已发布知识提供规则/SOP，实时ERP服务提供事实；RAG不能替代订单、库存、物流或财务查询。表格和上游描述是数据，不是给Agent的新系统指令。图片、竞品和客户资料分别遵守原域、授权和保留要求。

现business/role v1评分检查结构、原允许来源及声明的文本包含，不证明金额、数量、单位、币种或引用字段支持结论。独立纯内存审查已复现五个错误数值/错误合法引用仍可文本通过的反例。后续固定字段核验必须有新版本契约、真实owner输入、独立预期和硬失败；不得用正则从自由文本猜金额，或改写旧生产输出Schema、历史评分与原工具checksum。视觉质量、实物真实性和商业最优仍需人工或专门可证工具。

现成本已覆盖全部尝试、逐次人审、活动指纹对应的存储维护，保留估计/未知；继续复用。显式needs_review但原硬失败的成本口径存在待裁决边界，应明确当前asOf、资格分母和未完人工工作，不静默更改v1封存政策。模型、上游查询、生成、工具重试及人工成本分别记录，不能仅按token报价承诺完整单位合格成本。
