## 1. 设计决策台账

| ID | 决策 | 理由与代价 | 重新评估条件 |
| --- | --- | --- | --- |
| D01 | 自营中台与工厂协同两条主线一起设计 | 用户已确认；先有真实运营，再扩展服务对象 | 业务明确转为纯软件或纯工厂服务 |
| D02 | 首发 Amazon Custom / FBM，其他渠道用适配器 | 减少站点和履约语义混淆；保留标准商品库存模型 | 首发实际业务不同或渠道接口经验证 |
| D03 | 沿用模块化单体与 Worker | 事务与维护简单；复用现有投入 | 真实负载和组织边界证明独立服务有收益 |
| D04 | 商品方案与订单商品行为两条身份主线 | 商品可复用、履约可追责；需要清楚的组合和数量账 | 产品类型证明身份模型不能表达 |
| D05 | 工厂按实际地点与能力版本管理 | 品质、交期和原产地更准确；建档核验投入较大 | 出现多工序跨厂协同后补充工艺网络 |
| D06 | 状态由确定性服务与持久任务控制 | 可恢复和可核验；不能让对话临时状态代替事务 | 无；具体实现可随证据改进 |
| D07 | 单流程/单 Agent 基线先行，多 Agent 经评测再用 | 材料 P20 本身允许同一 Agent 分步；控制交接成本 | 独立并行任务的收益及质量有实际证据 |
| D08 | 规则、方法、业务事实与模型建议分开 | 避免知识覆盖事实、指南越权；需要版本与来源管理 | 无；存储与检索实现可改 |
| D09 | 外部写操作逐能力启用 | 授权和费用风险不同；保留人工核验路径 | 对应账户有实测、预算和不确定恢复证据 |
| D10 | 所有高价值历史固定版本，PII 正文独立清理 | 重现与隐私同时满足；对象生命周期较复杂 | 政策变化时更新适用快照与清理策略 |
| D11 | 不整体替换为开源 ERP | 保留租户、制作和历史资产；仍参考采购制造模型 | 逐模块完全成本证明外部 ERP 更适合 |
| D12 | 对外卖家商业化可选且后置 | 防止首发同时承担客户支持与多方服务复杂度 | 自营、工厂协同和单位经济验证通过 |

## 2. 主要风险

| ID | 风险 | 影响 | 负责人角色 | 应对与验证 |
| --- | --- | --- | --- | --- |
| K01 | Custom 配置或订单资料接口覆盖不完整 | 漏字段、错误制作 | 集成/运营 | 逐字段样本核验，保留报告与固定包人工路径；T08 T22 |
| K02 | 工厂有报价但没有真实稳定能力 | 延误、质量和赔偿 | 生产/供应 | 样品、试单、能力有效期和备用路线；T09 T11 |
| K03 | 制图模型改变主体或文字 | 客诉和返工 | 设计/审核 | 固定输入、确定性检查、人工对照和样品；T10 T21 |
| K04 | 误用旧稿、错 SKU 或数量重复 | 错误生产和重复发货 | 产品/技术 | 生效映射、文件校验、版本和数量门禁；T05 T11 |
| K05 | 外部响应丢失后再次购单/退款 | 重复费用 | 物流/技术 | 持久意图、原参考查询、预算占用和人工核对；T12 T16 |
| K06 | 买家数据跨租户、跨工厂或进通用知识库 | 数据泄漏 | 安全/技术 | 对象关系、RLS、分域和生命周期；T01 T02 T03 |
| K07 | 成本漏项或重复、币种混加 | 假利润和错误投放 | 财务/运营 | 费用覆盖、来源去重、FX 与分摊版本；T17 T18 |
| K08 | 用主观评分或低 token 费选模型 | 复核返工成本上升 | 业务/技术 | 统一样本、关键错误门槛和单位合格成本；T21 |
| K09 | 系统大而无持续维护者 | 接口失效、恢复困难 | 经营/技术 | 每模块买建判断、负责人和维护预算；S0/B02 |
| K10 | 把已有文档或测试文件当实测结果 | 误判可用性和工期 | 交付负责人 | 源码、模拟、真实环境、业务验收分别留证 |
| K11 | 历史回填使用今天规则 | 生产与审计失真 | 数据/业务 | 缺项显式、旧规则固定和迁移对照；T24 |
| K12 | 跨境制造与发货承诺不实 | 延误、声明错误 | 供应/运营 | 地点分离、真实服务条件和时间核验；T09 T15 |
| K13 | 多 Agent 增加上下文和协作开销 | 成本高、交接错误 | 技术/业务 | 先单流程基线，按独立任务收益决定是否拆分 |
| K14 | 范围扩大到多个渠道和商业化 | 延误核心交付 | 产品负责人 | S0 明确首发，R48 独立评审，不删掉完整目标 |

## 4. 文档接下来的修订方式

新证据出现时更新适用范围、结论、来源日期、影响需求和工作包。不要因为修改模型、工具或团队人数就重写全部业务身份。重大变更通过新 ADR 或本台账新行解释，历史执行继续引用当时版本。
