## 1. 设计目标

用户应当迅速知道当前处理哪个对象、依据哪个版本、哪里阻断、下一步由谁完成。界面采用安静、紧凑的工作台语言，白色为主、黑色承担层级、蓝色表示选择和动作。状态同时使用文字和图标，不仅靠颜色。

已使用 frontend-design 方法形成方向：以“从一条订单追到工厂交付的工作记录”为识别特征。保留稳定侧栏、业务列表和详情，不使用营销式首屏或嵌套装饰卡片。

## 7. 操作与纠错

- 新建、编辑、复制、归档和恢复使用一致位置。复制预填允许修改的字段，不复制原审批与外部执行结果。
- 草稿保存失败保留用户输入；陈旧版本冲突展示服务器最新版本及差异，不能静默覆盖。
- 已审核对象的“修改”创建新版本；表单清楚说明会使哪些后续批准失效。
- 批量操作先显示所选对象、合格数、阻断数、费用范围和处理策略，明确当前页或全部筛选结果。
- 搜索与分页写入安全 URL 状态；订单原图、地址和敏感文字不写入 URL、localStorage 或通用浏览历史。
- 停用、外部付费、退款、发布与生产放行按权限提供具体确认。无需给每次普通草稿保存增加确认框。

## 8. 动画与连续过渡

每类元素具有进入、状态变化和退出行为；通过共享容器与稳定 key 实现，避免给海量表格单元逐个延迟。

| 场景 | 动画 | 限制 |
| --- | --- | --- |
| 页面与列表出现 | 内容层 140—180 ms 渐入及不超过 4 px 位移 | 立即可操作，不逐行拖延业务列表 |
| 列表进入详情 | 保持行和详情共享标识，180—240 ms 连续布局变化 | Morph / View Transition 只用于安全的界面外壳 |
| 抽屉与弹层 | 进入 180 ms，退出 140 ms，背景同步变化 | 焦点先后顺序与可读性优先 |
| 按钮交互 | hover 1.01、press 0.98、120 ms | 尊重设备能力，禁用状态不缩放 |
| 保存和进度 | 状态标签交叉淡入，进度平稳更新 | 文案来自真实状态，不能提前显示成功 |
| 条目消失或归档 | 120—160 ms 退场，列表位置连续收拢 | 已执行事实不因退场被删除 |
| 筛选与空状态 | 同一内容区域过渡并保留筛选位置 | 不以闪烁和整页骨架反复打断 |

prefers-reduced-motion 下去除移动、缩放和形变，以即时状态或短淡入提供同等信息。敏感图片不进入跨页面截图式过渡缓存；生产预览像素不受界面动画改变。

## 9. 响应式与可访问性

1440 px 使用侧栏、列表与详情分栏；1024 px 压缩次要列，详情可切换；390 px 使用全高菜单、单列内容和可关闭详情层。宽表格仅在自身容器滚动，页面不能横向溢出。

长标题、SKU、诊断和备注换行；金额、时间和固定格式控件保持稳定宽度。关键动作不依赖 hover。键盘可完整完成导航、筛选、查看、审核和关闭；焦点可见，弹层圈定焦点且关闭后回到触发元素。

## 10. 状态设计与验证

所有页面设计 loading、empty、partial、unauthorized、failed、stale、unknown_outcome 七类状态，并为可恢复问题给出下一步。错误说明指出哪个对象、什么缺项、由谁处理，保留安全的诊断编号。

样稿覆盖订单、商品方案、工厂协同、经营成本和建设阶段入口；用于检查信息层级、选择与详情、筛选、空态、移动导航和动画。样稿中的“接受演示任务”等动作只更新虚构本地演示状态。

实际 ERP 的页面验收必须使用真实应用路径和隔离数据，覆盖 1440、1024、390 px、长文本、键盘、减少动态效果和浏览器返回。样稿通过不能代替这些生产页面测试。
