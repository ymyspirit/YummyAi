# 创作后台原执行、权限与恢复

## 决策

复用 BullMQ、PostgreSQL、现有 HarnessRegistry/方法治理、ai_budget_ledger 和 POD_EXECUTION_ENCRYPTION_KEY 加密机制。参考 [BullMQ 幂等作业](https://docs.bullmq.io/patterns/idempotent-jobs)。队列仅提供原拥有者引用，不承载权限或预算事实。

creative_executions 是此前缺失的五类原操作执行证据，使用真实租户外键绑定 candidate、creative version、PSD inspection、mockup item 或 studio generation。业务状态仍由原拥有者维护，费用只占用原预算账本。按原拥有者及步骤唯一，源数据只保存指纹，不复制提示词或私有文件正文。

新执行在原创建事务固定原权限上限、代码契约、方法选择和实际源指纹；历史原操作不自动补造。后续角色扩权不扩大原上限；执行时始终要求真实当前成员、逐权限对象范围、源版本及当前业务状态。显式服务器适配器的原上限不是虚构当前成员的授权。

API 和 Worker 共用核心拥有者/范围策略。资产与订单的原纯权限策略抽到 authz，原 API 和 order-core 入口继续导出同一策略；框架适配器保留原 HTTP 错误行为。API 的开发依赖显式声明已有的 mockup-renderer 与 BullMQ，使用 Node 24.17 / pnpm 11.10 离线安装并禁用安装脚本；外部包与快照另做字节核验。

## 真实适配边界

既有 adaptArtwork 依据实际原图像素、焦点、安全区和目标尺寸决定是否需要扩图，wrapMode 不能证明会不会付费。因此 spec 步骤为确定性原步骤；只有需要扩图时才激活 outpaint 子调用。子调用继承原上限和拥有者，不能以当下更宽角色重新授权。父方法固定允许的扩图工具，父子分别保存调用及费用，避免重复计费。

Studio 受控视觉任务已存在以 generation ID 为 request_id 的预算预留，必须复用该条，不能再为 execution ID 创建第二条。其他付费步骤以各自执行 ID 占用原账本；本地裁切、编译、套图不伪造付费调用或零费用回执。

付费提交前保存原预算和提交 token；收到原响应后先保存费用凭据与加密检查点。已经提交却没有可恢复响应时进入核对，不能自动重调。租约与时间用数据库时钟，失效 token 不采用产物；原响应/费用凭据仍须在撤权或租约变化后按原调用独立保留。

产物写入使用执行专属、内容寻址的原位置，回读字节后再由拥有者事务原子采用。对象存储等待不持有成员授权锁。私有文件、权属审核、操作员审核与生产放行继续分别记录。
