# 来料、检验与入库边界

2026-10-20，R03/R12/R27/R28，B28/B33/B39/B40/B45。本文是后续实施规格，不表示完整收货检验已经实现。当前141分类和142收货原提交绑定已完成隔离验证和受控普通本地142采用；本文的完整到货/检验/入账仍待实施。

先核对现有开源流程。[ERPNext Quality Inspection](https://docs.frappe.io/erpnext/quality-inspection)将检验与原业务单据、抽样和标准关联；[Purchase Receipt](https://docs.frappe.io/erpnext/purchase-receipt)区分接收与拒收库位、数量和单位换算。本项目借鉴这些分离原则，继续复用原采购、库存和权限拥有者，没有引入另一套ERP或复制外部代码。以下原子提交、历史和权限约束是本项目设计。

## 数据层

到货事实固定原采购单和版本、原行、供应商、实到数量与单位、批号、实到时间、交接来源及实际记录者。每次到货单独保存，不能用采购计划数量替代实际数量。来源修订、检验和接受入账都引用这条事实；已入账部分不能通过修改到货草稿抹去。

待检和拒收有明确保管位置、数量和责任，其可用量为零。到货登记不能直接产生可生产预留量；库存拥有者只接受已核准的入库数量。实物保管、商家所有权、供应商自备和成本确认分别记录，未知不能转为自有或零成本。跨责任转移必须有业务事实及对应数量，不依靠分类标签推断。

检验保留标准版本、原到货行、抽样口径、实际测量和单位、缺项、结论、证据引用、检验者与核准者。无测量或缺依据保持待处理，不用AI判断补齐。标准修订影响新检验，原检验仍固定原版本。复检追加事实，不覆盖旧结论；如果已有入账，其纠正走引用原事实的隔离、退货或差异流程。

原到货数量必须能分解为待处理、核准接受及拒收/退回等互斥去向；每一去向不得重复占用同一部分。持有、检验、核准和实际入账分别可追踪。新数量合同保持最多9位精确十进制；件/对/套只能是整数。采购单位与库存单位不同时固定经确认的换算版本，缺失时拒绝自动换算，不修改原采购历史。

## Harness层

到货、检验核准、接受入账和拒收处置各有固定输入和结果的命令，复用当前业务拥有者及持久命令恢复机制。最小成功请求校验不是完整持久命令；刷新、断线和新会话恢复必须另有准备意图、尝试和回执依据。

接受入账在同一事务内复核本人当前权限及原权限上限、采购版本、到货余量、检验版本/核准、实际地点、批号和原单位；锁定原到货行后，通过InventoryService取得租户重建共享锁、维度锁，写批次/流水、入账链接、数量去向和成功审计。相同原请求返回原回执；正文、原行或操作者不符拒绝。任一步失败不能留下库存、采购或审计的半笔成功。

并发接受、复检、撤权或退回都按同一原到货行协调。已核准不等于已入账，入账成功也不能由迟到旧页面撤销。差异进入明确待处理队列，未完成处置的拒收品不得消失。原生产质检域不直接拥有采购库存入账权，禁止跨模块直接改库存表。

特采是独立权限下的实际业务决定，保留不合格项、风险依据、范围和责任，不把检验改写为合格。是否允许特采、哪些产品必须双人复核以及适用标准须来自被确认的业务规则；缺规则时保持待处理，不能由Agent自行放宽。

## Agent层与界面

Agent可以从授权资料提取候选标准、整理测量和提示数量/版本冲突，输出含来源的待审建议。检验核准、特采、所有权与实际收货仍由有权限的操作者依据真实证据确认。任务固定知识/规则/方法版本，旧单缺依据明确显示，不能用当前知识覆盖历史。

操作台分别显示到货、待检、待核准、可入账及已入账的实际数量和原依据。页面填写在后台刷新后保持，依据变化时要求显式核对；只读、失权、证据不可读、部分处理和响应未知都有独立状态。再次点击保存不能绕过旧请求恢复。库存主档的五类分类只帮助检索和管理，不改变这些业务状态。

## 必须验证的行为

- 一张采购单可分批到货；一个到货行可部分接受和拒收，数量去向守恒，待检/拒收不可预留。
- 依据缺失、检验失败、待核准或批号/单位不符时不入可用库存；特采只在实际批准范围内有效。
- 两次并发入账或正文变更只产生被批准的数量；结果未知和本人新会话恢复不会重复移动库存。
- 后段审计失败使库存、入账、采购和去向全部回滚；当前成员撤权及窄范围不被旧授权或宽读取借用。
- 复检不覆盖原记录，已入账纠正引用原事实；拒收、退回及保管位置保持可解释。
- 真实旧库升级保持原收货、数量及迁移历史，不补造旧检验/换算/提交依据；普通采用另做新配对备份恢复。
- 真实个人界面在桌面/手机验收，测试数据和原始输出检查后清理，保留源码和简明证据。
