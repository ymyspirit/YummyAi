# 工厂外部编号绑定更正设计

2026-10-21，PRD 1.1.79。**不可变解除与更正已通过38项局部定向检查和本批清理，普通148未采用165，真实工厂及完整平台未验收。** 当前执行契约和实际证据分别记录，不把局部技术验证当作业务操作许可。

## 要解决的具体错误

工厂表的一行以同工厂外部编号对应本系统一整组原交付项。人工可能把编号绑定到错误组，或者工厂复用编号。直接改旧绑定会使原“已审核／已出库”的观察看似属于另一组，并改变历史含义，因此更正应新增证据。

## 已实现的操作

先查看原绑定ID、原工厂、原应用、完整交付项、生产版本、文件及制造hash、数量和已引用的观察。只有当前有权的运营人员可提出更正；必须说明原因并确认旧组和新组，禁止用最新订单版本自动代替原对象。原编号属于私文，到期后若无法重新核对，应重新提供明确来源，不从hash还原或猜测。

解绑新增不可变release事件，固定expectedRevision、原绑定itemsChecksum、最后观察sequence、来源证明、结构化理由及本人原请求；只阻止该绑定继续接受新观察。旧应用、原观察、实际生产与物流事实保留，页面明确显示该关联后来被更正，不能把旧记录隐藏成从未发生。

更正由同一事务登记旧绑定release与新的binding revision，并且只应用明确选中的新来源行。新绑定必须同工厂、完整满足原交付版本和数量约束，并通过原owner核验。允许旧新组部分重叠，完全相同组拒绝。序列化该工厂的应用，使用唯一活动修订和预期版本拒绝并发冲突；真实owner取得供应商UPDATE前不能先取其SHARE。原请求与审计闭包、丢响应同键恢复沿用现有机制，原文到期后仍按当前权限读原回执。

**旧观察不自动传播到新组。** 若新组需要“已审核”或“已出库”状态，必须对已确认来源建立新的明确应用；旧组的内部已提交、质检、实际发货、产能与物料账不得因解绑撤回或补造。作废仍为异常核对，不能自动取消生产。

## 实施与验收证据要求

新增共享契约、原绑定的修订/解除元数据、不可变更正事件、强制RLS与同事务审计，保持0163/0164字节和原不可变业务事实。服务只通过订单/交付/生产owner读取原事实。UI提供可核对的旧新组摘要、原因和版本冲突提示，明确确认后提交；Agent仅能建议。

定向验收覆盖重复外部编号、同组不同版本、数量汇总、跨工厂/租户/失权、并发释放与应用、过期私文、原请求恢复、旧状态不迁移以及提前触发延迟约束后的同事务后继拒绝。真正164旧源产生的历史凭据升级后原样可读且不回填更正事件。两种实际死锁在真实PID/锁屏障下复现后修复，最终9项current通过；不推论所有跨模块并发已验证。普通环境采用、上游真实订单和实际工厂业务确认单独记录。
