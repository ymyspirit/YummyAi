# 页面往返与操作连续性盘点

日期：2026-09-14。范围：当前本地 YummyAI 工作区。状态：收集与分析，未实施本清单中的功能调整。

存在与原先审单相似的问题，主要集中在两处：处理下一条记录时必须返回列表；跨板块后没有保留原来的 SKU、店铺或操作位置。订单中心刚增加的连续审单可作为对照。

本轮从当前导航登记表核对了 **33 个主入口、4 个辅助入口**，结合实际页面和组件代码整理出 **10 组需要改进的路径、2 组待进一步确认的问题**。这不是 37 个入口的完整业务验收；没有执行保存、审核、生产、收货、发货、发布或 AI 生成。

## 1. 记录口径

- **实际页面 + 代码**：只读页面可见结果与实现相互对应。未提交业务操作，因此不代表后续写入动作已经走通。
- **代码确认**：入口、参数、返回逻辑或连续操作缺口可以从当前实现确认；缺少适用记录或功能尚未启用的部分未实际执行。
- **待确认**：还需要明确操作角色、使用频率或用完整业务样本验证。
- “切换”包括整屏列表、详情、编辑器之间的工作视图替换。行内展开、保留列表的侧栏和同一记录内的标签切换，单独注明，不与跨页面往返混算。
- 以下是路径与额外步骤的分析，没有测量每单耗时，也没有推算节省工时。

### J01：四个履约中心仍是逐单进入、逐单退出

四个中心分别涉及：

| 中心 | 典型高频工作 | 当前连续性缺口 |
| --- | --- | --- |
| 制图中心 | 审核制作文件、记录客户校样确认、退回修改 | 详情只处理当前单；做下一单要回队列。需要编辑画布时还会进入整屏编辑会话 |
| 生产中心 | 登记工厂进度、完工数量、质检结果 | 多个订单商品逐一开详情，没有连续登记入口 |
| 发货中心 | 创建/审核包裹、记录交运、补录物流 | 操作集中在单条订单商品详情，下一条需返回列表 |
| 售后中心 | 查看沟通、记录处理决定、结案 | 当前单的操作在详情内；处理下一单仍需返回列表 |

通常从 A 详情开始处理 B，需要 **返回列表、进入 B** 两次工作视图切换。当前代码仅对订单中心启用连续审单侧栏；其余四中心在存在 `line` 参数时直接返回整屏详情。

同模块的“返回”会保留 URL 中已有的筛选参数，所以不能写成“所有筛选都丢失”。问题是列表组件被移出视图、没有同批次连续处理，并且未采用订单侧栏的滚动保留方式。

候选方向：沿用队列式侧栏、上一条/下一条和成功后继续。生产、交运、退款等各自的业务确认仍需保留，具体哪些动作允许“完成后下一条”要按岗位区分。

证据：[列表与详情分支](D:/YummyAI/apps/web/src/features/order-centers/order-center-workspace.tsx:247)、[导航滚动规则](D:/YummyAI/apps/web/src/features/order-centers/order-center-workspace.tsx:177)、[当前单操作面板](D:/YummyAI/apps/web/src/features/order-centers/order-operations-panel.tsx:103)、[制作编辑会话](D:/YummyAI/apps/web/src/features/order-centers/order-work-detail.tsx:286)。

### J02：跨环节带了订单身份，却没有保留处理队列

订单详情上方的“审单 / 制图 / 生产 / 发货 / 售后”都带 `line`，不会要求重新输入订单号。但链接没有来源筛选、页码或返回位置。例如从筛选后的队列去看生产，再点回审单，会进入只包含该订单身份的地址，原来的队列上下文没有随链接传递。

售后页的补做入口同样跳到当前单的生产页。跨岗位交接有独立页面的价值；同一操作者只是核对物流、文件或生产历史时，可以考虑在当前任务内查看摘要与明细，并支持准确返回原队列。

证据：[订单各环节链接](D:/YummyAI/apps/web/src/features/order-centers/order-work-detail.tsx:395)、[售后补做入口](D:/YummyAI/apps/web/src/features/order-centers/order-operations-panel.tsx:1022)。

### J03：销售 SKU 可以批量生成，后续仍逐条打开详情

产品开发支持按印花与多个规格组合生成 SKU；查看、制作、确认映射等后续工作在单 SKU 详情中完成。选择 SKU 时保留搜索、状态和页码，普通返回不等于筛选丢失，但没有下一 SKU 的操作入口。

本轮实际打开的是旧 SKU 映射详情。带完整制作配方的“编辑 → 审核 → 套图 → 资料包”部分依据代码梳理，未执行制作。

候选方向：保留左侧 SKU 清单或详情侧栏；允许按当前筛选连续核对。整屏生产编辑器继续携带当前 SKU 和回到该 SKU 的入口。

证据：[查询参数与选择状态](D:/YummyAI/apps/web/src/features/product-development/development-workspace.tsx:36)、[详情替换列表](D:/YummyAI/apps/web/src/features/product-development/development-workspace.tsx:141)、[单 SKU 返回入口](D:/YummyAI/apps/web/src/features/product-development/sales-sku-panel.tsx:255)。

### J04：套图后的返回目标过于宽泛

销售 SKU 的“进入套图工作台”已经带 `skuId` 和 `designVersionId`；套图页也接收设计版本作为初始选择。但套图页顶部“产品开发”固定指向 `/product-development`，没有回到原 SKU。切换套图批次的链接也只保留 `batch`，没有保留来源任务。

页面目前提示套图渲染未启用、缺少已批准模板包。因此已确认的是导航结构和返回目标，不能声称完整套图后返回流程已经实测。

候选方向：把“返回当前 SKU”作为明确入口，保留来源筛选与批次；成功后的下一步指向同一 SKU 的资料包准备。

证据：[SKU 到套图](D:/YummyAI/apps/web/src/features/product-development/sales-sku-panel.tsx:400)、[套图返回与批次切换](D:/YummyAI/apps/web/src/features/pod/mockup-batch-workbench.tsx:51)、[套图接收参数](<D:/YummyAI/apps/web/src/app/(erp)/pod-workbench/mockup-batches/page.tsx:9>)。

### J05：商品资料包链条中，Listing 编辑缺少回到当前 SKU 的入口

SKU 详情要求先在刊登控制台完善并审核 Listing，再回来封存资料包。打开 Listing 的链接只有 Listing ID；编辑器内没有“返回当前 SKU / 继续封存”的来源入口。操作者要通过产品开发列表重新定位，或依赖浏览器后退。

这与 Listing 自身的内容、媒体、合规标签页不同：后者已在同一编辑器中，无需拆成问题。

候选方向：保留当前 SKU 与资料包准备进度，完成文案/审核后明确回到相应 SKU；若 Listing 对应多个 SKU，显示本次来源，避免任意选一个返回。

证据：[资料包准备说明与 Listing 入口](D:/YummyAI/apps/web/src/features/product-development/sales-sku-panel.tsx:410)、[Listing 编辑器](D:/YummyAI/apps/web/src/features/listings/listing-editor.tsx:55)。

### J06：刊登缺少连续修订；返回目录没有来源筛选

目录中的每条记录打开独立 `/listings/:id`，没有携带原来的平台、状态、阻断项或页码筛选。实际编辑页没有上一条/下一条，面包屑“刊登控制台”链接指向无参数目录。

因此按“有阻断 / 低完整度”逐条修订时，内置路径需要反复返回与定位。浏览器后退可能恢复历史页；本轮没有把浏览器历史行为算作统一的产品返回能力。编辑器已有未保存改动保护，不能记成“没有保存保护”。

候选方向：以筛选结果作为修订队列，支持“保存新版本并下一条”、保留筛选的返回。现有批量发布功能与逐条修订是不同任务，不能替代这个入口。

证据：[目录详情链接](D:/YummyAI/apps/web/src/features/listings/listing-catalog.tsx:96)、[编辑标签与保存](D:/YummyAI/apps/web/src/features/listings/listing-editor.tsx:25)、[未保存保护](D:/YummyAI/apps/web/src/features/listings/listing-editor.tsx:41)、[面包屑实现](D:/YummyAI/apps/web/src/features/navigation/erp-breadcrumbs.tsx:27)。

### J07：已登记的印花到产品组合没有自动带入

创意项目已经支持在本页审核、登记印花与素材包，这部分无需额外去印花库。但登记完成后，每个“已登记”链接都只指向印花库首页，“进入产品组合”也只指向产品开发首页。组合表单的印花初始值为空，使用者还需重新选择刚处理的印花。

候选方向：登记结果可直接定位印花版本；“用此印花开发商品”带入当前已登记版本，再由操作者选择 SPU 与规格。

证据：[登记后的交接链接](D:/YummyAI/apps/web/src/features/canvas/creative-projects-workspace.tsx:941)、[组合表单初始选择](D:/YummyAI/apps/web/src/features/product-development/development-forms.tsx:525)。

### J08：采购链接传了 ID，但接收页没有使用

从供货报价创建采购草稿后，成功提示提供 `/procurement?order=...` 的“查看采购草稿”。当前采购页面没有接收查询参数，工作区也没有选中采购单、订单锚点或自动打开对应表单的逻辑；只渲染全部采购单。

这项主要是定位问题，采购本身的新建、审核、收货已经是页内弹窗。应优先补好这条定向入口，无需把已有采购操作全部改成新页面。

候选方向：消费订单 ID，定位/高亮或打开该采购单，并保留回到原供货报价的入口。

证据：[创建后查看链接](D:/YummyAI/apps/web/src/features/products/product-supply-workspace.tsx:37)、[采购页面入口](<D:/YummyAI/apps/web/src/app/(erp)/procurement/page.tsx:15>)、[采购单整表渲染](D:/YummyAI/apps/web/src/features/procurement/procurement-workspace.tsx:89)。

### J09：从单店看订单，范围变成同平台全部店铺

单店详情的“打开订单履约”仅传 `platform`。实际点击后订单中心的“店铺”仍为“全部”，需要再手动选择店铺。订单中心已有 `accountId` 筛选能力，缺口位于入口传参。

同页“打开 Listing 目录”只传 `marketplaceId`，表达的是站点范围；是否要提供按具体店铺的 Listing 投影视图，需要结合 Listing 与店铺的实际关联规则另行确认，不能直接把站点当成店铺。

候选方向：订单链接同时带店铺 ID；明确区分“这家店”和“这个平台/站点”的查看范围。

证据：[店铺下游链接](D:/YummyAI/apps/web/src/features/marketplaces/marketplace-accounts-workspace.tsx:56)、[订单支持 accountId](D:/YummyAI/apps/web/src/features/order-centers/order-center-workspace.tsx:19)。

### J10：临时补资料或配置后，缺少统一的回程

具体可见路径：

- 规格编辑缺工艺 → 工艺底稿库 → 生产文件与底稿 → 审核后回库登记 → 再回原规格。
- 组合商品缺规格 → SPU 与规格 → 登记 → 再回组合表单。
- 订单、创意或 Listing 的 AI 面板缺分析模型 → AI 模型配置；配置页只提供固定“进入生图工作台”，没有回到发起任务的入口。

前置准备有业务必要性；额外负担在于没有保留本次任务、填表位置和待选的新记录。这部分主要是低频配置和新产品准备，不应按日常审单的频率估算影响。未实测离开后的草稿是否丢失，先记录为草稿保留待核对。

候选方向：小型档案在原表单中补建并自动选中；完整编辑器和系统配置保留来源与返回入口。复杂工艺仍需实际编辑与审核。

证据：[规格的前置入口](D:/YummyAI/apps/web/src/features/product-development/development-forms.tsx:447)、[缺规格提示](D:/YummyAI/apps/web/src/features/product-development/development-forms.tsx:627)、[工艺底稿进入编辑器](D:/YummyAI/apps/web/src/features/order-centers/print-library-workspace.tsx:129)、[AI 配置跳转](D:/YummyAI/apps/web/src/features/ai-assist/assist-panel.tsx:270)、[配置页固定返回目标](D:/YummyAI/apps/web/src/features/creative-studio/model-settings.tsx:19)。

## 4. 已有较好连续性的部分

| 板块 | 当前做法 | 本轮结论 |
| --- | --- | --- |
| 订单中心 | 列表保持挂载，侧栏连续审单，保存成功才下一条 | 已改进，作为同类队列的参考；跨环节返回问题仍见 J02 |
| 研究资料库 | 同一行展开详情、快照、研究结论；图片独立预览 | 实际展开后仍保留列表，没有逐条详情往返 |
| 研究到创意 | 带研究项进入创意项目；固定来源可带快照与研究版本返回核对 | 已有对象和版本上下文，不应删除此类证据交接 |

## 6. 后续处理顺序建议

1. **先处理高频逐条工作**：制图/生产/发货/售后连续处理；销售 SKU 和 Listing 的同批次修订。
2. **同时修正小范围定位缺口**：店铺到订单补 accountId；采购页消费 order；套图/刊登准确返回来源 SKU。这些不需要重做整个导航。
3. **再贯通新产品准备**：已登记印花带入组合；工艺、规格、配置补齐后返回原任务。
4. **最后确认复杂整合**：人工工作流是否承接真实业务操作，以及长页台账是否需要对象侧栏。先选一个完整样本走通，再决定整合范围。

实施时的检查重点应包括：同一筛选队列能否连续处理、返回能否找回原对象与位置、保存失败是否保留输入、处理成功后才切换、未保存更改是否有保护、跨岗位动作是否仍要求各自确认。
